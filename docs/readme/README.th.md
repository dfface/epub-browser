# EPUB Browser

> **เปลี่ยนหนังสือให้เป็นเว็บไซต์ สร้างไลบรารีที่เป็นของคุณ**
>
> เผยแพร่หนังสือ EPUB และ PDF เป็นเว็บไซต์สแตติก หรือเรียกใช้ไลบรารีส่วนตัวแบบ self-hosted
> พร้อมบัญชี การซิงก์ความคืบหน้า คำอธิบายประกอบ และการอ่านแบบผสาน AI ที่เลือกใช้ได้

EPUB Browser ไม่ใช่เพียงตัวแปลงหนังสือ แต่เป็นแพลตฟอร์มการอ่านที่สมบูรณ์ ซึ่งคุณเผยแพร่ได้ทุกที่
หรือโฮสต์เอง EPUB และ PDF ใช้ Library หน้าหนังสือ สารบัญ โหมดการอ่าน ธีม การติดตามความคืบหน้า
และขั้นตอนคำอธิบายประกอบร่วมกัน หน้า PDF แต่ละหน้าจะกลายเป็นบทในตัวอ่าน โดย PDF.js เรนเดอร์ในเครื่อง
ภายในประสบการณ์การอ่านเดียวกัน ไม่ต้องมีตัวดูแยกและไม่ใช้ CDN ขณะรันไทม์

## ภาพรวมโครงการ

### เหตุผลที่เลือก EPUB Browser

- **เผยแพร่ได้ทุกที่และยังควบคุมทุกอย่างเอง** สร้างเว็บไซต์สแตติกที่สมบูรณ์สำหรับ Pages,
  object storage หรือ Nginx ด้วยคำสั่งเดียว หรือเรียกใช้ Server แบบถาวรที่มีบัญชี สิทธิ์หนังสือ
  และ OIDC ทรัพยากรของแอปพลิเคชัน ฟอนต์ PDF.js และตัวเรนเดอร์ทั้งหมดให้บริการจากเครื่อง
  การอ่านจึงไม่ต้องพึ่ง CDN
- **EPUB และ PDF ใช้ตัวอ่านเต็มรูปแบบชุดเดียวกัน** ทั้งสองรูปแบบใช้ Library หน้าหนังสือ สารบัญ
  เลย์เอาต์แบบ responsive โหมดอ่านสามแบบ ธีม โหมดเต็มหน้าจอ และความคืบหน้าร่วมกัน ทุกหน้า PDF
  อยู่ในพื้นที่อ่านเดิม พร้อมการซูม การเลือก text layer และคำอธิบายประกอบ แทนที่จะเปิดตัวดูตัวอย่างแยก
- **ค้นหาได้ทั้งเล่มและเฉพาะตอนที่ต้องการ** การค้นหาใน Library ครอบคลุมเมทาดาทา แท็ก และพินอิน
  พร้อมการจัดเรียงและแบ่งหน้า การค้นหาทั้งเล่มสำหรับ EPUB ฝั่ง Server ให้ผลลัพธ์ครบถ้วนโดยจัดกลุ่ม
  ตามบท และข้ามไปยังตอนที่ไฮไลต์ได้ รหัสหนังสือที่คงที่ช่วยให้จุดอ่านต่อ คำอธิบายประกอบ และประวัติ
  ยังผูกกับหนังสือเล่มเดิมเสมอ
- **เข้าใจเนื้อหา ไม่ใช่แค่เลื่อนอ่าน** ในโหมด Server คำแนะนำประจำบทของ EPUB คำอธิบายที่เชื่อมกับ
  หลักฐาน แผนผังความคิด และ Ask AI ส่วนตัวจะอยู่ข้างข้อความต้นฉบับ ไฮไลต์ บันทึก Dictionary และ
  Encyclopedia ใช้ได้ทั้งกับ EPUB และ PDF ที่มี text layer ส่วนรายการคำศัพท์บน Server บันทึกแหล่งที่มา
  และสถานะความชำนาญของแต่ละคำ
- **เปลี่ยนการอ่านให้เป็นประวัติที่น่าเก็บไว้** ชั้นหนังสือแบบซ้อน คะแนน รีวิว การส่งออกคำอธิบายประกอบ
  ปฏิทินกิจกรรม แนวโน้ม สถิติรายเล่ม และอันดับเวลาอ่าน เชื่อมโยงกันเป็นบันทึกเดียว Server เก็บข้อมูล
  การอ่านเป็นส่วนตัวตามบัญชีและซิงก์ระหว่างอุปกรณ์
- **เรียกใช้บริการอ่านหนังสือ ไม่ใช่แค่ตัวดู** ในโหมด Server ผู้ดูแลเพิ่มหนังสือผ่านการอัปโหลดบนเว็บ
  หรือโฟลเดอร์ที่เฝ้าดูได้ จำกัดการใช้ดิสก์ด้วยการขจัดแคช LRU ที่กำหนดค่าได้ จัดการสิทธิ์สมาชิกและ AI
  และเชื่อมต่อผ่าน OpenAPI, PAT และ WebHooks การอ่าน Kindle แบบมินิมัลรองรับอุปกรณ์ที่มีข้อจำกัด
  Server ยังมีแดชบอร์ดสกรีนเซฟเวอร์ Kindle ส่วนตัวพร้อมนาฬิกา ปฏิทิน กำหนดการ บันทึก และตัวจับเวลา Pomodoro

### เทคโนโลยีที่ใช้

EPUB Browser เลือกใช้ web stack ขนาดเล็กที่เรนเดอร์ฝั่งเซิร์ฟเวอร์โดยเจตนา แอปพลิเคชันที่ติดตั้งแล้ว
ไม่มี SPA framework และไม่ต้องใช้ Node.js runtime:

| ชั้น | เทคโนโลยี | บทบาท |
| --- | --- | --- |
| Frontend | Semantic HTML, CSS, VanillaJS พร้อม ES modules และ browser API | UI แบบ responsive ชุดเดียวที่ใช้ร่วมกันระหว่าง SSG และ Server |
| CLI และ Server | Python 3.9+, Starlette, Uvicorn | คำสั่งแปลง หน้าที่ต้องยืนยันตัวตน API และงานเบื้องหลัง |
| ข้อมูล | SQLite พร้อมแคชเนื้อหา JSON ที่สร้างใหม่ได้ | สถานะผู้ใช้แยกจากเนื้อหา EPUB/PDF ที่ derive |
| รูปแบบหนังสือ | lxml, pypdf, pypdfium2, PDF.js | การแยกวิเคราะห์และทำความสะอาด EPUB แบบรวมศูนย์โดยเข้มงวดก่อน เมทาดาทา/ปก PDF และการเรนเดอร์ในเบราว์เซอร์ภายในเครื่อง |
| ออฟไลน์และทรัพยากร | Service Worker, ทรัพยากรแบบ immutable ที่มี hash และ dependency ของ vendor ที่ล็อกไว้ | การให้บริการครบในตัวโดยไม่ใช้ CDN ขณะรันไทม์ |
| การเผยแพร่ | PyPI, Docker, static hosting ทั่วไป | codebase เดียวกันใช้ได้ทั้งสร้าง SSG และเรียกใช้ Server แบบถาวร |
| AI ที่เลือกใช้ | API ที่เข้ากันได้กับ OpenAI พร้อม Markdown, KaTeX และ Mermaid ที่เรนเดอร์ในเครื่อง | ชั้นการเรียนรู้ EPUB เฉพาะในโหมด Server |

Node.js ใช้โดยผู้ดูแลสำหรับทดสอบฝั่งเบราว์เซอร์เท่านั้น ไม่ได้เป็นส่วนหนึ่งของ production runtime ของผู้อ่าน

### เลือก SSG หรือ Server

การประมวลผลต้นฉบับและ page template ชุดเดียวกันรองรับโหมดการปรับใช้สองแบบที่แยกกันชัดเจน
เลือกตามตำแหน่งที่ควรเก็บข้อมูลการอ่าน ไม่ใช่ตามรูปแบบหนังสือ:

| ความสามารถ | `ssg` | `server` |
| --- | --- | --- |
| EPUB และ PDF | รองรับ | รองรับ |
| การให้บริการ | HTML/ทรัพยากรสแตติกแบบ atomic สำหรับ Pages, object storage หรือ Nginx | หน้าแบบไดนามิกที่ยืนยันตัวตน โดยอาศัยแคชเนื้อหาที่เปลี่ยนใหม่ได้ |
| บัญชีและการควบคุมการเข้าถึง | ไม่มี | บัญชี administrator/member การให้สิทธิ์หนังสือแบบจำกัด Session และการป้องกัน CSRF |
| การลงชื่อเพียงครั้งเดียวด้วย OIDC | ไม่รวม | Provider ทั่วไป การเชื่อมบัญชีเดิม และการจัดเตรียมสมาชิกแบบเลือกใช้ |
| ความคืบหน้า คำอธิบายประกอบ ชั้นหนังสือ | เก็บในเบราว์เซอร์ปัจจุบัน | ซิงก์ตามบัญชีที่ยืนยันตัวตนใน SQLite |
| คะแนน รีวิว เซสชันการอ่าน | ไม่สร้าง | บันทึกส่วนตัวตามบัญชีและข้อมูลเชิงลึกการอ่าน |
| การอัปเดตต้นฉบับ | เรียก `ssg` อีกครั้ง | รีสตาร์ต สแกนใหม่ หรือใช้ `--watch` |
| การดูแลระบบ แท็ก OpenAPI, WebHooks | ไม่รวม | มี |
| การอ่านด้วย AI และ Ask AI | ไม่รวม | ใช้กับ EPUB ได้เมื่อกำหนดค่าและอนุญาตอย่างชัดเจน ส่วน PDF จะซ่อนไว้ |
| ฐานข้อมูลขณะรันไทม์ | ไม่มี | จำเป็นสำหรับโหมดถาวร |
| เหมาะที่สุดสำหรับ | public/static hosting, ชุดออฟไลน์ และการเผยแพร่ส่วนตัวแบบง่าย | ไลบรารีส่วนตัว หลายอุปกรณ์หรือผู้อ่านหลายคน ระบบอัตโนมัติ และการควบคุมการเข้าถึง |

ใช้ `ssg` เมื่อผลลัพธ์ต้องเป็นไฟล์สแตติกทั่วไป ใช้ `server` เมื่อผู้อ่านต้องมีบัญชี ข้อมูลข้ามอุปกรณ์
การควบคุมการเข้าถึง หรือการปรับสถานะต้นฉบับให้ตรงกันโดยอัตโนมัติ

### การอ่านที่ผสาน AI (เฉพาะ Server)

สำหรับหนังสือ EPUB โหมด Server สามารถเพิ่มคำแนะนำประจำบท คำอธิบายที่เชื่อมกับหลักฐาน แผนผังความคิด
คำถามชวนสะท้อน และลิ้นชัก Ask AI ส่วนตัว โดยผู้อ่านไม่ต้องออกจากข้อความต้นฉบับ ผลลัพธ์ยังอยู่ภายใต้
สิทธิ์หนังสือ สมาชิกต้องได้รับอนุญาตอย่างชัดเจน และ SSG ไม่มีตัวควบคุม AI งาน ข้อมูลบัญชี หรือการตั้งค่า
provider ใด ๆ ส่วน PDF จะซ่อนการอ่านด้วย AI และ Ask AI โดยเจตนา

ดู [คู่มือการอ่านที่ผสาน AI](../ai-native-reading.md) สำหรับโมเดลการโต้ตอบฉบับเต็ม และ
[บันทึกเกี่ยวกับตัวเรนเดอร์ rich text ในเครื่อง](../third-party-ai-renderers.md) สำหรับขอบเขตด้านการเรนเดอร์และความปลอดภัยเครือข่าย

### โหมด Kindle แบบมินิมัล

Kindle e-Ink รุ่นเก่า (และเบราว์เซอร์ที่มีข้อจำกัดอื่น ๆ) จะได้พื้นที่อ่านแบบมินิมัลที่ไม่มี dependency
เปิดใช้ด้วย `--kindle`:

- SSG: `epub-browser ssg --kindle -o output/ SOURCE...`
- Server: `epub-browser server --kindle --server-dir data SOURCE...`

หนังสือ EPUB แต่ละเล่ม (ไม่รวม PDF) จะมีเพจเพิ่มสามหน้า:

- ชั้นหนังสือแบบมินิมัล `/kindle-library.html`
- หน้าหนังสือ `/book/<id>/kindle.html`
- หน้าบท `/book/<id>/kindle_chapter_N.html`

เพจเหล่านี้ปรับสำหรับ e-Ink โดยเฉพาะ: markup น้อย การเปลี่ยนธีมด้วย CSS เท่านั้น สคริปต์ที่เข้ากันได้กับ
ES5 ไม่มี Service Worker และไม่มี framework คุณอ่านได้โดยไม่ใช้ JavaScript เลย ส่วนการเปลี่ยนธีม
(Light / Sepia / Dark) ขนาดตัวอักษร (A- / A+) และการแปลอินเทอร์เฟซ ใช้ inline script ขนาดเล็กเสริมจาก HTML พื้นฐาน

ทุกหน้ามีตัวควบคุมธีมและฟอนต์ (ที่ header และซ้ำที่ footer ของบท) การนำทางสารบัญ บทก่อนหน้า/ถัดไป
และลิงก์ "Continue reading" สำหรับกลับไปยังความคืบหน้าที่บันทึกไว้

ความคืบหน้าการอ่านต่างกันตามโหมด:

- **SSG:** ความคืบหน้าเก็บในคุกกี้ของเบราว์เซอร์ปัจจุบัน เป็นแบบภายในเครื่องและไม่มีบัญชี
- **Server:** ความคืบหน้าและ heartbeat การอ่านซิงก์ตามบัญชีที่เข้าสู่ระบบใน SQLite พื้นที่ Kindle
  ใช้อ่าน/รายงานเท่านั้น โดยบันทึกบทปัจจุบันและรายงาน heartbeat แสดงชั้นหนังสือแบบอ่านอย่างเดียว
  และไม่เปิดเผยข้อมูลเชิงลึกหรือการจัดการเนื้อหา

การควบคุมการเข้าถึงมีผลกับทุกพื้นที่ Kindle หนังสือที่จำกัดการมองเห็นจะคืน 403 แก่ผู้ใช้ที่ไม่ได้รับอนุญาต
บนชั้นหนังสือแบบมินิมัล (รายการจะถูกละไว้) หน้าหนังสือ หน้าบท และ API ความคืบหน้า

เบราว์เซอร์ที่รองรับ (UA มี `Kindle/`, `Arora/` ฯลฯ) จะถูกเปลี่ยนเส้นทางจากตัวอ่านเต็มรูปแบบไปยังเพจ
มินิมัลโดยอัตโนมัติ URL ข้างต้นก็เปิดโดยตรงได้เช่นกัน โหมดมินิมัลจึงเป็น fallback ที่เหมาะกับอุปกรณ์
กำลังต่ำหรืออุปกรณ์ที่จำกัด JavaScript

## เริ่มต้นใช้งาน

### เลือกวิธีติดตั้ง

EPUB Browser รองรับการติดตั้งสองวิธี ทั้งสองวิธีรับไฟล์ `.epub` หรือ `.pdf` หนึ่งไฟล์ขึ้นไป ไดเรกทอรี
แบบซ้อน หรือไดเรกทอรีไลบรารีแบบ Calibre

| การติดตั้ง | ใช้สำหรับ | ข้อกำหนดของโฮสต์ |
| --- | --- | --- |
| PyPI | โหมด SSG หรือ Server | Python 3.9 หรือใหม่กว่า |
| Docker | โหมด Server แบบถาวร | Docker Engine; อิมเมจมี Python รวมอยู่แล้ว |

#### PyPI (SSG หรือ Server)

ติดตั้งแอปพลิเคชันบรรทัดคำสั่ง:

```bash
pip install epub-browser
```

แสดงข้อมูลอ้างอิงคำสั่งตามโหมด:

```bash
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

#### Docker (Server)

อิมเมจ [`dfface/epub-browser`](https://hub.docker.com/r/dfface/epub-browser) ที่เผยแพร่แล้วเรียกใช้
โหมด Server และไม่ต้องติดตั้ง Python บนโฮสต์:

```bash
docker pull dfface/epub-browser:latest
```

ใช้ `latest` เพื่อประเมินรุ่นปัจจุบัน สำหรับ production ที่ต้องทำซ้ำได้ ให้ปักหมุดแท็กรุ่นที่มีหมายเลข
ดู [Docker](#docker) สำหรับ mount ของหนังสือและสถานะที่จำเป็น วิธีเริ่ม Compose อย่างรวดเร็ว การตั้งค่าครั้งแรก และคำแนะนำเครือข่าย

### เริ่มต้นอย่างรวดเร็ว

#### สร้างเว็บไซต์สแตติก

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist
```

ให้บริการ `dist/` ผ่าน HTTP ไม่รองรับการเปิดเพจที่สร้างขึ้นโดยตรงผ่าน `file://` เนื่องจาก browser storage,
module, manifest และ Service Worker ต้องใช้ HTTP origin

สำหรับเว็บไซต์ที่โฮสต์ใต้ URL prefix ให้ตั้ง public path แยกจากปลายทางบน filesystem:

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist \
  --base-path /my-repository/
```

`--base-path` เปลี่ยน URL ที่สร้างขึ้น ไม่ได้เปลี่ยนตำแหน่งเขียนไฟล์ เมื่อใช้ `/my-repository/` ลิงก์ ไอคอน
manifest, เมทาดาทาหนังสือ และรายการ Service Worker จะใช้ prefix นี้ ขณะที่ไฟล์ยังอยู่ใน `dist/` โดยตรง

#### เรียกใช้ไลบรารี Server แบบถาวร

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/epub-browser-state \
  --watch
```

เปิด `http://127.0.0.1:8000/` เมื่อเข้าครั้งแรก EPUB Browser จะแจ้งให้สร้าง administrator เริ่มต้น
ไลบรารีจะยังไม่ถูกสแกนหรือเปิดเผยจนกว่าการตั้งค่าครั้งเดียวนี้จะเสร็จ

หากเลือก Docker ให้ข้ามคำสั่ง Python ข้างต้นแล้วไปที่
[วิธีเริ่ม Docker Compose อย่างรวดเร็ว](#docker-compose)

## รูปแบบหนังสือและการอ่าน

### แหล่งที่มาและรหัสประจำตัวหนังสือที่คงที่

`SOURCE` แบบ positional แต่ละรายการอาจเป็นไฟล์ EPUB ไฟล์ PDF หรือไดเรกทอรี ระบบค้นหาในไดเรกทอรี
แบบ recursive และส่งหลายแหล่งให้คำสั่งเดียวได้:

```bash
epub-browser server book.epub /srv/library /srv/periodicals \
  --server-dir /srv/epub-browser \
  --watch
```

หนังสือแต่ละเล่มได้รับ `book_id` ที่คงที่ และแสดงเป็น `book_hash` ใน URL กับข้อมูลเบราว์เซอร์ที่สร้างขึ้น
ค่าเริ่มต้นทั่วไปของ CLI คือ:

```bash
--book-id-storage sidecar
```

โหมด sidecar เขียนไฟล์รหัสประจำตัวที่มองเห็นไว้ข้างต้นฉบับ เช่น `BOOK.epub.epub-browser.json` หรือ
`BOOK.pdf.epub-browser.json` โดยไม่เปลี่ยนไบต์ของต้นฉบับ sidecar มี ID ที่คงที่และลายนิ้วมือ SHA-256
ของต้นฉบับที่ตรวจสอบแล้ว

หากต้องการใส่ ID ในเมทาดาทา OPF ของ EPUB หรือ document information dictionary ของ PDF ให้เลือก
embedded storage สำหรับการเรียกทั้งครั้ง:

```bash
--book-id-storage embedded
```

โหมด embedded อาจสร้าง EPUB ZIP ใหม่หรือต่อท้ายการอัปเดตเมทาดาทา PDF ก่อนแปลง หากอัปเดต PDF ไม่ได้
และต้นฉบับไม่เปลี่ยน EPUB Browser จะบันทึก ID เดิมลง sidecar ที่อยู่ติดกัน รวมถึง PDF ที่เซ็นชื่อ เข้ารหัส
และอ่านอย่างเดียว EPUB Browser จะหยุดเมื่อ ID ไม่ตรงกัน แหล่งที่ใช้งานมี ID ซ้ำ carrier ไม่ถูกต้อง
หรือเขียน carrier ที่จำเป็นไม่ได้

เมื่อย้ายโหมดการจัดเก็บ EPUB Browser จะคัดลอก ID เดิมไปยัง carrier ที่เลือกและเก็บ carrier อีกตัวที่ถูกต้องไว้
embedded ID เดิมจาก v2.0.4 จะถูกคัดลอกไปยัง sidecar เริ่มต้นโดยไม่เขียน EPUB ใหม่ ทั้ง SSG และ Server
ให้บริการสำเนา PDF ต้นฉบับแบบตรงกันทุกไบต์หลังการอัปเดตเมทาดาทา

### PDF: หนึ่งหน้าหนึ่งบท

ทั้งสองโหมดการปรับใช้รองรับ PDF ตัวอ่านถือว่าหน้า PDF แต่ละหน้าเป็นบท EPUB Browser ทั่วไป ดังนั้นหน้า Book,
การนำทางบท สารบัญ การแบ่งหน้า การอ่านต่อเนื่อง ความคืบหน้า เซสชันการอ่าน คำอธิบายประกอบ Dictionary และ
Encyclopedia จึงยังใช้ UI และโมเดลข้อมูลชุดเดียวกัน:

| แนวคิดของ PDF | SSG | Server |
| --- | --- | --- |
| URL หน้า 1 | `chapter_0.html` | `/book/<book-id>/chapter_0.html` |
| URL หน้า N | `chapter_{N-1}.html` | `/book/<book-id>/chapter_{N-1}.html` |
| ป้ายหน้าและสารบัญ | สร้างในเครื่อง แสดงทุกหน้า | เรนเดอร์จากแคชเมทาดาทา PDF แสดงทุกหน้า |
| Outline ที่ฝัง | Marker ในรายการสารบัญของหน้าปลายทาง | Marker เดียวกัน โดยไม่ลบหรือจัดลำดับรายการหน้าใหม่ |
| การเลื่อนและการแบ่งหน้า/พลิกหน้า | Chapter shell แบบสแตติกและ PDF.js ในเครื่อง | Chapter shell ร่วมแบบไดนามิกและ PDF.js ในเครื่อง |
| ไฮไลต์ บันทึก Dictionary, Encyclopedia | Component ร่วมที่เก็บในเบราว์เซอร์เมื่อมี text layer | Component ร่วมที่ยืนยันตัวตนเมื่อมี text layer |
| ไบต์ PDF ดิบ | มี `document.pdf` หนึ่งไฟล์ในเอาต์พุตหนังสือสแตติก | Route สำหรับเอกสารในแคชที่ใช้เฉพาะ Session และรองรับ Range |

เลขหน้าที่มองเห็นและใน PDF.js เริ่มที่ 1 ส่วนดัชนีบทใน URL สถานะ API และ SQLite เริ่มที่ 0 ดังนั้นหน้า PDF 1
จึงเป็น `chapter_0.html` เสมอ สารบัญที่ normalize แล้วมีรายการ `Page N` หนึ่งรายการต่อหน้า ชื่อ outline
ที่ฝังใน PDF จะถูกแนบเป็น outline marker กับรายการปลายทาง รวมถึงหลาย marker ในหน้าเดียว

SSG เขียน `document.pdf` เพียงไฟล์เดียวและ chapter shell `chapter_<index>.html` หนึ่งไฟล์ต่อหน้า เอาต์พุต
SSG ไม่มีสคริปต์ Session การเรียก `/api/*` ข้อมูลคำอธิบายประกอบที่ซิงก์ หรือ dependency ของ Server
Server เก็บต้นฉบับทั้งไฟล์ที่ตรงกันทุกไบต์ไว้ที่ `book/<book-id>/pdf/document.pdf` และไม่แยกหรือเขียนใหม่
Server เรนเดอร์ chapter shell ชุดเดียวกันแบบไดนามิกจากเมทาดาทา PDF เมื่อต้นฉบับเปลี่ยน แคช PDF จะใช้ไม่ได้
และถูกรีเฟรชทั้งหมด (เอกสาร เมทาดาทา และปกที่ derive) แทนการผสมหน้าเก่ากับหน้าใหม่

Endpoint เอกสารดิบของ Server ใช้เฉพาะ Session:
`GET`/`HEAD /api/books/<book-id>/document` โดยตรวจการยืนยันตัวตน การมองเห็นหนังสือ รูปแบบ PDF
และลายนิ้วมือต้นฉบับ/แคช จากนั้นรองรับการตอบกลับ single-range ที่จำกัดขอบเขต พร้อม `ETag`,
`Accept-Ranges`, private caching, `nosniff` และ inline PDF disposition ไม่เปิดเผยพาธสัมบูรณ์
ไม่รองรับการยืนยันตัวตนด้วย PAT และไม่อยู่ในพื้นที่ PAT/OpenAPI ส่วน SSG มีเพียง `document.pdf`
ในเครื่องและไม่มี API เอกสารดิบ

PDF ที่มี text layer ซึ่ง PDF.js ใช้ได้จะใช้ popup เลือกข้อความและ component คำอธิบายประกอบเดิมสำหรับ
Highlight และ Note รวมถึง Dictionary และ Encyclopedia การจัดเก็บ ความเป็นเจ้าของ การส่งออก การแสดงรายการ
และ deep link ของคำอธิบายประกอบยังใช้ร่วมกัน ไม่มีตารางคำอธิบายประกอบหรือ UI ตั้งค่าเฉพาะ PDF
PDF ที่สแกนหรือมีเฉพาะภาพยังอ่านได้ แต่ Highlight, Note, Dictionary, Encyclopedia ที่อาศัยการเลือกข้อความ
และการค้นหาเอกสารจะระบุชัดเจนว่าใช้ไม่ได้เมื่อไม่มี text layer ที่ใช้งานได้ การเลือกข้ามหน้ายังคัดลอกได้
ขณะที่การกระทำคำอธิบายประกอบและการค้นคำจะแสดงข้อความไม่รองรับที่แปลแล้ว ส่วนการเลือกภายในหน้ายังทำงาน

PDF.js ไม่ใช่ viewer shell ที่สอง ก่อน build หรือเผยแพร่ ให้เตรียมและตรวจสอบทรัพยากรบุคคลที่สามที่ล็อกไว้:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
```

จากนั้นแอปพลิเคชันจะให้บริการ module และ worker ของ PDF.js ในเครื่องที่มี hash ขณะรันไทม์ โดยไม่ดึงจาก CDN
image lightbox ใช้ dependency GLightbox ที่ล็อกไว้ ส่วน Fancyapps/Fancybox ไม่ใช่ dependency ขณะรันไทม์
และไม่ได้เผยแพร่ซ้ำ ดู [third_party/README.md](../../third_party/README.md) สำหรับขั้นตอนทรัพยากรที่ล็อกและการเผยแพร่รุ่น

## การปรับใช้

### SSG

SSG สร้าง snapshot ที่สมบูรณ์ในไดเรกทอรี staging ข้างกัน ตรวจสอบ แล้วแทนที่ปลายทาง หากการแปลงใดล้มเหลว
ปลายทางเดิมจะไม่เปลี่ยน เอาต์พุตที่สร้างไม่มีฐานข้อมูล Server สถานะ migration หน้าบัญชี หรือเมทาดาทา runtime cache

SSG ตั้งใจทำงานในเครื่องและไม่มีบัญชี:

- ความคืบหน้าการอ่านและคำอธิบายประกอบใช้ browser storage บน origin ปัจจุบัน
- ชั้นหนังสือรองรับ Import และ Export JSON ในเครื่อง ไม่มีการกระทำ Sync บนคลาวด์
- ไม่มีการเข้าสู่ระบบ การตั้งค่าบัญชี Server API และตัวควบคุมที่ขึ้นกับผู้ใช้
- ปลายทางการจัดเก็บถูกกำหนดเป็น local browser storage และไม่แสดงเป็นตัวเลือกการตั้งค่า
- เอาต์พุตสแตติกมี Service Worker ที่จำเป็นสำหรับทรัพยากรที่ใช้ออฟไลน์ได้

JavaScript, CSS, ฟอนต์ และไอคอนของแอปพลิเคชันที่จำเป็นทั้งหมดรวมอยู่ในเอาต์พุต ดู
[การให้บริการครบในตัวและพฤติกรรมเครือข่าย](#การให้บริการครบในตัวและพฤติกรรมเครือข่าย) สำหรับคำขอเครือข่ายที่เลือกใช้เพียงรายการเดียว

### Server

#### การตั้งค่าเริ่มต้น บัญชี และสิทธิ์

ในไดเรกทอรีสถานะถาวรใหม่ เพจทั่วไปจะเปลี่ยนเส้นทางไป `/setup` API, event stream, ทรัพยากรที่สร้าง และหนังสือ
จะตอบกลับว่าต้องตั้งค่าก่อนจนกว่าจะสร้าง administrator เริ่มต้น ตั้งค่าให้เสร็จผ่าน loopback หรือเส้นทางส่วนตัว
ที่เชื่อถือได้ก่อนเปิดพอร์ต เนื่องจากการส่งการตั้งค่าที่สำเร็จครั้งแรกจะยึดบัญชี administrator

หลังตั้งค่า:

- ปิดการลงทะเบียนสาธารณะ ผู้ดูแลสร้างและจัดการผู้ใช้
- บัญชีมีบทบาท `administrator` หรือ `member`
- หนังสือทั่วไปมองเห็นได้จากทุกบัญชีที่ยืนยันตัวตน
- หนังสือแบบจำกัดมองเห็นได้เฉพาะผู้ดูแลและผู้ใช้ที่เลือกไว้อย่างชัดเจน
- ผู้ใช้แต่ละคนเป็นเจ้าของชั้นหนังสือ ความคืบหน้า คำอธิบายประกอบ และเซสชันที่ใช้งานของตน
- ผู้ใช้เปลี่ยนรหัสผ่านและเพิกถอนเซสชันของตนได้
- ผู้ดูแลจัดการผู้ใช้ บทบาท รหัสผ่าน เซสชัน และสิทธิ์หนังสือได้
- เซสชันใช้คุกกี้ HttpOnly การป้องกัน CSRF และอายุแบบเลื่อนต่อ 30 วัน

#### การลงชื่อเพียงครั้งเดียวด้วย OIDC และการเชื่อมบัญชี

โหมด Server ใช้ OpenID Connect (OIDC) Provider ทั่วไปได้หนึ่งราย รวมถึง Authelia, Keycloak, Authentik
และบริการที่เข้ากันได้ ใน **Administration → OIDC login** ให้กรอกชื่อ Provider ที่แสดงแก่ผู้อ่าน issuer URL,
client ID, client secret, redirect URI ที่ตรงกัน, scope และ username claim EPUB Browser ใช้ discovery
กับ Authorization Code flow พร้อม S256 PKCE ตรวจสอบ ID token ที่ลงนาม และระบุบัญชีภายนอกด้วย
`(issuer, sub)` เท่านั้น email และ username claim เป็นเพียงข้อมูลช่วยแสดงผล/จัดเตรียมบัญชี ไม่ใช่คีย์รหัสประจำตัว

ลงทะเบียน callback นี้ให้ตรงกันที่ Provider รวม scheme และ host:

```text
https://reader.example.com/auth/oidc/callback
```

ผู้ใช้เดิมเข้าสู่ระบบในเครื่องแล้วเชื่อม Provider จาก Account settings ได้ หากเป็นตัวตนภายนอกที่ไม่รู้จัก
ระบบจะถามชื่อผู้ใช้และรหัสผ่านในเครื่องเดิมหนึ่งครั้ง การจัดเตรียมอัตโนมัติแบบเลือกใช้จะสร้างสมาชิกที่ไม่มี
รหัสผ่าน และไม่นำเข้าบทบาท administrator เสมอ ควรให้ผู้ใช้เดิมผูกบัญชีก่อน เพราะเปิดการจัดเตรียมอัตโนมัติ
เร็วเกินไปอาจสร้าง **บัญชีในเครื่องซ้ำ** การเข้าสู่ระบบด้วยรหัสผ่านของ **administrator ในเครื่อง**
ยังใช้ได้เสมอแม้ปิดการเข้าสู่ระบบด้วยรหัสผ่านของสมาชิกในเครื่อง ควรทดสอบและปกป้องข้อมูลกู้คืนนี้
ระบบไม่ทำ Provider logout และไม่เก็บ Provider access/refresh token

สำหรับ Authelia ให้กำหนด confidential client ในส่วน OIDC Provider ตัวอย่างต่อไปนี้ใช้ค่าปลอมโดยเจตนา
และถือว่ากำหนด provider key กับ policy ที่ Authelia จำเป็นไว้แล้ว เก็บ hash ของ client secret แบบสุ่มที่คาดเดายาก
ใน Authelia แล้วกรอก raw secret ที่เกี่ยวข้องใน EPUB Browser หนึ่งครั้ง:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: 'epub-browser'
        client_name: 'EPUB Browser'
        client_secret: '<AUTHELIA_HASH_OF_A_RANDOM_SECRET>'
        public: false
        authorization_policy: 'two_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://reader.example.com/auth/oidc/callback'
        scopes: ['openid', 'profile', 'email']
        response_types: ['code']
        grant_types: ['authorization_code']
        token_endpoint_auth_method: 'client_secret_basic'
```

ใน EPUB Browser ให้ใช้ issuer `https://auth.example.com`, client ID
`epub-browser`, scope `openid profile email` และ username claim
`preferred_username` การ Save จะทำ live discovery และตรวจสอบความสามารถ หากล้มเหลวการตั้งค่าเดิมยังมีผล

#### กำหนดค่าและกำกับการอ่านด้วย AI

ผู้ดูแลกำหนดค่าการอ่านด้วย AI ใน **Administration** ซึ่งอยู่หลังการจัดการผู้ใช้และก่อนการจัดการหนังสือโดยตรง
หน้านี้เก็บ Base URL ที่เข้ากันได้กับ OpenAI, API key, model, timeout, งบประมาณ context, เพดาน concurrency
และขีดจำกัดการเรียก provider ต่อวันเริ่มต้นไว้ในฐานข้อมูล Server SQLite เริ่มแรก AI ปิดสำหรับสมาชิก
ผู้ดูแลต้องให้สิทธิ์รายสมาชิกและอาจตั้งขีดจำกัดรายวันเฉพาะบุคคล (`0` หมายถึงไม่จำกัด)

ชั้นการเรียนรู้ประจำบทและรีวิวระดับเล่มจะใช้ร่วมกันตามภาษาที่รองรับ ขณะที่บทสนทนาต่อเนื่องเป็นส่วนตัวของแต่ละบัญชี
ผลลัพธ์ สถานะงาน แท็กที่กำหนดเอง การจำแนกการอ่านหนังสือ และบทสนทนาต่อเนื่องส่วนตัวเก็บใน SQLite
ผลลัพธ์เก่ายังใช้ได้หลังเปลี่ยนการตั้งค่า model จนกว่าผู้ดูแลจะสร้างใหม่โดยชัดแจ้ง

เมื่อผู้อ่านขอคำแนะนำ AI หรือถามคำถาม ข้อความ EPUB ที่เลือกและ context บทสนทนาที่บีบอัดจะถูกส่งไปยัง
provider ภายนอกที่กำหนดค่า อย่าเปิดฟีเจอร์นี้หากผู้อ่านไม่ได้รับอนุญาตให้ส่งเนื้อหาดังกล่าวไปยัง provider
API key จะไม่ถูกส่งกลับไปยังเบราว์เซอร์หรือเปิดเผยผ่าน API ควรปกป้องไดเรกทอรีสถานะ Server ตามนั้น

สำหรับการเริ่มครั้งแรกแบบไม่มีผู้ควบคุม ให้ระบุไฟล์ชื่อผู้ใช้และรหัสผ่าน:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --admin-username admin \
  --admin-password-file /run/secrets/epub-browser-admin-password \
  --no-browser
```

ไฟล์รหัสผ่านควรมี mode `0600` EPUB Browser ลบ newline ท้ายไฟล์หนึ่งตัว เก็บ hash Argon2id และไม่พิมพ์ secret
การตั้งค่าไม่ครบ ไฟล์ว่าง หรืออ่านไฟล์ไม่ได้จะทำให้เริ่มระบบไม่สำเร็จ เมื่อตั้งค่าเสร็จแล้ว การเริ่มครั้งต่อไปจะไม่อ่าน bootstrap secret

ตัวแปรสภาพแวดล้อมที่เท่ากันคือ `EPUB_BROWSER_ADMIN_USERNAME` และ `EPUB_BROWSER_ADMIN_PASSWORD_FILE`
`EPUB_BROWSER_ADMIN_PASSWORD` เป็น plaintext fallback เฉพาะเมื่อไม่ได้กำหนดไฟล์รหัสผ่าน
พาธไฟล์รหัสผ่านใน CLI มีลำดับความสำคัญเหนือแหล่งรหัสผ่านจากสภาพแวดล้อม

#### การเปิดเบราว์เซอร์และการบันทึก log

ตามค่าเริ่มต้น Server จะพยายามเปิดเบราว์เซอร์เริ่มต้นของระบบปฏิบัติการหลัง HTTP listener เริ่มแล้ว
`--no-browser` ป้องกันการเปิดในเครื่องนี้ โดย **ไม่ปิดเว็บอินเทอร์เฟซหรือการเข้าถึงผ่านเบราว์เซอร์**
แต่เพียงระงับการเรียก `webbrowser.open(...)` ในเครื่อง ใช้กับ Docker, systemd, เซสชัน SSH, เครื่อง headless และสคริปต์

ตามค่าเริ่มต้น (`--log-level error`) CLI แสดงเฉพาะข้อผิดพลาด เพื่อไม่ให้ข้อความหรือคำเตือนตามปกติรบกวน
การแสดงความคืบหน้าบนเทอร์มินัล เทอร์มินัลแบบโต้ตอบจะพิมพ์ URL ที่ bind หนึ่งครั้ง ส่วนการเรียก Docker
และ service แบบไม่โต้ตอบจะเงียบ ใช้ `--log-level warning` เพื่อรวมคำเตือน `--log-level info` สำหรับ log
การดำเนินงานและ HTTP access หรือ `--log-level debug` เพื่อรายละเอียดสูงสุด `--log` ยังเป็น alias
เพื่อความเข้ากันได้ของ `--log-level info`

การสแกนเริ่มต้นและ watch จะแสดงในเว็บอินเทอร์เฟซแทน `tqdm` บนเทอร์มินัล สรุปที่สำเร็จจะปิดอัตโนมัติ
ข้อผิดพลาดจะค้างจนกว่าจะปิด เมื่อใช้ `--watch` การแก้ไขหรือแทนที่ต้นฉบับจะเริ่มสแกนอีกครั้งโดยไม่ต้องกดลองใหม่

#### สถานะถาวรและชั่วคราว

โหมด Server แบบถาวรต้องใช้ `--server-dir` สำหรับการเรียกแบบใช้ครั้งเดียว ให้ใช้ `--ephemeral`:

```bash
epub-browser server book.epub --ephemeral
```

สถานะ ephemeral จะถูกลบเมื่อปิด เนื่องจากฐานข้อมูลเป็นของใหม่ทุกครั้ง การตั้งค่าจึงต้องทำซ้ำ เว้นแต่ระบุ
ข้อมูล bootstrap แบบไม่มีผู้ควบคุม

โครงสร้างแบบถาวร:

```text
<server-dir>/
├── .server.lock                 # reusable process-lock metadata
├── data/
│   ├── epub-browser.db          # authoritative accounts, books, grants, reading data
│   ├── migration-state.json     # restart-safe migration state
│   └── backups/                 # verified pre-migration database copies
└── cache/
    ├── catalog.json             # generated-cache status
    ├── public/                  # served application and converted books
    └── staging/                 # replaceable conversion work
```

เฉพาะ `data/` เป็นแหล่งข้อมูลหลัก `cache/` ลบได้และจะถูกสร้างใหม่ เก็บ `data/` ไว้ระหว่างอัปเกรดและเปลี่ยนคอนเทนเนอร์
lock ของระบบปฏิบัติการควบคุมการใช้งานแบบผูกขาด `.server.lock` อาจเหลือหลังปิดตามปกติเพื่อเป็นเมทาดาทาวินิจฉัย

เก็บ `data/epub-browser.db` แบบถาวรบน filesystem ในเครื่อง ไม่รองรับ shared หรือ network filesystem
สำหรับ WAL concurrency ข้อมูลสำรองที่ตรวจสอบแล้วอยู่ใน `data/backups/` และมีข้อมูล WAL ที่ commit ทั้งหมด

#### LAN และ reverse proxy

Server bind ที่ `127.0.0.1:8000` ตามค่าเริ่มต้น สำหรับ LAN ที่เชื่อถือได้:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --port 8080 \
  --no-browser
```

อย่าเปิด HTTP server ในตัวสู่อินเทอร์เน็ตสาธารณะโดยตรง ให้ terminate TLS ที่ reverse proxy ใช้การควบคุมเครือข่าย และเปิด secure cookie

หากต้องการบันทึก client IP จริงในเซสชันที่ใช้งานและ login-rate limit เมื่ออยู่หลัง reverse proxy ให้กำหนด
**direct socket network** ของ proxy (ไม่ใช่ public client range):

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --trusted-proxy-cidr 172.32.11.1/32 \
  --trusted-proxy-cidr 10.42.0.0/16 \
  --cookie-secure \
  --no-browser
```

ใส่ `--trusted-proxy-cidr` ซ้ำหนึ่งครั้งต่อที่อยู่หรือเครือข่าย proxy โดยตรง เฉพาะคำขอที่ direct peer อยู่ใน
CIDR เหล่านี้เท่านั้นที่ระบุ `X-Forwarded-For` ได้ peer อื่นจะบันทึกเฉพาะที่อยู่โดยตรง การประมวลผล forwarded
address ของ Uvicorn ถูกปิด ดังนั้น `Forwarded` และ `FORWARDED_ALLOW_IPS` ขยายขอบเขตความเชื่อถือนี้ไม่ได้
ใช้ `--cookie-secure` เฉพาะเมื่อเบราว์เซอร์เข้าถึงบริการผ่าน HTTPS

### Docker

อิมเมจเรียกใช้โหมด Server แบบถาวรด้วยค่าเริ่มต้นเหล่านี้:

- `/app/Library` เป็นต้นฉบับ
- `/app/EpubBrowserFiles` เป็นสถานะถาวร
- `--watch`
- `--no-browser`
- `--host 0.0.0.0 --port 80`
- `--book-id-storage embedded`

เนื่องจาก embedded identity อาจอัปเดตไฟล์ EPUB หรือ PDF ให้เมานต์ไลบรารีแบบอ่านเขียน เมานต์สถานะ Server
แบบอ่านเขียนและเก็บไว้เมื่อเปลี่ยนคอนเทนเนอร์:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  dfface/epub-browser:latest
```

เปิด `http://127.0.0.1:8080/setup` ก่อนเปลี่ยน port binding หรือกฎ proxy

#### Docker Compose

รีพอซิทอรีมี [docker-compose.yml](../../docker-compose.yml) สำหรับผู้ที่ต้องการใช้ Compose จาก checkout
ให้สร้าง `Library/` ใส่หนังสือ EPUB หรือ PDF แล้วเรียก:

```bash
docker compose up -d --build
```

ค่านี้ publish เฉพาะ `127.0.0.1:8080` เก็บหนังสือ EPUB/PDF ต้นฉบับใน `./Library` และเก็บสถานะ Server ถาวรใน
`./EpubBrowserFiles` `command` ทั้งหมดของ Server แสดงในไฟล์โดยเจตนา เพื่อเพิ่ม flag ตามการปรับใช้ได้โดยไม่
แทนที่ค่าเริ่มต้นโดยนัยของอิมเมจ ตั้งค่าครั้งเดียวให้เสร็จที่ `http://127.0.0.1:8080/setup` สำหรับการเข้าถึง
ระยะไกล ให้คง loopback binding นี้และวาง reverse proxy TLS ที่ยืนยันตัวตนไว้ข้างหน้า

สำหรับการตั้งค่าแบบไม่มีผู้ควบคุม:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  -e EPUB_BROWSER_ADMIN_USERNAME=admin \
  -e EPUB_BROWSER_ADMIN_PASSWORD_FILE=/run/secrets/epub-browser-admin-password \
  --mount type=bind,src=/path/to/admin-password,dst=/run/secrets/epub-browser-admin-password,readonly \
  dfface/epub-browser:latest
```

หลังเริ่มสำเร็จครั้งแรก สามารถถอด secret mount ครั้งเดียวออกได้ ไลบรารีแบบอ่านอย่างเดียวใช้ได้เมื่อ EPUB ทุกเล่ม
มี embedded ID ที่ถูกต้องและตรงกันเท่านั้น sidecar เดิมจะถูกเก็บไว้เมื่อฝัง ID ของ sidecar เหล่านั้น

เมานต์ `/app/SyncData:ro` เฉพาะขณะนำเข้า bookshelf JSON รุ่นเก่า:

```bash
-v /path/to/legacy-sync:/app/SyncData:ro
```

loopback published port ในตัวอย่างทำให้คอนเทนเนอร์อยู่หลังขอบเขตโฮสต์ สำหรับการเข้าถึงระยะไกล ให้ใช้ reverse proxy
TLS กำหนด CIDR ของ container-network จริง และเพิ่ม `--cookie-secure`

## ข้อมูลอ้างอิงและการดำเนินงาน

### ข้อมูลอ้างอิงคำสั่ง

#### `epub-browser ssg SOURCE [SOURCE ...]`

| ตัวเลือก | ความหมาย |
| --- | --- |
| `--output-dir DIR`, `-o DIR` | ปลายทางที่จำเป็นสำหรับ snapshot สแตติกแบบ atomic |
| `--base-path PATH` | Public URL prefix; ค่าเริ่มต้น `/` ต้องขึ้นต้นและลงท้ายด้วย `/` |
| `--book-id-storage sidecar\|embedded` | Carrier ของรหัสประจำตัวที่คงที่สำหรับทุกแหล่งที่เลือก; ค่าเริ่มต้น `sidecar` |
| `--kindle` | สร้างเพจมินิมัลที่ไม่มี dependency สำหรับ Kindle e-Ink รุ่นเก่าและเปลี่ยนเส้นทางเบราว์เซอร์ Kindle WebKit ไปยังเพจเหล่านั้น; ปิดตามค่าเริ่มต้น |
| `--log` | Alias เพื่อความเข้ากันได้ของ `--log-level info` |
| `--log-level debug\|info\|warning\|error` | ระดับรายละเอียด log การดำเนินงาน; ค่าเริ่มต้น `error` ซึ่งทำให้เอาต์พุตการแปลงและคำเตือนตามปกติเงียบ |

#### `epub-browser server SOURCE [SOURCE ...]`

ต้องระบุเพียงหนึ่งใน `--server-dir` หรือ `--ephemeral`

| ตัวเลือก | ความหมาย |
| --- | --- |
| `--server-dir DIR` | รูทของข้อมูลหลักแบบถาวรและแคชที่เปลี่ยนใหม่ได้ |
| `--ephemeral` | ใช้สถานะแบบใช้ครั้งเดียว ใช้ร่วมกับ `--server-dir` ไม่ได้ |
| `--watch`, `-w` | เฝ้าดูต้นฉบับและปรับข้อมูลเมื่อมีการเพิ่ม อัปเดต ย้าย และลบ |
| `--host ADDRESS` | ที่อยู่ bind; ค่าเริ่มต้น `127.0.0.1` |
| `--port PORT`, `-p PORT` | พอร์ต bind; ค่าเริ่มต้น `8000` |
| `--no-browser` | ไม่เปิดเบราว์เซอร์เริ่มต้นในเครื่อง Web UI ยังใช้ได้ |
| `--log` | Alias เพื่อความเข้ากันได้ของ `--log-level info` |
| `--log-level debug\|info\|warning\|error` | ระดับรายละเอียด log การดำเนินงาน; ค่าเริ่มต้น `error` HTTP access log เปิดที่ `info` และ `debug` |
| `--legacy-sync-dir DIR` | อ่าน bookshelf JSON รุ่นเก่าระหว่าง migration ตอนเริ่มระบบ |
| `--book-id-storage sidecar\|embedded` | Carrier ของรหัสประจำตัวที่คงที่สำหรับทุกแหล่งที่เลือก; ค่าเริ่มต้น `sidecar` |
| `--admin-username NAME` | Administrator เริ่มต้นแบบไม่มีผู้ควบคุม; fallback คือ `EPUB_BROWSER_ADMIN_USERNAME` |
| `--admin-password-file FILE` | ไฟล์ secret เริ่มต้นที่แนะนำ; fallback คือ `EPUB_BROWSER_ADMIN_PASSWORD_FILE` แล้ว `EPUB_BROWSER_ADMIN_PASSWORD` เมื่อไม่ได้ตั้งไฟล์ |
| `--trusted-proxy-cidr CIDR` | ขอบเขตความเชื่อถือเครือข่าย proxy โดยตรงที่ระบุซ้ำได้ สำหรับแยก client IP จาก `X-Forwarded-For` อย่างปลอดภัย |
| `--cookie-secure` | ส่งคุกกี้เซสชันผ่าน HTTPS ฝั่งเบราว์เซอร์เท่านั้น |
| `--kindle` | ให้บริการเพจมินิมัลที่ไม่มี dependency สำหรับ Kindle e-Ink รุ่นเก่าและเปลี่ยนเส้นทางเบราว์เซอร์ Kindle WebKit ไปยังเพจเหล่านั้น; ปิดตามค่าเริ่มต้น |

#### ไวยากรณ์ v1 รุ่นเก่า

รองรับไวยากรณ์รุ่นเก่าตลอด major line v2:

| คำสั่ง v1 | การแมปเป็น v2 |
| --- | --- |
| `epub-browser BOOKS` | `epub-browser server BOOKS --ephemeral` |
| `epub-browser BOOKS --output-dir STATE` | `epub-browser server BOOKS --server-dir STATE` |
| `epub-browser BOOKS --no-server --output-dir DIST` | `epub-browser ssg BOOKS --output-dir DIST` |
| `--sync-dir DIR` | `server --legacy-sync-dir DIR` |

`--keep-files` ที่มีเฉพาะรุ่นเก่าจะเก็บไดเรกทอรี Server ชั่วคราว ไดเรกทอรี Server แบบถาวรมีความถาวรอยู่แล้ว
เมื่อใช้ `--log` compatibility adapter จะพิมพ์คำสั่ง v2 ที่เท่ากัน มิฉะนั้นจะเงียบ

### ข้อมูลการอ่านและตำแหน่งฟีเจอร์

- การค้นพบ EPUB/PDF และไลบรารี Calibre แบบ recursive, แท็กเมทาดาทา การค้นหา และการค้นหาพินอิน
- อินเทอร์เฟซ Library รายละเอียดหนังสือ และการอ่านบทแบบ responsive
- การเลื่อน พลิกหน้า อ่านต่อเนื่อง ปรับความกว้างเนื้อหา ฟอนต์ CSS ที่กำหนดเอง ธีม และโหมดอ่านล้วน
- ไฮไลต์ บันทึก การเรียกดูคำอธิบายประกอบ กลุ่มชั้นหนังสือแบบซ้อน แท็ก และ Import/Export JSON
- อินเทอร์เฟซรองรับภาษาอังกฤษ จีนตัวย่อ จีนตัวเต็ม เกาหลี ญี่ปุ่น สเปน เยอรมัน ฝรั่งเศส รัสเซีย อิตาลี
  โปรตุเกสบราซิล อาหรับ อินโดนีเซีย ฮินดี เวียดนาม ไทย และมลายู
- การทำงานที่เหมาะกับ e-reader สำหรับเบราว์เซอร์ Kindle/Silk ฟีเจอร์ที่ใช้เบราว์เซอร์มากอาจถูกลดลง

| ข้อมูล | SSG | Server |
| --- | --- | --- |
| ความคืบหน้าการอ่าน | ในเครื่องของเบราว์เซอร์ | ระเบียน SQLite ของผู้ใช้ที่ยืนยันตัวตน |
| ไฮไลต์และบันทึก | ในเครื่องของเบราว์เซอร์ | ระเบียน SQLite ของผู้ใช้ที่ยืนยันตัวตน |
| คะแนน รีวิวส่วนตัว และประวัติเซสชันการอ่าน | ไม่มี | ระเบียน SQLite ของผู้ใช้ที่ยืนยันตัวตน |
| ชั้นหนังสือ | ในเครื่องของเบราว์เซอร์; Import/Export | เอกสารคลาวด์ที่มีเวอร์ชันของผู้ใช้ที่ยืนยันตัวตน; บันทึกอัตโนมัติ |
| บัญชีและเซสชัน | ไม่มี | SQLite ใต้ `<server-dir>/data` |
| สิทธิ์หนังสือ | ไม่มี | SQLite ใต้ `<server-dir>/data` |

Server ไม่มีตัวเลือกการจัดเก็บ local/cloud ข้อมูลการอ่านที่ยืนยันตัวตนจะเก็บบน Server เสมอ SSG ไม่สร้าง
ประวัติเซสชันการอ่านส่วนตัวแบบละเอียด SSG ไม่ตรวจสอบ Server API และใช้ local storage ของ browser origin ปัจจุบันเสมอ

### การให้บริการครบในตัวและพฤติกรรมเครือข่าย

แอปพลิเคชันครบในตัวสำหรับการอ่าน JavaScript, CSS, ฟอนต์ ไอคอน manifest และทรัพยากร EPUB ที่แปลงแล้ว
ซึ่งจำเป็นจะให้บริการในเครื่อง ไม่มี CDN dependency ขณะรันไทม์ การบล็อกอินเทอร์เน็ตขาออกไม่ขัดขวางการตั้งค่า
เข้าสู่ระบบ เรียกดู อ่าน ใช้คำอธิบายประกอบ ความคืบหน้า ใช้ชั้นหนังสือ ดูแลระบบ หรือแปลงต้นฉบับ

footer อาจส่งคำขอที่เลือกใช้ไปยัง GitHub Releases API เพื่อค้นหารุ่น EPUB Browser ที่ใหม่กว่า หากล้มเหลว
ถูกบล็อก หรือใช้ออฟไลน์ จะซ่อนเฉพาะข้อความแจ้งอัปเดต

SSG เผยแพร่ Service Worker แบบสแตติก ส่วน Server ปิดและเลิกใช้ Service Worker ทั่ว origin โดยเจตนา
เพื่อไม่ให้บัญชีหนึ่งได้รับเนื้อหาที่ป้องกันซึ่งแคชไว้ของอีกบัญชี

### Server API และ WebHooks

บัญชี Server สร้าง personal access token ที่มี scope ได้ใน Account settings ไคลเอนต์ภายนอกใช้
`Authorization: Bearer <PAT>` กับ `/api/v1/*` API ที่มีเวอร์ชัน คุกกี้เบราว์เซอร์ไม่ยืนยันตัวตน route เหล่านี้
API ครอบคลุมหนังสือและเนื้อหาบทที่มองเห็น ชั้นหนังสือของเจ้าของ token ความคืบหน้า คำอธิบายประกอบและรีวิว
รวมถึงข้อมูลข้ามผู้ใช้แบบอ่านอย่างเดียวสำหรับ administrator PAT ที่มี `admin:data:read`

เอกสาร OpenAPI 3.1 อยู่ที่ `/openapi.json` ผู้ใช้ที่เข้าสู่ระบบเรียกดูข้อมูลอ้างอิงในเครื่องได้ที่ `/api-docs`
ตัวอย่าง: `curl -H 'Authorization: Bearer …' https://reader.example/api/v1/books` รายละเอียดบทจะคืน
HTML ที่ทำความสะอาดแล้วตามค่าเริ่มต้น และคืน plain text เมื่อใช้ `?format=text`

List endpoint คืน `items` และ `next_cursor` ค่า `limit` เริ่มต้นคือ 24 และสูงสุด 100 ส่ง `next_cursor`
เป็น `cursor` พร้อมตัวกรองเดิมเพื่อดึงหน้าถัดไป cursor ที่เป็น null หมายถึงหน้าสุดท้าย ตัวอย่างเช่น ใช้
`/api/v1/me/annotations?book_id=BOOK_ID&chapter_index=0&fields=id,text,note` เพื่อดึงฟิลด์คำอธิบายประกอบ
ที่เลือกจากบท EPUB หรือหน้า PDF หนึ่งหน้า ตัวกรอง query และฟิลด์ที่รองรับระบุในเอกสาร OpenAPI

Vocabulary ใช้รูปแบบ list เดียวกันตามค่าเริ่มต้น ไคลเอนต์ที่ใช้การตอบกลับ `words` แบบเก่าส่ง `page=1`
หรือ `page_size` เพื่อเลือกรูปแบบการแบ่งหน้ารุ่นเก่าได้

ผู้ดูแลจัดการ WebHook endpoint ใน Administration Secret แสดงเฉพาะตอนสร้างหรือหมุนเวียน Delivery มีลายเซ็น
คงทน และลองใหม่เมื่อได้รับการตอบกลับ non-2xx เหตุการณ์ book-review มี ID และ timestamp ของการกระทำ
แต่ไม่มีคะแนนหรือข้อความรีวิว

### ความปลอดภัยของข้อมูลและการย้ายข้อมูล

ก่อนอัปเกรดการติดตั้ง Server แบบถาวร ให้สำรองหนังสือ EPUB/PDF ต้นฉบับและ `<server-dir>/data`
เก็บโวลุมสถานะถาวรเดิมไว้เมื่อเปลี่ยนคอนเทนเนอร์

Migration ตอนเริ่มระบบเป็นอัตโนมัติและปลอดภัยเมื่อรีสตาร์ต ระบบตรวจสอบฐานข้อมูลเก่า สร้างข้อมูลสำรอง
อัปเกรดสำเนา นำเข้าข้อมูลชั้นหนังสือ/ความคืบหน้า/คำอธิบายประกอบรุ่นเก่าที่มีสิทธิ์ไปยัง administrator
เริ่มต้นที่รอดำเนินการ และเลิกใช้ artifact สาธารณะเก่าที่เปลี่ยนใหม่ได้เท่านั้นหลัง checkpoint สำเร็จ
คำขอทั่วไปไม่สแกนไดเรกทอรี legacy sync ฐานข้อมูลเสีย password hash ไม่ถูกต้อง ฐานข้อมูลเก่าที่กำกวม
และ ID ขัดแย้งจะ fail closed แทนการเดาหรือเขียนทับ

`epub-browser.db` หรือ `annotations.db` ที่ย้ายแล้วในรูทจะถูกเก็บเป็นสำเนากู้คืนที่ละเอียดอ่อนและไม่ใช่แหล่งข้อมูลหลัก
`data/epub-browser.db` เป็นแหล่งข้อมูลหลัก และคำขอ Server ไม่ใช้ไฟล์รูทที่เก็บไว้ เก็บสำเนากู้คืนให้เป็นส่วนตัว
ลบด้วยตนเองเฉพาะขณะ Server หยุด หลังตรวจสอบฐานข้อมูลหลักและข้อมูลสำรองที่บันทึกไว้ และเมื่อไม่ต้อง rollback
ไป v1 อีกเท่านั้น EPUB Browser ไม่ลบไฟล์นี้โดยอัตโนมัติ

หากมีทั้ง `epub-browser.db` และ `annotations.db` ที่ legacy root การเริ่มระบบจะหยุดและไม่แตะต้องไฟล์
ดู [การย้ายไป v2](../migration-v2.md) สำหรับการสำรอง rollback การสร้างแคชใหม่ และการกู้คืนจากความขัดแย้ง

### การแก้ไขปัญหา

#### คำสั่งเริ่มทำงานแล้วแต่เบราว์เซอร์ไม่เปิด

นำ `--no-browser` ออกเมื่อเรียกบนเครื่องในเครื่องที่มีกราฟิก หรือเปิด URL ที่พิมพ์/ผูกไว้ด้วยตนเอง ใน Docker,
systemd, SSH และเซสชันแบบไม่โต้ตอบ การเปิด URL เองเป็นพฤติกรรมที่คาดไว้

#### CLI ดูเงียบ

การทำงานเงียบเป็นเรื่องตั้งใจเมื่อไม่มี `--log` โดยเฉพาะในสภาพแวดล้อมแบบไม่โต้ตอบ เพิ่ม `--log` เพื่อดูรายละเอียด
การดำเนินงานและการเข้าถึง ความคืบหน้าการสแกนของ Server แสดงในเว็บอินเทอร์เฟซ

#### Docker เขียนรหัสประจำตัวที่คงที่ไม่ได้

อิมเมจใช้ embedded identity ตามค่าเริ่มต้น เมานต์ `/app/Library` แบบอ่านเขียนหรือฝัง ID ที่ถูกต้องและตรงกันล่วงหน้า
ใช้ custom command กับ `--book-id-storage sidecar` เฉพาะเมื่อต้องการ carrier sidecar ที่เขียนได้มากกว่า

#### เว็บไซต์ SSG ที่สร้างมีลิงก์เสียใต้ subpath

สร้างใหม่ด้วย `--base-path` ที่ normalize แล้ว เช่น `/reader/` และตั้งค่า static host ให้ให้บริการเอาต์พุตที่ prefix เดียวกัน

#### Server ปฏิเสธการเริ่มหลังอัปเกรด

อ่านข้อผิดพลาด migration หรือ validation แรกที่บันทึก log เก็บข้อมูลและไฟล์ต้นฉบับไว้ แล้วดู
[docs/migration-v2.md](https://raw.githubusercontent.com/dfface/epub-browser/main/docs/migration-v2.md)
อย่าลบไดเรกทอรี `data/` ซึ่งเป็นแหล่งข้อมูลหลักเพื่อหลีกเลี่ยงข้อผิดพลาด

สรุปสั้น ๆ คือ ใช้ UI ตัวอ่านชุดเดียว อย่านำข้อมูลเฉพาะ Server ไปไว้ใน SSG แยกแคชที่ derive ของ EPUB และ PDF
จากข้อมูลผู้ใช้ SQLite และอย่าเพิ่ม CDN dependency ขณะรันไทม์ การเปลี่ยนแปลงที่กระทบพื้นที่ร่วมต้องทดสอบกับ
ทั้งสองรูปแบบและทั้งสองโหมดการปรับใช้เมื่อเกี่ยวข้อง

#### การพัฒนาจาก source checkout

ไฟล์เบราว์เซอร์บุคคลที่สามเป็น build input ที่สร้างขึ้น ไม่ใช่ project source `epub_browser/assets/vendor/`
จึงไม่มีใน Git โดยเจตนา ให้เตรียมเวอร์ชันที่ล็อกไว้อย่างชัดเจนก่อนพัฒนาหรือ build แล้วตรวจสอบแบบออฟไลน์:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
python3 -m unittest tests.test_vendor_assets -v
python3 -m build
```

`fetch` เป็นคำสั่งเดียวข้างต้นที่ดาวน์โหลด browser vendor asset lock บันทึก npm tarball แบบ immutable,
file digest, allowlist และสัญญาอนุญาต `verify`, การทดสอบ การ build จาก checkout ที่เตรียมแล้ว และตัวอ่านที่ติดตั้ง
จะไม่ดาวน์โหลด browser asset คำสั่ง `python3 -m build` แบบ isolated มาตรฐานยังอาจติดต่อ Python package index
สำหรับ build requirement หากต้องการ build โดยปิดเครือข่ายทั้งหมด ให้เตรียม vendor tree และติดตั้ง `build`,
`setuptools` และ `wheel` ล่วงหน้าก่อนตัดการเชื่อมต่อ แล้วเรียก
`PIP_NO_INDEX=1 python3 -m build --no-isolation` Wheel, source distribution, Docker image และเว็บไซต์ SSG
ที่สร้างมีไฟล์ที่ตรวจสอบแล้วและไม่มี CDN dependency ขณะรันไทม์ ดู [third_party/README.md](../../third_party/README.md)
สำหรับขั้นตอนอัปเดต เผยแพร่รุ่น และรักษาความสะอาดของรีพอซิทอรี
