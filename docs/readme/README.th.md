# EPUB Browser

> **เปลี่ยนหนังสือให้เป็นเว็บไซต์ สร้างไลบรารีที่เป็นของคุณ**
>
> เผยแพร่หนังสือ EPUB และ PDF เป็นเว็บไซต์สแตติก หรือเปิดใช้ไลบรารีส่วนตัวที่โฮสต์เอง
> พร้อมบัญชี การซิงก์ความคืบหน้า คำอธิบายประกอบ และการอ่านแบบผสาน AI ที่เลือกใช้ได้

EPUB Browser ไม่ใช่เพียงตัวแปลงหนังสือ แต่เป็นแพลตฟอร์มการอ่านที่สมบูรณ์ ซึ่งคุณเผยแพร่ได้ทุกที่
หรือโฮสต์เอง EPUB และ PDF ใช้ Library หน้าหนังสือ สารบัญ โหมดการอ่าน ธีม การติดตามความคืบหน้า
และขั้นตอนการทำคำอธิบายประกอบร่วมกัน หน้า PDF แต่ละหน้าจะกลายเป็นบทในตัวอ่าน โดย PDF.js เรนเดอร์ในเครื่อง
ภายในประสบการณ์การอ่านเดียวกัน ไม่ต้องมีตัวดูแยกและไม่ใช้ CDN ขณะรันไทม์

## ภาพรวมโครงการ

### เหตุผลที่เลือก EPUB Browser

- **เผยแพร่ได้ทุกที่และยังควบคุมทุกอย่างเอง** สร้างเว็บไซต์สแตติกที่สมบูรณ์สำหรับ Pages,
  object storage หรือ Nginx ด้วยคำสั่งเดียว หรือเปิดใช้ Server แบบถาวรที่มีบัญชี สิทธิ์การเข้าถึงหนังสือ
  และ OIDC ทรัพยากรของแอปพลิเคชัน ฟอนต์ PDF.js และตัวเรนเดอร์ทั้งหมดล้วนให้บริการจากเครื่อง
  การอ่านจึงไม่ต้องพึ่ง CDN
- **EPUB และ PDF ใช้ตัวอ่านเต็มรูปแบบชุดเดียวกัน** ทั้งสองรูปแบบใช้ Library หน้าหนังสือ สารบัญ
  เลย์เอาต์แบบ responsive โหมดอ่านสามแบบ ธีม โหมดเต็มหน้าจอ และความคืบหน้าร่วมกัน ทุกหน้า PDF
  อยู่ในพื้นที่อ่านเดิม พร้อมการซูม การเลือกข้อความบน text layer และคำอธิบายประกอบ แทนที่จะใช้ตัวดูตัวอย่างแยกต่างหาก
- **ค้นหาได้ทั้งเล่มและเฉพาะตอนที่ต้องการ** การค้นหาใน Library ครอบคลุมเมทาดาทา แท็ก และพินอิน
  พร้อมการจัดเรียงและแบ่งหน้า การค้นหาทั้งเล่มของ EPUB บน Server ให้ผลลัพธ์ครบถ้วนโดยจัดกลุ่ม
  ตามบท และข้ามไปยังตำแหน่งที่ไฮไลต์ไว้ได้ รหัสหนังสือที่คงที่ช่วยให้จุดอ่านต่อ คำอธิบายประกอบ และประวัติ
  ยังผูกกับหนังสือเล่มเดิมเสมอ
- **เข้าใจเนื้อหา ไม่ใช่แค่เลื่อนอ่าน** ในโหมด Server คำแนะนำประจำบทของ EPUB คำอธิบายที่อ้างอิงหลักฐาน
  แผนผังความคิด และ Ask AI ส่วนตัวจะอยู่ข้างข้อความต้นฉบับ ไฮไลต์ บันทึก Dictionary และ
  Encyclopedia ใช้ได้ทั้งกับ EPUB และ PDF ที่มี text layer ส่วนรายการคำศัพท์บน Server บันทึกแหล่งที่มา
  และสถานะความชำนาญของแต่ละคำ
- **เปลี่ยนการอ่านให้เป็นประวัติที่น่าเก็บไว้** ชั้นหนังสือแบบซ้อน คะแนน รีวิว การส่งออกคำอธิบายประกอบ
  ปฏิทินกิจกรรม แนวโน้ม สถิติรายเล่ม และอันดับเวลาอ่าน เชื่อมโยงกันเป็นบันทึกเดียว Server เก็บข้อมูล
  การอ่านเป็นส่วนตัวตามบัญชีและซิงก์ระหว่างอุปกรณ์
- **ให้บริการการอ่านหนังสือ ไม่ใช่แค่ตัวดู** ในโหมด Server ผู้ดูแลเพิ่มหนังสือผ่านการอัปโหลดบนเว็บ
  หรือโฟลเดอร์ที่เฝ้าดูได้ จำกัดการใช้ดิสก์ด้วยการนำรายการในแคชออกตามหลัก LRU ซึ่งกำหนดค่าได้ จัดการสิทธิ์สมาชิกและ AI
  และเชื่อมต่อผ่าน OpenAPI, PAT และ WebHooks การอ่าน Kindle แบบมินิมัลรองรับอุปกรณ์ที่มีข้อจำกัด
  Server ยังมีแดชบอร์ดสกรีนเซฟเวอร์ Kindle ส่วนตัวพร้อมนาฬิกา ปฏิทิน กำหนดการ บันทึก และตัวจับเวลา Pomodoro

### เทคโนโลยีที่ใช้

EPUB Browser เลือกใช้ web stack ขนาดเล็กที่เรนเดอร์ฝั่งเซิร์ฟเวอร์โดยเจตนา แอปพลิเคชันที่ติดตั้งแล้ว
ไม่มี SPA framework และไม่ต้องใช้ Node.js runtime:

| ชั้น | เทคโนโลยี | บทบาท |
| --- | --- | --- |
| Frontend | Semantic HTML, CSS, VanillaJS พร้อม ES modules และ browser API | UI แบบ responsive ชุดเดียวที่ใช้ร่วมกันระหว่าง SSG และ Server |
| CLI และ Server | Python 3.9+, Starlette, Uvicorn | คำสั่งแปลง หน้าที่ต้องยืนยันตัวตน API และงานเบื้องหลัง |
| ข้อมูล | SQLite พร้อมแคชเนื้อหา JSON ที่สร้างใหม่ได้ | สถานะผู้ใช้แยกจากเนื้อหา EPUB/PDF ที่ได้จากการประมวลผล |
| รูปแบบหนังสือ | lxml, pypdf, pypdfium2, PDF.js | การแยกวิเคราะห์และทำความสะอาด EPUB แบบรวมศูนย์ โดยใช้โหมดเข้มงวดก่อน เมทาดาทา/ปก PDF และการเรนเดอร์ในเบราว์เซอร์ภายในเครื่อง |
| ออฟไลน์และทรัพยากร | Service Worker, ทรัพยากรแบบ immutable ที่มี hash และ dependency ของ vendor ที่ล็อกไว้ | ทำงานได้ครบถ้วนด้วยตัวเองโดยไม่ใช้ CDN ขณะรันไทม์ |
| การเผยแพร่ | PyPI, Docker, static hosting ทั่วไป | codebase เดียวกันใช้ได้ทั้งสร้าง SSG และเปิดใช้ Server แบบถาวร |
| AI ที่เลือกใช้ | API ที่เข้ากันได้กับ OpenAI พร้อม Markdown, KaTeX และ Mermaid ที่เรนเดอร์ในเครื่อง | เลเยอร์การเรียนรู้สำหรับ EPUB เฉพาะในโหมด Server |

ผู้ดูแลใช้ Node.js เฉพาะสำหรับทดสอบฝั่งเบราว์เซอร์เท่านั้น Node.js ไม่ได้เป็นส่วนหนึ่งของ production runtime ของผู้อ่าน

### เลือก SSG หรือ Server

การประมวลผลต้นฉบับและ page template ชุดเดียวกันรองรับโหมดการปรับใช้สองแบบที่แยกกันชัดเจน
เลือกตามตำแหน่งที่ควรเก็บข้อมูลการอ่าน ไม่ใช่ตามรูปแบบหนังสือ:

| ความสามารถ | `ssg` | `server` |
| --- | --- | --- |
| EPUB และ PDF | รองรับ | รองรับ |
| การให้บริการ | HTML/ทรัพยากรสแตติกแบบ atomic สำหรับ Pages, object storage หรือ Nginx | หน้าแบบไดนามิกที่ยืนยันตัวตน โดยอาศัยแคชเนื้อหาที่แทนที่ได้ |
| บัญชีและการควบคุมการเข้าถึง | ไม่มี | บัญชี administrator/member การให้สิทธิ์หนังสือแบบจำกัด เซสชัน และการป้องกัน CSRF |
| การลงชื่อเพียงครั้งเดียวด้วย OIDC | ไม่รวม | Provider ทั่วไป การเชื่อมบัญชีเดิม และการสร้างบัญชีสมาชิกอัตโนมัติแบบเลือกใช้ |
| ความคืบหน้า คำอธิบายประกอบ ชั้นหนังสือ | เก็บในเบราว์เซอร์ปัจจุบัน | ซิงก์ตามบัญชีที่ยืนยันตัวตนใน SQLite |
| คะแนน รีวิว เซสชันการอ่าน | ไม่มีการสร้างข้อมูล | บันทึกส่วนตัวตามบัญชีและข้อมูลเชิงลึกการอ่าน |
| การอัปเดตต้นฉบับ | รัน `ssg` อีกครั้ง | รีสตาร์ต สแกนใหม่ หรือใช้ `--watch` |
| การดูแลระบบ แท็ก OpenAPI, WebHooks | ไม่รวม | มี |
| การอ่านด้วย AI และ Ask AI | ไม่รวม | ใช้กับ EPUB ได้เมื่อกำหนดค่าและอนุญาตอย่างชัดเจน ส่วน PDF จะซ่อนไว้ |
| ฐานข้อมูลขณะรันไทม์ | ไม่มี | จำเป็นสำหรับโหมดถาวร |
| เหมาะที่สุดสำหรับ | public/static hosting, ชุดออฟไลน์ และการเผยแพร่ส่วนตัวแบบง่าย | ไลบรารีส่วนตัว หลายอุปกรณ์หรือผู้อ่านหลายคน ระบบอัตโนมัติ และการควบคุมการเข้าถึง |

ใช้ `ssg` เมื่อผลลัพธ์ต้องเป็นไฟล์สแตติกทั่วไป ใช้ `server` เมื่อผู้อ่านต้องมีบัญชี ข้อมูลข้ามอุปกรณ์
การควบคุมการเข้าถึง หรือการปรับข้อมูลให้ตรงกับต้นฉบับโดยอัตโนมัติ

### การอ่านที่ผสาน AI (เฉพาะ Server)

สำหรับหนังสือ EPUB โหมด Server สามารถเพิ่มคำแนะนำประจำบท คำอธิบายที่เชื่อมกับหลักฐาน แผนผังความคิด
คำถามชวนสะท้อน และลิ้นชัก Ask AI ส่วนตัว โดยผู้อ่านไม่ต้องออกจากข้อความต้นฉบับ ผลลัพธ์ยังอยู่ภายใต้
สิทธิ์การเข้าถึงหนังสือ สมาชิกต้องได้รับอนุญาตอย่างชัดเจน และ SSG ไม่มีตัวควบคุม AI งาน ข้อมูลบัญชี หรือการตั้งค่า
provider ใด ๆ ส่วน PDF จะซ่อนการอ่านด้วย AI และ Ask AI โดยเจตนา

ดู [คู่มือการอ่านที่ผสาน AI](../ai-native-reading.md) สำหรับโมเดลการโต้ตอบฉบับเต็ม และ
[บันทึกเกี่ยวกับตัวเรนเดอร์ rich text ในเครื่อง](../third-party-ai-renderers.md) สำหรับขอบเขตด้านการเรนเดอร์และความปลอดภัยเครือข่าย

### โหมด Kindle แบบมินิมัล

Kindle e-Ink รุ่นเก่า (และเบราว์เซอร์ที่มีข้อจำกัดอื่น ๆ) จะได้หน้าอ่านแบบมินิมัลที่ไม่ต้องใช้ dependency
เปิดใช้ด้วย `--kindle`:

- SSG: `epub-browser ssg --kindle -o output/ SOURCE...`
- Server: `epub-browser server --kindle --server-dir data SOURCE...`

หนังสือ EPUB แต่ละเล่ม (ไม่รวม PDF) จะมีหน้าเพิ่มเติมอีกสามหน้า:

- ชั้นหนังสือแบบมินิมัล `/kindle-library.html`
- หน้าหนังสือ `/book/<id>/kindle.html`
- หน้าบท `/book/<id>/kindle_chapter_N.html`

เพจเหล่านี้ปรับสำหรับ e-Ink โดยเฉพาะ: markup น้อย การเปลี่ยนธีมด้วย CSS เท่านั้น สคริปต์ที่เข้ากันได้กับ
ES5 ไม่มี Service Worker และไม่มี framework คุณอ่านได้โดยไม่ใช้ JavaScript เลย ส่วนการเปลี่ยนธีม
(Light / Sepia / Dark) ขนาดตัวอักษร (A- / A+) และการแปลอินเทอร์เฟซ ใช้ inline script ขนาดเล็กเสริมจาก HTML พื้นฐาน

ทุกหน้ามีตัวควบคุมธีมและฟอนต์ (ที่ header และซ้ำที่ footer ของบท) การนำทางสารบัญ บทก่อนหน้า/ถัดไป
และลิงก์ "Continue reading" สำหรับกลับไปยังความคืบหน้าที่บันทึกไว้

ความคืบหน้าการอ่านต่างกันตามโหมด:

- **SSG:** ความคืบหน้าเก็บในคุกกี้ของเบราว์เซอร์ปัจจุบัน เป็นแบบภายในเครื่องและไม่มีบัญชี
- **Server:** ความคืบหน้าและ heartbeat การอ่านซิงก์ตามบัญชีที่เข้าสู่ระบบใน SQLite ส่วน Kindle
  ใช้สำหรับอ่านและรายงานความคืบหน้าเท่านั้น โดยบันทึกบทปัจจุบันและรายงาน heartbeat แสดงชั้นหนังสือแบบอ่านอย่างเดียว
  และไม่เปิดเผยข้อมูลเชิงลึกหรือการจัดการเนื้อหา

การควบคุมการเข้าถึงมีผลกับทุกหน้าของ Kindle หนังสือที่จำกัดการมองเห็นจะคืน 403 แก่ผู้ใช้ที่ไม่ได้รับอนุญาต
โดยชั้นหนังสือแบบมินิมัลจะไม่แสดงหนังสือดังกล่าว ส่วนหน้าหนังสือ หน้าบท และ API ความคืบหน้าจะคืน 403

เบราว์เซอร์ที่รองรับ (UA มี `Kindle/`, `Arora/` ฯลฯ) จะถูกเปลี่ยนเส้นทางจากตัวอ่านเต็มรูปแบบไปยังเพจ
มินิมัลโดยอัตโนมัติ URL ข้างต้นก็เปิดโดยตรงได้เช่นกัน โหมดมินิมัลจึงเป็น fallback ที่เหมาะกับอุปกรณ์
ที่มีทรัพยากรจำกัดหรือจำกัด JavaScript

## เริ่มต้นใช้งาน

### เลือกวิธีติดตั้ง

EPUB Browser รองรับการติดตั้งสองวิธี ทั้งสองวิธีรับไฟล์ `.epub` หรือ `.pdf` หนึ่งไฟล์ขึ้นไป ไดเรกทอรี
แบบซ้อน หรือไดเรกทอรีไลบรารีแบบ Calibre

| การติดตั้ง | ใช้สำหรับ | ข้อกำหนดของโฮสต์ |
| --- | --- | --- |
| PyPI | โหมด SSG หรือ Server | Python 3.9 หรือใหม่กว่า |
| Docker | โหมด Server แบบถาวร | Docker Engine; อิมเมจมี Python รวมอยู่แล้ว |

#### PyPI (SSG หรือ Server)

ติดตั้งแอปพลิเคชันบรรทัดคำสั่ง:

```bash
pip install epub-browser
```

แสดงข้อมูลอ้างอิงคำสั่งตามโหมด:

```bash
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

#### Docker (Server)

อิมเมจ [`dfface/epub-browser`](https://hub.docker.com/r/dfface/epub-browser) ที่เผยแพร่แล้วทำงานใน
โหมด Server และไม่ต้องติดตั้ง Python บนโฮสต์:

```bash
docker pull dfface/epub-browser:latest
```

ใช้ `latest` เพื่อประเมินรุ่นปัจจุบัน สำหรับการปรับใช้ production ที่ทำซ้ำได้ ให้ระบุแท็กรุ่นที่มีหมายเลขให้ตายตัว
ดู [Docker](#docker) สำหรับการ mount ที่จำเป็นสำหรับหนังสือและข้อมูลสถานะ วิธีเริ่ม Compose อย่างรวดเร็ว การตั้งค่าครั้งแรก และคำแนะนำเครือข่าย

### เริ่มต้นอย่างรวดเร็ว

#### สร้างเว็บไซต์สแตติก

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist
```

ให้บริการไฟล์ใน `dist/` ผ่าน HTTP ไม่รองรับการเปิดเพจที่สร้างขึ้นโดยตรงผ่าน `file://` เนื่องจาก browser storage,
module, manifest และ Service Worker ต้องใช้ HTTP origin

สำหรับเว็บไซต์ที่โฮสต์ใต้ URL prefix ให้ตั้ง public path แยกจากปลายทางบน filesystem:

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist \
  --base-path /my-repository/
```

`--base-path` เปลี่ยน URL ที่สร้างขึ้น ไม่ได้เปลี่ยนตำแหน่งเขียนไฟล์ เมื่อใช้ `/my-repository/` ลิงก์ ไอคอน
manifest, เมทาดาทาหนังสือ และรายการ Service Worker จะใช้ prefix นี้ ขณะที่ไฟล์ยังอยู่ใน `dist/` โดยตรง

#### เปิดใช้ไลบรารีบน Server แบบถาวร

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/epub-browser-state \
  --watch
```

เมื่อเปิด `http://127.0.0.1:8000/` เป็นครั้งแรก EPUB Browser จะแสดงข้อความให้คุณสร้างบัญชี administrator เริ่มต้น
ไลบรารีจะยังไม่ถูกสแกนหรือเปิดเผยจนกว่าการตั้งค่าครั้งเดียวนี้จะเสร็จ

หากเลือก Docker ให้ข้ามคำสั่ง Python ข้างต้นแล้วไปที่
[วิธีเริ่ม Docker Compose อย่างรวดเร็ว](#docker-compose)

## รูปแบบหนังสือและการอ่าน

### แหล่งที่มาและรหัสประจำตัวหนังสือที่คงที่

`SOURCE` แบบ positional แต่ละรายการอาจเป็นไฟล์ EPUB ไฟล์ PDF หรือไดเรกทอรี ระบบค้นหาในไดเรกทอรี
แบบ recursive และส่งหลายแหล่งให้คำสั่งเดียวได้:

```bash
epub-browser server book.epub /srv/library /srv/periodicals \
  --server-dir /srv/epub-browser \
  --watch
```

หนังสือแต่ละเล่มได้รับ `book_id` ที่คงที่ และแสดงเป็น `book_hash` ใน URL กับข้อมูลเบราว์เซอร์ที่สร้างขึ้น
ค่าเริ่มต้นทั่วไปของ CLI คือ:

```bash
--book-id-storage sidecar
```

โหมด sidecar เขียนไฟล์ข้อมูล ID ที่มองเห็นได้ไว้ข้างต้นฉบับ เช่น `BOOK.epub.epub-browser.json` หรือ
`BOOK.pdf.epub-browser.json` โดยไม่เปลี่ยนไบต์ของต้นฉบับ sidecar มี ID ที่คงที่และลายนิ้วมือ SHA-256
ของต้นฉบับที่ตรวจสอบแล้ว

หากต้องการใส่ ID ในเมทาดาทา OPF ของ EPUB หรือ document information dictionary ของ PDF ให้เลือก
embedded storage สำหรับการรันคำสั่งทั้งครั้งนั้น:

```bash
--book-id-storage embedded
```

โหมด embedded อาจสร้าง EPUB ZIP ใหม่หรือเพิ่มการอัปเดตเมทาดาทา PDF ต่อท้ายไฟล์ก่อนแปลง หากไม่สามารถอัปเดต PDF ได้
และต้นฉบับไม่เปลี่ยน EPUB Browser จะบันทึก ID เดิมลง sidecar ที่อยู่ติดกัน รวมถึง PDF ที่เซ็นชื่อ เข้ารหัส
และอ่านอย่างเดียว EPUB Browser จะหยุดเมื่อ ID ไม่ตรงกัน แหล่งที่ใช้งานมี ID ซ้ำกัน ตัวเก็บ ID ไม่ถูกต้อง
หรือไม่สามารถเขียนตัวเก็บ ID ที่จำเป็นได้

เมื่อเปลี่ยนโหมดการจัดเก็บ EPUB Browser จะคัดลอก ID เดิมไปยังตัวเก็บ ID ที่เลือก และคงตัวเก็บ ID อีกแบบที่ยังถูกต้องไว้
embedded ID เดิมจาก v2.0.4 จะถูกคัดลอกไปยัง sidecar เริ่มต้นโดยไม่เขียน EPUB ใหม่ ทั้ง SSG และ Server
ให้บริการสำเนา PDF ต้นฉบับแบบตรงกันทุกไบต์หลังการอัปเดตเมทาดาทา

### PDF: หนึ่งหน้าหนึ่งบท

ทั้งสองโหมดการปรับใช้รองรับ PDF ตัวอ่านถือว่าหน้า PDF แต่ละหน้าเป็นบททั่วไปของ EPUB Browser ดังนั้นหน้า Book,
การนำทางบท สารบัญ การแบ่งหน้า การอ่านแบบต่อเนื่อง ความคืบหน้า เซสชันการอ่าน คำอธิบายประกอบ Dictionary และ
Encyclopedia จึงยังใช้ UI และโมเดลข้อมูลชุดเดียวกัน:

| แนวคิดของ PDF | SSG | Server |
| --- | --- | --- |
| URL หน้า 1 | `chapter_0.html` | `/book/<book-id>/chapter_0.html` |
| URL หน้า N | `chapter_{N-1}.html` | `/book/<book-id>/chapter_{N-1}.html` |
| ป้ายหน้าและสารบัญ | สร้างในเครื่อง แสดงทุกหน้า | เรนเดอร์จากแคชเมทาดาทา PDF แสดงทุกหน้า |
| Outline ที่ฝัง | Marker ในรายการสารบัญของหน้าปลายทาง | Marker เดียวกัน โดยไม่ลบหรือจัดลำดับรายการหน้าใหม่ |
| การเลื่อนและการแบ่งหน้า/พลิกหน้า | Chapter shell แบบสแตติกและ PDF.js ในเครื่อง | Chapter shell แบบไดนามิกที่ใช้ร่วมกันและ PDF.js ในเครื่อง |
| ไฮไลต์ บันทึก Dictionary, Encyclopedia | Component ที่ใช้ร่วมกันและจัดเก็บข้อมูลในเบราว์เซอร์เมื่อมี text layer | Component ที่ใช้ร่วมกันสำหรับผู้ใช้ที่ยืนยันตัวตนแล้วเมื่อมี text layer |
| ไบต์ PDF ดิบ | มี `document.pdf` หนึ่งไฟล์ในเอาต์พุตหนังสือสแตติก | Route สำหรับเอกสารในแคช ซึ่งใช้ได้เฉพาะ Session และรองรับ Range |

เลขหน้าที่มองเห็นและใน PDF.js เริ่มที่ 1 ส่วนดัชนีบทใน URL ข้อมูลสถานะ API และ SQLite เริ่มที่ 0 ดังนั้นหน้า PDF 1
จึงเป็น `chapter_0.html` เสมอ สารบัญที่ทำให้เป็นรูปแบบเดียวกันแล้วมีรายการ `Page N` หนึ่งรายการต่อหน้า ชื่อ outline
ที่ฝังใน PDF จะถูกแนบเป็น outline marker กับรายการปลายทาง รวมถึงหลาย marker ในหน้าเดียว

SSG เขียน `document.pdf` เพียงไฟล์เดียวและ chapter shell `chapter_<index>.html` หนึ่งไฟล์ต่อหน้า เอาต์พุต
SSG ไม่มีสคริปต์ที่เกี่ยวข้องกับ Session การเรียก `/api/*` ข้อมูลคำอธิบายประกอบที่ซิงก์ หรือ dependency ของ Server
Server เก็บสำเนาต้นฉบับทั้งไฟล์ที่ตรงกันทุกไบต์ไว้ที่ `book/<book-id>/pdf/document.pdf` และไม่แยกหรือเขียนใหม่
Server เรนเดอร์ chapter shell ชุดเดียวกันแบบไดนามิกจากเมทาดาทา PDF เมื่อต้นฉบับเปลี่ยน ระบบจะถือว่าแคช PDF ใช้ไม่ได้
และรีเฟรชทั้งหมด (เอกสาร เมทาดาทา และปกที่สร้างจากต้นฉบับ) แทนการผสมหน้าเก่ากับหน้าใหม่

Endpoint สำหรับไฟล์เอกสารต้นฉบับของ Server ใช้ได้เฉพาะ Session:
`GET`/`HEAD /api/books/<book-id>/document` ซึ่งตรวจสอบการยืนยันตัวตน การมองเห็นหนังสือ รูปแบบ PDF
และลายนิ้วมือต้นฉบับ/แคช จากนั้นรองรับการตอบกลับ single-range ที่มีขอบเขตจำกัด พร้อม `ETag`,
`Accept-Ranges`, private caching, `nosniff` และ inline PDF disposition ไม่เปิดเผยพาธสัมบูรณ์
ไม่รองรับการยืนยันตัวตนด้วย PAT และไม่อยู่ในชุด API ของ PAT/OpenAPI ส่วน SSG มีเพียง `document.pdf`
ในเครื่องและไม่มี API สำหรับไฟล์เอกสารต้นฉบับ

PDF ที่มี text layer ซึ่ง PDF.js ใช้งานได้จะใช้ popup เลือกข้อความและ component เดิมสำหรับคำอธิบายประกอบ
Highlight และ Note รวมถึง Dictionary และ Encyclopedia การจัดเก็บ ความเป็นเจ้าของ การส่งออก การแสดงรายการ
และ deep link ของคำอธิบายประกอบยังใช้ร่วมกัน ไม่มีตารางฐานข้อมูลคำอธิบายประกอบหรือ UI ตั้งค่าเฉพาะ PDF
PDF ที่สแกนหรือมีเฉพาะภาพยังอ่านได้ แต่ Highlight, Note, Dictionary, Encyclopedia ที่อาศัยการเลือกข้อความ
และการค้นหาเอกสารจะระบุชัดเจนว่าใช้ไม่ได้เมื่อไม่มี text layer ที่ใช้งานได้ การเลือกข้ามหน้ายังคัดลอกได้
ขณะที่คำสั่งสำหรับคำอธิบายประกอบและการค้นคำจะแสดงข้อความไม่รองรับที่แปลแล้ว ส่วนการเลือกภายในหน้ายังทำงาน

PDF.js ไม่ใช่ viewer shell ที่สอง ก่อน build หรือเผยแพร่ ให้เตรียมทรัพยากรบุคคลที่สามที่ล็อกไว้ให้พร้อมและตรวจสอบ:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
```

จากนั้นแอปพลิเคชันจะให้บริการไฟล์ module และ worker ของ PDF.js แบบมี hash จากเครื่องขณะรันไทม์ โดยไม่ดึงจาก CDN
image lightbox ใช้ dependency GLightbox ที่ล็อกไว้ ส่วน Fancyapps/Fancybox ไม่ใช่ dependency ขณะรันไทม์
และไม่ได้เผยแพร่ซ้ำ ดู [third_party/README.md](../../third_party/README.md) สำหรับขั้นตอนทรัพยากรที่ล็อกและการเผยแพร่รุ่น

## การปรับใช้

### SSG

SSG สร้าง snapshot ที่สมบูรณ์ในไดเรกทอรี staging ข้างกัน ตรวจสอบ แล้วแทนที่ปลายทาง หากการแปลงใดล้มเหลว
ปลายทางเดิมจะไม่เปลี่ยน เอาต์พุตที่สร้างไม่มีฐานข้อมูล Server สถานะ migration หน้าบัญชี หรือเมทาดาทา runtime cache

SSG ตั้งใจทำงานในเครื่องและไม่มีบัญชี:

- ความคืบหน้าการอ่านและคำอธิบายประกอบใช้ browser storage บน origin ปัจจุบัน
- ชั้นหนังสือรองรับ Import และ Export JSON ในเครื่อง ไม่มีคำสั่ง Sync บนคลาวด์
- ไม่มีการเข้าสู่ระบบ การตั้งค่าบัญชี Server API และตัวควบคุมที่ขึ้นกับผู้ใช้
- ตำแหน่งจัดเก็บข้อมูลถูกกำหนดเป็น local browser storage และไม่แสดงเป็นตัวเลือกการตั้งค่า
- เอาต์พุตสแตติกมี Service Worker ที่จำเป็นสำหรับทรัพยากรที่ใช้ออฟไลน์ได้

JavaScript, CSS, ฟอนต์ และไอคอนของแอปพลิเคชันที่จำเป็นทั้งหมดรวมอยู่ในเอาต์พุต ดู
[การให้บริการครบในตัวและพฤติกรรมเครือข่าย](#การให้บริการครบในตัวและพฤติกรรมเครือข่าย) สำหรับคำขอเครือข่ายที่เลือกใช้เพียงรายการเดียว

### Server

#### การตั้งค่าเริ่มต้น บัญชี และสิทธิ์

เมื่อใช้ไดเรกทอรีสถานะถาวรใหม่ เพจทั่วไปจะเปลี่ยนเส้นทางไป `/setup` API, event stream, ทรัพยากรที่ระบบสร้างขึ้น และหนังสือ
จะตอบกลับว่าต้องตั้งค่าก่อนจนกว่าจะสร้าง administrator เริ่มต้น ตั้งค่าให้เสร็จผ่าน loopback หรือเส้นทางส่วนตัว
ที่เชื่อถือได้ก่อนเปิดพอร์ต เนื่องจากผู้ที่ส่งการตั้งค่าสำเร็จเป็นคนแรกจะได้บัญชี administrator

หลังตั้งค่า:

- ปิดการลงทะเบียนสาธารณะ ผู้ดูแลสร้างและจัดการผู้ใช้
- บัญชีมีบทบาท `administrator` หรือ `member`
- หนังสือทั่วไปมองเห็นได้จากทุกบัญชีที่ยืนยันตัวตน
- หนังสือแบบจำกัดมองเห็นได้เฉพาะผู้ดูแลและผู้ใช้ที่เลือกไว้อย่างชัดเจน
- ผู้ใช้แต่ละคนเป็นเจ้าของชั้นหนังสือ ความคืบหน้า คำอธิบายประกอบ และเซสชันที่ใช้งานของตน
- ผู้ใช้เปลี่ยนรหัสผ่านและเพิกถอนเซสชันของตนได้
- ผู้ดูแลจัดการผู้ใช้ บทบาท รหัสผ่าน เซสชัน และสิทธิ์หนังสือได้
- เซสชันใช้คุกกี้ HttpOnly การป้องกัน CSRF และมีอายุ 30 วันแบบเลื่อนต่ออัตโนมัติ

#### การลงชื่อเพียงครั้งเดียวด้วย OIDC และการเชื่อมบัญชี

โหมด Server ใช้ OpenID Connect (OIDC) Provider แบบทั่วไปได้หนึ่งราย รวมถึง Authelia, Keycloak, Authentik
และบริการที่เข้ากันได้ ใน **Administration → OIDC login** ให้กรอกชื่อ Provider ที่แสดงแก่ผู้อ่าน issuer URL,
client ID, client secret, redirect URI ที่ตรงกัน, scope และ username claim EPUB Browser ใช้ discovery
กับ Authorization Code flow พร้อม S256 PKCE ตรวจสอบลายเซ็นของ ID token และระบุบัญชีภายนอกด้วย
`(issuer, sub)` เท่านั้น email และ username claim เป็นข้อมูลประกอบการแสดงผลและการสร้างบัญชีเท่านั้น ไม่ใช่คีย์สำหรับระบุตัวตน

ลงทะเบียน callback นี้ที่ Provider ให้ตรงกันทุกประการ รวมถึง scheme และ host:

```text
https://reader.example.com/auth/oidc/callback
```

ผู้ใช้เดิมสามารถเข้าสู่ระบบด้วยบัญชีในเครื่องแล้วเชื่อม Provider จาก Account settings ได้ หากเป็นตัวตนภายนอกที่ไม่รู้จัก
ระบบจะถามชื่อผู้ใช้และรหัสผ่านในเครื่องเดิมหนึ่งครั้ง การสร้างบัญชีอัตโนมัติแบบเลือกใช้จะสร้างบัญชีสมาชิกที่ไม่มี
รหัสผ่าน และไม่นำเข้าบทบาท administrator เสมอ ควรให้ผู้ใช้เดิมผูกบัญชีก่อน เพราะเปิดการสร้างบัญชีอัตโนมัติ
เร็วเกินไปอาจสร้าง **บัญชีในเครื่องซ้ำ** การเข้าสู่ระบบด้วยรหัสผ่านของ **administrator ในเครื่อง**
ยังใช้ได้เสมอแม้ปิดการเข้าสู่ระบบด้วยรหัสผ่านของสมาชิกในเครื่อง ควรทดสอบและปกป้องข้อมูลกู้คืนนี้
ระบบไม่ได้ออกจากระบบที่ Provider และไม่เก็บ Provider access/refresh token

สำหรับ Authelia ให้กำหนด confidential client ในส่วน OIDC Provider ตัวอย่างต่อไปนี้ใช้ค่าปลอมโดยเจตนา
และถือว่ากำหนด provider key กับ policy ที่ Authelia จำเป็นไว้แล้ว เก็บ hash ของ client secret แบบสุ่มที่คาดเดาได้ยาก
ใน Authelia แล้วกรอก raw secret ที่เกี่ยวข้องใน EPUB Browser หนึ่งครั้ง:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: 'epub-browser'
        client_name: 'EPUB Browser'
        client_secret: '<AUTHELIA_HASH_OF_A_RANDOM_SECRET>'
        public: false
        authorization_policy: 'two_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://reader.example.com/auth/oidc/callback'
        scopes: ['openid', 'profile', 'email']
        response_types: ['code']
        grant_types: ['authorization_code']
        token_endpoint_auth_method: 'client_secret_basic'
```

ใน EPUB Browser ให้ใช้ issuer `https://auth.example.com`, client ID
`epub-browser`, scope `openid profile email` และ username claim
`preferred_username` เมื่อกด Save ระบบจะทำ live discovery และตรวจสอบความสามารถ หากล้มเหลว การตั้งค่าเดิมจะยังคงใช้งานอยู่

#### กำหนดค่าและกำกับการอ่านด้วย AI

ผู้ดูแลกำหนดค่าการอ่านด้วย AI ใน **Administration** ซึ่งอยู่ถัดจากส่วนจัดการผู้ใช้และอยู่ก่อนส่วนจัดการหนังสือ
หน้านี้เก็บ Base URL ที่เข้ากันได้กับ OpenAI, API key, model, timeout, ขีดจำกัดปริมาณ context, จำนวนงานพร้อมกันสูงสุด
และขีดจำกัดเริ่มต้นของจำนวนการเรียก provider ต่อวันไว้ในฐานข้อมูล Server SQLite ตอนเริ่มต้น AI จะถูกปิดสำหรับสมาชิก
ผู้ดูแลต้องให้สิทธิ์แก่สมาชิกแต่ละคนและอาจตั้งขีดจำกัดรายวันเฉพาะบุคคล (`0` หมายถึงไม่จำกัด)

เลเยอร์การเรียนรู้ประจำบทและรีวิวระดับเล่มจะใช้ร่วมกันในแต่ละภาษาที่รองรับ ขณะที่บทสนทนาต่อเนื่องเป็นส่วนตัวของแต่ละบัญชี
ผลลัพธ์ สถานะงาน แท็กที่กำหนดเอง การจำแนกประเภทการอ่านของหนังสือ และบทสนทนาต่อเนื่องส่วนตัวเก็บใน SQLite
ผลลัพธ์เก่ายังใช้ได้หลังเปลี่ยนการตั้งค่า model จนกว่าผู้ดูแลจะสั่งสร้างผลลัพธ์ใหม่อย่างชัดเจน

เมื่อผู้อ่านขอคำแนะนำ AI หรือถามคำถาม ข้อความที่เลือกจาก EPUB และ context บทสนทนาที่บีบอัดจะถูกส่งไปยัง
provider ภายนอกที่กำหนดค่า อย่าเปิดฟีเจอร์นี้หากผู้อ่านไม่ได้รับอนุญาตให้ส่งเนื้อหาดังกล่าวไปยัง provider
API key จะไม่ถูกส่งกลับไปยังเบราว์เซอร์หรือเปิดเผยผ่าน API ควรปกป้องไดเรกทอรีสถานะ Server ตามนั้น

สำหรับการเริ่มครั้งแรกแบบอัตโนมัติ ให้ระบุชื่อผู้ใช้และไฟล์รหัสผ่าน:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --admin-username admin \
  --admin-password-file /run/secrets/epub-browser-admin-password \
  --no-browser
```

ควรตั้ง permission ของไฟล์รหัสผ่านเป็น `0600` EPUB Browser ตัด newline ท้ายไฟล์ออกหนึ่งตัว เก็บ hash Argon2id และไม่แสดง secret ในเอาต์พุต
หากการตั้งค่าไม่ครบ ไฟล์ว่าง หรืออ่านไฟล์ไม่ได้ ระบบจะเริ่มทำงานไม่สำเร็จ เมื่อตั้งค่าเสร็จแล้ว การเริ่มครั้งต่อไปจะไม่อ่าน bootstrap secret

ตัวแปรสภาพแวดล้อมที่เท่ากันคือ `EPUB_BROWSER_ADMIN_USERNAME` และ `EPUB_BROWSER_ADMIN_PASSWORD_FILE`
`EPUB_BROWSER_ADMIN_PASSWORD` เป็นค่าสำรองแบบ plaintext ซึ่งใช้เฉพาะเมื่อไม่ได้กำหนดไฟล์รหัสผ่าน
พาธไฟล์รหัสผ่านที่ระบุใน CLI มีลำดับความสำคัญสูงกว่าแหล่งรหัสผ่านจากตัวแปรสภาพแวดล้อม

#### การเปิดเบราว์เซอร์และการบันทึก log

โดยค่าเริ่มต้น Server จะพยายามเปิดเบราว์เซอร์เริ่มต้นของระบบปฏิบัติการหลัง HTTP listener เริ่มแล้ว
`--no-browser` ป้องกันการเปิดเบราว์เซอร์ในเครื่องนั้น โดย **ไม่ปิดเว็บอินเทอร์เฟซหรือการเข้าถึงผ่านเบราว์เซอร์**
แต่เพียงระงับการเรียก `webbrowser.open(...)` ในเครื่อง ใช้กับ Docker, systemd, เซสชัน SSH, เครื่อง headless และสคริปต์

ตามค่าเริ่มต้น (`--log-level error`) CLI แสดงเฉพาะข้อผิดพลาด เพื่อไม่ให้ข้อความหรือคำเตือนตามปกติรบกวน
การแสดงความคืบหน้าบนเทอร์มินัล เทอร์มินัลแบบโต้ตอบจะพิมพ์ URL ที่ bind หนึ่งครั้ง ส่วนการรันผ่าน Docker
และ service แบบไม่โต้ตอบจะเงียบ ใช้ `--log-level warning` เพื่อรวมคำเตือน `--log-level info` สำหรับ log
การดำเนินงานและ HTTP access หรือ `--log-level debug` เพื่อรายละเอียดมากที่สุด `--log` ยังเป็น alias
เพื่อความเข้ากันได้ของ `--log-level info`

การสแกนเริ่มต้นและ watch จะแสดงในเว็บอินเทอร์เฟซแทน `tqdm` บนเทอร์มินัล เมื่อสแกนสำเร็จ สรุปผลจะปิดโดยอัตโนมัติ
ข้อความข้อผิดพลาดจะยังแสดงอยู่จนกว่าจะปิด เมื่อใช้ `--watch` การแก้ไขหรือแทนที่ต้นฉบับจะเริ่มสแกนอีกครั้งโดยไม่ต้องกดลองใหม่ด้วยตนเอง

#### สถานะถาวรและชั่วคราว

โหมด Server แบบถาวรต้องใช้ `--server-dir` สำหรับการรันแบบใช้ครั้งเดียว ให้ใช้ `--ephemeral` แทน:

```bash
epub-browser server book.epub --ephemeral
```

สถานะ ephemeral จะถูกลบเมื่อปิด เนื่องจากฐานข้อมูลเป็นของใหม่ทุกครั้ง จึงต้องตั้งค่าใหม่ทุกครั้ง เว้นแต่จะระบุ
ข้อมูล bootstrap สำหรับการตั้งค่าอัตโนมัติ

โครงสร้างแบบถาวร:

```text
<server-dir>/
├── .server.lock                 # reusable process-lock metadata
├── data/
│   ├── epub-browser.db          # authoritative accounts, books, grants, reading data
│   ├── migration-state.json     # restart-safe migration state
│   └── backups/                 # verified pre-migration database copies
└── cache/
    ├── catalog.json             # generated-cache status
    ├── public/                  # served application and converted books
    └── staging/                 # replaceable conversion work
```

เฉพาะ `data/` เท่านั้นที่เป็นแหล่งข้อมูลที่ถือเป็นหลัก `cache/` ลบได้และจะถูกสร้างใหม่ เก็บ `data/` ไว้ระหว่างอัปเกรดและเปลี่ยนคอนเทนเนอร์
lock ของระบบปฏิบัติการควบคุมการเข้าถึงให้เป็นแบบผูกขาด `.server.lock` อาจเหลือหลังปิดตามปกติเพื่อเป็นเมทาดาทาสำหรับวินิจฉัย

จัดเก็บ `data/epub-browser.db` แบบถาวรบน filesystem ในเครื่อง ไม่รองรับ shared หรือ network filesystem
สำหรับ WAL concurrency ข้อมูลสำรองที่ผ่านการตรวจสอบจะอยู่ใน `data/backups/` และรวมข้อมูล WAL ที่ commit แล้วทั้งหมด

#### LAN และ reverse proxy

โดยค่าเริ่มต้น Server จะ bind ที่ `127.0.0.1:8000` สำหรับ LAN ที่เชื่อถือได้:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --port 8080 \
  --no-browser
```

อย่าเปิด HTTP server ในตัวสู่อินเทอร์เน็ตสาธารณะโดยตรง ให้ terminate TLS ที่ reverse proxy ใช้การควบคุมเครือข่าย และเปิด secure cookie

หากต้องการบันทึก IP ของ client ที่แท้จริงในเซสชันที่ใช้งานและการจำกัดอัตราการเข้าสู่ระบบเมื่ออยู่หลัง reverse proxy ให้กำหนด
**direct socket network** ของ proxy (ไม่ใช่ช่วง IP ของ client สาธารณะ):

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --trusted-proxy-cidr 172.32.11.1/32 \
  --trusted-proxy-cidr 10.42.0.0/16 \
  --cookie-secure \
  --no-browser
```

ระบุ `--trusted-proxy-cidr` ซ้ำหนึ่งครั้งสำหรับที่อยู่หรือเครือข่ายของ proxy ที่เชื่อมต่อโดยตรงแต่ละรายการ เฉพาะคำขอที่ direct peer อยู่ใน
CIDR เหล่านี้เท่านั้นที่ระบุ `X-Forwarded-For` ได้ สำหรับ peer อื่น ระบบจะบันทึกเฉพาะที่อยู่ที่เชื่อมต่อโดยตรง ระบบปิดการประมวลผล forwarded
address ของ Uvicorn ไว้ ดังนั้น `Forwarded` และ `FORWARDED_ALLOW_IPS` ขยายขอบเขตความเชื่อถือนี้ไม่ได้
ใช้ `--cookie-secure` เฉพาะเมื่อเบราว์เซอร์เข้าถึงบริการผ่าน HTTPS

### Docker

อิมเมจทำงานในโหมด Server แบบถาวรด้วยค่าเริ่มต้นเหล่านี้:

- `/app/Library` เป็นต้นฉบับ
- `/app/EpubBrowserFiles` เป็นสถานะถาวร
- `--watch`
- `--no-browser`
- `--host 0.0.0.0 --port 80`
- `--book-id-storage embedded`
- `--kindle`

เนื่องจากการฝัง ID อาจอัปเดตไฟล์ EPUB หรือ PDF ให้ mount ไลบรารีแบบอ่านเขียน และ mount สถานะ Server
แบบอ่านเขียนพร้อมเก็บข้อมูลนั้นไว้เมื่อเปลี่ยนคอนเทนเนอร์:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  dfface/epub-browser:latest
```

เปิด `http://127.0.0.1:8080/setup` ก่อนเปลี่ยน port binding หรือกฎ proxy

#### Docker Compose

รีพอซิทอรีมี [docker-compose.yml](../../docker-compose.yml) สำหรับผู้ที่ต้องการใช้ Compose จาก source checkout
ให้สร้าง `Library/` ใส่หนังสือ EPUB หรือ PDF แล้วเรียก:

```bash
docker compose up -d --build
```

การตั้งค่านี้ publish เฉพาะพอร์ต `127.0.0.1:8080` เก็บไฟล์หนังสือ EPUB/PDF ต้นฉบับใน `./Library` และเก็บสถานะ Server ถาวรใน
`./EpubBrowserFiles` `command` ทั้งหมดของ Server แสดงในไฟล์โดยเจตนา เพื่อเพิ่ม flag ตามการปรับใช้ได้โดยไม่
แทนที่ค่าเริ่มต้นที่ซ่อนอยู่ในอิมเมจ ตั้งค่าครั้งเดียวให้เสร็จที่ `http://127.0.0.1:8080/setup` สำหรับการเข้าถึง
ระยะไกล ให้คง loopback binding นี้และติดตั้ง reverse proxy ที่รองรับ TLS และการยืนยันตัวตนไว้ด้านหน้า

สำหรับการตั้งค่าแบบอัตโนมัติ:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  -e EPUB_BROWSER_ADMIN_USERNAME=admin \
  -e EPUB_BROWSER_ADMIN_PASSWORD_FILE=/run/secrets/epub-browser-admin-password \
  --mount type=bind,src=/path/to/admin-password,dst=/run/secrets/epub-browser-admin-password,readonly \
  dfface/epub-browser:latest
```

หลังเริ่มสำเร็จครั้งแรก สามารถถอด secret mount ครั้งเดียวออกได้ ไลบรารีแบบอ่านอย่างเดียวใช้ได้เมื่อ EPUB ทุกเล่ม
มี embedded ID ที่ถูกต้องและตรงกันเท่านั้น เมื่อนำ ID จาก sidecar ไปฝังแล้ว ระบบจะเก็บ sidecar เดิมไว้

mount `/app/SyncData:ro` เฉพาะขณะนำเข้า bookshelf JSON รุ่นเก่า:

```bash
-v /path/to/legacy-sync:/app/SyncData:ro
```

การ publish พอร์ตแบบ loopback ในตัวอย่างช่วยจำกัดการเข้าถึงคอนเทนเนอร์ให้อยู่ภายในโฮสต์ สำหรับการเข้าถึงระยะไกล ให้ใช้ reverse proxy
TLS กำหนด CIDR ของเครือข่ายคอนเทนเนอร์ที่ proxy ใช้จริง และเพิ่ม `--cookie-secure`

## ข้อมูลอ้างอิงและการดำเนินงาน

### ข้อมูลอ้างอิงคำสั่ง

#### `epub-browser ssg SOURCE [SOURCE ...]`

| ตัวเลือก | ความหมาย |
| --- | --- |
| `--output-dir DIR`, `-o DIR` | ปลายทางที่จำเป็นสำหรับ snapshot สแตติกแบบ atomic |
| `--base-path PATH` | Public URL prefix; ค่าเริ่มต้น `/` ต้องขึ้นต้นและลงท้ายด้วย `/` |
| `--book-id-storage sidecar\|embedded` | ตัวเก็บ ID แบบคงที่สำหรับทุกแหล่งที่เลือก; ค่าเริ่มต้น `sidecar` |
| `--kindle` | สร้างเพจมินิมัลที่ไม่มี dependency สำหรับ Kindle e-Ink รุ่นเก่าและเปลี่ยนเส้นทางเบราว์เซอร์ Kindle WebKit ไปยังเพจเหล่านั้น; ปิดตามค่าเริ่มต้น |
| `--log` | Alias เพื่อความเข้ากันได้ของ `--log-level info` |
| `--log-level debug\|info\|warning\|error` | ระดับรายละเอียด log การดำเนินงาน; ค่าเริ่มต้น `error` ซึ่งทำให้เอาต์พุตการแปลงและคำเตือนตามปกติเงียบ |

#### `epub-browser server SOURCE [SOURCE ...]`

ต้องระบุเพียงหนึ่งใน `--server-dir` หรือ `--ephemeral`

| ตัวเลือก | ความหมาย |
| --- | --- |
| `--server-dir DIR` | รูทสำหรับข้อมูลหลักแบบถาวรและแคชที่แทนที่ได้ |
| `--ephemeral` | ใช้สถานะแบบใช้ครั้งเดียว ใช้ร่วมกับ `--server-dir` ไม่ได้ |
| `--watch`, `-w` | เฝ้าดูต้นฉบับและปรับข้อมูลให้ตรงกับการเพิ่ม การอัปเดต การย้าย และการลบ |
| `--host ADDRESS` | ที่อยู่ bind; ค่าเริ่มต้น `127.0.0.1` |
| `--port PORT`, `-p PORT` | พอร์ต bind; ค่าเริ่มต้น `8000` |
| `--no-browser` | ไม่เปิดเบราว์เซอร์เริ่มต้นในเครื่อง Web UI ยังใช้ได้ |
| `--log` | Alias เพื่อความเข้ากันได้ของ `--log-level info` |
| `--log-level debug\|info\|warning\|error` | ระดับรายละเอียด log การดำเนินงาน; ค่าเริ่มต้น `error` HTTP access log เปิดที่ `info` และ `debug` |
| `--legacy-sync-dir DIR` | อ่าน bookshelf JSON รุ่นเก่าระหว่าง migration ตอนเริ่มระบบ |
| `--book-id-storage sidecar\|embedded` | ตัวเก็บ ID แบบคงที่สำหรับทุกแหล่งที่เลือก; ค่าเริ่มต้น `sidecar` |
| `--admin-username NAME` | Administrator เริ่มต้นสำหรับการตั้งค่าอัตโนมัติ; fallback คือ `EPUB_BROWSER_ADMIN_USERNAME` |
| `--admin-password-file FILE` | ไฟล์ secret เริ่มต้นที่แนะนำ; fallback คือ `EPUB_BROWSER_ADMIN_PASSWORD_FILE` แล้ว `EPUB_BROWSER_ADMIN_PASSWORD` เมื่อไม่ได้ตั้งไฟล์ |
| `--trusted-proxy-cidr CIDR` | ขอบเขตความเชื่อถือสำหรับเครือข่าย proxy ที่เชื่อมต่อโดยตรง ระบุซ้ำได้ เพื่อแยก client IP จาก `X-Forwarded-For` อย่างปลอดภัย |
| `--cookie-secure` | ส่งคุกกี้เซสชันผ่าน HTTPS ฝั่งเบราว์เซอร์เท่านั้น |
| `--kindle` | ให้บริการเพจมินิมัลที่ไม่มี dependency สำหรับ Kindle e-Ink รุ่นเก่าและเปลี่ยนเส้นทางเบราว์เซอร์ Kindle WebKit ไปยังเพจเหล่านั้น; ปิดตามค่าเริ่มต้น |

#### ไวยากรณ์ v1 รุ่นเก่า

รองรับไวยากรณ์รุ่นเก่าตลอดชุดเวอร์ชันหลัก v2:

| คำสั่ง v1 | การแมปเป็น v2 |
| --- | --- |
| `epub-browser BOOKS` | `epub-browser server BOOKS --ephemeral` |
| `epub-browser BOOKS --output-dir STATE` | `epub-browser server BOOKS --server-dir STATE` |
| `epub-browser BOOKS --no-server --output-dir DIST` | `epub-browser ssg BOOKS --output-dir DIST` |
| `--sync-dir DIR` | `server --legacy-sync-dir DIR` |

`--keep-files` ที่มีเฉพาะรุ่นเก่าจะเก็บไดเรกทอรี Server ชั่วคราว ไดเรกทอรี Server แบบถาวรจะคงอยู่แล้ว
เมื่อใช้ `--log` ตัวปรับความเข้ากันได้จะพิมพ์คำสั่ง v2 ที่เท่ากัน มิฉะนั้นจะเงียบ

### ข้อมูลการอ่านและตำแหน่งฟีเจอร์

- การค้นพบ EPUB/PDF และไลบรารี Calibre แบบ recursive, แท็กเมทาดาทา การค้นหา และการค้นหาพินอิน
- อินเทอร์เฟซ Library รายละเอียดหนังสือ และการอ่านบทแบบ responsive
- การเลื่อน พลิกหน้า อ่านแบบต่อเนื่อง ปรับความกว้างเนื้อหา ฟอนต์ CSS ที่กำหนดเอง ธีม และโหมดอ่านอย่างเดียว
- ไฮไลต์ บันทึก การเรียกดูคำอธิบายประกอบ กลุ่มชั้นหนังสือแบบซ้อนกัน แท็ก และ Import/Export JSON
- อินเทอร์เฟซรองรับภาษาอังกฤษ จีนตัวย่อ จีนตัวเต็ม เกาหลี ญี่ปุ่น สเปน เยอรมัน ฝรั่งเศส รัสเซีย อิตาลี
  โปรตุเกสบราซิล อาหรับ อินโดนีเซีย ฮินดี เวียดนาม ไทย และมลายู
- การทำงานที่เหมาะกับ e-reader สำหรับเบราว์เซอร์ Kindle/Silk ฟีเจอร์ที่ใช้เบราว์เซอร์มากอาจถูกลดลง

| ข้อมูล | SSG | Server |
| --- | --- | --- |
| ความคืบหน้าการอ่าน | ในเครื่องของเบราว์เซอร์ | เรคอร์ดใน SQLite ของผู้ใช้ที่ยืนยันตัวตนแล้ว |
| ไฮไลต์และบันทึก | ในเครื่องของเบราว์เซอร์ | เรคอร์ดใน SQLite ของผู้ใช้ที่ยืนยันตัวตนแล้ว |
| คะแนน รีวิวส่วนตัว และประวัติเซสชันการอ่าน | ไม่มี | เรคอร์ดใน SQLite ของผู้ใช้ที่ยืนยันตัวตนแล้ว |
| ชั้นหนังสือ | ในเครื่องของเบราว์เซอร์; Import/Export | เอกสารคลาวด์แบบมีเวอร์ชันของผู้ใช้ที่ยืนยันตัวตนแล้ว; บันทึกอัตโนมัติ |
| บัญชีและเซสชัน | ไม่มี | SQLite ใต้ `<server-dir>/data` |
| สิทธิ์หนังสือ | ไม่มี | SQLite ใต้ `<server-dir>/data` |

Server ไม่มีตัวเลือกการจัดเก็บ local/cloud ข้อมูลการอ่านของผู้ใช้ที่ยืนยันตัวตนแล้วจะเก็บบน Server เสมอ SSG ไม่สร้าง
ประวัติเซสชันการอ่านส่วนตัวแบบละเอียด SSG ไม่ตรวจสอบ Server API และใช้ local storage ของ browser origin ปัจจุบันเสมอ

### การให้บริการครบในตัวและพฤติกรรมเครือข่าย

แอปพลิเคชันพร้อมใช้งานสำหรับการอ่านได้ด้วยตัวเอง JavaScript, CSS, ฟอนต์ ไอคอน manifest และทรัพยากร EPUB ที่แปลงแล้ว
ซึ่งจำเป็นทั้งหมดจะให้บริการจากเครื่อง ไม่ต้องพึ่ง CDN ขณะรันไทม์ แม้บล็อกการเชื่อมต่ออินเทอร์เน็ตขาออก ก็ยังตั้งค่า
เข้าสู่ระบบ เรียกดู อ่าน ใช้คำอธิบายประกอบ บันทึกความคืบหน้า ใช้ชั้นหนังสือ ดูแลระบบ หรือแปลงต้นฉบับได้

footer อาจส่งคำขอที่เลือกใช้ไปยัง GitHub Releases API เพื่อค้นหารุ่น EPUB Browser ที่ใหม่กว่า หากล้มเหลว
ถูกบล็อก หรือใช้ออฟไลน์ จะซ่อนเฉพาะข้อความแจ้งอัปเดต

SSG เผยแพร่ Service Worker แบบสแตติก ส่วน Server จะปิดและยกเลิก Service Worker ระดับ origin โดยเจตนา
เพื่อไม่ให้บัญชีหนึ่งได้รับเนื้อหาที่มีการป้องกันซึ่งแคชไว้ของอีกบัญชี

### Server API และ WebHooks

บัญชีบน Server สามารถสร้าง personal access token ที่จำกัด scope ได้ใน Account settings ไคลเอนต์ภายนอกใช้
`Authorization: Bearer <PAT>` กับ `/api/v1/*` API ที่มีเวอร์ชัน คุกกี้เบราว์เซอร์ไม่ยืนยันตัวตน route เหล่านี้
API ครอบคลุมหนังสือและเนื้อหาบทที่ผู้ใช้มองเห็นได้ ชั้นหนังสือของเจ้าของ token ความคืบหน้า คำอธิบายประกอบและรีวิว
รวมถึงข้อมูลแบบอ่านอย่างเดียวของผู้ใช้คนอื่นสำหรับ administrator PAT ที่มี scope `admin:data:read`

เอกสาร OpenAPI 3.1 อยู่ที่ `/openapi.json` ผู้ใช้ที่เข้าสู่ระบบสามารถดูเอกสารอ้างอิงในเครื่องได้ที่ `/api-docs`
ตัวอย่าง: `curl -H 'Authorization: Bearer …' https://reader.example/api/v1/books` รายละเอียดบทจะคืน
HTML ที่ทำความสะอาดแล้วตามค่าเริ่มต้น และคืน plain text เมื่อใช้ `?format=text`

List endpoint จะคืนค่า `items` และ `next_cursor` ค่า `limit` เริ่มต้นคือ 24 และสูงสุด 100 ส่ง `next_cursor`
เป็น `cursor` พร้อมตัวกรองเดิมเพื่อดึงหน้าถัดไป cursor ที่มีค่า null หมายถึงหน้าสุดท้าย ตัวอย่างเช่น ใช้
`/api/v1/me/annotations?book_id=BOOK_ID&chapter_index=0&fields=id,text,note` เพื่อดึงฟิลด์คำอธิบายประกอบ
ที่เลือกจากบท EPUB หรือหน้า PDF หนึ่งหน้า ตัวกรอง query และฟิลด์ที่รองรับระบุในเอกสาร OpenAPI

Vocabulary ใช้รูปแบบรายการเดียวกันเป็นค่าเริ่มต้น ไคลเอนต์ที่ยังใช้การตอบกลับแบบ `words` รุ่นเก่า สามารถส่ง `page=1`
หรือ `page_size` เพื่อเลือกรูปแบบการแบ่งหน้ารุ่นเก่าได้

ผู้ดูแลจัดการ WebHook endpoint ใน Administration Secret จะแสดงเฉพาะตอนสร้างหรือหมุนเวียนเท่านั้น การส่ง WebHook มีลายเซ็น
มีการบันทึกไว้อย่างคงทน และจะลองใหม่เมื่อได้รับการตอบกลับ non-2xx เหตุการณ์ book-review มี ID และ timestamp ของการกระทำ
แต่ไม่มีคะแนนหรือข้อความรีวิว

### ความปลอดภัยของข้อมูลและการย้ายข้อมูล

ก่อนอัปเกรด Server ที่ติดตั้งแบบถาวร ให้สำรองหนังสือ EPUB/PDF ต้นฉบับและ `<server-dir>/data`
เก็บโวลุมสถานะถาวรเดิมไว้เมื่อเปลี่ยนคอนเทนเนอร์

การ migrate ตอนเริ่มระบบทำงานอัตโนมัติและปลอดภัยแม้ต้องรีสตาร์ต ระบบตรวจสอบฐานข้อมูลเก่า สร้างข้อมูลสำรอง
อัปเกรดบนสำเนา นำเข้าข้อมูลชั้นหนังสือ/ความคืบหน้า/คำอธิบายประกอบรุ่นเก่าที่เข้าเงื่อนไขไปยังบัญชี administrator
เริ่มต้นที่รอสร้างอยู่ และจะเลิกใช้ artifact สาธารณะรุ่นเก่าที่แทนที่ได้เท่านั้นหลังจาก checkpoint สำเร็จ
คำขอทั่วไปจะไม่สแกนไดเรกทอรี legacy sync หากพบฐานข้อมูลเสีย password hash ไม่ถูกต้อง ฐานข้อมูลรุ่นเก่าที่ตีความได้กำกวม
หรือ ID ที่ขัดแย้งกัน ระบบจะ fail closed แทนที่จะเดาหรือเขียนทับ

`epub-browser.db` หรือ `annotations.db` ที่ย้ายแล้วในรูทจะถูกเก็บเป็นสำเนาสำหรับกู้คืนที่มีข้อมูลละเอียดอ่อนและไม่ใช่ฐานข้อมูลหลัก
`data/epub-browser.db` เป็นฐานข้อมูลหลัก และ Server จะไม่ใช้ไฟล์รูทที่เก็บไว้เมื่อประมวลผลคำขอ เก็บสำเนากู้คืนให้เป็นส่วนตัว
ลบด้วยตนเองได้เฉพาะขณะที่ Server หยุดทำงาน หลังตรวจสอบฐานข้อมูลหลักและข้อมูลสำรองที่บันทึกไว้ และเมื่อไม่จำเป็นต้อง rollback
ไป v1 แล้วเท่านั้น EPUB Browser ไม่ลบไฟล์นี้โดยอัตโนมัติ

หากมีไฟล์ `epub-browser.db` และ `annotations.db` ทั้งสองไฟล์อยู่ใน legacy root การเริ่มระบบจะหยุดและจะไม่แตะต้องไฟล์เหล่านั้น
ดู [การย้ายไป v2](../migration-v2.md) สำหรับการสำรอง rollback การสร้างแคชใหม่ และการกู้คืนจากความขัดแย้ง

### การแก้ไขปัญหา

#### คำสั่งเริ่มทำงานแล้วแต่เบราว์เซอร์ไม่เปิด

นำ `--no-browser` ออกเมื่อรันบนเครื่องของคุณที่มีสภาพแวดล้อมกราฟิก หรือเปิด URL ที่พิมพ์ออกมาหรือที่ผูกไว้ด้วยตนเอง
ใน Docker, systemd, SSH และเซสชันแบบไม่โต้ตอบ การเปิด URL ด้วยตนเองถือเป็นพฤติกรรมปกติ

#### CLI ไม่แสดงข้อความ

การทำงานเงียบเป็นเรื่องตั้งใจเมื่อไม่มี `--log` โดยเฉพาะในสภาพแวดล้อมแบบไม่โต้ตอบ เพิ่ม `--log` เพื่อดูรายละเอียด
การดำเนินงานและการเข้าถึง ความคืบหน้าการสแกนของ Server แสดงในเว็บอินเทอร์เฟซ

#### Docker เขียนรหัสประจำตัวที่คงที่ไม่ได้

อิมเมจใช้ embedded identity ตามค่าเริ่มต้น เมานต์ `/app/Library` แบบอ่านเขียนหรือฝัง ID ที่ถูกต้องและตรงกันล่วงหน้า
ใช้ custom command กับ `--book-id-storage sidecar` เฉพาะเมื่อต้องการใช้ sidecar ที่เขียนได้เป็นตัวเก็บ ID แทน

#### เว็บไซต์ SSG ที่สร้างมีลิงก์เสียใต้ subpath

สร้างใหม่ด้วย `--base-path` ที่ normalize แล้ว เช่น `/reader/` และตั้งค่า static host ให้ให้บริการเอาต์พุตที่ prefix เดียวกัน

#### Server ปฏิเสธการเริ่มหลังอัปเกรด

อ่านข้อผิดพลาด migration หรือ validation แรกที่บันทึก log เก็บข้อมูลและไฟล์ต้นฉบับไว้ แล้วดู
[docs/migration-v2.md](https://raw.githubusercontent.com/dfface/epub-browser/main/docs/migration-v2.md)
อย่าลบไดเรกทอรี `data/` ซึ่งเป็นแหล่งข้อมูลหลักเพื่อหลบเลี่ยงข้อผิดพลาด

## การพัฒนาและสัญญาอนุญาต

### การมีส่วนร่วม

ยินดีรับ Issues และ pull requests ที่ [dfface/epub-browser](https://github.com/dfface/epub-browser)
รายงานที่มีประโยชน์ควรมีคำสั่งที่แน่นอน เบราว์เซอร์/อุปกรณ์ ขั้นตอนทำซ้ำ log ที่เกี่ยวข้อง และไฟล์ EPUB หรือ PDF
หากแชร์ได้อย่างถูกกฎหมาย

#### ข้อกำหนดด้านสถาปัตยกรรมสำหรับผู้ดูแล

อ่าน [AGENTS.md](../../AGENTS.md) ก่อนเปลี่ยนการประมวลผลเนื้อหา page template, แคช สิทธิ์ ทรัพยากร
หรือพฤติกรรมการปรับใช้ เอกสารนี้กำหนดขอบเขตรูปแบบ EPUB/PDF ขอบเขตความรับผิดชอบของ SSG/Server
cache revision ที่เป็นอิสระ ข้อกำหนด i18n ขณะรันไทม์ การตรวจสอบความปลอดภัย และการทดสอบที่จำเป็น
ศัพท์เฉพาะของผลิตภัณฑ์ที่ใช้ร่วมกัน เช่น *reader chapter*, *reading window*, *reading stage* และ *content cache*
มีนิยามอยู่ใน [CONTEXT.md](../../CONTEXT.md)

สรุปสั้น ๆ คือ ใช้ UI ตัวอ่านชุดเดียว อย่านำข้อมูลเฉพาะ Server ไปไว้ใน SSG แยกแคชเนื้อหาที่สร้างจาก EPUB และ PDF
ออกจากข้อมูลผู้ใช้ใน SQLite และอย่าเพิ่ม CDN dependency ขณะรันไทม์ การเปลี่ยนแปลงที่กระทบส่วนที่ใช้ร่วมกัน
ต้องทดสอบกับทั้งสองรูปแบบและทั้งสองโหมดการปรับใช้เมื่อเกี่ยวข้อง

#### การพัฒนาจาก source checkout

ไฟล์สำหรับเบราว์เซอร์จากบุคคลที่สามเป็น build input ที่สร้างขึ้น ไม่ใช่ project source `epub_browser/assets/vendor/`
จึงไม่มีใน Git โดยเจตนา ให้ดึงไฟล์ตามเวอร์ชันที่ล็อกไว้อย่างชัดเจนก่อนพัฒนาหรือ build แล้วตรวจสอบไฟล์เหล่านั้นแบบออฟไลน์:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
python3 -m unittest tests.test_vendor_assets -v
python3 -m build
```

`fetch` เป็นคำสั่งเดียวในชุดข้างต้นที่ดาวน์โหลด asset ของ vendor สำหรับเบราว์เซอร์ ส่วน lockfile บันทึก
npm tarball แบบ immutable, file digest, allowlist และสัญญาอนุญาต `verify`, การทดสอบ การ build จาก checkout
ที่เตรียม asset ครบแล้ว และตัวอ่านที่ติดตั้ง จะไม่ดาวน์โหลด browser asset คำสั่ง `python3 -m build` แบบ isolated
มาตรฐานยังอาจติดต่อ Python package index สำหรับ build requirement หากต้องการ build โดยปิดเครือข่ายทั้งหมด
ให้เตรียม vendor tree และติดตั้ง `build`, `setuptools` และ `wheel` ล่วงหน้าก่อนตัดการเชื่อมต่อ แล้วเรียก
`PIP_NO_INDEX=1 python3 -m build --no-isolation` Wheel, source distribution, Docker image และเว็บไซต์ SSG
ที่สร้างขึ้นล้วนมีไฟล์ที่ตรวจสอบแล้วและไม่มี CDN dependency ขณะรันไทม์ ดู [third_party/README.md](../../third_party/README.md)
สำหรับขั้นตอนอัปเดต เผยแพร่รุ่น และดูแลรีพอซิทอรีให้เป็นระเบียบ
