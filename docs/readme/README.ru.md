EPUB Browser обрабатывает `.epub` и `.pdf` в двух режимах с чётко разделёнными обязанностями:

| | `ssg` | `server` |
| --- | --- | --- |
| EPUB и PDF | Да | Да |
| Развёртывание | Статический хостинг, Pages, объектное хранилище, Nginx | Постоянный приватный сервис чтения |
| Учётные записи | Нет | Локальные учётные записи |
| Прогресс, заметки, книжная полка | Только в этом браузере | Данные авторизованной учётной записи в SQLite |
| Обновление источников | Повторно запустить `ssg` | Перезапустить сервис или использовать `--watch` |
| База данных во время работы | Нет | Обязательна |

PDF — полноценный формат книги: страница 1 становится `chapter_0.html`, каждая страница присутствует в оглавлении, а локальный PDF.js отображает её в той же библиотеке, карточке книги, оболочке чтения, поиске и потоке аннотаций. Неподдерживаемые для PDF возможности, например чтение с ИИ, явно скрыты; во время чтения CDN не требуется.

Используйте `ssg`, когда нужны обычные статические файлы. Выбирайте `server`, если требуются учётные записи, синхронизация между устройствами, контроль доступа к книгам или автоматическое отслеживание источников.

## Чтение с ИИ (только Server)

ИИ создаёт поверх исходного текста общую проверяемую учебную прослойку, а не отдельное общее резюме. Она включает маршрут перед чтением, обзор главы по запросу, объяснения, привязанные к цитатам, подсказки о роли абзацев, пояснения слов, простое итоговое объяснение и вопросы для дальнейшего размышления.

Результаты формируются фоновыми заданиями, хранятся в SQLite и доступны читателям, у которых есть доступ к книге. Последующие диалоги остаются приватными для каждой учётной записи. Администратор должен настроить OpenAI-совместимого поставщика и отдельно разрешить доступ участникам. Выбранный текст EPUB передаётся этому поставщику, поэтому включайте функцию только с согласия читателей. В SSG-вывод никогда не попадают учётные записи, элементы управления ИИ, задания или настройки поставщика.

## Требования и установка

- Python 3.9 или новее
- Один или несколько файлов `.epub` или `.pdf`, вложенные каталоги с книгами или библиотека в стиле Calibre

Установка из PyPI поддерживает режимы SSG и Server:

```bash
pip install epub-browser

# Полная справка по каждому режиму
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

Для постоянного Server в Docker используйте опубликованный образ; Python на хосте не требуется:

```bash
docker pull dfface/epub-browser:latest
```

## Быстрый старт

### Создание статического сайта

```bash
epub-browser ssg /путь/к/книгам \
  --output-dir /путь/к/dist
```

Раздавайте `dist/` по HTTP; не открывайте созданные страницы напрямую через `file://`. Для публикации в подпути добавьте `--base-path /мой-репозиторий/`; этот параметр меняет создаваемые URL, а не каталог вывода.

### Запуск постоянной Server-библиотеки

```bash
epub-browser server /путь/к/книгам \
  --server-dir /путь/к/состоянию-epub-browser \
  --watch
```

Откройте `http://127.0.0.1:8000/`. При первом посещении создаётся начальный администратор; до завершения настройки библиотека не сканируется и не публикуется. `--no-browser` лишь отключает автоматическое открытие локального браузера.

## Данные, учётные записи и границы доступа

У каждой книги есть стабильный `book_id`. По умолчанию `--book-id-storage sidecar` хранит идентификатор рядом с исходным файлом, не изменяя его байты. Для EPUB вариант `--book-id-storage embedded` записывает идентификатор в метаданные OPF; для PDF он всегда использует соседний sidecar.

В режиме Server каталог `--server-dir` является основным местом хранения SQLite, кэшей и резервных копий миграций. Там же находятся учётные записи, книжные полки, прогресс, заметки, результаты ИИ и задания. Администраторы управляют пользователями, ролями, сеансами и правами на книги; участники используют только разрешённые книги и собственные приватные данные. Защитите права доступа к этому каталогу и его резервным копиям.

## Docker, обратный прокси и полная документация

В контейнере подключайте книги только для чтения, а `--server-dir` — как постоянный том. Принимайте прокси-заголовки только от доверенных прокси и используйте HTTPS для публичных развёртываний.

Docker Compose, все параметры CLI, миграции, работу в LAN, обратный прокси и устранение неполадок см. в [полном README на английском](../../README.md) или [полном README на упрощённом китайском](README.zh-CN.md). Поведение обоих режимов одинаково на всех языках.
