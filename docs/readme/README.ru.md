EPUB Browser — не просто конвертер книг, а полноценная платформа для чтения, которую
можно опубликовать где угодно или разместить на своём сервере. EPUB и PDF используют
одни и те же библиотеку, страницу книги, оглавление, режимы чтения, темы, отслеживание
прогресса и работу с аннотациями. Каждая страница PDF становится главой в интерфейсе
чтения и локально отображается PDF.js внутри общего окна чтения — без отдельного
просмотрщика и обращений к CDN во время работы.

## Обзор проекта

### Почему EPUB Browser

- **Публикуйте где угодно и сохраняйте контроль.** Одной командой создайте полный
  статический сайт для Pages, объектного хранилища или Nginx либо запустите постоянный
  Server с учётными записями, правами доступа к книгам и OIDC. Ресурсы приложения,
  шрифты, PDF.js и средства отображения обслуживаются локально, поэтому чтение не
  зависит от CDN.
- **EPUB и PDF в одном полноценном интерфейсе чтения.** Оба формата используют общие
  библиотеку, страницу книги, оглавление, адаптивную вёрстку, три режима чтения, темы,
  полноэкранный режим и прогресс. Каждая страница PDF остаётся в области чтения: доступны
  масштабирование, выделение текстового слоя и аннотации, а не отдельный просмотрщик.
- **Находите и книгу, и нужный фрагмент.** Поиск по библиотеке охватывает метаданные,
  теги и пиньинь, поддерживает сортировку и разбивку на страницы. Поиск по всей книге
  EPUB на стороне Server возвращает полные результаты, сгруппированные по главам, и
  переходит к подсвеченному фрагменту. Стабильные идентификаторы книг сохраняют
  привязку места продолжения чтения, аннотаций и истории к той же книге.
- **Понимайте текст, а не просто прокручивайте его.** В режиме Server путеводители
  по главам EPUB, объяснения со ссылками на доказательства, интеллект-карты и приватный
  Ask AI находятся рядом с исходным текстом. Выделения, заметки, словарь и энциклопедия
  работают с EPUB и PDF с текстовым слоем; списки словарного запаса на Server сохраняют
  источник каждого слова и степень его усвоения.
- **Превращайте чтение в историю, которую стоит сохранить.** Вложенные полки,
  оценки, рецензии, экспорт аннотаций, календари активности, тенденции, статистика по
  каждой книге и рейтинги по времени чтения образуют единую связанную историю. Server
  хранит данные чтения приватно для каждой учётной записи и синхронизирует их между
  устройствами.
- **Запустите сервис для чтения, а не только просмотрщик.** В режиме Server книги можно
  добавлять через веб-интерфейс администратора или отслеживаемые каталоги, ограничивать
  использование диска с настраиваемым вытеснением кэша по LRU, управлять правами
  участников и доступа к ИИ, а также выполнять интеграцию через OpenAPI, PAT и WebHooks.
  Минималистичный интерфейс Kindle подходит для устройств с ограниченными возможностями;
  Server также предоставляет персональную панель-заставку Kindle с часами, календарём,
  расписанием, заметками и таймером Pomodoro.

### Технологический стек

EPUB Browser намеренно использует компактный веб-стек с отрисовкой на сервере. В
установленном приложении нет SPA-фреймворка, а для его работы не требуется Node.js:

| Слой | Технология | Назначение |
| --- | --- | --- |
| Frontend | Семантический HTML, CSS, VanillaJS с ES-модулями и браузерными API | Единый адаптивный интерфейс для SSG и Server |
| CLI и Server | Python 3.9+, Starlette, Uvicorn | Команды преобразования, страницы с аутентификацией, API и фоновые задачи |
| Данные | SQLite и восстанавливаемые JSON-кэши содержимого | Состояние пользователей отделено от производного содержимого EPUB/PDF |
| Форматы книг | lxml, pypdf, pypdfium2, PDF.js | Разбор и очистка EPUB по единой схеме с приоритетом строгого режима; метаданные и обложки PDF; локальная отрисовка в браузере |
| Автономная работа и ресурсы | Service Worker, неизменяемые ресурсы с хешами, зафиксированные вендорные зависимости | Самодостаточная доставка без CDN во время работы |
| Распространение | PyPI, Docker, обычный статический хостинг | Одна кодовая база работает как SSG или постоянный Server |
| Необязательный ИИ | OpenAI-совместимые API с локальной отрисовкой Markdown, KaTeX и Mermaid | Учебные слои для EPUB только в режиме Server |

Node.js нужен только разработчикам для браузерных тестов; он не входит в рабочее
окружение читателя.

### Выбор между SSG и Server

Два явно разделённых режима развёртывания используют одну обработку источников и одни
шаблоны страниц. Выбирайте по месту хранения данных чтения, а не по формату книги:

| Возможность | `ssg` | `server` |
| --- | --- | --- |
| EPUB и PDF | Да | Да |
| Доставка | Атомарно публикуемые статические HTML и ресурсы для Pages, объектного хранилища или Nginx | Динамические страницы с аутентификацией на основе заменяемого кэша содержимого |
| Учётные записи и контроль доступа | Нет | Учётные записи администраторов и участников, права на ограниченные книги, сеансы и защита от CSRF |
| Единый вход OIDC | Не входит | Универсальный Provider, привязка существующих учётных записей и необязательное создание участников |
| Прогресс, аннотации, полка | Хранятся в текущем браузере | Синхронизируются для каждой аутентифицированной учётной записи в SQLite |
| Оценки, рецензии, сеансы чтения | Не создаются | Приватные записи каждой учётной записи и статистика чтения |
| Обновления источников | Повторно запустите `ssg` | Перезапустите сервис, выполните повторное сканирование или используйте `--watch` |
| Администрирование, теги, OpenAPI, WebHooks | Не входят | Входят |
| ИИ-чтение и Ask AI | Не входят | Доступны для EPUB после настройки и явного разрешения; скрыты для PDF |
| База данных во время работы | Нет | Обязательна для постоянного режима |
| Лучше всего подходит для | Публичного или статического хостинга, автономных комплектов, простой личной публикации | Приватной библиотеки, нескольких устройств или читателей, автоматизации и управляемого доступа |

Используйте `ssg`, когда результатом должны быть обычные статические файлы. Используйте `server`, если читателям нужны учётные записи, доступ к данным с разных устройств, контроль доступа или автоматическое согласование источников.

### ИИ-чтение (только Server)

Для книг EPUB режим Server может добавлять путеводители по главам, объяснения со
ссылками на доказательства, интеллект-карты, вопросы для размышления и приватную панель
Ask AI, не уводя читателя от исходного текста. Доступ к результатам определяется правами
на книгу; участникам доступ нужно выдавать явно. В SSG нет элементов управления ИИ,
заданий, данных учётных записей и настроек поставщика. Для PDF ИИ-чтение и Ask AI
намеренно скрыты.

Полную модель взаимодействия см. в [руководстве по ИИ-чтению](../ai-native-reading.md);
границы отрисовки и сетевой безопасности описаны в [примечаниях о локальных средствах
отрисовки форматированного текста](../third-party-ai-renderers.md).

### Минималистичный режим Kindle

На старых Kindle с e-Ink и в любых браузерах с ограниченными возможностями доступен
минималистичный интерфейс чтения без зависимостей. Включите его с помощью `--kindle`:

- SSG: `epub-browser ssg --kindle -o output/ SOURCE...`
- Server: `epub-browser server --kindle --server-dir data SOURCE...`

Для каждой книги EPUB (книги PDF исключены) создаются три дополнительные страницы:

- минимальная полка `/kindle-library.html`
- страница книги `/book/<id>/kindle.html`
- страница главы `/book/<id>/kindle_chapter_N.html`

Эти страницы рассчитаны на e-Ink: минимальная разметка, оформление только средствами CSS,
сценарии, совместимые с ES5, без Service Worker и фреймворков. Читать можно вообще без
JavaScript; переключение темы (Light / Sepia / Dark), размера шрифта (A- / A+) и
локализация интерфейса реализованы небольшими встроенными сценариями поверх обычного HTML.

На каждой странице есть элементы управления темой и шрифтом (в верхнем колонтитуле и
повторно в нижнем колонтитуле главы), навигация по оглавлению, переходы к предыдущей и
следующей главе, а также ссылка «Продолжить чтение», возвращающая к сохранённому прогрессу.

Хранение прогресса зависит от режима:

- **SSG:** прогресс хранится в cookie текущего браузера — локально и без учётной записи.
- **Server:** прогресс и сигналы активности чтения синхронизируются в SQLite для каждой
  вошедшей учётной записи. Интерфейсы Kindle только читают и передают данные: сохраняют
  текущую главу и отправляют сигналы активности, показывают полку только для чтения и
  никогда не открывают статистику или управление содержимым.

Контроль доступа действует на всех страницах Kindle. Для книги с ограниченной видимостью
неавторизованный пользователь получает 403: на минимальной полке такая книга не показывается,
а страницы книги и главы и API прогресса возвращают отказ.

Поддерживаемые браузеры (с UA, содержащим `Kindle/`, `Arora/` и т. п.) автоматически
перенаправляются из полного интерфейса чтения на минимальные страницы; указанные выше URL
также работают напрямую. Так минималистичный режим становится корректным запасным вариантом
для маломощных устройств и устройств с ограниченной поддержкой JavaScript.

## Начало работы

### Выбор способа установки

EPUB Browser поддерживает два способа установки. Оба принимают один или несколько файлов
`.epub` или `.pdf`, вложенные каталоги либо каталог библиотеки в стиле Calibre.

| Установка | Для чего подходит | Требование к хосту |
| --- | --- | --- |
| PyPI | Режим SSG или Server | Python 3.9 или новее |
| Docker | Постоянный режим Server | Docker Engine; Python включён в образ |

#### PyPI (SSG или Server)

Установите приложение командной строки:

```bash
pip install epub-browser
```

Покажите справку по командам конкретного режима:

```bash
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

#### Docker (Server)

Опубликованный образ [`dfface/epub-browser`](https://hub.docker.com/r/dfface/epub-browser)
запускает режим Server и не требует Python на хосте:

```bash
docker pull dfface/epub-browser:latest
```

Используйте `latest` для оценки текущего выпуска; для воспроизводимого рабочего
развёртывания зафиксируйте тег с номером выпуска. Обязательные монтирования книг и
состояния, быстрый старт Compose, настройка при первом запуске и рекомендации по сети
описаны в разделе [Docker](#docker).

### Быстрый старт

#### Создание статического сайта

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist
```

Раздавайте `dist/` по HTTP. Открытие созданных страниц напрямую через `file://` не поддерживается, поскольку браузерному хранилищу, модулям, манифестам и Service Worker требуется HTTP-источник.

Если сайт размещён под префиксом URL, задайте публичный путь отдельно от каталога назначения в файловой системе:

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist \
  --base-path /my-repository/
```

`--base-path` меняет создаваемые URL, а не место записи файлов. С префиксом `/my-repository/` его используют ссылки, значки, манифесты, метаданные книг и записи Service Worker, а файлы по-прежнему находятся непосредственно в `dist/`.

#### Запуск постоянной библиотеки в режиме Server

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/epub-browser-state \
  --watch
```

Откройте `http://127.0.0.1:8000/`. При первом обращении EPUB Browser предложит создать начального администратора. Библиотека не сканируется и не становится доступной, пока не завершится эта одноразовая настройка.

Если вы выбрали Docker, пропустите приведённую выше команду Python и перейдите к
[быстрому старту Docker Compose](#docker-compose).

## Форматы и чтение

### Источники и стабильная идентичность книг

Каждый позиционный аргумент `SOURCE` может быть файлом EPUB, файлом PDF или каталогом.
Каталоги просматриваются рекурсивно. В одной команде можно передать несколько источников:

```bash
epub-browser server book.epub /srv/library /srv/periodicals \
  --server-dir /srv/epub-browser \
  --watch
```

Каждая книга получает стабильный `book_id`, который также представлен как `book_hash` в создаваемых URL и браузерных данных. Общее значение CLI по умолчанию:

```bash
--book-id-storage sidecar
```

В режиме sidecar рядом с источником записывается видимый файл идентичности, например `BOOK.epub.epub-browser.json` или `BOOK.pdf.epub-browser.json`, а байты источника не меняются. Sidecar содержит стабильный идентификатор и проверенный отпечаток SHA-256 источника.

Чтобы поместить идентификатор в метаданные OPF книги EPUB или словарь информации о документе PDF, выберите встроенное хранение для всего вызова:

```bash
--book-id-storage embedded
```

Встроенный режим может пересобрать ZIP EPUB или добавить обновление метаданных PDF перед преобразованием. Если PDF невозможно обновить, а его источник не изменился, EPUB Browser сохраняет тот же идентификатор в соседнем sidecar. Это относится и к подписанным, зашифрованным и доступным только для чтения PDF. EPUB Browser останавливается, если идентификаторы не совпадают, активные источники дублируют идентификатор, носитель недействителен или необходимый носитель невозможно записать.

При смене режима хранения EPUB Browser копирует существующий идентификатор в выбранный носитель и сохраняет другой действительный носитель. Существующий встроенный идентификатор из v2.0.4 копируется в sidecar по умолчанию без перезаписи EPUB. После любого обновления метаданных и SSG, и Server доставляют побайтово идентичную копию исходного PDF.

### PDF: одна страница — одна глава

PDF поддерживается в обоих режимах развёртывания. Интерфейс чтения рассматривает каждую
страницу PDF как обычную главу EPUB Browser, поэтому существующие страница книги,
навигация по главам, оглавление, постраничный режим, непрерывное чтение, прогресс,
сеансы чтения, аннотации, словарь и энциклопедия остаются единым общим интерфейсом и
моделью данных:

| Понятие PDF | SSG | Server |
| --- | --- | --- |
| URL страницы 1 | `chapter_0.html` | `/book/<book-id>/chapter_0.html` |
| URL страницы N | `chapter_{N-1}.html` | `/book/<book-id>/chapter_{N-1}.html` |
| Метки страниц и оглавление | Создаются локально; перечислена каждая страница | Отображаются из кэша метаданных PDF; перечислена каждая страница |
| Встроенная структура документа | Маркер в записи оглавления целевой страницы | Тот же маркер без удаления или изменения порядка записей страниц |
| Прокрутка и постраничный режим/листание | Статические оболочки глав и локальный PDF.js | Динамические общие оболочки глав и локальный PDF.js |
| Выделения, заметки, словарь, энциклопедия | Общие компоненты с локальным хранением в браузере при наличии текстового слоя | Общие компоненты с аутентификацией при наличии текстового слоя |
| Исходные байты PDF | Один `document.pdf` в статическом выводе книги | Маршрут с поддержкой Range только для Session к кэшированному документу |

Видимые метки страниц и PDF.js используют нумерацию с единицы; индексы глав в URL,
состоянии, API и SQLite начинаются с нуля. Поэтому страница PDF 1 всегда соответствует
`chapter_0.html`. Нормализованное оглавление содержит одну запись `Page N` для каждой
страницы; заголовки встроенной структуры PDF прикрепляются как маркеры структуры к записи
целевой страницы, в том числе несколько маркеров на одной странице.

SSG записывает один `document.pdf` и одну оболочку `chapter_<index>.html` на страницу.
В выводе SSG нет сценариев Session, вызовов `/api/*`, синхронизируемых данных аннотаций
и зависимостей Server. Server хранит полный побайтово идентичный источник как
`book/<book-id>/pdf/document.pdf` и никогда не разделяет и не перезаписывает его. Server
динамически отрисовывает те же оболочки глав из метаданных PDF; изменённый источник
делает кэш PDF недействительным и полностью обновляет его (документ, метаданные и
производную обложку), не смешивая старые и новые страницы.

Конечная точка Server для исходного документа доступна только через Session:
`GET`/`HEAD /api/books/<book-id>/document`. Она проверяет аутентификацию, видимость
книги, формат PDF и отпечатки источника и кэша, затем поддерживает ответы на запросы
одного ограниченного диапазона с `ETag`, `Accept-Ranges`, приватным кэшированием, `nosniff` и встроенным
отображением PDF. Она не раскрывает абсолютный путь, недоступна при аутентификации PAT и
не входит в интерфейс PAT/OpenAPI. В SSG есть только локальный `document.pdf` и нет API
исходного документа.

PDF с пригодным для работы текстовым слоем в PDF.js используют точно те же всплывающее меню выделения
и компонент аннотаций для выделений и заметок, а также словарь и энциклопедию. Хранение,
владение, экспорт, списки и прямые ссылки аннотаций остаются общими; отдельной таблицы
аннотаций или интерфейса настроек специально для PDF нет. Отсканированные PDF и PDF,
состоящие только из изображений, по-прежнему можно читать, но выделения и заметки на
основе выбора текста, словарь, энциклопедия и поиск по документу явно недоступны, если
нет пригодного текстового слоя. Выделение, охватывающее несколько страниц, всё ещё можно
скопировать, а действия аннотирования и поиска показывают локализованное сообщение о
неподдерживаемой операции; выделение в пределах страницы продолжает работать.

PDF.js — не вторая оболочка просмотрщика. Перед сборкой или публикацией загрузите и
проверьте зафиксированные сторонние ресурсы:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
```

Затем приложение обслуживает локальные хешированные ресурсы модулей и worker PDF.js во
время работы и никогда не загружает их из CDN. Лайтбоксы изображений используют
зафиксированную зависимость GLightbox; Fancyapps/Fancybox не является рабочей или
распространяемой зависимостью. Процесс работы с зафиксированными ресурсами и выпусками
описан в [third_party/README.md](../../third_party/README.md).

## Развёртывание

### SSG

SSG создаёт полный снимок в соседнем промежуточном каталоге, проверяет его и только затем заменяет каталог назначения. Если какое-либо преобразование завершится ошибкой, прежний каталог назначения останется неизменным. Созданный вывод не содержит базы данных Server, состояния миграций, страницы учётной записи и метаданных рабочего кэша.

SSG намеренно работает локально и без учётных записей:

- Прогресс чтения и аннотации используют хранилище браузера текущего источника.
- Книжная полка поддерживает локальный импорт и экспорт JSON; действия облачной синхронизации нет.
- Вход, настройки учётной записи, API Server и зависящие от пользователя элементы управления отсутствуют.
- Место хранения зафиксировано в локальном хранилище браузера и не предлагается как настройка.
- Статический вывод включает Service Worker, необходимый для автономной работы ресурсов.

Все необходимые JavaScript, CSS, шрифты и значки приложения включены в вывод. Единственный необязательный сетевой запрос описан в разделе [Самодостаточность и сетевое поведение](#самодостаточность-и-сетевое-поведение).

### Server

#### Первоначальная настройка, учётные записи и разрешения

В новом каталоге постоянного состояния обычные страницы перенаправляются на `/setup`. API, потоки событий, создаваемые ресурсы и книги возвращают ответ о необходимости настройки, пока не будет создан начальный администратор. Завершите настройку через loopback или другой доверенный приватный путь до открытия порта: первая успешная отправка формы настройки закрепляет учётную запись администратора.

После настройки:

- Публичная регистрация закрыта. Администраторы создают пользователей и управляют ими.
- У учётных записей есть роль `administrator` или `member`.
- Обычные книги видны всем аутентифицированным учётным записям.
- Ограниченные книги видны только администраторам и явно выбранным пользователям.
- Каждому пользователю принадлежат его книжная полка, прогресс, аннотации и активные сеансы.
- Пользователи могут менять пароль и отзывать свои сеансы.
- Администраторы могут управлять пользователями, ролями, паролями, сеансами и правами на книги.
- Сеансы используют cookie HttpOnly, защиту от CSRF и скользящий срок действия 30 дней.

#### Единый вход OIDC и привязка учётных записей

Режим Server может использовать один универсальный OpenID Connect (OIDC) Provider,
включая Authelia, Keycloak, Authentik и совместимые сервисы. В **Administration →
OIDC login** укажите имя Provider, которое увидят читатели, URL издателя, client ID,
client secret, точный redirect URI, области и claim имени пользователя. EPUB Browser
использует discovery и Authorization Code flow с S256 PKCE, проверяет подписанный
ID token и идентифицирует внешнюю учётную запись только по `(issuer, sub)`; claim
адреса электронной почты и имени пользователя служат подсказками для отображения и
создания учётной записи, но никогда не являются ключами идентичности.

Зарегистрируйте у Provider точно этот callback, включая схему и хост:

```text
https://reader.example.com/auth/oidc/callback
```

Существующие пользователи могут войти локально и подключить Provider в настройках
учётной записи. В остальных случаях у неизвестной внешней идентичности один раз
запрашиваются имя пользователя и пароль существующей локальной учётной записи.
Необязательное автоматическое создание учётных записей создаёт участника без пароля
и никогда не импортирует роль администратора. Сначала дайте существующим пользователям
выполнить привязку: слишком раннее включение автоматического создания может привести
к **дублированию локальных учётных записей**. Вход по паролю **локального администратора**
всегда остаётся доступным, даже если вход участников по локальному паролю отключён.
Проверяйте и защищайте эти учётные данные для восстановления. Выход из Provider не
выполняется, а его access/refresh tokens не сохраняются.

Для Authelia настройте конфиденциальный клиент в разделе её OIDC Provider. В следующем
фрагменте намеренно используются вымышленные значения; предполагается, что необходимые
ключи и политики поставщика Authelia уже настроены. Сохраните в Authelia хеш стойкого
случайного client secret, затем один раз введите соответствующий исходный секрет в
EPUB Browser:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: 'epub-browser'
        client_name: 'EPUB Browser'
        client_secret: '<AUTHELIA_HASH_OF_A_RANDOM_SECRET>'
        public: false
        authorization_policy: 'two_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://reader.example.com/auth/oidc/callback'
        scopes: ['openid', 'profile', 'email']
        response_types: ['code']
        grant_types: ['authorization_code']
        token_endpoint_auth_method: 'client_secret_basic'
```

В EPUB Browser используйте issuer `https://auth.example.com`, client ID
`epub-browser`, scopes `openid profile email` и username claim
`preferred_username`. Сохранение выполняет реальное discovery и проверку возможностей;
при ошибке прежняя конфигурация остаётся активной.

#### Настройка и управление ИИ-чтением

Администраторы настраивают ИИ-чтение в **Administration**, сразу после управления
пользователями и перед управлением книгами. Страница сохраняет OpenAI-совместимый
Base URL, API key, модель, тайм-аут, бюджет контекста, предел параллелизма и дневной
лимит вызовов поставщика по умолчанию в базе данных Server SQLite. Для участников ИИ
изначально отключён; администратор должен предоставить доступ каждому участнику и может
задать индивидуальный дневной лимит (`0` означает без ограничений).

Учебные слои глав и рецензии на уровне книги являются общими для каждого допустимого
языка, а последующие диалоги остаются приватными для каждой учётной записи. Результаты,
состояние задач, пользовательские теги, классификация чтения книги и приватные
последующие диалоги хранятся в SQLite. После изменения конфигурации модели старые
результаты остаются доступными, пока администратор явно не создаст их заново.

Когда читатель запрашивает путеводитель ИИ или задаёт вопрос, выбранный текст EPUB и
сжатый контекст диалога отправляются настроенному внешнему поставщику. Не включайте
функцию, если читателям не разрешено передавать этому поставщику такое содержимое.
API key никогда не возвращается в браузер и не раскрывается через API; соответствующим
образом защитите каталог состояния Server.

Для автоматического первого запуска укажите имя пользователя и файл пароля:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --admin-username admin \
  --admin-password-file /run/secrets/epub-browser-admin-password \
  --no-browser
```

Файл пароля должен иметь права доступа `0600`. EPUB Browser удаляет один завершающий перевод строки, сохраняет хеш Argon2id и никогда не выводит секрет. Неполная конфигурация, пустой или недоступный для чтения файл останавливает запуск. После завершения настройки последующие запуски не читают начальный секрет.

Эквиваленты в переменных окружения — `EPUB_BROWSER_ADMIN_USERNAME` и `EPUB_BROWSER_ADMIN_PASSWORD_FILE`. `EPUB_BROWSER_ADMIN_PASSWORD` служит резервным вариантом с открытым текстом только тогда, когда файл пароля не настроен. Путь к файлу пароля в CLI имеет приоритет над источниками пароля в окружении.

#### Запуск браузера и ведение журнала

По умолчанию после запуска HTTP-прослушивателя Server пытается открыть браузер операционной системы по умолчанию. `--no-browser` предотвращает этот локальный запуск. Он **не отключает веб-интерфейс и доступ через браузер**, а лишь подавляет локальный вызов `webbrowser.open(...)`. Используйте его для Docker, systemd, сеансов SSH, машин без графического интерфейса и сценариев.

По умолчанию (`--log-level error`) CLI выводит только ошибки, чтобы обычные сообщения и предупреждения не мешали выводу индикаторов прогресса в терминале. Интерактивный терминал один раз выводит привязанный URL; неинтерактивные запуски в Docker и в виде служб в остальном не выводят сообщений. Используйте `--log-level warning`, чтобы добавить предупреждения, `--log-level info` для операционных сообщений и журнала HTTP-доступа или `--log-level debug` для максимально подробного вывода. `--log` остаётся псевдонимом совместимости для `--log-level info`.

Начальное сканирование и сканирование при наблюдении отображаются в веб-интерфейсе, а не через `tqdm` в терминале. Сводка об успехе закрывается автоматически; ошибки остаются видимыми, пока их не закроют. С `--watch` исправление или замена источника запускает новое сканирование без необходимости вручную запускать его повторно.

#### Постоянное и временное состояние

Постоянный режим Server требует `--server-dir`. Для одноразового запуска используйте `--ephemeral`:

```bash
epub-browser server book.epub --ephemeral
```

Временное состояние удаляется при завершении работы. Поскольку при каждом запуске создаётся новая база данных, настройка также повторяется, если не заданы учётные данные для автоматического начального запуска.

Структура постоянного состояния:

```text
<server-dir>/
├── .server.lock                 # reusable process-lock metadata
├── data/
│   ├── epub-browser.db          # authoritative accounts, books, grants, reading data
│   ├── migration-state.json     # restart-safe migration state
│   └── backups/                 # verified pre-migration database copies
└── cache/
    ├── catalog.json             # generated-cache status
    ├── public/                  # served application and converted books
    └── staging/                 # replaceable conversion work
```

Авторитетным источником является только `data/`. Каталог `cache/` можно удалить, и он будет создан заново. Сохраняйте `data/` при обновлениях и замене контейнера. Эксклюзивность обеспечивает блокировка операционной системы; `.server.lock` может остаться после нормального завершения как диагностические метаданные.

Храните постоянный `data/epub-browser.db` в локальной файловой системе. Общие и сетевые файловые системы не поддерживаются для параллельной работы WAL. Проверенные резервные копии остаются в `data/backups/` и включают все зафиксированные данные WAL.

#### LAN и обратный прокси

По умолчанию Server привязывается к `127.0.0.1:8000`. Для доверенной LAN:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --port 8080 \
  --no-browser
```

Не открывайте встроенный HTTP-сервер напрямую в публичный интернет. Завершайте TLS на обратном прокси, применяйте сетевые ограничения и включайте защищённые cookie.

Чтобы записывать реальные IP клиентов в активных сеансах и ограничениях частоты входа за обратным прокси, укажите **сеть, к которой принадлежит непосредственный адрес прокси**, а не диапазоны публичных клиентов:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --trusted-proxy-cidr 172.32.11.1/32 \
  --trusted-proxy-cidr 10.42.0.0/16 \
  --cookie-secure \
  --no-browser
```

Повторите `--trusted-proxy-cidr` для каждого адреса или сети непосредственного прокси. Только запросы, пришедшие напрямую с адреса из одного из этих CIDR, могут содержать `X-Forwarded-For`; для всех остальных записывается только их непосредственный адрес. Обработка пересланных адресов в Uvicorn отключена, поэтому `Forwarded` и `FORWARDED_ALLOW_IPS` не могут расширить эту границу доверия. Используйте `--cookie-secure`, только когда браузер обращается к сервису по HTTPS.

### Docker

Образ запускает постоянный режим Server со следующими значениями по умолчанию:

- `/app/Library` как источник
- `/app/EpubBrowserFiles` как постоянное состояние
- `--watch`
- `--no-browser`
- `--host 0.0.0.0 --port 80`
- `--book-id-storage embedded`
- `--kindle`

Поскольку встроенная идентичность может обновлять файлы EPUB или PDF, монтируйте библиотеку для чтения и записи. Монтируйте состояние Server для чтения и записи и сохраняйте его при замене контейнера:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  dfface/epub-browser:latest
```

Откройте `http://127.0.0.1:8080/setup` до изменения привязки порта или правил прокси.

#### Docker Compose

В репозиторий включён [docker-compose.yml](../../docker-compose.yml) для тех, кто предпочитает Compose. В рабочей копии создайте `Library/`, поместите туда книги EPUB или PDF и запустите:

```bash
docker compose up -d --build
```

Публикуется только `127.0.0.1:8080`, исходные книги EPUB/PDF хранятся в `./Library`, а состояние Server — в `./EpubBrowserFiles`. Полная команда Server `command` намеренно видна в файле, поэтому флаги конкретного развёртывания можно добавлять, не заменяя неявное значение образа по умолчанию. Завершите одноразовую настройку по адресу `http://127.0.0.1:8080/setup`. Для удалённого доступа сохраните привязку loopback и разместите перед ней обратный TLS-прокси с аутентификацией.

Для автоматической настройки:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  -e EPUB_BROWSER_ADMIN_USERNAME=admin \
  -e EPUB_BROWSER_ADMIN_PASSWORD_FILE=/run/secrets/epub-browser-admin-password \
  --mount type=bind,src=/path/to/admin-password,dst=/run/secrets/epub-browser-admin-password,readonly \
  dfface/epub-browser:latest
```

После первого успешного запуска монтирование одноразового секрета можно удалить. Библиотека только для чтения работает, только если каждый EPUB уже содержит соответствующий действительный встроенный идентификатор. Существующие sidecar сохраняются, когда их идентификаторы встроены.

Монтируйте `/app/SyncData:ro` только во время импорта устаревшего JSON книжной полки:

```bash
-v /path/to/legacy-sync:/app/SyncData:ro
```

Опубликованный порт loopback в примерах оставляет контейнер за границей хоста. Для удалённого доступа используйте обратный TLS-прокси, настройте его фактический CIDR сети контейнера и добавьте `--cookie-secure`.

## Справочник и эксплуатация

### Справочник команд

#### `epub-browser ssg SOURCE [SOURCE ...]`

| Параметр | Значение |
| --- | --- |
| `--output-dir DIR`, `-o DIR` | Обязательный каталог назначения для атомарного статического снимка. |
| `--base-path PATH` | Префикс публичного URL; по умолчанию `/`. Должен начинаться и заканчиваться `/`. |
| `--book-id-storage sidecar\|embedded` | Носитель стабильной идентичности для каждого выбранного источника; по умолчанию `sidecar`. |
| `--kindle` | Создаёт минимальные страницы без зависимостей для старых Kindle с e-Ink и перенаправляет на них браузеры Kindle WebKit; по умолчанию отключено. |
| `--log` | Псевдоним совместимости для `--log-level info`. |
| `--log-level debug\|info\|warning\|error` | Подробность операционного журнала; по умолчанию `error`, при котором обычный вывод преобразования и предупреждения не отображаются. |

#### `epub-browser server SOURCE [SOURCE ...]`

Требуется ровно один из параметров `--server-dir` и `--ephemeral`.

| Параметр | Значение |
| --- | --- |
| `--server-dir DIR` | Корень постоянных авторитетных данных и заменяемого кэша. |
| `--ephemeral` | Использовать одноразовое состояние; несовместимо с `--server-dir`. |
| `--watch`, `-w` | Отслеживать источники и согласовывать добавления, обновления, перемещения и удаления. |
| `--host ADDRESS` | Адрес привязки; по умолчанию `127.0.0.1`. |
| `--port PORT`, `-p PORT` | Порт привязки; по умолчанию `8000`. |
| `--no-browser` | Не запускать локальный браузер по умолчанию. Веб-интерфейс остаётся доступным. |
| `--log` | Псевдоним совместимости для `--log-level info`. |
| `--log-level debug\|info\|warning\|error` | Подробность операционного журнала; по умолчанию `error`. Журналы HTTP-доступа включаются при `info` и `debug`. |
| `--legacy-sync-dir DIR` | Читать устаревший JSON книжной полки во время миграции при запуске. |
| `--book-id-storage sidecar\|embedded` | Носитель стабильной идентичности для каждого выбранного источника; по умолчанию `sidecar`. |
| `--admin-username NAME` | Начальный администратор для автоматической настройки; резервный вариант `EPUB_BROWSER_ADMIN_USERNAME`. |
| `--admin-password-file FILE` | Предпочтительный файл начального секрета; резервный вариант `EPUB_BROWSER_ADMIN_PASSWORD_FILE`, затем `EPUB_BROWSER_ADMIN_PASSWORD`, если файл не задан. |
| `--trusted-proxy-cidr CIDR` | Можно повторять; задаёт доверенную сеть непосредственного прокси для безопасного извлечения IP клиента из `X-Forwarded-For`. |
| `--cookie-secure` | Отправлять cookie сеанса только через HTTPS между браузером и сервисом. |
| `--kindle` | Обслуживать минимальные страницы без зависимостей для старых Kindle с e-Ink и перенаправлять на них браузеры Kindle WebKit; по умолчанию отключено. |

#### Устаревший синтаксис v1

Устаревший синтаксис поддерживается во всей основной линейке v2:

| Команда v1 | Соответствие v2 |
| --- | --- |
| `epub-browser BOOKS` | `epub-browser server BOOKS --ephemeral` |
| `epub-browser BOOKS --output-dir STATE` | `epub-browser server BOOKS --server-dir STATE` |
| `epub-browser BOOKS --no-server --output-dir DIST` | `epub-browser ssg BOOKS --output-dir DIST` |
| `--sync-dir DIR` | `server --legacy-sync-dir DIR` |

Параметр `--keep-files`, существующий только в устаревшем синтаксисе, сохраняет временный каталог Server. Постоянные каталоги Server и так сохраняются. С `--log` адаптер совместимости выводит эквивалентную команду v2; без него он не выводит сообщений.

### Данные чтения и размещение функций

- Рекурсивное обнаружение EPUB/PDF и библиотек Calibre, теги метаданных, поиск и поиск по пиньиню
- Адаптивные интерфейсы библиотеки, сведений о книге и чтения глав
- Прокрутка, листание, непрерывное чтение, настраиваемая ширина содержимого, шрифты, пользовательский CSS, темы и режим чтения без отвлекающих элементов
- Выделения, заметки, просмотр аннотаций, вложенные группы книжной полки, теги и импорт/экспорт JSON
- Локали интерфейса: английский, упрощённый китайский, традиционный китайский,
  корейский, японский, испанский, немецкий, французский, русский, итальянский,
  бразильский португальский, арабский, индонезийский, хинди, вьетнамский, тайский
  и малайский
- Поведение, удобное для электронных книг с браузерами Kindle/Silk; ресурсоёмкие браузерные функции могут быть сокращены

| Данные | SSG | Server |
| --- | --- | --- |
| Прогресс чтения | Локально в браузере | Запись аутентифицированного пользователя в SQLite |
| Выделения и заметки | Локально в браузере | Записи аутентифицированного пользователя в SQLite |
| Приватные оценки, рецензии и история сеансов чтения | Отсутствуют | Записи аутентифицированного пользователя в SQLite |
| Книжная полка | Локально в браузере; импорт/экспорт | Версионируемый облачный документ аутентифицированного пользователя; автоматическое сохранение |
| Учётные записи и сеансы | Отсутствуют | SQLite в `<server-dir>/data` |
| Права на книги | Отсутствуют | SQLite в `<server-dir>/data` |

Server не предлагает выбор между локальным и облачным хранилищем: данные чтения аутентифицированного пользователя всегда хранятся на Server. Подробная приватная история сеансов чтения никогда не создаётся SSG. SSG никогда не опрашивает API Server и всегда использует локальное хранилище браузера для текущего источника.

### Самодостаточность и сетевое поведение

Приложение самодостаточно для чтения: необходимые JavaScript, CSS, шрифты, значки, манифесты и преобразованные ресурсы EPUB обслуживаются локально. Зависимостей от CDN во время работы нет. Блокировка исходящего доступа в интернет не мешает настройке, входу, просмотру, чтению, аннотациям, прогрессу, работе с книжной полкой, администрированию и преобразованию источников.

Нижний колонтитул может выполнять необязательный запрос к GitHub Releases API для обнаружения более новой версии EPUB Browser. Ошибка, блокировка или автономная работа лишь скрывают это уведомление об обновлении.

SSG публикует статический Service Worker. Server намеренно отключает и выводит из эксплуатации Service Worker всего источника, чтобы одна учётная запись не могла получить кэшированное защищённое содержимое другой учётной записи.

### Server API и WebHooks

Учётные записи Server могут создавать персональные токены доступа с ограниченной областью действия в настройках учётной записи. Внешние клиенты используют `Authorization: Bearer <PAT>` с версионированным API `/api/v1/*`; браузерные cookie не аутентифицируют эти маршруты. API охватывает видимые книги и содержимое глав, книжную полку владельца токена, прогресс, аннотации и рецензии, а также доступные только для чтения данные разных пользователей для PAT администратора с `admin:data:read`.

Документ OpenAPI 3.1 доступен по `/openapi.json`; вошедшие пользователи могут просматривать локальную справку по `/api-docs`. Например: `curl -H 'Authorization: Bearer …' https://reader.example/api/v1/books`. Сведения о главе по умолчанию возвращают очищенный HTML, а с `?format=text` — обычный текст.

Конечные точки списков возвращают `items` и `next_cursor`. Значение `limit` по умолчанию — 24, максимум — 100. Передайте `next_cursor` как `cursor` с теми же фильтрами, чтобы получить следующую страницу. Курсор null обозначает последнюю страницу. Например, используйте `/api/v1/me/annotations?book_id=BOOK_ID&chapter_index=0&fields=id,text,note`, чтобы получить выбранные поля аннотаций из одной главы EPUB или страницы PDF. Фильтры запросов и поддерживаемые поля перечислены в документе OpenAPI.

Словарный запас по умолчанию использует тот же формат списка. Клиенты, использующие прежний ответ `words`, могут передать `page=1` или `page_size`, чтобы выбрать устаревший формат разбивки на страницы.

Администраторы управляют конечными точками WebHook в Administration. Секреты показываются только при создании или ротации. Доставки подписываются, сохраняются и повторяются при ответах не 2xx; события рецензий на книги содержат идентификаторы и метки времени действий, но никогда не содержат оценку или текст рецензии.

### Безопасность данных и миграция

Перед обновлением постоянных установок Server создайте резервные копии исходных книг EPUB/PDF и `<server-dir>/data`. При замене контейнера сохраняйте тот же том постоянного состояния.

Миграция при запуске выполняется автоматически и безопасна при перезапуске. Она проверяет устаревшие базы данных, создаёт резервную копию, обновляет копию, импортирует подходящие устаревшие данные книжной полки, прогресса и аннотаций в учётную запись ещё не созданного начального администратора и выводит из эксплуатации только заменяемые устаревшие публичные артефакты после успешных контрольных точек. Обычные запросы никогда не сканируют устаревшие каталоги синхронизации. Повреждённые базы данных, недействительные хеши паролей, неоднозначные устаревшие базы данных и конфликтующие идентификаторы приводят к безопасному отказу, а не к догадкам или перезаписи.

Перенесённый корневой `epub-browser.db` или `annotations.db` сохраняется как конфиденциальная копия для восстановления, не являющаяся авторитетным источником; авторитетным является `data/epub-browser.db`, и запросы Server не используют сохранённый корневой файл. Храните копию для восстановления приватно. Удаляйте её вручную только при остановленном Server, после проверки авторитетной базы данных и созданной резервной копии и только если откат к v1 больше не нужен. EPUB Browser никогда не удаляет её автоматически.

Если в устаревшем корне существуют и `epub-browser.db`, и `annotations.db`, запуск останавливается, а файлы остаются нетронутыми. Резервное копирование, откат, пересоздание кэша и восстановление после конфликтов описаны в разделе [Миграция на v2](../migration-v2.md).

### Устранение неполадок

#### Команда запустилась, но браузер не открылся

Уберите `--no-browser` при запуске на локальной машине с графическим интерфейсом или откройте выведенный/привязанный URL вручную. В Docker, systemd, SSH и неинтерактивных сеансах предполагается самостоятельное открытие URL.

#### CLI ничего не выводит

Работа без вывода намеренна при отсутствии `--log`, особенно в неинтерактивных средах. Добавьте `--log` для операционных сведений и сведений о доступе. Прогресс сканирования Server показывается в веб-интерфейсе.

#### Docker не может записать стабильный идентификатор

Образ по умолчанию использует встроенную идентичность. Монтируйте `/app/Library` для чтения и записи или заранее встройте действительные соответствующие идентификаторы. Используйте пользовательскую команду с `--book-id-storage sidecar`, только если предпочтителен доступный для записи sidecar-носитель.

#### В созданном сайте SSG не работают ссылки под подпутём

Создайте сайт заново с нормализованным `--base-path`, например `/reader/`, и настройте статический хост на обслуживание вывода по тому же префиксу.

#### Server отказывается запускаться после обновления

Прочитайте первую зарегистрированную ошибку миграции или проверки, сохраните данные и исходные файлы и обратитесь к [docs/migration-v2.md](https://raw.githubusercontent.com/dfface/epub-browser/main/docs/migration-v2.md). Не удаляйте авторитетный каталог `data/`, чтобы обойти ошибку.

## Разработка и лицензия

### Участие в разработке

Issues и pull requests приветствуются в [dfface/epub-browser](https://github.com/dfface/epub-browser). Полезный отчёт включает точную команду, браузер и устройство, шаги воспроизведения, соответствующие журналы и файл EPUB или PDF, если им можно законно поделиться.

#### Архитектурный контракт для разработчиков

Перед изменением обработки содержимого, шаблонов страниц, кэшей, разрешений, ресурсов
или поведения развёртывания прочитайте [AGENTS.md](../../AGENTS.md). В нём определены
граница форматов EPUB/PDF, зоны ответственности SSG/Server, независимые ревизии кэшей,
требования к i18n во время работы, проверки безопасности и необходимая верификация.
Общие термины продукта, такие как *глава интерфейса чтения*, *окно чтения*, *область
чтения* и *кэш содержимого*, определены в [CONTEXT.md](../../CONTEXT.md).

Краткая версия: сохраняйте единый интерфейс чтения, не включайте данные только для Server
в SSG, храните производные кэши EPUB и PDF отдельно от пользовательских данных SQLite
и никогда не добавляйте зависимость от CDN во время работы. Изменения, затрагивающие общие компоненты,
необходимо тестировать с обоими форматами и обоими режимами развёртывания, где это
применимо.

#### Разработка из исходной рабочей копии

Сторонние браузерные файлы — создаваемые входные данные сборки, а не исходный код
проекта, поэтому `epub_browser/assets/vendor/` намеренно отсутствует в Git. Перед
разработкой или сборкой явно загрузите точные зафиксированные версии, затем проверьте
их автономно:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
python3 -m unittest tests.test_vendor_assets -v
python3 -m build
```

`fetch` — единственная команда выше, которая загружает вендорные браузерные ресурсы.
Файл блокировки записывает неизменяемые tarball npm, дайджесты файлов, списки разрешённых
файлов и лицензии; `verify`, тесты, сборки из подготовленной рабочей копии и установленный
интерфейс чтения не загружают браузерные ресурсы. Стандартная изолированная команда
`python3 -m build` всё ещё может обращаться к индексу пакетов Python за требованиями
сборки. Для полностью автономной сборки подготовьте вендорное дерево и заранее установите
`build`, `setuptools` и `wheel` до отключения сети, затем запустите
`PIP_NO_INDEX=1 python3 -m build --no-isolation`. Wheels, исходные дистрибутивы, образы
Docker и созданные сайты SSG содержат проверенные файлы и не зависят от CDN во время
работы. Процесс обновления, выпуска и поддержания чистоты репозитория описан в
[third_party/README.md](../../third_party/README.md).
