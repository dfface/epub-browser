> **حوّل الكتب إلى مواقع ويب، وأنشئ مكتبة تملكها.**

EPUB Browser ليس مجرد محوّل كتب، بل منصة قراءة متكاملة يمكنك نشرها في أي مكان
أو استضافتها بنفسك. يشترك EPUB وPDF في المكتبة نفسها، وصفحة الكتاب، والفهرس،
وأوضاع القراءة، والسمات، وتتبّع التقدّم، ومسار التعليقات التوضيحية. تصبح كل صفحة
PDF فصلاً في القارئ، ويعرضها PDF.js محلياً داخل تجربة القراءة ذاتها، من دون عارض
منفصل ومن دون CDN أثناء التشغيل.

## نظرة عامة على المشروع

### لماذا EPUB Browser؟

- **انشر في أي مكان واحتفظ بالسيطرة.** أنشئ موقعاً ثابتاً متكاملاً لمنصات Pages
  أو تخزين الكائنات أو Nginx بأمر واحد، أو شغّل Server دائماً مع حسابات وأذونات
  كتب وOIDC. تُقدَّم أصول التطبيق والخطوط وPDF.js والعارضات محلياً، لذلك لا تعتمد
  القراءة على CDN إطلاقاً.
- **EPUB وPDF في قارئ حقيقي واحد.** يشترك التنسيقان في المكتبة وصفحة الكتاب
  والفهرس والتخطيط المتجاوب وأوضاع القراءة الثلاثة والسمات وملء الشاشة والتقدّم.
  تبقى كل صفحة PDF داخل منطقة القراءة، مع التكبير وتحديد النص في طبقة النص والتعليقات
  التوضيحية بدلاً من عارض معاينة منفصل.
- **اعثر على الكتاب والمقطع الذي تريده.** يشمل بحث المكتبة البيانات الوصفية
  والوسوم وpinyin، مع الفرز وترقيم الصفحات. ويعيد بحث الكتاب الكامل في Server
  لملفات EPUB نتائج كاملة مجمعة حسب الفصول، وينتقل إلى المقطع المميّز. وتحافظ
  معرّفات الكتب الثابتة على ارتباط نقاط الاستئناف والتعليقات والسجل بالكتاب نفسه.
- **افهم النص، لا تكتفِ بالتمرير.** في وضع Server، تبقى أدلة فصول EPUB والشروح
  المرتبطة بالأدلة وخرائط الأفكار وAsk AI الخاص بجوار النص المصدر. تعمل التظليلات
  والملاحظات وDictionary وEncyclopedia مع EPUB وملفات PDF ذات طبقة النص؛ وتسجّل
  قوائم المفردات في Server مصدر كل كلمة وحالة إتقانها.
- **حوّل القراءة إلى سجل يستحق الحفظ.** تشكّل الرفوف المتداخلة والتقييمات
  والمراجعات وتصدير التعليقات وتقويمات النشاط والاتجاهات وإحصاءات كل كتاب وترتيب
  أوقات القراءة سجلاً مترابطاً. يحافظ Server على خصوصية بيانات القراءة لكل حساب
  ويزامنها بين الأجهزة.
- **شغّل خدمة قراءة، لا مجرد عارض.** في وضع Server، أضف الكتب عبر تحميلات الويب
  الإدارية أو المجلدات المراقَبة، وحدّد استخدام القرص من خلال الإخلاء القابل للضبط لعناصر ذاكرة التخزين المؤقت
  وفق LRU، وأدر أذونات الأعضاء والذكاء الاصطناعي، وتكامل عبر OpenAPI وPAT
  وWebHooks. تدعم القراءة المبسطة في Kindle الأجهزة محدودة القدرات؛ ويوفّر Server
  أيضاً لوحة شخصية لشاشة توقف Kindle تضم ساعة وتقويماً وجدول أعمال ومذكرة ومؤقت Pomodoro.

### المكدس التقني

يستخدم EPUB Browser عمداً مكدس ويب صغيراً يعرض الصفحات من الخادم. لا يتضمن
التطبيق المثبّت إطار SPA، ولا يحتاج إلى Node.js أثناء التشغيل:

| الطبقة | التقنية | الدور |
| --- | --- | --- |
| الواجهة | HTML دلالية وCSS وVanillaJS مع وحدات ES وواجهات المتصفح | واجهة متجاوبة واحدة مشتركة بين SSG وServer |
| CLI وServer | Python 3.9+ وStarlette وUvicorn | أوامر التحويل والصفحات التي تتطلب المصادقة وواجهات API والعمل في الخلفية |
| البيانات | SQLite مع ذاكرات محتوى JSON قابلة لإعادة البناء | تبقى حالة المستخدم منفصلة عن محتوى EPUB/PDF المشتق |
| تنسيقات الكتب | lxml وpypdf وpypdfium2 وPDF.js | تحليل وتنقية EPUB موحّدان يبدآن بالوضع الصارم، وبيانات PDF الوصفية وأغلفته، وعرض محلي في المتصفح |
| العمل دون اتصال والأصول | Service Worker وأصول ثابتة ذات بصمات تجزئة وتبعيات مورّدة مقفلة | تسليم مكتفٍ ذاتياً من دون CDN أثناء التشغيل |
| التوزيع | PyPI وDocker والاستضافة الثابتة العادية | تُنشر قاعدة الشيفرة نفسها كـSSG أو Server دائم |
| ذكاء اصطناعي اختياري | واجهات API متوافقة مع OpenAI مع Markdown وKaTeX وMermaid معروضة محلياً | طبقات تعلّم EPUB في وضع Server فقط |

يستخدم المشرفون Node.js لاختبارات المتصفح فقط؛ فهو ليس جزءاً من بيئة تشغيل
القارئ في الإنتاج.

### اختيار SSG أو Server

تشغّل معالجة المصدر وقوالب الصفحات نفسها وضعي نشر صريحين. اختر وفق المكان الذي
ينبغي أن توجد فيه بيانات القراءة، لا وفق تنسيق الكتاب:

| القدرة | `ssg` | `server` |
| --- | --- | --- |
| EPUB وPDF | نعم | نعم |
| التسليم | HTML وأصول ثابتة تُستبدل ذرياً لمنصات Pages أو تخزين الكائنات أو Nginx | صفحات ديناميكية تتطلب المصادقة تستند إلى ذاكرة محتوى قابلة للاستبدال |
| الحسابات والتحكم في الوصول | لا شيء | حسابات مسؤول/عضو، ومنح الوصول إلى الكتب المقيّدة، وجلسات، وحماية CSRF |
| تسجيل الدخول الموحّد عبر OIDC | غير مضمّن | Provider عام، وربط الحسابات الحالية، وإنشاء الأعضاء اختيارياً |
| التقدّم والتعليقات والرف | تُحفظ في المتصفح الحالي | تُزامن لكل حساب بعد تسجيل الدخول في SQLite |
| التقييمات والمراجعات وجلسات القراءة | لا تُنشأ | سجلات خاصة لكل حساب ورؤى قراءة |
| تحديثات المصدر | شغّل `ssg` مجدداً | أعد التشغيل أو أعد الفحص أو استخدم `--watch` |
| الإدارة والوسوم وOpenAPI وWebHooks | غير مضمّنة | مضمّنة |
| القراءة بالذكاء الاصطناعي وAsk AI | غير مضمّنة | متاحة لـEPUB عند ضبطها والسماح بها صراحةً؛ ومخفية لـPDF |
| قاعدة بيانات وقت التشغيل | لا توجد | مطلوبة للوضع الدائم |
| الأنسب لـ | الاستضافة العامة/الثابتة، وحزم العمل دون اتصال، والنشر الشخصي البسيط | مكتبة خاصة، وأجهزة أو قرّاء متعددون، وأتمتة، ووصول مُدار |

استخدم `ssg` عندما يجب أن تكون النتيجة ملفات ثابتة عادية. واستخدم `server` عندما يحتاج القرّاء إلى حسابات أو بيانات بين الأجهزة أو تحكم في الوصول أو مطابقة تلقائية للمصادر.

### القراءة المدمجة بالذكاء الاصطناعي (Server فقط)

بالنسبة إلى كتب EPUB، يستطيع وضع Server إضافة أدلة فصول وشروح مرتبطة بالأدلة
وخرائط أفكار وأسئلة تأمل ودرج Ask AI خاص من دون إبعاد القارئ عن النص الأصلي.
تظل النتائج خاضعة لأذونات الكتاب؛ ويجب تخويل الأعضاء صراحةً، ولا يحتوي SSG على
أي عناصر تحكم أو مهام أو بيانات حسابات أو إعدادات مزوّد تخص الذكاء الاصطناعي.
أما PDF فيخفي القراءة بالذكاء الاصطناعي وAsk AI عمداً.

راجع [دليل القراءة المدمجة بالذكاء الاصطناعي](../ai-native-reading.md) لمعرفة نموذج
التفاعل الكامل، و[ملاحظات عارض النص المنسّق المحلي](../third-party-ai-renderers.md)
لحدود العرض وسلامة الشبكة.

### وضع Kindle المبسط

تحصل أجهزة Kindle القديمة ذات شاشات e-Ink (وأي متصفح محدود القدرات) على واجهة
قراءة مبسطة بلا تبعيات. فعّلها باستخدام `--kindle`:

- SSG: `epub-browser ssg --kindle -o output/ SOURCE...`
- Server: `epub-browser server --kindle --server-dir data SOURCE...`

يكتسب كل كتاب EPUB (تُستثنى كتب PDF) ثلاث صفحات إضافية:

- الرف المبسط `/kindle-library.html`
- صفحة الكتاب `/book/<id>/kindle.html`
- صفحة الفصل `/book/<id>/kindle_chapter_N.html`

هذه الصفحات مضبوطة لشاشات e-Ink: ترميز محدود، وسمات بـCSS فقط، وسكربتات متوافقة
مع ES5، ولا Service Worker ولا إطار عمل. يمكنك القراءة من دون JavaScript إطلاقاً؛
أما تبديل السمة (فاتح / بني فاتح / داكن)، وحجم الخط (A- / A+)، وتوطين الواجهة
فتستخدم سكربتات مضمّنة خفيفة فوق HTML العادي.

توفر كل صفحة عناصر تحكم بالسمة والخط (في الترويسة، ومرة أخرى في تذييل الفصل)،
وتنقلاً في الفهرس، والفصل السابق/التالي، ورابط «متابعة القراءة» يستأنف من التقدّم المحفوظ.

يختلف تقدّم القراءة بحسب الوضع:

- **SSG:** يُحفظ التقدّم في ملفات تعريف الارتباط بالمتصفح الحالي؛ محلياً ومن دون حساب.
- **Server:** يُزامن التقدّم ونبضات القراءة لكل حساب مسجّل الدخول في SQLite. واجهات
  Kindle للقراءة وإرسال التقارير فقط: تسجّل الفصل الحالي وترسل النبضات، وتعرض رفاً
  للقراءة فقط، ولا تكشف الرؤى أو إدارة المحتوى إطلاقاً.

يُفرض التحكم في الوصول على كل واجهات Kindle. يعيد الكتاب مقيّد الظهور الخطأ 403
للمستخدمين غير المخوّلين في الرف المبسط (حيث يُحذف من القائمة)، وصفحتي الكتاب
والفصل، وواجهة API للتقدّم.

تُعيد المتصفحات المدعومة (التي يحتوي UA فيها على `Kindle/` أو `Arora/` وغيرهما)
التوجيه تلقائياً من القارئ الكامل إلى الصفحات المبسطة؛ وتعمل عناوين URL أعلاه مباشرةً
أيضاً. وبذلك يوفّر الوضع المبسط بديلاً سلساً للأجهزة منخفضة القدرة أو محدودة JavaScript.

## البدء

### اختيار طريقة التثبيت

يدعم EPUB Browser مسارين للتثبيت. ويقبل كلاهما ملف `.epub` أو `.pdf` واحداً أو أكثر،
أو مجلدات متداخلة، أو مجلد مكتبة بنمط Calibre.

| التثبيت | استخدامه | متطلبات المضيف |
| --- | --- | --- |
| PyPI | وضع SSG أو Server | Python 3.9 أو أحدث |
| Docker | وضع Server الدائم | Docker Engine؛ وPython مضمّن في الصورة |

#### PyPI (SSG أو Server)

ثبّت تطبيق سطر الأوامر:

```bash
pip install epub-browser
```

اعرض مرجع الأوامر الخاص بكل وضع:

```bash
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

#### Docker (Server)

تشغّل صورة [`dfface/epub-browser`](https://hub.docker.com/r/dfface/epub-browser)
المنشورة وضع Server ولا تحتاج إلى Python على المضيف:

```bash
docker pull dfface/epub-browser:latest
```

استخدم `latest` لتقييم الإصدار الحالي؛ وثبّت وسم إصدار رقمي للحصول على نشر إنتاجي
قابل للتكرار. راجع [Docker](#docker) لمعرفة عمليات ربط الكتب والحالة المطلوبة،
وبدء Compose السريع، وإعداد التشغيل الأول، وإرشادات الشبكة.

### بدء سريع

#### إنشاء موقع ثابت

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist
```

قدّم `dist/` عبر HTTP. فتح الصفحات المنشأة مباشرةً عبر `file://` غير مدعوم، لأن تخزين المتصفح والوحدات وملفات manifest وService Workers تتطلب أصل HTTP.

لموقع مستضاف تحت بادئة URL، اضبط المسار العام منفصلاً عن وجهة نظام الملفات:

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist \
  --base-path /my-repository/
```

يغيّر `--base-path` عناوين URL المنشأة، لا مكان كتابة الملفات. عند استخدام `/my-repository/`، تستخدم الروابط والأيقونات وملفات manifest والبيانات الوصفية للكتب وإدخالات Service Worker تلك البادئة كلها، بينما تبقى الملفات مباشرةً داخل `dist/`.

#### تشغيل مكتبة Server دائمة

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/epub-browser-state \
  --watch
```

افتح `http://127.0.0.1:8000/`. عند الوصول الأول، يطلب EPUB Browser إنشاء المسؤول الأول. لا تُفحص المكتبة أو تُكشف حتى ينتهي هذا الإعداد لمرة واحدة.

إذا اخترت Docker، فتجاوز أمر Python أعلاه وتابع إلى
[بدء Docker Compose السريع](#docker-compose).

## التنسيقات والقراءة

### المصادر وهوية الكتاب الثابتة

يمكن أن يكون كل `SOURCE` موضعي ملف EPUB أو ملف PDF أو مجلداً. وتُبحث المجلدات
بشكل متكرر. ويمكن تمرير مصادر متعددة إلى أمر واحد:

```bash
epub-browser server book.epub /srv/library /srv/periodicals \
  --server-dir /srv/epub-browser \
  --watch
```

يحصل كل كتاب على `book_id` ثابت، يظهر أيضاً باسم `book_hash` في عناوين URL المنشأة
وبيانات المتصفح. الإعداد الافتراضي العام لـCLI هو:

```bash
--book-id-storage sidecar
```

يكتب وضع sidecar ملف هوية ظاهراً بجوار المصدر، مثل `BOOK.epub.epub-browser.json` أو
`BOOK.pdf.epub-browser.json`، ويترك بايتات المصدر بلا تغيير. يحتوي ملف sidecar على
المعرّف الثابت وبصمة مصدر SHA-256 تم التحقق منها.

لوضع المعرّف في بيانات EPUB OPF الوصفية أو قاموس معلومات مستند PDF، اختر التخزين
المضمّن لاستدعاء الأمر بالكامل:

```bash
--book-id-storage embedded
```

يمكن للوضع المضمّن إعادة بناء ZIP الخاص بـEPUB أو إلحاق تحديث بيانات وصفية بـPDF
قبل التحويل. إذا تعذّر تحديث PDF ولم يتغير مصدره، يحفظ EPUB Browser المعرّف نفسه
في sidecar مجاور. ويشمل ذلك ملفات PDF الموقّعة والمشفّرة والمخصصة للقراءة فقط.
يتوقف EPUB Browser عند اختلاف المعرّفات، أو تكرار معرّف بين مصادر نشطة، أو عدم صلاحية
حامل، أو تعذّر كتابة حامل مطلوب.

عند ترحيل أوضاع التخزين، ينسخ EPUB Browser المعرّف الحالي إلى الحامل المحدد ويحتفظ
بالحامل الصالح الآخر. يُنسخ معرّف مضمّن موجود منذ v2.0.4 إلى sidecar الافتراضي من دون
إعادة كتابة EPUB. ويقدّم كل من SSG وServer نسخة مطابقة للمصدر بايتاً ببايت بعد أي
تحديث للبيانات الوصفية في PDF.

### PDF: صفحة واحدة، فصل واحد

يدعم وضعا النشر كلاهما PDF. يتعامل القارئ مع كل صفحة PDF بوصفها فصلاً عادياً في
EPUB Browser، لذلك تبقى صفحة الكتاب الحالية والتنقل بين الفصول والفهرس وترقيم الصفحات
والقراءة المستمرة والتقدّم وجلسات القراءة والتعليقات وDictionary وEncyclopedia واجهة
ونموذج بيانات واحداً مشتركاً:

| مفهوم PDF | SSG | Server |
| --- | --- | --- |
| عنوان URL للصفحة 1 | `chapter_0.html` | `/book/<book-id>/chapter_0.html` |
| عنوان URL للصفحة N | `chapter_{N-1}.html` | `/book/<book-id>/chapter_{N-1}.html` |
| تسميات الصفحات والفهرس | تُنشأ محلياً؛ وتُدرج كل صفحة | تُعرض من ذاكرة بيانات PDF الوصفية؛ وتُدرج كل صفحة |
| المخطط التفصيلي المضمّن | علامة في إدخال الفهرس لصفحة الوجهة | العلامة نفسها، من دون حذف إدخالات الصفحات أو إعادة ترتيبها |
| التمرير وترقيم الصفحات/تقليبها | أغلفة فصول ثابتة وPDF.js محلي | أغلفة فصول مشتركة ديناميكية وPDF.js محلي |
| التظليلات والملاحظات وDictionary وEncyclopedia | مكونات مشتركة محلية في المتصفح عند وجود طبقة نص | مكونات مشتركة تتطلب المصادقة عند وجود طبقة نص |
| بايتات PDF الخام | ملف `document.pdf` واحد في مخرجات الكتاب الثابت | مسار للجلسات فقط يدعم النطاقات للمستند المخزّن مؤقتاً |

تكون أرقام الصفحات مبنية على 1 في التسمية المرئية وPDF.js؛ أما فهارس الفصول فتكون
مبنية على 0 في عناوين URL والحالة وواجهات API وSQLite. ولذلك تكون صفحة PDF رقم 1
دائماً `chapter_0.html`. يحتفظ الفهرس المُعايَر بإدخال `Page N` واحد لكل صفحة؛ وتُرفق
عناوين المخطط التفصيلي المضمّن في PDF كعلامات مخطط بإدخال الوجهة، بما في ذلك علامات
متعددة في صفحة واحدة.

يكتب SSG ملف `document.pdf` واحداً وغلاف `chapter_<index>.html` واحداً لكل صفحة.
لا تحتوي مخرجات SSG على سكربتات Session أو استدعاءات `/api/*` أو بيانات تعليقات
متزامنة أو تبعيات Server. يخزّن Server المصدر الكامل المطابق بايتاً ببايت في
`book/<book-id>/pdf/document.pdf` ولا يقسّمه أو يعيد كتابته إطلاقاً. ويعرض Server
أغلفة الفصول نفسها ديناميكياً من بيانات PDF الوصفية، ويؤدي تغيّر المصدر إلى إبطال ذاكرة
PDF وتحديثها بالكامل (المستند والبيانات الوصفية والغلاف المشتق) بدلاً من مزج صفحات
قديمة وجديدة.

نقطة نهاية المستند الخام في Server مخصصة للجلسات فقط:
`GET`/`HEAD /api/books/<book-id>/document`. تتحقق من المصادقة وظهور الكتاب وتنسيق
PDF وبصمات المصدر/الذاكرة المؤقتة، ثم تدعم استجابات نطاق واحد محدودة مع `ETag` و
`Accept-Ranges` والتخزين المؤقت الخاص و`nosniff` وعرض PDF مضمّناً. لا تكشف
مساراً مطلقاً، ولا تتاح لمصادقة PAT، ولا تُدرج في واجهة PAT/OpenAPI. لا يملك SSG
سوى ملف `document.pdf` المحلي، ولا توجد فيه واجهة API للمستند الخام.

تعيد ملفات PDF ذات طبقة نص PDF.js صالحة استخدام نافذة التحديد المنبثقة ومكوّن
التعليقات الحاليين نفسيهما لـHighlight وNote، إضافةً إلى Dictionary وEncyclopedia.
يبقى تخزين التعليقات وملكيتها وتصديرها وإدراجها وروابطها العميقة مشتركاً؛ فلا يوجد
جدول تعليقات أو واجهة إعدادات خاص بـPDF. تبقى ملفات PDF الممسوحة ضوئياً أو المعتمدة
على الصور فقط قابلة للقراءة، لكن Highlight وNote وDictionary وEncyclopedia والبحث
في المستند المبنية على التحديد تكون غير متاحة صراحةً عندما لا توجد طبقة نص صالحة.
قد يظل بالإمكان نسخ تحديد يمتد عبر صفحات، بينما تعرض إجراءات التعليقات والبحث عن
الكلمات رسالة عدم الدعم الموطّنة؛ ويستمر التحديد داخل الصفحة في العمل.

PDF.js ليس غلاف عارض ثانياً. قبل البناء أو النشر، جهّز أصول الطرف الثالث المقفلة
وتحقق منها:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
```

يقدّم التطبيق بعد ذلك أصول وحدة PDF.js وworker المحلية ذات بصمات التجزئة أثناء
التشغيل؛ ولا يجلبها من CDN إطلاقاً. تستخدم صناديق عرض الصور تبعية GLightbox المقفلة؛
وليست Fancyapps/Fancybox تبعية تشغيل أو تبعية يعاد توزيعها. راجع
[third_party/README.md](../../third_party/README.md) لسير عمل الأصول والإصدارات المقفلة.

## النشر

### SSG

يبني SSG لقطة كاملة في مجلد تجهيز مجاور، ويتحقق منها، ثم يستبدل الوجهة. إذا فشل أي
تحويل، تبقى الوجهة السابقة بلا تغيير. لا تحتوي المخرجات المنشأة على قاعدة بيانات Server
أو حالة ترحيل أو صفحة حساب أو بيانات وصفية لذاكرة تشغيل مؤقتة.

سلوك SSG محلي وبلا حسابات عمداً:

- يستخدم تقدّم القراءة والتعليقات تخزين المتصفح على الأصل الحالي.
- يدعم رف الكتب استيراد JSON وتصديره محلياً؛ ولا يتضمن إجراء مزامنة سحابية.
- لا توجد صفحة تسجيل دخول أو إعدادات حساب أو واجهات Server API أو عناصر تحكم تعتمد على المستخدم.
- تُثبّت وجهة التخزين على التخزين المحلي للمتصفح ولا تُعرض كإعداد.
- تتضمن المخرجات الثابتة Service Worker اللازم للأصول القابلة للعمل دون اتصال.

تُضمّن كل JavaScript وCSS والخطوط والأيقونات المطلوبة للتطبيق في المخرجات. راجع
[الاكتفاء الذاتي وسلوك الشبكة](#الاكتفاء-الذاتي-وسلوك-الشبكة) لمعرفة طلب الشبكة الاختياري الوحيد.

### Server

#### الإعداد الأول والحسابات والأذونات

في مجلد حالة دائمة جديد، تعيد الصفحات العادية التوجيه إلى `/setup`. وتعيد واجهات API
وتدفقات الأحداث والأصول المنشأة والكتب استجابة تشترط الإعداد حتى إنشاء المسؤول الأول.
أكمل الإعداد عبر loopback أو مسار خاص موثوق آخر قبل كشف المنفذ: أول إرسال إعداد ناجح
يستحوذ على حساب المسؤول.

بعد الإعداد:

- يُغلق التسجيل العام. وينشئ المسؤولون المستخدمين ويديرونهم.
- يكون لكل حساب دور `administrator` أو `member`.
- تكون الكتب العادية مرئية لكل مستخدم سجّل الدخول.
- تكون الكتب المقيّدة مرئية للمسؤولين والمستخدمين المحددين صراحةً فقط.
- يملك كل مستخدم رف كتبه وتقدّمه وتعليقاته وجلساته النشطة.
- يستطيع المستخدمون تغيير كلمات مرورهم وإبطال جلساتهم.
- يستطيع المسؤولون إدارة المستخدمين والأدوار وكلمات المرور والجلسات ومنح الوصول إلى الكتب.
- تستخدم الجلسات ملف تعريف ارتباط HttpOnly وحماية CSRF وعمراً منزلقاً مدته 30 يوماً.

#### تسجيل الدخول الموحّد عبر OIDC وربط الحسابات

يمكن لوضع Server استخدام OpenID Connect (OIDC) Provider عام واحد، بما في ذلك
Authelia وKeycloak وAuthentik والخدمات المتوافقة. في **Administration → OIDC login**،
أدخل اسم Provider الظاهر للقرّاء، وعنوان URL للمُصدر، ومعرّف العميل، وسر العميل،
وURI لإعادة التوجيه المطابق تماماً، والنطاقات، ومطالبة اسم المستخدم. يستخدم EPUB Browser
الاكتشاف مع تدفق Authorization Code وS256 PKCE، ويتحقق من رمز ID الموقّع، ويحدد
الحساب الخارجي بواسطة `(issuer, sub)` فقط؛ أما مطالبتا البريد الإلكتروني واسم المستخدم
فتُستخدمان تلميحين للعرض/الإنشاء، وليستا مفاتيح هوية إطلاقاً.

سجّل callback المطابق تماماً لدى Provider، بما في ذلك المخطط والمضيف:

```text
https://reader.example.com/auth/oidc/callback
```

يستطيع المستخدمون الحاليون تسجيل الدخول محلياً وربط Provider من إعدادات الحساب.
وإلا يُطلب من الهوية الخارجية غير المعروفة مرة واحدة إدخال اسم مستخدم وكلمة مرور
محليين موجودين. ينشئ الإنشاء التلقائي الاختياري عضواً بلا كلمة مرور؛ ولا يستورد دور
مسؤول إطلاقاً. اسمح للمستخدمين الحاليين بالربط أولاً: تفعيل الإنشاء التلقائي مبكراً جداً
قد ينشئ **حسابات محلية مكررة**. ويظل تسجيل دخول **المسؤول المحلي** بكلمة المرور متاحاً
دائماً حتى عند تعطيل تسجيل دخول الأعضاء المحليين بكلمة المرور. حافظ على اختبار بيانات
الاسترداد هذه وحمايتها. لا يُنفّذ تسجيل الخروج من Provider، ولا تُحفظ رموز الوصول/التحديث
الخاصة به.

بالنسبة إلى Authelia، اضبط عميلاً سرياً في قسم OIDC Provider. يستخدم المقتطف التالي
قيمًا زائفة عمداً ويفترض أن مفاتيح وسياسات provider المطلوبة في Authelia مضبوطة مسبقاً.
احفظ تجزئة لسر عميل عشوائي قوي في Authelia، ثم أدخل السر الخام المقابل مرة واحدة
في EPUB Browser:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: 'epub-browser'
        client_name: 'EPUB Browser'
        client_secret: '<AUTHELIA_HASH_OF_A_RANDOM_SECRET>'
        public: false
        authorization_policy: 'two_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://reader.example.com/auth/oidc/callback'
        scopes: ['openid', 'profile', 'email']
        response_types: ['code']
        grant_types: ['authorization_code']
        token_endpoint_auth_method: 'client_secret_basic'
```

استخدم في EPUB Browser المُصدر `https://auth.example.com`، ومعرّف العميل
`epub-browser`، والنطاقات `openid profile email`، ومطالبة اسم المستخدم
`preferred_username`. ينفّذ الحفظ اكتشافاً مباشراً والتحقق من القدرات؛ وعند الفشل
يبقى الإعداد السابق نشطاً.

#### ضبط القراءة بالذكاء الاصطناعي وحوكمتها

يضبط المسؤولون القراءة بالذكاء الاصطناعي في **Administration**، مباشرةً بعد إدارة
المستخدمين وقبل إدارة الكتب. تخزّن الصفحة Base URL متوافقاً مع OpenAI ومفتاح API
والنموذج والمهلة وميزانية السياق والحد الأقصى للتزامن والحد الافتراضي اليومي لاستدعاءات
المزوّد في قاعدة SQLite الخاصة بـServer. يبدأ الذكاء الاصطناعي معطلاً للأعضاء؛ ويجب
على المسؤول منح الوصول لكل عضو، ويمكنه تعيين حد يومي فردي (`0` تعني بلا حد).

تُشارك طبقات تعلّم الفصول ومراجعات مستوى الكتاب لكل لغة مؤهلة، بينما تبقى محادثات
المتابعة خاصة بكل حساب. تُحفظ النتائج وحالة المهام والوسوم المخصصة وتصنيف قراءة الكتاب
والمتابعات الخاصة في SQLite. تبقى النتائج القديمة متاحة بعد تغيير إعداد النموذج حتى
يعيد المسؤول إنشاءها صراحةً.

عندما يطلب قارئ دليلاً بالذكاء الاصطناعي أو يطرح سؤالاً، يُرسل نص EPUB المحدد وسياق
المحادثة المضغوط إلى المزوّد الخارجي المضبوط. لا تفعّل الميزة إلا إذا كان مسموحاً للقرّاء
إرسال ذلك المحتوى إلى المزوّد. لا يُعاد مفتاح API إلى المتصفح ولا تكشفه واجهة API إطلاقاً؛
لذا احمِ مجلد حالة Server وفقاً لذلك.

للتشغيل الأول غير المراقَب، وفّر اسم مستخدم وملفاً لكلمة المرور:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --admin-username admin \
  --admin-password-file /run/secrets/epub-browser-admin-password \
  --no-browser
```

يجب ضبط أذونات ملف كلمة المرور على `0600`. يزيل EPUB Browser سطراً جديداً ختامياً
واحداً، ويخزّن تجزئة Argon2id، ولا يطبع السر إطلاقاً. يؤدي الإعداد غير المكتمل أو الملف
الفارغ أو غير القابل للقراءة إلى إيقاف التشغيل. وبعد اكتمال الإعداد، لا تقرأ عمليات
التشغيل اللاحقة سر التهيئة.

المكافئان البيئيان هما `EPUB_BROWSER_ADMIN_USERNAME` و
`EPUB_BROWSER_ADMIN_PASSWORD_FILE`. ويُستخدم `EPUB_BROWSER_ADMIN_PASSWORD`
كبديل بنص صريح فقط عندما لا يكون ملف كلمة مرور مضبوطاً. ويملك مسار ملف كلمة المرور
في CLI أولوية على مصادر كلمة المرور في البيئة.

#### تشغيل المتصفح والتسجيل

يحاول Server افتراضياً فتح متصفح نظام التشغيل الافتراضي بعد بدء مستمع HTTP. يمنع
`--no-browser` هذا التشغيل المحلي. لكنه **لا يعطّل واجهة الويب أو الوصول عبر المتصفح**؛
إذ يكبح استدعاء `webbrowser.open(...)` المحلي فقط. استخدمه مع Docker وsystemd وجلسات
SSH والأجهزة بلا واجهة رسومية والسكربتات.

افتراضياً (`--log-level error`)، يخرج CLI الأخطاء فقط حتى لا تقاطع الرسائل أو التحذيرات
الروتينية عروض التقدّم في الطرفية. يطبع الطرف التفاعلي عنوان URL المرتبط مرة واحدة؛
أما تشغيلات Docker والخدمات غير التفاعلية فلا تُخرج رسائل أخرى. استخدم
`--log-level warning` لتضمين التحذيرات، أو `--log-level info` للتسجيل التشغيلي والوصول
عبر HTTP، أو `--log-level debug` لأكبر قدر من التفاصيل. يبقى `--log` اسماً مستعاراً
للتوافق مع `--log-level info`.

تظهر عمليات الفحص الأولية والمراقبة في واجهة الويب بدلاً من `tqdm` في الطرفية. يُغلق
الملخص الناجح تلقائياً؛ وتبقى الإخفاقات ظاهرة حتى يغلقها المستخدم. ومع `--watch`، يبدأ إصلاح
مصدر أو استبداله فحصاً آخر من دون إجراء إعادة محاولة يدوي.

#### الحالة الدائمة والمؤقتة

يتطلب وضع Server الدائم `--server-dir`. ولتشغيل يُستخدم مرة واحدة، استخدم
`--ephemeral` بدلاً منه:

```bash
epub-browser server book.epub --ephemeral
```

تُحذف الحالة المؤقتة عند الإيقاف. ولأن قاعدة بياناتها جديدة في كل تشغيل، يتكرر الإعداد
أيضاً ما لم تُقدَّم بيانات اعتماد تهيئة غير مراقَبة.

التخطيط الدائم:

```text
<server-dir>/
├── .server.lock                 # reusable process-lock metadata
├── data/
│   ├── epub-browser.db          # authoritative accounts, books, grants, reading data
│   ├── migration-state.json     # restart-safe migration state
│   └── backups/                 # verified pre-migration database copies
└── cache/
    ├── catalog.json             # generated-cache status
    ├── public/                  # served application and converted books
    └── staging/                 # replaceable conversion work
```

`data/` وحدها هي المصدر المعتمد. يمكن حذف `cache/` وستُعاد بناؤها. حافظ على `data/`
عبر الترقيات واستبدال الحاوية. يتحكم قفل نظام التشغيل في الحصرية؛ وقد يبقى `.server.lock`
بعد الإيقاف العادي كبيانات وصفية للتشخيص.

احفظ `data/epub-browser.db` الدائمة على نظام ملفات محلي. لا تدعم أنظمة الملفات المشتركة
أو الشبكية تزامن WAL. تبقى النسخ الاحتياطية المتحقق منها ضمن `data/backups/` وتتضمن
كل بيانات WAL المثبتة.

#### LAN والوكيل العكسي

يرتبط Server افتراضياً بـ`127.0.0.1:8000`. لشبكة LAN موثوقة:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --port 8080 \
  --no-browser
```

لا تكشف خادم HTTP المدمج مباشرةً للإنترنت العام. أنهِ TLS عند وكيل عكسي، وطبّق ضوابط
الشبكة، وفعّل ملفات تعريف الارتباط الآمنة.

لتسجيل عناوين IP الحقيقية للعملاء في الجلسات النشطة وحدود معدل تسجيل الدخول خلف وكيل
عكسي، اضبط **شبكة المقبس المباشر** الخاصة به (وليس نطاقات العملاء العامة):

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --trusted-proxy-cidr 172.32.11.1/32 \
  --trusted-proxy-cidr 10.42.0.0/16 \
  --cookie-secure \
  --no-browser
```

كرّر `--trusted-proxy-cidr` مرة لكل عنوان وكيل مباشر أو شبكة. لا يمكن تقديم
`X-Forwarded-For` إلا للطلبات التي ينتمي نظيرها المباشر إلى أحد نطاقات CIDR هذه؛
وتسجّل بقية الأقران عنوانها المباشر فقط. تُعطّل معالجة العناوين المعاد توجيهها في Uvicorn،
لذلك لا يستطيع `Forwarded` و`FORWARDED_ALLOW_IPS` توسيع حدود الثقة هذه. استخدم
`--cookie-secure` فقط عندما يصل المتصفح إلى الخدمة عبر HTTPS.

### Docker

تشغّل الصورة وضع Server الدائم بالإعدادات الافتراضية التالية:

- `/app/Library` كمصدر
- `/app/EpubBrowserFiles` كحالة دائمة
- `--watch`
- `--no-browser`
- `--host 0.0.0.0 --port 80`
- `--book-id-storage embedded`
- `--kindle`

لأن الهوية المضمّنة قد تحدّث ملفات EPUB أو PDF، اربط المكتبة للقراءة والكتابة. اربط حالة
Server للقراءة والكتابة واحتفظ بها عبر استبدال الحاوية:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  dfface/epub-browser:latest
```

زر `http://127.0.0.1:8080/setup` قبل تغيير ربط المنفذ أو قواعد الوكيل.

#### Docker Compose

يتضمن المستودع ملف [docker-compose.yml](../../docker-compose.yml) للمستخدمين الذين
يفضلون Compose. من نسخة مستودع، أنشئ `Library/`، وضع كتب EPUB أو PDF فيها، ثم شغّل:

```bash
docker compose up -d --build
```

ينشر `127.0.0.1:8080` فقط، ويحتفظ بكتب EPUB/PDF المصدر في `./Library`، ويحفظ حالة
Server بصورة دائمة في `./EpubBrowserFiles`. يظهر `command` الكامل لـServer عمداً في
الملف، بحيث يمكن إضافة رايات خاصة بالنشر من دون استبدال إعداد صورة ضمني افتراضي.
أكمل الإعداد لمرة واحدة في `http://127.0.0.1:8080/setup`. وللوصول البعيد، احتفظ بربط
loopback هذا وضع أمامه وكيلاً عكسياً يدعم TLS والمصادقة.

للإعداد غير المراقَب:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  -e EPUB_BROWSER_ADMIN_USERNAME=admin \
  -e EPUB_BROWSER_ADMIN_PASSWORD_FILE=/run/secrets/epub-browser-admin-password \
  --mount type=bind,src=/path/to/admin-password,dst=/run/secrets/epub-browser-admin-password,readonly \
  dfface/epub-browser:latest
```

بعد أول تشغيل ناجح، يمكن إزالة ربط السر المستخدم مرة واحدة. لا تعمل مكتبة للقراءة فقط
إلا عندما يحتوي كل EPUB مسبقاً على معرّف مضمّن صالح مطابق. وتُحفظ ملفات sidecar
الحالية عند تضمين معرّفاتها.

اربط `/app/SyncData:ro` فقط أثناء استيراد JSON لرف كتب قديم:

```bash
-v /path/to/legacy-sync:/app/SyncData:ro
```

يحافظ منفذ loopback المنشور في الأمثلة على الحاوية خلف حدود المضيف. للوصول البعيد،
استخدم وكيلاً عكسياً لـTLS، واضبط CIDR الفعلي لشبكة الحاوية، وأضف `--cookie-secure`.

## المرجع والتشغيل

### مرجع الأوامر

#### `epub-browser ssg SOURCE [SOURCE ...]`

| الخيار | المعنى |
| --- | --- |
| `--output-dir DIR`, `-o DIR` | الوجهة المطلوبة للقطة الثابتة الذرية. |
| `--base-path PATH` | بادئة URL العامة؛ الافتراضية `/`. يجب أن تبدأ وتنتهي بـ`/`. |
| `--book-id-storage sidecar\|embedded` | حامل الهوية الثابتة لكل مصدر محدد؛ الافتراضي `sidecar`. |
| `--kindle` | إنشاء صفحات مبسطة بلا تبعيات لأجهزة Kindle e-Ink القديمة وإعادة توجيه متصفحات Kindle WebKit إليها؛ معطّل افتراضياً. |
| `--log` | اسم مستعار للتوافق مع `--log-level info`. |
| `--log-level debug\|info\|warning\|error` | مستوى تفصيل السجل التشغيلي؛ الافتراضي `error`، الذي لا يُخرج رسائل التحويل والتحذيرات الروتينية. |

#### `epub-browser server SOURCE [SOURCE ...]`

يجب تحديد واحد فقط من `--server-dir` و`--ephemeral`.

| الخيار | المعنى |
| --- | --- |
| `--server-dir DIR` | جذر البيانات الدائمة المعتمدة والذاكرة المؤقتة القابلة للاستبدال. |
| `--ephemeral` | استخدام حالة تُستخدم مرة واحدة؛ يتعارض مع `--server-dir`. |
| `--watch`, `-w` | مراقبة المصادر ومطابقة الإضافات والتحديثات والنقل والحذف. |
| `--host ADDRESS` | عنوان الربط؛ الافتراضي `127.0.0.1`. |
| `--port PORT`, `-p PORT` | منفذ الربط؛ الافتراضي `8000`. |
| `--no-browser` | عدم تشغيل المتصفح المحلي الافتراضي. تبقى واجهة الويب متاحة. |
| `--log` | اسم مستعار للتوافق مع `--log-level info`. |
| `--log-level debug\|info\|warning\|error` | مستوى تفصيل السجل التشغيلي؛ الافتراضي `error`. تُفعّل سجلات الوصول عبر HTTP عند `info` و`debug`. |
| `--legacy-sync-dir DIR` | قراءة JSON لرف الكتب القديم أثناء ترحيل بدء التشغيل. |
| `--book-id-storage sidecar\|embedded` | حامل الهوية الثابتة لكل مصدر محدد؛ الافتراضي `sidecar`. |
| `--admin-username NAME` | المسؤول الأول غير المراقَب؛ البديل `EPUB_BROWSER_ADMIN_USERNAME`. |
| `--admin-password-file FILE` | ملف السر الأول المفضل؛ البديل `EPUB_BROWSER_ADMIN_PASSWORD_FILE`، ثم `EPUB_BROWSER_ADMIN_PASSWORD` عند عدم تعيين ملف. |
| `--trusted-proxy-cidr CIDR` | يمكن تكراره؛ يحدد شبكة الوكيل المباشر الموثوقة لتحليل عنوان IP للعميل في `X-Forwarded-For` بأمان. |
| `--cookie-secure` | إرسال ملف تعريف ارتباط الجلسة عبر HTTPS المواجه للمتصفح فقط. |
| `--kindle` | تقديم صفحات مبسطة بلا تبعيات لأجهزة Kindle e-Ink القديمة وإعادة توجيه متصفحات Kindle WebKit إليها؛ معطّل افتراضياً. |

#### صيغة أوامر v1 القديمة

تدعم صيغة الأوامر القديمة طوال سلسلة الإصدارات الرئيسية v2:

| أمر v1 | مقابله في v2 |
| --- | --- |
| `epub-browser BOOKS` | `epub-browser server BOOKS --ephemeral` |
| `epub-browser BOOKS --output-dir STATE` | `epub-browser server BOOKS --server-dir STATE` |
| `epub-browser BOOKS --no-server --output-dir DIST` | `epub-browser ssg BOOKS --output-dir DIST` |
| `--sync-dir DIR` | `server --legacy-sync-dir DIR` |

يحتفظ `--keep-files` الخاص بالإصدار القديم فقط بمجلد Server مؤقت. أما مجلدات Server
الدائمة فهي دائمة بالفعل. مع `--log`، يطبع محوّل التوافق أمر v2 المكافئ؛ وإلا فلا يطبع شيئاً.

### بيانات القراءة وموضع الميزات

- اكتشاف متكرر لـEPUB/PDF ومكتبات Calibre، ووسوم البيانات الوصفية، والبحث، والبحث بـpinyin
- واجهات متجاوبة للمكتبة وتفاصيل الكتاب وقراءة الفصول
- التمرير وتقليب الصفحات والقراءة المستمرة وعرض المحتوى القابل للضبط والخطوط وCSS المخصص والسمات ووضع القراءة الخالي من المشتتات
- التظليلات والملاحظات وتصفح التعليقات ومجموعات رف الكتب المتداخلة والوسوم واستيراد/تصدير JSON
- دعم لغات الواجهة: الإنجليزية والصينية المبسطة والصينية التقليدية والكورية واليابانية
  والإسبانية والألمانية والفرنسية والروسية والإيطالية والبرتغالية البرازيلية والعربية
  والإندونيسية والهندية والفيتنامية والتايلاندية والملايوية
- سلوك ملائم لأجهزة القراءة الإلكترونية لمتصفحات Kindle/Silk؛ وقد تُخفّض الميزات الكثيفة الاعتماد على المتصفح

| البيانات | SSG | Server |
| --- | --- | --- |
| تقدّم القراءة | محلي في المتصفح | سجل المستخدم الذي سجّل الدخول في SQLite |
| التظليلات والملاحظات | محلية في المتصفح | سجلات المستخدم الذي سجّل الدخول في SQLite |
| التقييمات والمراجعات الخاصة وسجل جلسات القراءة | غير موجودة | سجلات المستخدم الذي سجّل الدخول في SQLite |
| رف الكتب | محلي في المتصفح؛ استيراد/تصدير | مستند سحابي ذو إصدارات للمستخدم الذي سجّل الدخول؛ حفظ تلقائي |
| الحسابات والجلسات | غير موجودة | SQLite ضمن `<server-dir>/data` |
| منح الوصول إلى الكتب | غير موجودة | SQLite ضمن `<server-dir>/data` |

لا يوفّر Server خياراً بين التخزين المحلي والسحابي: تُحفظ بيانات قراءة المستخدم الذي سجّل الدخول على Server دائماً.
لا يُنشئ SSG سجل جلسات القراءة الخاصة التفصيلي إطلاقاً. ولا يستقصي SSG واجهات Server API
إطلاقاً، ويستخدم دائماً التخزين المحلي لأصل المتصفح الحالي.

### الاكتفاء الذاتي وسلوك الشبكة

التطبيق مكتفٍ ذاتياً للقراءة: تُقدَّم JavaScript وCSS والخطوط والأيقونات وملفات manifest وموارد
EPUB المحوّلة المطلوبة محلياً. لا توجد تبعيات CDN أثناء التشغيل. لا يمنع حجب الوصول
الصادر إلى الإنترنت الإعداد أو تسجيل الدخول أو التصفح أو القراءة أو التعليقات أو التقدّم
أو استخدام رف الكتب أو الإدارة أو تحويل المصادر.

قد يرسل التذييل طلباً اختيارياً إلى GitHub Releases API لاكتشاف إصدار أحدث من
EPUB Browser. ولا يؤدي الفشل أو الحجب أو الاستخدام دون اتصال إلا إلى إخفاء تلميح التحديث.

ينشر SSG Service Worker ثابتاً. أما Server فيعطّل Service Worker على مستوى الأصل
ويتخلص منه عمداً حتى لا يتلقى حساب محتوى محمياً مخزّناً مؤقتاً لحساب آخر.

### واجهة Server API وWebHooks

يمكن لحسابات Server إنشاء رموز وصول شخصية محددة النطاق في إعدادات الحساب. يستخدم
العملاء الخارجيون `Authorization: Bearer <PAT>` مع واجهة `/api/v1/*` ذات الإصدارات؛
ولا تُستخدم ملفات تعريف ارتباط المتصفح للمصادقة على هذه المسارات. تغطي الواجهة الكتب المرئية ومحتوى
الفصول، ورف كتب مالك الرمز، والتقدّم، والتعليقات والمراجعات، إضافةً إلى بيانات مشتركة بين المستخدمين
للقراءة فقط لرموز PAT الإدارية ذات `admin:data:read`.

مستند OpenAPI 3.1 متاح في `/openapi.json`؛ ويمكن للمستخدمين المسجّلين تصفح المرجع
المحلي في `/api-docs`. على سبيل المثال:
`curl -H 'Authorization: Bearer …' https://reader.example/api/v1/books`. تعيد تفاصيل
الفصل HTML منقّى افتراضياً، ونصاً عادياً مع `?format=text`.

تعيد نقاط نهاية القوائم `items` و`next_cursor`. القيمة الافتراضية لـ`limit` هي 24 والحد
الأقصى 100. مرّر `next_cursor` كـ`cursor` مع عوامل التصفية نفسها لجلب الصفحة التالية.
يشير مؤشر null إلى الصفحة الأخيرة. على سبيل المثال، استخدم
`/api/v1/me/annotations?book_id=BOOK_ID&chapter_index=0&fields=id,text,note`
لاسترداد حقول تعليقات محددة من فصل EPUB أو صفحة PDF واحدة. تُدرج عوامل تصفية
الاستعلام والحقول المدعومة في مستند OpenAPI.

تستخدم المفردات تنسيق القائمة نفسه افتراضياً. يمكن للعملاء الذين يستخدمون استجابة
`words` الأقدم إرسال `page=1` أو `page_size` لاختيار تنسيق ترقيم الصفحات القديم.

يدير المسؤولون نقاط نهاية WebHook في Administration. تظهر الأسرار عند الإنشاء أو التدوير
فقط. وتكون عمليات التسليم موقّعة ودائمة ويُعاد تجربتها للاستجابات غير 2xx، وتحتوي أحداث
مراجعات الكتب على المعرّفات وطوابع وقت الإجراءات، لكنها لا تحتوي إطلاقاً على التقييم
أو نص المراجعة.

### سلامة البيانات والترحيل

قبل ترقية عمليات تثبيت Server الدائمة، انسخ احتياطياً كتب EPUB/PDF المصدر و
`<server-dir>/data`. واحتفظ بوحدة تخزين الحالة الدائمة نفسها أثناء استبدال الحاوية.

ترحيل بدء التشغيل تلقائي وآمن عند إعادة التشغيل. يتحقق من قواعد البيانات القديمة، وينشئ
نسخة احتياطية، ويرقّي نسخة، ويستورد بيانات رف الكتب/التقدّم/التعليقات القديمة المؤهلة
إلى حساب المسؤول الأول الذي لم يُنشأ بعد، ولا يتخلص إلا من الأصول العامة القديمة القابلة للاستبدال بعد
نقاط تفتيش ناجحة. لا تفحص الطلبات العادية مجلدات المزامنة القديمة إطلاقاً. تؤدي قواعد
البيانات التالفة وتجزئات كلمات المرور غير الصالحة وقواعد البيانات القديمة الغامضة والمعرّفات
المتعارضة إلى إيقاف العملية احتياطياً بدلاً من التخمين أو الكتابة فوقها.

تُحفظ `epub-browser.db` أو `annotations.db` التي رُحّلت في الجذر كنسخة استرداد حساسة
غير معتمدة؛ وتكون `data/epub-browser.db` هي المعتمدة ولا تستخدم طلبات Server ملف
الجذر المحفوظ. حافظ على خصوصية نسخة الاسترداد. لا تحذفها يدوياً إلا أثناء توقف Server،
وبعد التحقق من قاعدة البيانات المعتمدة والنسخة الاحتياطية المسجلة، وعند عدم الحاجة إلى
الرجوع إلى v1. لا يحذفها EPUB Browser تلقائياً إطلاقاً.

إذا وجدت `epub-browser.db` و`annotations.db` معاً في جذر قديم، يتوقف بدء التشغيل
ويتركهما بلا تغيير. راجع [الترحيل إلى v2](../migration-v2.md) للنسخ الاحتياطي والرجوع
وإعادة بناء الذاكرة المؤقتة والتعافي من التعارضات.

### استكشاف الأخطاء

#### بدأ الأمر لكن لم يُفتح متصفح

أزل `--no-browser` عند التشغيل على جهاز محلي رسومي، أو افتح عنوان URL المطبوع/المرتبط
يدوياً. في Docker وsystemd وSSH والجلسات غير التفاعلية، من المتوقع أن تفتح عنوان URL بنفسك.

#### يبدو CLI هادئاً

التشغيل الهادئ مقصود من دون `--log`، وخصوصاً في البيئات غير التفاعلية. أضف `--log`
للتفاصيل التشغيلية والوصول. يظهر تقدّم فحص Server في واجهة الويب.

#### لا يستطيع Docker كتابة معرّف ثابت

تستخدم الصورة الهوية المضمّنة افتراضياً. اربط `/app/Library` للقراءة والكتابة أو ضمّن مسبقاً
معرّفات صالحة متطابقة. استخدم أمراً مخصصاً مع `--book-id-storage sidecar` فقط إذا كان
حامل sidecar قابل للكتابة هو الخيار المفضل.

#### روابط مكسورة في موقع SSG منشأ تحت مسار فرعي

أعد إنشاءه باستخدام `--base-path` مُعايَر، مثل `/reader/`، واضبط المضيف الثابت لتقديم
المخرجات عند البادئة نفسها.

#### يرفض Server بدء التشغيل بعد ترقية

اقرأ أول خطأ ترحيل أو تحقق مسجّل، واحتفظ بالبيانات وملفات المصدر، وراجع
[docs/migration-v2.md](https://raw.githubusercontent.com/dfface/epub-browser/main/docs/migration-v2.md).

## التطوير والترخيص

### المساهمة

نرحب بالـIssues والـPull Requests في
[dfface/epub-browser](https://github.com/dfface/epub-browser). يتضمن البلاغ المفيد
الأمر الدقيق، والمتصفح/الجهاز، وخطوات إعادة الإنتاج، والسجلات ذات الصلة، وملف EPUB
أو PDF عندما يمكن مشاركته قانوناً.

#### عقد البنية للمشرفين

اقرأ [AGENTS.md](../../AGENTS.md) قبل تغيير معالجة المحتوى أو قوالب الصفحات أو
الذاكرات المؤقتة أو الأذونات أو الأصول أو سلوك النشر. يحدد حدود تنسيق EPUB/PDF،
وملكية SSG/Server، ومراجعات الذاكرة المؤقتة المستقلة، ومتطلبات i18n أثناء التشغيل،
وفحوصات الأمان، والتحقق المطلوب. تُعرّف مصطلحات المنتج المشتركة مثل *فصل القارئ*
و*نافذة القراءة* و*منطقة القراءة* و*ذاكرة المحتوى المؤقتة* في
[CONTEXT.md](../../CONTEXT.md).

باختصار: حافظ على واجهة قارئ واحدة، وأبقِ بيانات Server فقط خارج SSG، وافصل ذاكرات
EPUB وPDF المشتقة عن بيانات مستخدمي SQLite، ولا تضف تبعية CDN أثناء التشغيل إطلاقاً.
يجب اختبار أي تغيير يؤثر في مكوّن مشترك بالتنسيقين ووضعي النشر حيثما ينطبق ذلك.

#### التطوير من نسخة مستودع المصدر

ملفات المتصفح من الطرف الثالث مدخلات بناء منشأة وليست مصدر المشروع، لذلك يُستبعد
`epub_browser/assets/vendor/` من Git عمداً. جهّز الإصدارات المقفلة الدقيقة صراحةً قبل
التطوير أو البناء، ثم تحقق منها دون اتصال:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
python3 -m unittest tests.test_vendor_assets -v
python3 -m build
```

`fetch` هو الأمر الوحيد أعلاه الذي ينزّل أصول مورّدي المتصفح. يسجّل القفل حزم npm tarball
غير القابلة للتغيير وملخصات الملفات وقوائم السماح والتراخيص؛ ولا تنزّل `verify` أو
الاختبارات أو البناء من نسخة مجهزة أو القارئ المثبّت أصول المتصفح. قد يستمر أمر البناء
المعزول القياسي `python3 -m build` في الرجوع إلى فهرس حزم Python لمتطلبات البناء.
للبناء المعطل شبكياً بالكامل، جهّز شجرة المورّدين وثبّت `build` و`setuptools` و`wheel`
مسبقاً قبل قطع الاتصال، ثم شغّل `PIP_NO_INDEX=1 python3 -m build --no-isolation`.
تحتوي ملفات wheel وتوزيعات المصدر وصور Docker ومواقع SSG المنشأة على الملفات
المتحقق منها ولا تملك تبعية CDN أثناء التشغيل. راجع
[third_party/README.md](../../third_party/README.md) لسير عمل التحديث والإصدار
وصحة المستودع.
