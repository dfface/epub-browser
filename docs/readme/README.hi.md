EPUB Browser सिर्फ़ पुस्तक कनवर्टर नहीं है। यह एक पूरा पठन प्लेटफ़ॉर्म है जिसे आप
कहीं भी प्रकाशित या स्वयं होस्ट कर सकते हैं। EPUB और PDF में एक ही Library, पुस्तक
पृष्ठ, विषय-सूची, पठन मोड, थीम, प्रगति ट्रैकिंग और एनोटेशन वर्कफ़्लो साझा होते हैं।
PDF का हर पृष्ठ रीडर का अध्याय बनता है और उसी पठन अनुभव के भीतर PDF.js उसे
स्थानीय रूप से रेंडर करता है—न कोई अलग व्यूअर, न रनटाइम CDN।

## परियोजना का अवलोकन

### EPUB Browser क्यों

- **कहीं भी प्रकाशित करें, नियंत्रण अपने पास रखें।** एक कमांड से Pages,
  ऑब्जेक्ट स्टोरेज या Nginx के लिए पूरी स्थैतिक साइट बनाएँ, या खातों, पुस्तक
  अनुमतियों और OIDC वाला स्थायी Server चलाएँ। एप्लिकेशन एसेट, फ़ॉन्ट, PDF.js और
  रेंडरर स्थानीय रूप से परोसे जाते हैं, इसलिए पठन कभी CDN पर निर्भर नहीं होता।
- **EPUB और PDF, एक वास्तविक रीडर।** दोनों फ़ॉर्मैट Library, पुस्तक पृष्ठ, TOC,
  रिस्पॉन्सिव लेआउट, तीन पठन मोड, थीम, फ़ुलस्क्रीन और प्रगति साझा करते हैं। PDF
  का हर पृष्ठ अलग प्रीव्यूअर के बजाय पठन क्षेत्र के भीतर रहता है, जिसमें ज़ूम,
  टेक्स्ट-लेयर चयन और एनोटेशन उपलब्ध हैं।
- **पुस्तक और उसका अंश, दोनों खोजें।** Library खोज में मेटाडेटा, टैग और pinyin
  शामिल हैं, साथ में सॉर्टिंग और पेजिनेशन भी। EPUB के लिए Server-साइड सम्पूर्ण-पुस्तक
  खोज अध्याय के अनुसार समूहित पूरे परिणाम देती है और हाइलाइट किए अंश पर पहुँचाती है।
  स्थिर पुस्तक ID पढ़ना जारी रखने के स्थान, एनोटेशन और इतिहास को उसी पुस्तक से जोड़े रखती है।
- **सिर्फ़ स्क्रॉल न करें, समझें।** Server मोड में EPUB अध्याय गाइड, साक्ष्य से जुड़े
  स्पष्टीकरण, माइंड मैप और निजी Ask AI मूल पाठ के पास रहते हैं। हाइलाइट, नोट,
  Dictionary और Encyclopedia, EPUB और टेक्स्ट-लेयर वाली PDF दोनों में काम करते हैं;
  Server शब्दसूचियाँ हर शब्द का स्रोत और निपुणता की स्थिति दर्ज करती हैं।
- **पठन को सहेजने योग्य इतिहास में बदलें।** नेस्टेड शेल्फ़, रेटिंग, समीक्षाएँ,
  एनोटेशन एक्सपोर्ट, गतिविधि कैलेंडर, रुझान, पुस्तक-वार आँकड़े और पठन-समय रैंकिंग
  मिलकर एक जुड़ा हुआ रिकॉर्ड बनाते हैं। Server हर खाते का पठन डेटा निजी रखता है
  और उसे उपकरणों के बीच सिंक करता है।
- **सिर्फ़ व्यूअर नहीं, पठन सेवा चलाएँ।** Server मोड में व्यवस्थापक वेब अपलोड या
  निगरानी वाले फ़ोल्डर से पुस्तकें जोड़ें, कॉन्फ़िगरेबल LRU कैश इविक्शन से डिस्क उपयोग
  सीमित करें, सदस्य और AI अनुमतियाँ प्रबंधित करें, तथा OpenAPI, PAT और WebHooks से
  इंटीग्रेट करें। Kindle न्यूनतम पठन सीमित क्षमता वाले उपकरणों के लिए है; Server में
  घड़ी, कैलेंडर, एजेंडा, मेमो और Pomodoro टाइमर वाला निजी Kindle स्क्रीनसेवर डैशबोर्ड भी है।

### तकनीकी स्टैक

EPUB Browser जान-बूझकर छोटा, सर्वर-रेंडर्ड वेब स्टैक इस्तेमाल करता है। इंस्टॉल किए
एप्लिकेशन में कोई SPA फ्रेमवर्क नहीं है और Node.js रनटाइम की आवश्यकता नहीं है:

| परत | तकनीक | भूमिका |
| --- | --- | --- |
| फ्रंटएंड | सिमैंटिक HTML, CSS, ES मॉड्यूल और ब्राउज़र API वाला VanillaJS | SSG और Server के लिए एक साझा रिस्पॉन्सिव UI |
| CLI और Server | Python 3.9+, Starlette, Uvicorn | कनवर्ज़न कमांड, प्रमाणीकरण आवश्यक पृष्ठ, API और बैकग्राउंड कार्य |
| डेटा | SQLite और फिर से बनाए जा सकने वाले JSON कंटेंट कैश | उपयोगकर्ता स्थिति, व्युत्पन्न EPUB/PDF कंटेंट से अलग रहती है |
| पुस्तक फ़ॉर्मैट | lxml, pypdf, pypdfium2, PDF.js | एकीकृत स्ट्रिक्ट-फ़र्स्ट EPUB पार्सिंग/सैनिटाइज़ेशन, PDF मेटाडेटा/कवर, स्थानीय ब्राउज़र रेंडरिंग |
| ऑफ़लाइन और एसेट | Service Worker, हैश किए गए अपरिवर्तनीय एसेट, लॉक की गई वेंडर निर्भरताएँ | रनटाइम CDN के बिना स्व-निहित डिलीवरी |
| वितरण | PyPI, Docker, सामान्य स्थैतिक होस्टिंग | एक ही कोडबेस SSG या स्थायी Server के रूप में उपलब्ध |
| वैकल्पिक AI | OpenAI-संगत API, स्थानीय रूप से रेंडर होने वाले Markdown, KaTeX और Mermaid के साथ | केवल Server मोड में EPUB लर्निंग लेयर |

Node.js केवल मेंटेनर ब्राउज़र-साइड परीक्षणों के लिए उपयोग करते हैं; यह रीडर के
प्रोडक्शन रनटाइम का हिस्सा नहीं है।

### SSG या Server चुनें

एक ही स्रोत प्रोसेसिंग और पेज टेम्पलेट दो स्पष्ट डिप्लॉयमेंट मोड चलाते हैं। पुस्तक
के फ़ॉर्मैट के आधार पर नहीं, बल्कि पठन डेटा कहाँ रहना चाहिए, इस आधार पर चुनें:

| क्षमता | `ssg` | `server` |
| --- | --- | --- |
| EPUB और PDF | हाँ | हाँ |
| डिलीवरी | Pages, ऑब्जेक्ट स्टोरेज या Nginx के लिए ऐटॉमिक स्थैतिक HTML/एसेट | बदले जा सकने वाले कंटेंट कैश पर आधारित प्रमाणीकरण आवश्यक डायनामिक पृष्ठ |
| खाते और पहुँच नियंत्रण | नहीं | व्यवस्थापक/सदस्य खाते, प्रतिबंधित पुस्तक अनुमतियाँ, सत्र और CSRF सुरक्षा |
| OIDC सिंगल साइन-ऑन | शामिल नहीं | सामान्य Provider, मौजूदा खाता लिंकिंग और वैकल्पिक सदस्य प्रोविज़निंग |
| प्रगति, एनोटेशन, शेल्फ़ | वर्तमान ब्राउज़र में सहेजे जाते हैं | SQLite में साइन-इन किए प्रत्येक खाते के लिए सिंक होते हैं |
| रेटिंग, समीक्षाएँ, पठन सत्र | आउटपुट में शामिल नहीं होते | प्रत्येक खाते के निजी रिकॉर्ड और पठन अंतर्दृष्टियाँ |
| स्रोत अपडेट | `ssg` फिर चलाएँ | पुनः आरंभ करें, फिर स्कैन करें या `--watch` उपयोग करें |
| प्रशासन, टैग, OpenAPI, WebHooks | शामिल नहीं | शामिल |
| AI पठन और Ask AI | शामिल नहीं | कॉन्फ़िगर और स्पष्ट रूप से अनुमत होने पर EPUB के लिए उपलब्ध; PDF के लिए छिपा हुआ |
| रनटाइम डेटाबेस | नहीं | स्थायी मोड के लिए आवश्यक |
| सर्वोत्तम उपयोग | सार्वजनिक/स्थैतिक होस्टिंग, ऑफ़लाइन बंडल, सरल व्यक्तिगत प्रकाशन | निजी लाइब्रेरी, कई उपकरण या पाठक, ऑटोमेशन और प्रबंधित पहुँच |

जब परिणाम सामान्य स्थैतिक फ़ाइलें होनी चाहिए तब `ssg` उपयोग करें। पाठकों को खाते,
उपकरणों के बीच डेटा, पहुँच नियंत्रण या स्रोतों का स्वतः मिलान चाहिए तब `server` उपयोग करें।

### AI-नेटिव पठन (केवल Server)

EPUB पुस्तकों के लिए Server मोड पाठक को मूल पाठ से दूर किए बिना अध्याय गाइड,
साक्ष्य से जुड़े स्पष्टीकरण, माइंड मैप, चिंतन के प्रश्न और निजी Ask AI ड्रॉअर जोड़
सकता है। परिणाम पुस्तक अनुमतियों के अधीन रहते हैं; सदस्यों को स्पष्ट रूप से अधिकृत
करना आवश्यक है, और SSG में AI नियंत्रण, कार्य, खाता डेटा या प्रदाता कॉन्फ़िगरेशन
कुछ भी नहीं होता। PDF में AI पठन और Ask AI जान-बूझकर छिपाए जाते हैं।

पूरे इंटरैक्शन मॉडल के लिए [AI-नेटिव पठन गाइड](../ai-native-reading.md) और रेंडरिंग
व नेटवर्क-सुरक्षा सीमा के लिए [स्थानीय रिच-टेक्स्ट रेंडरर नोट्स](../third-party-ai-renderers.md) देखें।

### Kindle न्यूनतम मोड

पुराने e-Ink Kindle (और किसी भी सीमित ब्राउज़र) को निर्भरता-रहित न्यूनतम पठन
इंटरफ़ेस मिलता है। इसे `--kindle` से सक्षम करें:

- SSG: `epub-browser ssg --kindle -o output/ SOURCE...`
- Server: `epub-browser server --kindle --server-dir data SOURCE...`

हर EPUB पुस्तक (PDF पुस्तकें शामिल नहीं हैं) के लिए तीन अतिरिक्त पृष्ठ बनते हैं:

- न्यूनतम शेल्फ़ `/kindle-library.html`
- पुस्तक पृष्ठ `/book/<id>/kindle.html`
- अध्याय पृष्ठ `/book/<id>/kindle_chapter_N.html`

ये पृष्ठ e-Ink के अनुरूप हैं: न्यूनतम मार्कअप, केवल CSS थीम, ES5-संगत स्क्रिप्ट,
कोई Service Worker नहीं और कोई फ्रेमवर्क नहीं। आप बिना JavaScript के पढ़ सकते हैं;
थीम बदलना (Light / Sepia / Dark), फ़ॉन्ट आकार (A- / A+) और इंटरफ़ेस स्थानीयकरण
साधारण HTML के ऊपर हल्की इनलाइन स्क्रिप्ट से काम करते हैं।

हर पृष्ठ में थीम और फ़ॉन्ट नियंत्रण (हेडर में और अध्याय के फुटर में फिर से),
विषय-सूची नेविगेशन, पिछला/अगला अध्याय और सहेजी प्रगति से पढ़ना जारी रखने वाला
"Continue reading" लिंक होता है।

पठन प्रगति मोड के अनुसार अलग होती है:

- **SSG:** प्रगति वर्तमान ब्राउज़र की कुकीज़ में सहेजी जाती है—स्थानीय, बिना खाते के।
- **Server:** प्रगति और पठन हार्टबीट SQLite में साइन-इन किए खाते के अनुसार सिंक होते हैं।
  Kindle इंटरफ़ेस केवल पढ़ने और रिपोर्ट करने के लिए हैं: वे वर्तमान अध्याय दर्ज करते हैं
  और हार्टबीट रिपोर्ट करते हैं, केवल-पढ़ने वाली शेल्फ़ दिखाते हैं, और अंतर्दृष्टियाँ या
  कंटेंट प्रबंधन कभी नहीं दिखाते।

हर Kindle इंटरफ़ेस पर पहुँच नियंत्रण लागू होता है। प्रतिबंधित दृश्यता वाली पुस्तक
अनधिकृत उपयोगकर्ताओं की न्यूनतम शेल्फ़ में शामिल नहीं होती; पुस्तक और अध्याय पृष्ठ तथा
प्रगति API उन्हें 403 लौटाते हैं।

समर्थित ब्राउज़र (जिनके UA में `Kindle/`, `Arora/` आदि हैं) पूर्ण रीडर से न्यूनतम
पृष्ठों पर स्वतः रीडायरेक्ट होते हैं; ऊपर दिए URL सीधे भी काम करते हैं। इससे कम
क्षमता या सीमित JavaScript वाले उपकरणों के लिए न्यूनतम मोड सहज फ़ॉलबैक बनता है।

## शुरुआत करें

### इंस्टॉलेशन चुनें

EPUB Browser दो इंस्टॉलेशन मार्गों का समर्थन करता है। दोनों एक या अधिक `.epub`
या `.pdf` फ़ाइलें, नेस्टेड डायरेक्टरी या Calibre-शैली की लाइब्रेरी डायरेक्टरी स्वीकार करते हैं।

| इंस्टॉलेशन | उपयोग | होस्ट आवश्यकता |
| --- | --- | --- |
| PyPI | SSG या Server मोड | Python 3.9 या नया |
| Docker | स्थायी Server मोड | Docker Engine; इमेज में Python शामिल है |

#### PyPI (SSG या Server)

कमांड-लाइन एप्लिकेशन इंस्टॉल करें:

```bash
pip install epub-browser
```

मोड के अनुसार कमांड संदर्भ देखें:

```bash
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

#### Docker (Server)

प्रकाशित [`dfface/epub-browser`](https://hub.docker.com/r/dfface/epub-browser)
इमेज Server मोड चलाती है और होस्ट पर Python की आवश्यकता नहीं होती:

```bash
docker pull dfface/epub-browser:latest
```

वर्तमान रिलीज़ का मूल्यांकन करने के लिए `latest` उपयोग करें; दोहराए जा सकने वाले
प्रोडक्शन डिप्लॉयमेंट के लिए संख्यित रिलीज़ टैग पिन करें। आवश्यक पुस्तक और स्थिति
माउंट, Compose त्वरित शुरुआत, पहली बार का सेटअप और नेटवर्क मार्गदर्शन के लिए
[Docker](#docker) देखें।

### त्वरित शुरुआत

#### स्थैतिक साइट बनाएँ

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist
```

`dist/` को HTTP पर परोसें। ब्राउज़र स्टोरेज, मॉड्यूल, मैनिफ़ेस्ट और Service Workers को HTTP origin चाहिए, इसलिए बने पृष्ठों को सीधे `file://` से खोलना समर्थित नहीं है।

URL प्रीफ़िक्स के नीचे होस्ट की गई साइट के लिए सार्वजनिक पथ, फ़ाइलसिस्टम गंतव्य से अलग सेट करें:

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist \
  --base-path /my-repository/
```

`--base-path` बनी हुई URL बदलता है, फ़ाइलें कहाँ लिखी जाती हैं वह नहीं। `/my-repository/` के साथ लिंक, आइकन, मैनिफ़ेस्ट, पुस्तक मेटाडेटा और Service Worker प्रविष्टियाँ सभी उसी प्रीफ़िक्स का उपयोग करते हैं, जबकि फ़ाइलें सीधे `dist/` के भीतर रहती हैं।

#### स्थायी Server लाइब्रेरी चलाएँ

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/epub-browser-state \
  --watch
```

`http://127.0.0.1:8000/` खोलें। पहली बार खोलने पर EPUB Browser प्रारंभिक व्यवस्थापक बनाने का संकेत देता है। यह एक बार का सेटअप पूरा होने तक लाइब्रेरी न तो स्कैन की जाती है, न पाठकों को दिखाई जाती है।

यदि आपने Docker चुना है, तो ऊपर का Python कमांड छोड़ें और
[Docker Compose त्वरित शुरुआत](#docker-compose) पर जाएँ।

## फ़ॉर्मैट और पठन

### स्रोत और पुस्तक की स्थिर पहचान

हर पोज़िशनल `SOURCE` EPUB फ़ाइल, PDF फ़ाइल या डायरेक्टरी हो सकता है। डायरेक्टरी
में पुनरावर्ती रूप से खोजा जाता है। एक कमांड में कई स्रोत दिए जा सकते हैं:

```bash
epub-browser server book.epub /srv/library /srv/periodicals \
  --server-dir /srv/epub-browser \
  --watch
```

हर पुस्तक को स्थिर `book_id` मिलता है, जो बनी हुई URL और ब्राउज़र डेटा में `book_hash`
के रूप में भी दिखाई देता है। सामान्य CLI डिफ़ॉल्ट है:

```bash
--book-id-storage sidecar
```

Sidecar मोड स्रोत के पास `BOOK.epub.epub-browser.json` या `BOOK.pdf.epub-browser.json`
जैसी दिखाई देने वाली पहचान फ़ाइल लिखता है और स्रोत की बाइट्स अपरिवर्तित छोड़ता है।
Sidecar में स्थिर ID और सत्यापित SHA-256 स्रोत फ़िंगरप्रिंट होता है।

ID को EPUB OPF मेटाडेटा या PDF दस्तावेज़ सूचना डिक्शनरी में रखने के लिए पूरे
इनवोकेशन के लिए एम्बेडेड स्टोरेज चुनें:

```bash
--book-id-storage embedded
```

एम्बेडेड मोड कनवर्ज़न से पहले EPUB ZIP फिर बना सकता है या PDF मेटाडेटा अपडेट जोड़
सकता है। यदि PDF अपडेट नहीं हो सकती और उसका स्रोत अपरिवर्तित है, तो EPUB Browser
वही ID पास की sidecar में सहेजता है। इसमें हस्ताक्षरित, एन्क्रिप्ट की गई और केवल-पढ़ने
वाली PDF शामिल हैं। ID असंगत होने, सक्रिय स्रोतों में एक ID दोहराने, कैरियर अमान्य
होने या आवश्यक कैरियर लिखा न जा सकने पर EPUB Browser रुक जाता है।

स्टोरेज मोड माइग्रेट करते समय EPUB Browser मौजूदा ID को चुने हुए कैरियर में कॉपी
करता है और दूसरे मान्य कैरियर को बनाए रखता है। v2.0.4 की मौजूदा एम्बेडेड ID को EPUB
फिर लिखे बिना डिफ़ॉल्ट sidecar में कॉपी किया जाता है। मेटाडेटा अपडेट के बाद SSG और
Server दोनों PDF स्रोत की बाइट-दर-बाइट समान प्रति देते हैं।

### PDF: एक पृष्ठ, एक अध्याय

दोनों डिप्लॉयमेंट मोड PDF का समर्थन करते हैं। रीडर PDF के हर पृष्ठ को EPUB Browser
के सामान्य अध्याय की तरह मानता है, इसलिए मौजूदा Book पृष्ठ, अध्याय नेविगेशन, TOC,
पेजिनेशन, निरंतर पठन, प्रगति, पठन सत्र, एनोटेशन, Dictionary और Encyclopedia एक ही
साझा UI और डेटा मॉडल बनाए रखते हैं:

| PDF अवधारणा | SSG | Server |
| --- | --- | --- |
| पृष्ठ 1 URL | `chapter_0.html` | `/book/<book-id>/chapter_0.html` |
| पृष्ठ N URL | `chapter_{N-1}.html` | `/book/<book-id>/chapter_{N-1}.html` |
| पृष्ठ लेबल और TOC | स्थानीय रूप से बनाए जाते हैं; हर पृष्ठ सूचीबद्ध होता है | PDF मेटाडेटा कैश से रेंडर होते हैं; हर पृष्ठ सूचीबद्ध होता है |
| एम्बेडेड आउटलाइन | गंतव्य पृष्ठ की TOC प्रविष्टि पर मार्कर | वही मार्कर, पृष्ठ प्रविष्टियाँ हटाए या उनका क्रम बदले बिना |
| स्क्रॉलिंग और पेजिनेशन/पलटना | स्थैतिक अध्याय शेल और स्थानीय PDF.js | डायनामिक साझा अध्याय शेल और स्थानीय PDF.js |
| हाइलाइट, नोट, Dictionary, Encyclopedia | टेक्स्ट लेयर होने पर साझा ब्राउज़र-लोकल कॉम्पोनेंट | टेक्स्ट लेयर होने पर प्रमाणीकरण वाले साझा कॉम्पोनेंट |
| PDF की कच्ची बाइट्स | स्थैतिक पुस्तक आउटपुट में एक `document.pdf` | कैश किए गए दस्तावेज़ के लिए केवल Session से पहुँचा जा सकने वाला, Range-सक्षम रूट |

दिखाई देने वाले लेबल और PDF.js में पृष्ठ संख्या 1 से शुरू होती है; URL, स्थिति, API
और SQLite में अध्याय सूचकांक 0 से शुरू होते हैं। इसलिए PDF पृष्ठ 1 हमेशा
`chapter_0.html` होता है। मानकीकृत TOC हर पृष्ठ के लिए एक `Page N` प्रविष्टि रखता है;
एम्बेडेड PDF आउटलाइन शीर्षक गंतव्य प्रविष्टि से आउटलाइन मार्कर के रूप में जुड़ते हैं,
जिसमें एक पृष्ठ पर कई मार्कर भी शामिल हैं।

SSG एक `document.pdf` और हर पृष्ठ के लिए एक `chapter_<index>.html` शेल लिखता है।
SSG आउटपुट में Session स्क्रिप्ट, `/api/*` कॉल, सिंक हुआ एनोटेशन डेटा या Server
निर्भरताएँ नहीं होतीं। Server पूरे, बाइट-दर-बाइट समान स्रोत को
`book/<book-id>/pdf/document.pdf` में सहेजता है और उसे कभी विभाजित या फिर नहीं लिखता।
Server PDF मेटाडेटा से वही अध्याय शेल डायनामिक रूप से रेंडर करता है, और बदला स्रोत
PDF कैश को अमान्य कर उसे पूरी तरह ताज़ा करता है (दस्तावेज़, मेटाडेटा और व्युत्पन्न कवर),
पुराने और नए पृष्ठों को मिलाता नहीं है।

Server का कच्चा-दस्तावेज़ एंडपॉइंट केवल Session के लिए है:
`GET`/`HEAD /api/books/<book-id>/document`. यह प्रमाणीकरण, पुस्तक दृश्यता, PDF फ़ॉर्मैट
और स्रोत/कैश फ़िंगरप्रिंट जाँचता है, फिर `ETag`, `Accept-Ranges`, निजी कैशिंग,
`nosniff` और इनलाइन PDF डिस्पोज़िशन के साथ सीमित सिंगल-रेंज रिस्पॉन्स देता है। यह
कोई निरपेक्ष पथ उजागर नहीं करता, PAT प्रमाणीकरण के लिए उपलब्ध नहीं है और PAT/OpenAPI
इंटरफ़ेस में सूचीबद्ध नहीं है। SSG में केवल स्थानीय `document.pdf` होती है, कोई कच्चा-
दस्तावेज़ API नहीं।

उपयोग करने योग्य PDF.js टेक्स्ट लेयर वाली PDF, Highlight और Note के लिए मौजूदा चयन पॉपअप और
एनोटेशन कॉम्पोनेंट का यथावत पुनः उपयोग करती हैं, साथ ही Dictionary और Encyclopedia भी।
एनोटेशन स्टोरेज, स्वामित्व, एक्सपोर्ट, सूची और डीप लिंक साझा रहते हैं; PDF-विशिष्ट
एनोटेशन तालिका या सेटिंग UI नहीं है। स्कैन की गई या केवल छवियों वाली PDF पढ़ी जा सकती हैं,
लेकिन उपयोग करने योग्य टेक्स्ट लेयर न होने पर चयन-आधारित Highlight, Note, Dictionary,
Encyclopedia और दस्तावेज़ खोज स्पष्ट रूप से अनुपलब्ध होते हैं। कई पृष्ठों में फैले चयन को
फिर भी कॉपी किया जा सकता है, जबकि एनोटेशन और लुकअप क्रियाएँ स्थानीयकृत असमर्थित
संदेश दिखाती हैं; एक पृष्ठ के भीतर चयन काम करता रहता है।

PDF.js दूसरा व्यूअर शेल नहीं है। बिल्ड या प्रकाशन से पहले लॉक की गई थर्ड-पार्टी
एसेट तैयार और सत्यापित करें:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
```

इसके बाद एप्लिकेशन रनटाइम में स्थानीय हैश किए गए PDF.js मॉड्यूल और worker एसेट परोसता है;
उन्हें कभी CDN से नहीं लाता। इमेज लाइटबॉक्स लॉक की गई GLightbox निर्भरता उपयोग करते हैं;
Fancyapps/Fancybox रनटाइम या पुनर्वितरित निर्भरता नहीं है। लॉक की गई एसेट और रिलीज़
वर्कफ़्लो के लिए [third_party/README.md](../../third_party/README.md) देखें।

## डिप्लॉयमेंट

### SSG

SSG पड़ोसी स्टेजिंग डायरेक्टरी में पूरा स्नैपशॉट बनाता है, उसे सत्यापित करता है और फिर
गंतव्य बदलता है। कोई भी कनवर्ज़न विफल होने पर पिछला गंतव्य अपरिवर्तित रहता है। बने
आउटपुट में Server डेटाबेस, माइग्रेशन स्थिति, खाता पृष्ठ या रनटाइम कैश मेटाडेटा नहीं होता।

SSG व्यवहार जान-बूझकर स्थानीय और खाता-रहित है:

- पठन प्रगति और एनोटेशन वर्तमान origin पर ब्राउज़र स्टोरेज उपयोग करते हैं।
- बुकशेल्फ़ स्थानीय JSON Import और Export का समर्थन करती है; इसमें क्लाउड Sync क्रिया नहीं है।
- लॉगिन, खाता सेटिंग, Server API और उपयोगकर्ता-निर्भर नियंत्रण मौजूद नहीं हैं।
- स्टोरेज गंतव्य स्थानीय ब्राउज़र स्टोरेज पर निश्चित है और इसे सेटिंग के रूप में नहीं दिखाया जाता।
- स्थैतिक आउटपुट में ऑफ़लाइन-सक्षम एसेट के लिए आवश्यक Service Worker शामिल है।

सभी आवश्यक एप्लिकेशन JavaScript, CSS, फ़ॉन्ट और आइकन आउटपुट में शामिल हैं। एकमात्र
वैकल्पिक नेटवर्क अनुरोध के लिए [स्व-निहितता और नेटवर्क व्यवहार](#स्व-निहितता-और-नेटवर्क-व्यवहार) देखें।

### Server

#### प्रारंभिक सेटअप, खाते और अनुमतियाँ

नई स्थायी स्थिति डायरेक्टरी में सामान्य पृष्ठ `/setup` पर रीडायरेक्ट होते हैं। प्रारंभिक
व्यवस्थापक बनने तक API, इवेंट स्ट्रीम, बनी हुई एसेट और पुस्तकें सेटअप आवश्यक बताने वाला
रिस्पॉन्स देते हैं। पोर्ट उजागर करने से पहले loopback या किसी अन्य विश्वसनीय निजी मार्ग
से सेटअप पूरा करें: जो उपयोगकर्ता पहले सफलतापूर्वक सेटअप सबमिट करता है, वही व्यवस्थापक खाता प्राप्त करता है।

सेटअप के बाद:

- सार्वजनिक पंजीकरण बंद रहता है। व्यवस्थापक उपयोगकर्ता बनाते और प्रबंधित करते हैं।
- खातों की भूमिका `administrator` या `member` होती है।
- सामान्य पुस्तकें साइन-इन किए हर खाते को दिखाई देती हैं।
- प्रतिबंधित पुस्तकें केवल व्यवस्थापकों और स्पष्ट रूप से चुने उपयोगकर्ताओं को दिखाई देती हैं।
- हर उपयोगकर्ता की अपनी बुकशेल्फ़, प्रगति, एनोटेशन और सक्रिय सत्र होते हैं।
- उपयोगकर्ता अपना पासवर्ड बदल और अपने सत्र रद्द कर सकते हैं।
- व्यवस्थापक उपयोगकर्ता, भूमिकाएँ, पासवर्ड, सत्र और पुस्तक अनुमतियाँ प्रबंधित कर सकते हैं।
- सत्र HttpOnly कुकी, CSRF सुरक्षा और 30-दिन की स्लाइडिंग अवधि उपयोग करते हैं।

#### OIDC सिंगल साइन-ऑन और खाता लिंकिंग

Server मोड एक सामान्य OpenID Connect (OIDC) Provider उपयोग कर सकता है, जिसमें
Authelia, Keycloak, Authentik और संगत सेवाएँ शामिल हैं। **Administration → OIDC login**
में पाठकों को दिखने वाला Provider नाम, issuer URL, client ID, client secret, सटीक
redirect URI, scopes और username claim दर्ज करें। EPUB Browser discovery और S256
PKCE वाले Authorization Code फ़्लो का उपयोग करता है, हस्ताक्षरित ID token सत्यापित
करता है और बाहरी खाते की पहचान केवल `(issuer, sub)` से करता है; email और username
claim केवल प्रदर्शन/प्रोविज़निंग संकेत हैं, कभी पहचान की कुंजियाँ नहीं।

Provider पर यह सटीक callback पंजीकृत करें, scheme और host सहित:

```text
https://reader.example.com/auth/oidc/callback
```

मौजूदा उपयोगकर्ता स्थानीय रूप से साइन इन करके Account सेटिंग से Provider जोड़ सकते हैं।
अन्यथा अज्ञात बाहरी पहचान से एक बार मौजूदा स्थानीय उपयोगकर्ता नाम और पासवर्ड पूछा जाता है।
वैकल्पिक स्वतः प्रोविज़निंग बिना पासवर्ड वाला सदस्य बनाती है; यह कभी व्यवस्थापक भूमिका
इम्पोर्ट नहीं करती। मौजूदा उपयोगकर्ताओं को पहले बाइंड करने दें: स्वतः प्रोविज़निंग बहुत जल्दी
सक्षम करने से **डुप्लिकेट स्थानीय खाते** बन सकते हैं। स्थानीय सदस्य पासवर्ड लॉगिन अक्षम
होने पर भी **स्थानीय व्यवस्थापक** का पासवर्ड लॉगिन हमेशा उपलब्ध रहता है। उस रिकवरी
क्रेडेंशियल को जाँचा और सुरक्षित रखें। Provider logout नहीं किया जाता और Provider
access/refresh token सहेजे नहीं जाते।

Authelia के लिए उसके OIDC Provider सेक्शन में confidential client कॉन्फ़िगर करें। नीचे
का अंश जान-बूझकर नकली मान उपयोग करता है और मानता है कि Authelia की आवश्यक provider
कुंजियाँ और नीतियाँ पहले से कॉन्फ़िगर हैं। Authelia में मजबूत यादृच्छिक client secret का हैश सहेजें, फिर EPUB Browser में
उसी secret को बिना हैश किए एक बार दर्ज करें:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: 'epub-browser'
        client_name: 'EPUB Browser'
        client_secret: '<AUTHELIA_HASH_OF_A_RANDOM_SECRET>'
        public: false
        authorization_policy: 'two_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://reader.example.com/auth/oidc/callback'
        scopes: ['openid', 'profile', 'email']
        response_types: ['code']
        grant_types: ['authorization_code']
        token_endpoint_auth_method: 'client_secret_basic'
```

EPUB Browser में issuer `https://auth.example.com`, client ID `epub-browser`,
scopes `openid profile email` और username claim `preferred_username` उपयोग करें।
Save लाइव discovery और क्षमता सत्यापन करता है; विफलता पर पिछला कॉन्फ़िगरेशन सक्रिय रहता है।

#### AI पठन कॉन्फ़िगर और नियंत्रित करें

व्यवस्थापक **Administration** में AI पठन कॉन्फ़िगर करते हैं, जो उपयोगकर्ता प्रबंधन के
ठीक बाद और पुस्तक प्रबंधन से पहले आता है। पृष्ठ Server के SQLite डेटाबेस में OpenAI-
संगत Base URL, API key, model, timeout, context budget, concurrency cap और प्रदाता-
कॉल की डिफ़ॉल्ट दैनिक सीमा सहेजता है। सदस्यों के लिए AI शुरू में अक्षम रहता है; व्यवस्थापक
को प्रत्येक सदस्य को पहुँच देनी होती है और वह व्यक्तिगत दैनिक सीमा भी तय कर सकता है
(`0` का अर्थ असीमित है)।

अध्याय लर्निंग लेयर और पुस्तक-स्तरीय समीक्षाएँ प्रत्येक योग्य भाषा के लिए साझा होती हैं,
जबकि आगे की बातचीत हर खाते के लिए निजी रहती है। परिणाम, कार्य स्थिति, कस्टम टैग,
पुस्तक के पठन का वर्गीकरण और निजी फ़ॉलो-अप SQLite में सहेजे जाते हैं। मॉडल कॉन्फ़िगरेशन बदलने
के बाद पुराने परिणाम तब तक उपलब्ध रहते हैं जब तक व्यवस्थापक स्पष्ट रूप से उन्हें फिर
नहीं बनाता।

जब पाठक AI गाइड माँगता या प्रश्न पूछता है, तो चुना हुआ EPUB पाठ और संपीड़ित बातचीत
संदर्भ कॉन्फ़िगर किए बाहरी प्रदाता को भेजे जाते हैं। यह सुविधा तभी सक्षम करें जब पाठकों
को वह कंटेंट प्रदाता को भेजने की अनुमति हो। API key कभी ब्राउज़र को नहीं लौटाई या
किसी API से उजागर नहीं की जाती; Server स्थिति डायरेक्टरी की उसी अनुसार रक्षा करें।

बिना निगरानी पहली बार शुरू करने के लिए उपयोगकर्ता नाम और पासवर्ड फ़ाइल दें:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --admin-username admin \
  --admin-password-file /run/secrets/epub-browser-admin-password \
  --no-browser
```

पासवर्ड फ़ाइल की अनुमतियाँ `0600` होनी चाहिए। EPUB Browser अंत की एक न्यूलाइन हटाता है,
Argon2id हैश सहेजता है और secret कभी प्रिंट नहीं करता। अधूरा कॉन्फ़िगरेशन, खाली फ़ाइल
या अपठनीय फ़ाइल स्टार्टअप रोक देती है। सेटअप पूरा होने के बाद बाद के स्टार्टअप में
bootstrap secret नहीं पढ़ा जाता।

इनके Environment समकक्ष `EPUB_BROWSER_ADMIN_USERNAME` और
`EPUB_BROWSER_ADMIN_PASSWORD_FILE` हैं। `EPUB_BROWSER_ADMIN_PASSWORD` केवल तब
प्लेनटेक्स्ट फ़ॉलबैक है जब कोई पासवर्ड फ़ाइल कॉन्फ़िगर नहीं है। CLI पासवर्ड-फ़ाइल पथ को
Environment पासवर्ड स्रोतों पर प्राथमिकता मिलती है।

#### ब्राउज़र लॉन्च और लॉगिंग

डिफ़ॉल्ट रूप से HTTP लिसनर शुरू होने के बाद Server ऑपरेटिंग सिस्टम का डिफ़ॉल्ट ब्राउज़र
खोलने का प्रयास करता है। `--no-browser` उस स्थानीय लॉन्च को रोकता है। यह **वेब इंटरफ़ेस
या ब्राउज़र पहुँच अक्षम नहीं करता**; यह केवल स्थानीय `webbrowser.open(...)` कॉल रोकता है।
Docker, systemd, SSH सत्र, हेडलेस मशीन और स्क्रिप्ट के लिए इसका उपयोग करें।

डिफ़ॉल्ट (`--log-level error`) में CLI केवल त्रुटियाँ दिखाता है ताकि सामान्य संदेश या
चेतावनियाँ टर्मिनल प्रगति डिस्प्ले में बाधा न डालें। इंटरैक्टिव टर्मिनल बाइंड हुई URL एक
बार प्रिंट करता है; गैर-इंटरैक्टिव Docker और सेवा रन अन्यथा शांत रहते हैं। चेतावनियों के
लिए `--log-level warning`, संचालन और HTTP पहुँच लॉगिंग के लिए `--log-level info`, और
सबसे अधिक विवरण के लिए `--log-level debug` उपयोग करें। `--log`, पुराने संस्करणों के साथ संगतता के लिए `--log-level info` का alias बना रहता है।

प्रारंभिक और watch स्कैन टर्मिनल `tqdm` के बजाय वेब इंटरफ़ेस में दिखते हैं। सफल सारांश
स्वतः बंद हो जाता है; विफलताएँ खारिज किए जाने तक दिखती हैं। `--watch` के साथ स्रोत ठीक
या बदलने पर मैन्युअल पुनः प्रयास किए बिना दूसरा स्कैन शुरू होता है।

#### स्थायी और अस्थायी स्थिति

स्थायी Server मोड के लिए `--server-dir` आवश्यक है। एक बार उपयोग वाले रन के लिए इसके
बजाय `--ephemeral` उपयोग करें:

```bash
epub-browser server book.epub --ephemeral
```

अस्थायी स्थिति शटडाउन पर हटा दी जाती है। हर रन में उसका डेटाबेस नया होता है, इसलिए
बिना निगरानी bootstrap क्रेडेंशियल दिए सेटअप भी दोहराया जाता है।

स्थायी लेआउट:

```text
<server-dir>/
├── .server.lock                 # reusable process-lock metadata
├── data/
│   ├── epub-browser.db          # authoritative accounts, books, grants, reading data
│   ├── migration-state.json     # restart-safe migration state
│   └── backups/                 # verified pre-migration database copies
└── cache/
    ├── catalog.json             # generated-cache status
    ├── public/                  # served application and converted books
    └── staging/                 # replaceable conversion work
```

केवल `data/` प्रामाणिक है। `cache/` हटाया जा सकता है और फिर बन जाएगा। अपग्रेड और
कंटेनर बदलने के दौरान `data/` बनाए रखें। ऑपरेटिंग-सिस्टम लॉक अनन्यता नियंत्रित करता है;
सामान्य शटडाउन के बाद `.server.lock` डायग्नोस्टिक मेटाडेटा के रूप में रह सकता है।

स्थायी `data/epub-browser.db` को स्थानीय फ़ाइलसिस्टम पर रखें। WAL concurrency के लिए
साझा या नेटवर्क फ़ाइलसिस्टम समर्थित नहीं हैं। सत्यापित बैकअप `data/backups/` में रहते हैं
और उनमें सारा committed WAL डेटा शामिल होता है।

#### LAN और रिवर्स प्रॉक्सी

Server डिफ़ॉल्ट रूप से `127.0.0.1:8000` से बाइंड होता है। विश्वसनीय LAN के लिए:

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --port 8080 \
  --no-browser
```

बिल्ट-इन HTTP सर्वर को सीधे सार्वजनिक इंटरनेट पर उजागर न करें। रिवर्स प्रॉक्सी पर TLS
समाप्त करें, नेटवर्क नियंत्रण लागू करें और सुरक्षित कुकीज़ सक्षम करें।

रिवर्स प्रॉक्सी के पीछे सक्रिय सत्रों और लॉगिन की दर की सीमाओं में वास्तविक क्लाइंट IP दर्ज करने
के लिए उसका **डायरेक्ट सॉकेट नेटवर्क** कॉन्फ़िगर करें (सार्वजनिक क्लाइंट रेंज नहीं):

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/state \
  --watch \
  --host 0.0.0.0 \
  --trusted-proxy-cidr 172.32.11.1/32 \
  --trusted-proxy-cidr 10.42.0.0/16 \
  --cookie-secure \
  --no-browser
```

हर डायरेक्ट प्रॉक्सी पते या नेटवर्क के लिए `--trusted-proxy-cidr` एक बार दोहराएँ। केवल
वही अनुरोध `X-Forwarded-For` दे सकते हैं जिनका डायरेक्ट पीयर इनमें से किसी CIDR से है;
अन्य सभी पीयर केवल अपना डायरेक्ट पता दर्ज करते हैं। Uvicorn forwarded-address प्रोसेसिंग
अक्षम है, इसलिए `Forwarded` और `FORWARDED_ALLOW_IPS` इस ट्रस्ट सीमा को नहीं बढ़ा
सकते। `--cookie-secure` केवल तब उपयोग करें जब ब्राउज़र सेवा तक HTTPS से पहुँचता हो।

### Docker

इमेज इन डिफ़ॉल्ट के साथ स्थायी Server मोड चलाती है:

- स्रोत के रूप में `/app/Library`
- स्थायी स्थिति के रूप में `/app/EpubBrowserFiles`
- `--watch`
- `--no-browser`
- `--host 0.0.0.0 --port 80`
- `--book-id-storage embedded`

एम्बेडेड पहचान EPUB या PDF फ़ाइलें अपडेट कर सकती है, इसलिए लाइब्रेरी को रीड-राइट
माउंट करें। Server स्थिति रीड-राइट माउंट करें और कंटेनर बदलने पर भी उसे बनाए रखें:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  dfface/epub-browser:latest
```

पोर्ट बाइंडिंग या प्रॉक्सी नियम बदलने से पहले `http://127.0.0.1:8080/setup` पर जाएँ।

#### Docker Compose

Compose पसंद करने वालों के लिए रिपॉज़िटरी में [docker-compose.yml](../../docker-compose.yml)
शामिल है। चेकआउट से `Library/` बनाएँ, उसमें EPUB या PDF पुस्तकें रखें, फिर चलाएँ:

```bash
docker compose up -d --build
```

यह केवल `127.0.0.1:8080` प्रकाशित करता है, स्रोत EPUB/PDF पुस्तकों को `./Library` में
रखता है और Server स्थिति `./EpubBrowserFiles` में स्थायी करता है। पूरा Server `command`
जान-बूझकर फ़ाइल में दिखाया गया है, ताकि डिप्लॉयमेंट-विशिष्ट फ़्लैग अंतर्निहित इमेज डिफ़ॉल्ट
बदले बिना जोड़े जा सकें। `http://127.0.0.1:8080/setup` पर एक बार का सेटअप पूरा करें।
दूरस्थ पहुँच के लिए यह loopback बाइंडिंग रखें और उसके आगे प्रमाणीकरण सक्षम TLS रिवर्स प्रॉक्सी लगाएँ।

बिना निगरानी सेटअप के लिए:

```bash
docker run -d \
  --name epub-browser \
  -p 127.0.0.1:8080:80 \
  -v /path/to/books:/app/Library:rw \
  -v /path/to/epub-browser-state:/app/EpubBrowserFiles \
  -e EPUB_BROWSER_ADMIN_USERNAME=admin \
  -e EPUB_BROWSER_ADMIN_PASSWORD_FILE=/run/secrets/epub-browser-admin-password \
  --mount type=bind,src=/path/to/admin-password,dst=/run/secrets/epub-browser-admin-password,readonly \
  dfface/epub-browser:latest
```

पहली सफल शुरुआत के बाद एक बार वाला secret माउंट हटाया जा सकता है। केवल-पढ़ने वाली
लाइब्रेरी तभी काम करती है जब हर EPUB में पहले से मिलान करती मान्य एम्बेडेड ID हो।
ID एम्बेड किए जाने पर मौजूदा sidecar बनाए रखे जाते हैं।

पुरानी बुकशेल्फ़ JSON इम्पोर्ट करते समय ही `/app/SyncData:ro` माउंट करें:

```bash
-v /path/to/legacy-sync:/app/SyncData:ro
```

उदाहरणों का loopback प्रकाशित पोर्ट कंटेनर को होस्ट सीमा के पीछे रखता है। दूरस्थ पहुँच
के लिए TLS रिवर्स प्रॉक्सी उपयोग करें, उसका वास्तविक कंटेनर-नेटवर्क CIDR कॉन्फ़िगर करें
और `--cookie-secure` जोड़ें।

## संदर्भ और संचालन

### कमांड संदर्भ

#### `epub-browser ssg SOURCE [SOURCE ...]`

| विकल्प | अर्थ |
| --- | --- |
| `--output-dir DIR`, `-o DIR` | ऐटॉमिक स्थैतिक स्नैपशॉट के लिए आवश्यक गंतव्य। |
| `--base-path PATH` | सार्वजनिक URL प्रीफ़िक्स; डिफ़ॉल्ट `/`। इसकी शुरुआत और अंत `/` से होना चाहिए। |
| `--book-id-storage sidecar\|embedded` | हर चुने स्रोत के लिए स्थिर पहचान कैरियर; डिफ़ॉल्ट `sidecar`। |
| `--kindle` | पुराने e-Ink Kindle के लिए निर्भरता-रहित न्यूनतम पृष्ठ बनाएँ और Kindle WebKit ब्राउज़र को उन पर रीडायरेक्ट करें; डिफ़ॉल्ट में बंद। |
| `--log` | पुराने संस्करणों के साथ संगतता के लिए `--log-level info` का alias। |
| `--log-level debug\|info\|warning\|error` | संचालन लॉग की विस्तृतता; डिफ़ॉल्ट `error`, जिसमें सामान्य कनवर्ज़न आउटपुट और चेतावनियाँ प्रिंट नहीं होतीं। |

#### `epub-browser server SOURCE [SOURCE ...]`

`--server-dir` और `--ephemeral` में से ठीक एक आवश्यक है।

| विकल्प | अर्थ |
| --- | --- |
| `--server-dir DIR` | स्थायी प्रामाणिक डेटा और बदले जा सकने वाले कैश का मूल। |
| `--ephemeral` | एक बार उपयोग वाली स्थिति उपयोग करें; `--server-dir` के साथ परस्पर अनन्य। |
| `--watch`, `-w` | स्रोतों की निगरानी करें और जोड़, अपडेट, स्थानांतरण व हटाने का मिलान करें। |
| `--host ADDRESS` | बाइंड पता; डिफ़ॉल्ट `127.0.0.1`। |
| `--port PORT`, `-p PORT` | बाइंड पोर्ट; डिफ़ॉल्ट `8000`। |
| `--no-browser` | स्थानीय डिफ़ॉल्ट ब्राउज़र न खोलें। वेब UI उपलब्ध रहता है। |
| `--log` | पुराने संस्करणों के साथ संगतता के लिए `--log-level info` का alias। |
| `--log-level debug\|info\|warning\|error` | संचालन लॉग की विस्तृतता; डिफ़ॉल्ट `error`। HTTP पहुँच लॉग `info` और `debug` पर सक्षम होते हैं। |
| `--legacy-sync-dir DIR` | स्टार्टअप माइग्रेशन के दौरान पुरानी बुकशेल्फ़ JSON पढ़ें। |
| `--book-id-storage sidecar\|embedded` | हर चुने स्रोत के लिए स्थिर पहचान कैरियर; डिफ़ॉल्ट `sidecar`। |
| `--admin-username NAME` | प्रारंभिक बिना-निगरानी व्यवस्थापक; फ़ॉलबैक `EPUB_BROWSER_ADMIN_USERNAME`। |
| `--admin-password-file FILE` | पसंदीदा प्रारंभिक secret फ़ाइल; फ़ॉलबैक `EPUB_BROWSER_ADMIN_PASSWORD_FILE`, फिर फ़ाइल सेट न होने पर `EPUB_BROWSER_ADMIN_PASSWORD`। |
| `--trusted-proxy-cidr CIDR` | सुरक्षित `X-Forwarded-For` क्लाइंट-IP पार्सिंग के लिए डायरेक्ट प्रॉक्सी नेटवर्क की ट्रस्ट सीमा; इस विकल्प को दोहराया जा सकता है। |
| `--cookie-secure` | सत्र कुकी केवल ब्राउज़र-सामने वाले HTTPS पर भेजें। |
| `--kindle` | पुराने e-Ink Kindle के लिए निर्भरता-रहित न्यूनतम पृष्ठ परोसें और Kindle WebKit ब्राउज़र को उन पर रीडायरेक्ट करें; डिफ़ॉल्ट में बंद। |

#### पुरानी v1 सिंटैक्स

पूरे v2 मेजर लाइन में पुरानी सिंटैक्स समर्थित है:

| v1 कमांड | v2 मैपिंग |
| --- | --- |
| `epub-browser BOOKS` | `epub-browser server BOOKS --ephemeral` |
| `epub-browser BOOKS --output-dir STATE` | `epub-browser server BOOKS --server-dir STATE` |
| `epub-browser BOOKS --no-server --output-dir DIST` | `epub-browser ssg BOOKS --output-dir DIST` |
| `--sync-dir DIR` | `server --legacy-sync-dir DIR` |

केवल पुराने `--keep-files` से अस्थायी Server डायरेक्टरी बनी रहती है। स्थायी Server
डायरेक्टरी पहले से स्थायी होती हैं। `--log` के साथ संगतता एडाप्टर समकक्ष v2 कमांड
प्रिंट करता है; अन्यथा वह कुछ प्रिंट नहीं करता।

### पठन डेटा और सुविधाओं का स्थान

- पुनरावर्ती EPUB/PDF और Calibre-लाइब्रेरी खोज, मेटाडेटा टैग, खोज और pinyin खोज
- रिस्पॉन्सिव Library, पुस्तक विवरण और अध्याय-पठन इंटरफ़ेस
- स्क्रॉलिंग, पृष्ठ पलटना, निरंतर पठन, समायोज्य कंटेंट चौड़ाई, फ़ॉन्ट, कस्टम CSS, थीम और बिना भटकाव वाला पठन मोड
- हाइलाइट, नोट, एनोटेशन ब्राउज़िंग, नेस्टेड बुकशेल्फ़ समूह, टैग और JSON Import/Export
- इंटरफ़ेस भाषा समर्थन: अंग्रेज़ी, सरलीकृत चीनी, पारंपरिक चीनी, कोरियाई, जापानी,
  स्पेनी, जर्मन, फ़्रांसीसी, रूसी, इतालवी, ब्राज़ीली पुर्तगाली, अरबी, इंडोनेशियाई,
  हिन्दी, वियतनामी, थाई और मलय
- Kindle/Silk ब्राउज़र के लिए ई-रीडर-अनुकूल व्यवहार; ब्राउज़र-भारी सुविधाएँ सीमित हो सकती हैं

| डेटा | SSG | Server |
| --- | --- | --- |
| पठन प्रगति | ब्राउज़र-लोकल | साइन-इन किए उपयोगकर्ता का SQLite रिकॉर्ड |
| हाइलाइट और नोट | ब्राउज़र-लोकल | साइन-इन किए उपयोगकर्ता के SQLite रिकॉर्ड |
| निजी रेटिंग, समीक्षाएँ और पठन-सत्र इतिहास | मौजूद नहीं | साइन-इन किए उपयोगकर्ता के SQLite रिकॉर्ड |
| बुकशेल्फ़ | ब्राउज़र-लोकल; Import/Export | साइन-इन किए उपयोगकर्ता का वर्ज़न वाला क्लाउड दस्तावेज़; स्वतः सहेजना |
| खाते और सत्र | मौजूद नहीं | `<server-dir>/data` के भीतर SQLite |
| पुस्तक अनुमतियाँ | मौजूद नहीं | `<server-dir>/data` के भीतर SQLite |

Server स्थानीय/क्लाउड स्टोरेज चयनकर्ता नहीं देता: साइन-इन किए उपयोगकर्ता का पठन डेटा हमेशा Server पर
सहेजा जाता है। SSG विस्तृत निजी पठन-सत्र इतिहास कभी आउटपुट में शामिल नहीं करता। SSG कभी
Server API की जाँच नहीं करता और हमेशा वर्तमान ब्राउज़र origin का स्थानीय स्टोरेज उपयोग करता है।

### स्व-निहितता और नेटवर्क व्यवहार

एप्लिकेशन पठन के लिए स्व-निहित है: आवश्यक JavaScript, CSS, फ़ॉन्ट, आइकन, मैनिफ़ेस्ट
और कनवर्ट किए EPUB संसाधन स्थानीय रूप से परोसे जाते हैं। कोई CDN रनटाइम निर्भरता नहीं है।
आउटबाउंड इंटरनेट पहुँच रोकने से सेटअप, लॉगिन, ब्राउज़िंग, पठन, एनोटेशन, प्रगति,
बुकशेल्फ़ उपयोग, प्रशासन या स्रोत कनवर्ज़न नहीं रुकता।

फुटर नया EPUB Browser संस्करण खोजने के लिए GitHub Releases API को वैकल्पिक अनुरोध
भेज सकता है। विफलता, रोक या ऑफ़लाइन उपयोग से केवल वह अपडेट संकेत छिपता है।

SSG स्थैतिक Service Worker प्रकाशित करता है। Server जान-बूझकर origin-व्यापी Service
Worker को अक्षम और समाप्त करता है ताकि एक खाते को दूसरे खाते का कैश किया संरक्षित
कंटेंट न मिले।

### Server API और WebHooks

Server खाते Account सेटिंग में स्कोप वाले personal access token बना सकते हैं। बाहरी
क्लाइंट `Authorization: Bearer <PAT>` का उपयोग वर्ज़न वाले `/api/v1/*` API के साथ करते हैं;
ब्राउज़र कुकीज़ इन रूट पर प्रमाणीकरण नहीं करतीं। API में दृश्यमान पुस्तकें और अध्याय कंटेंट,
टोकन मालिक की बुकशेल्फ़, प्रगति, एनोटेशन और समीक्षाएँ शामिल हैं, साथ ही `admin:data:read`
वाले व्यवस्थापक PAT के लिए केवल-पढ़ने वाला क्रॉस-उपयोगकर्ता डेटा भी।

OpenAPI 3.1 दस्तावेज़ `/openapi.json` पर उपलब्ध है; साइन-इन उपयोगकर्ता `/api-docs` पर
स्थानीय संदर्भ देख सकते हैं। उदाहरण:
`curl -H 'Authorization: Bearer …' https://reader.example/api/v1/books`. अध्याय विवरण
डिफ़ॉल्ट रूप से सैनिटाइज़ किया HTML और `?format=text` के साथ सादा पाठ लौटाता है।

लिस्ट एंडपॉइंट `items` और `next_cursor` लौटाते हैं। डिफ़ॉल्ट `limit` 24 और अधिकतम 100 है।
अगला पृष्ठ लाने के लिए उन्हीं फ़िल्टर के साथ `next_cursor` को `cursor` के रूप में पास करें।
Null cursor अंतिम पृष्ठ दर्शाता है। उदाहरण के लिए, एक EPUB अध्याय या PDF पृष्ठ से चुने
एनोटेशन फ़ील्ड लाने हेतु `/api/v1/me/annotations?book_id=BOOK_ID&chapter_index=0&fields=id,text,note`
उपयोग करें। क्वेरी फ़िल्टर और समर्थित फ़ील्ड OpenAPI दस्तावेज़ में सूचीबद्ध हैं।

Vocabulary डिफ़ॉल्ट रूप से वही लिस्ट फ़ॉर्मैट उपयोग करती है। पुराने `words` रिस्पॉन्स वाले
क्लाइंट लेगसी पेजिनेशन फ़ॉर्मैट चुनने के लिए `page=1` या `page_size` भेज सकते हैं।

व्यवस्थापक Administration में WebHook एंडपॉइंट प्रबंधित करते हैं। Secret केवल बनाने या
rotate करने पर दिखाए जाते हैं। डिलीवरी हस्ताक्षरित और टिकाऊ होती हैं, गैर-2xx रिस्पॉन्स पर
उनका पुनः प्रयास होता है, और पुस्तक-समीक्षा इवेंट में ID और क्रिया टाइमस्टैम्प होते हैं,
लेकिन रेटिंग या समीक्षा पाठ कभी नहीं।

### डेटा सुरक्षा और माइग्रेशन

स्थायी Server इंस्टॉलेशन अपग्रेड करने से पहले स्रोत EPUB/PDF पुस्तकों और
`<server-dir>/data` का बैकअप लें। कंटेनर बदलने के दौरान वही स्थायी स्थिति वॉल्यूम रखें।

स्टार्टअप माइग्रेशन स्वतः और पुनः आरंभ-सुरक्षित है। यह पुराने डेटाबेस सत्यापित करता है,
बैकअप बनाता है, एक प्रति अपग्रेड करता है, अभी बनाए जाने वाले प्रारंभिक व्यवस्थापक खाते में योग्य पुरानी
बुकशेल्फ़/प्रगति/एनोटेशन डेटा इम्पोर्ट करता है और सफल चेकपॉइंट के बाद केवल बदले जा
सकने वाले पुराने सार्वजनिक आर्टिफ़ैक्ट समाप्त करता है। सामान्य अनुरोध कभी पुरानी sync
डायरेक्टरी स्कैन नहीं करते। दूषित डेटाबेस, अमान्य पासवर्ड हैश, अस्पष्ट पुराने डेटाबेस
और विरोधी ID के मामले में अनुमान लगाने या ओवरराइट करने के बजाय प्रक्रिया सुरक्षित रूप से रोक दी जाती है।

माइग्रेट की गई मूल `epub-browser.db` या `annotations.db` संवेदनशील, गैर-प्रामाणिक
रिकवरी कॉपी के रूप में रखी जाती है; `data/epub-browser.db` प्रामाणिक है और Server
अनुरोध सुरक्षित रखी गई मूल फ़ाइल का उपयोग नहीं करते। रिकवरी कॉपी निजी रखें। उसे केवल Server बंद
होने पर, प्रामाणिक डेटाबेस और दर्ज बैकअप सत्यापित करने के बाद, और केवल जब v1 रोलबैक
की आवश्यकता न हो, मैन्युअली हटाएँ। EPUB Browser उसे कभी स्वतः नहीं हटाता।

यदि पुराने मूल में `epub-browser.db` और `annotations.db` दोनों मौजूद हैं, तो स्टार्टअप
रुक जाता है और दोनों अछूते रहते हैं। बैकअप, रोलबैक, कैश पुनर्निर्माण और विरोध से उबरने के
लिए [v2 में माइग्रेट करना](../migration-v2.md) देखें।

### समस्या निवारण

#### कमांड शुरू हुआ, लेकिन ब्राउज़र नहीं खुला

ग्राफ़िकल स्थानीय मशीन पर चलाते समय `--no-browser` हटाएँ, या प्रिंट/बाइंड हुई URL
मैन्युअली खोलें। Docker, systemd, SSH और गैर-इंटरैक्टिव सत्रों में URL स्वयं खोलना अपेक्षित है।

#### CLI शांत दिखता है

`--log` के बिना शांत संचालन जान-बूझकर है, विशेषकर गैर-इंटरैक्टिव वातावरण में। संचालन
और पहुँच विवरण के लिए `--log` जोड़ें। Server स्कैन प्रगति वेब इंटरफ़ेस में दिखती है।

#### Docker स्थिर ID नहीं लिख सकता

इमेज डिफ़ॉल्ट में एम्बेडेड पहचान उपयोग करती है। `/app/Library` को रीड-राइट माउंट करें
या पहले से मिलान करती मान्य ID एम्बेड करें। केवल तभी `--book-id-storage sidecar`
वाले कस्टम कमांड उपयोग करें जब लिखने योग्य sidecar कैरियर बेहतर हो।

#### उप-पथ के नीचे बनी SSG साइट के लिंक टूटे हैं

मानकीकृत `--base-path`, जैसे `/reader/`, से साइट फिर बनाएँ और स्थैतिक होस्ट को
उसी प्रीफ़िक्स पर आउटपुट परोसने के लिए कॉन्फ़िगर करें।

#### अपग्रेड के बाद Server शुरू होने से इनकार करता है

लॉग की गई पहली माइग्रेशन या सत्यापन त्रुटि पढ़ें, डेटा और स्रोत फ़ाइलें सुरक्षित रखें और
[docs/migration-v2.md](https://raw.githubusercontent.com/dfface/epub-browser/main/docs/migration-v2.md)
देखें। त्रुटि से बचने के लिए प्रामाणिक `data/` डायरेक्टरी न हटाएँ।

## विकास और लाइसेंस

### योगदान

[dfface/epub-browser](https://github.com/dfface/epub-browser) पर Issues और Pull Requests
का स्वागत है। उपयोगी रिपोर्ट में सटीक कमांड, ब्राउज़र/उपकरण, समस्या दोहराने के चरण,
संबंधित लॉग और कानूनी रूप से साझा किए जा सकने पर EPUB या PDF शामिल होते हैं।

#### मेंटेनर आर्किटेक्चर अनुबंध

कंटेंट प्रोसेसिंग, पेज टेम्पलेट, कैश, अनुमतियाँ, एसेट या डिप्लॉयमेंट व्यवहार बदलने से पहले
[AGENTS.md](../../AGENTS.md) पढ़ें। इसमें EPUB/PDF फ़ॉर्मैट सीमा, SSG/Server स्वामित्व,
स्वतंत्र कैश संशोधन, रनटाइम i18n आवश्यकताएँ, सुरक्षा जाँच और आवश्यक सत्यापन बताए गए हैं।
*रीडर अध्याय*, *पठन विंडो*, *पठन क्षेत्र* और *कंटेंट कैश* जैसे साझा उत्पाद शब्द
[CONTEXT.md](../../CONTEXT.md) में परिभाषित हैं।

संक्षेप में: एक रीडर UI रखें, Server-only डेटा SSG से बाहर रखें, EPUB और PDF के
व्युत्पन्न कैश को SQLite उपयोगकर्ता डेटा से अलग रखें और कभी रनटाइम CDN निर्भरता न जोड़ें।
किसी साझा घटक को प्रभावित करने वाले बदलाव का, जहाँ लागू हो, दोनों फ़ॉर्मैट और दोनों
डिप्लॉयमेंट मोड के साथ परीक्षण करना आवश्यक है।

#### स्रोत चेकआउट से विकास

थर्ड-पार्टी ब्राउज़र फ़ाइलें बनाई गई बिल्ड इनपुट हैं, प्रोजेक्ट स्रोत नहीं, इसलिए
`epub_browser/assets/vendor/` जान-बूझकर Git में नहीं है। विकास या बिल्ड से पहले सटीक
लॉक किए संस्करण स्पष्ट रूप से तैयार करें, फिर उन्हें ऑफ़लाइन सत्यापित करें:

```bash
python3 tools/sync_vendor_assets.py fetch
python3 tools/sync_vendor_assets.py verify
python3 -m unittest tests.test_vendor_assets -v
python3 -m build
```

ऊपर के कमांड में केवल `fetch` ब्राउज़र वेंडर एसेट डाउनलोड करता है। लॉक में अपरिवर्तनीय
npm tarball, फ़ाइल डाइजेस्ट, allowlist और लाइसेंस दर्ज हैं; `verify`, परीक्षण, तैयार किए
चेकआउट से बिल्ड और इंस्टॉल किया रीडर ब्राउज़र एसेट डाउनलोड नहीं करते। मानक आइसोलेटेड
`python3 -m build` कमांड बिल्ड आवश्यकताओं के लिए Python पैकेज इंडेक्स देख सकता है।
पूरी तरह नेटवर्क-निष्क्रिय बिल्ड के लिए डिस्कनेक्ट करने से पहले vendor tree तैयार करें
और `build`, `setuptools`, `wheel` पहले से इंस्टॉल करें, फिर
`PIP_NO_INDEX=1 python3 -m build --no-isolation` चलाएँ। Wheel, स्रोत वितरण, Docker
इमेज और बनी SSG साइटों में सत्यापित फ़ाइलें होती हैं और कोई रनटाइम CDN निर्भरता नहीं
होती। अपडेट, रिलीज़ और रिपॉज़िटरी रखरखाव के वर्कफ़्लो के लिए
[third_party/README.md](../../third_party/README.md) देखें।
