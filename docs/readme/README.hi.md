EPUB Browser `.epub` और `.pdf` को दो स्पष्ट रूप से अलग जिम्मेदारियों वाले मोड में संभालता है:

| | `ssg` | `server` |
| --- | --- | --- |
| EPUB और PDF | हाँ | हाँ |
| परिनियोजन | स्थैतिक होस्टिंग, Pages, ऑब्जेक्ट स्टोरेज, Nginx | स्थायी निजी पठन सेवा |
| खाते | नहीं | स्थानीय खाते |
| प्रगति, टिप्पणियाँ, बुकशेल्फ़ | केवल इसी ब्राउज़र में | SQLite में प्रमाणित खाते का डेटा |
| स्रोत अपडेट | `ssg` फिर चलाएँ | सेवा पुनः आरंभ करें या `--watch` उपयोग करें |
| रनटाइम डेटाबेस | नहीं | आवश्यक |

PDF प्रथम-श्रेणी पुस्तक प्रारूप है: पृष्ठ 1 `chapter_0.html` बनता है, हर पृष्ठ विषय-सूची में आता है और स्थानीय PDF.js उसे उसी लाइब्रेरी, पुस्तक पृष्ठ, पठन इंटरफ़ेस, खोज और टिप्पणी प्रवाह में दिखाता है। PDF के लिए असमर्थित AI पठन जैसी सुविधाएँ स्पष्ट रूप से छिपी रहती हैं और पढ़ते समय किसी CDN की आवश्यकता नहीं होती।

सामान्य स्थैतिक फ़ाइलें प्रकाशित करने के लिए `ssg` चुनें। खाते, अलग-अलग उपकरणों पर डेटा, पुस्तक पहुँच नियंत्रण या स्रोतों की स्वतः निगरानी चाहिए तो `server` चुनें।

## AI-आधारित मूल पठन (केवल Server)

AI पठन पुस्तक के पास कोई सामान्य सारांश रखने के बजाय मूल पाठ पर साझा और समीक्षा योग्य सीखने की परत बनाता है। इसमें पढ़ने से पहले मार्गदर्शन, माँग पर अध्याय का अवलोकन, उद्धरणों से जुड़े स्पष्टीकरण, अनुच्छेद की भूमिका बताने वाली टिप्पणियाँ, शब्दावली सहायता, अंत में सरल व्याख्या और आगे सोचने के प्रश्न शामिल हैं।

परिणाम पृष्ठभूमि कार्यों से बनाए जाते हैं, SQLite में सहेजे जाते हैं और पुस्तक तक पहुँच वाले पाठकों के बीच साझा होते हैं। आगे की बातचीत हर खाते के लिए निजी रहती है। व्यवस्थापक को OpenAI-संगत प्रदाता कॉन्फ़िगर करना और प्रत्येक सदस्य को अनुमति देना आवश्यक है। चुना हुआ EPUB पाठ उस प्रदाता को भेजा जाता है, इसलिए यह सुविधा केवल पाठकों की सहमति से चालू करें। SSG आउटपुट में खाते, AI नियंत्रण, कार्य या प्रदाता कॉन्फ़िगरेशन कभी शामिल नहीं होते।

## आवश्यकताएँ और स्थापना

- Python 3.9 या नया
- एक या अधिक `.epub` या `.pdf` फ़ाइलें, पुस्तकों वाले नेस्टेड फ़ोल्डर या Calibre-शैली की लाइब्रेरी

PyPI स्थापना SSG और Server दोनों मोड उपलब्ध कराती है:

```bash
pip install epub-browser

# प्रत्येक मोड की पूरी सहायता
epub-browser --help
epub-browser ssg --help
epub-browser server --help
```

Docker में स्थायी Server चलाने के लिए प्रकाशित इमेज का उपयोग करें; होस्ट पर Python आवश्यक नहीं है:

```bash
docker pull dfface/epub-browser:latest
```

## त्वरित शुरुआत

### स्थैतिक साइट बनाएँ

```bash
epub-browser ssg /path/to/books \
  --output-dir /path/to/dist
```

`dist/` को HTTP पर परोसें; बनी हुई पृष्ठों को सीधे `file://` से न खोलें। उप-पथ पर परिनियोजन के लिए `--base-path /my-repository/` जोड़ें; यह विकल्प आउटपुट फ़ोल्डर नहीं, बनी हुई URL बदलता है।

### स्थायी Server लाइब्रेरी चलाएँ

```bash
epub-browser server /path/to/books \
  --server-dir /path/to/epub-browser-state \
  --watch
```

`http://127.0.0.1:8000/` खोलें। पहली बार प्रारंभिक व्यवस्थापक बनाएँ; सेटअप पूरा होने से पहले लाइब्रेरी स्कैन या प्रकाशित नहीं होती। `--no-browser` केवल सेवा को स्थानीय ब्राउज़र स्वतः खोलने से रोकता है।

## डेटा, खाते और पहुँच सीमाएँ

हर पुस्तक का स्थिर `book_id` होता है। डिफ़ॉल्ट रूप से `--book-id-storage sidecar` स्रोत की बाइट बदले बिना पहचान उसके साथ सहेजता है। EPUB के लिए `--book-id-storage embedded` पहचान को OPF मेटाडेटा में लिखता है; PDF के लिए यह हमेशा पास वाली sidecar फ़ाइल का उपयोग करता है।

Server मोड में `--server-dir`, SQLite, कैश और माइग्रेशन बैकअप का प्रामाणिक स्थान है। खाते, बुकशेल्फ़, पठन प्रगति, टिप्पणियाँ, AI परिणाम और कार्य भी वहीं सहेजे जाते हैं। व्यवस्थापक उपयोगकर्ता, भूमिकाएँ, सत्र और पुस्तक अनुमतियाँ प्रबंधित करते हैं; सदस्य केवल अधिकृत पुस्तकें और अपना निजी डेटा उपयोग करते हैं। इस फ़ोल्डर और उसके बैकअप की फ़ाइल अनुमतियों की रक्षा करें।

## Docker, रिवर्स प्रॉक्सी और पूरा दस्तावेज़

कंटेनर में पुस्तकों को केवल-पढ़ने योग्य और `--server-dir` को स्थायी वॉल्यूम के रूप में माउंट करें। प्रॉक्सी हेडर केवल विश्वसनीय प्रॉक्सी से स्वीकार करें और सार्वजनिक परिनियोजन में HTTPS उपयोग करें।

Docker Compose, सभी CLI विकल्प, माइग्रेशन, LAN, रिवर्स प्रॉक्सी और समस्या निवारण के लिए [पूरा अंग्रेज़ी README](../../README.md) या [पूरा सरलीकृत चीनी README](README.zh-CN.md) देखें। दोनों मोड का व्यवहार सभी भाषाओं में समान है।
