# EPUB Browser 项目级 I18N 与中英双语界面设计

日期：2026-08-18

状态：已完成聊天评审，等待书面规格评审

## 1. 背景

EPUB Browser 当前能从 EPUB 元数据读取书籍语言，但该语言只描述书籍内容。浏览器界面、动态提示、无障碍文案和 PWA 元数据仍以英文硬编码在 Python 生成模板和多个前端脚本中，项目没有统一的界面语言状态或翻译接口。

AI 帮读功能需要让界面语言和 AI 输出语言彼此独立，因此在引入 AI 子系统前，项目先建立统一的 I18N 基础设施，并完成现有浏览器界面的简体中文与英文迁移。后续 AI 界面直接复用这套能力；AI 输出语言则在 AI 子项目中单独设计。

## 2. 目标

本子项目交付以下结果：

1. 建立全站共享的 `window.EpubBrowserI18n` 运行时。
2. 首批支持 `en` 和 `zh-CN` 两种界面语言。
3. 完整迁移现有浏览器界面的静态文案、动态文案、错误提示、确认框、占位符、无障碍属性和 PWA 元数据。
4. 首次访问按浏览器语言选择界面语言，无法识别时回退英文；用户手动选择后持久化。
5. 语言只在书架首页 `library-breadcrumb` 中切换，选择对全站生效。
6. 保持 server 模式与 `--no-server` 静态模式行为一致。
7. 不改变书架、标注、阅读进度等现有持久化数据和同步协议中的稳定业务值。

## 3. 非目标

本子项目不包含：

- AI 模型接入、AI 输出语言或 AI 帮读界面。
- EPUB 正文、书名、作者、标签、章节标题、标注和其他用户内容的机器翻译。
- CLI 帮助、命令行运行提示和开发日志的本地化。
- README、发布说明及开发文档的完整双语迁移。
- `en` 与 `zh-CN` 之外的第三种语言。
- 基于 URL 路径或查询参数维护语言版本。

## 4. 已确认的产品决策

| 主题 | 决策 |
| --- | --- |
| 首次语言 | 按浏览器语言选择中文或英文，无法识别时回退英文 |
| 用户选择 | 持久化，后续页面和会话继续使用 |
| 语言入口 | 仅放在书架页 `library-breadcrumb` 的 `library-meta` 内 |
| 其他页面 | 不在顶部悬浮区、书籍页或阅读器设置中重复语言入口 |
| 切换行为 | 当前书架页即时切换，不刷新页面 |
| 支持语言 | 英文 `en`、简体中文 `zh-CN` |
| 浏览器迁移范围 | 所有可见界面和无障碍文案，包括 PWA 元数据 |
| CLI 与日志 | 保持英文 |
| 全局对象 | `window.EpubBrowserI18n` |
| 部署方式 | 同一套运行时同时支持 server 和纯静态部署 |

## 5. 总体架构

### 5.1 单一共享运行时

新增一个由所有页面加载的 I18N 前端资源。第一版只支持两种语言，运行时和两份词典放在同一个可内容寻址的静态资源中，避免额外网络请求、异步词典竞态和静态部署路径差异。

运行时暴露以下稳定接口：

```text
window.EpubBrowserI18n.init()
window.EpubBrowserI18n.t(key, params)
window.EpubBrowserI18n.getLocale()
window.EpubBrowserI18n.setLocale(locale)
window.EpubBrowserI18n.translateDocument(root?)
window.EpubBrowserI18n.formatDate(value, options?)
window.EpubBrowserI18n.formatNumber(value, options?)
window.EpubBrowserI18n.onLocaleChange(listener)
```

`init()` 可重复调用且只完成一次初始化。`onLocaleChange()` 返回取消订阅函数。`t()` 支持命名参数插值，并在参数包含 `count` 时按当前语言的复数规则选择文案。所有参数按纯文本处理，翻译字符串和插值参数都不能成为可信 HTML。

### 5.2 词典结构

词典以功能命名空间组织，避免同一英文单词在不同上下文中共享含义不清的键：

- `common.*`
- `library.*`
- `book.*`
- `reader.*`
- `bookshelf.*`
- `annotations.*`
- `settings.*`
- `errors.*`
- `pwa.*`

英文词典是完整性基准，中文词典必须与英文键集合一致。测试在构建阶段检查缺失键、多余键和空翻译。

### 5.3 语言解析与持久化

语言解析顺序如下：

1. 已持久化的有效用户选择。
2. `navigator.languages` 或 `navigator.language`。
3. 英文 `en`。

`zh`、`zh-CN`、`zh-SG` 等简体中文区域映射为 `zh-CN`；当前不支持的语言映射为 `en`。无效或损坏的存储值被忽略。

用户选择优先存入 `localStorage`，并同步到现有 `window.epubBrowserCache`。在禁止访问本地存储或 Kindle 降级环境中，使用 Cookie 和当前页面内存状态作为后备。语言状态不写入 SQLite，也不与用户名绑定。

### 5.4 页面语言与书籍语言分离

`<html lang>` 始终表示当前界面语言。书籍内容语言继续来自 EPUB 元数据，并标注在书籍描述、章节正文等内容容器上。两者不能互相覆盖：

```html
<html lang="zh-CN">
  <article id="eb-content" lang="en">...</article>
</html>
```

这样屏幕阅读器、断词、字体选择和浏览器语言工具能分别正确理解界面与正文。

## 6. 模板与前端组件迁移

### 6.1 Python 生成模板

Python 模板中的静态文案保留可读的英文回退文本，并添加语义明确的翻译属性：

- `data-i18n`：元素文本。
- `data-i18n-placeholder`：输入占位符。
- `data-i18n-title`：`title` 属性。
- `data-i18n-aria-label`：无障碍名称。
- `data-i18n-content`：允许本地化的元数据内容。

运行时只处理明确标记的属性，不扫描和猜测普通英文文本，因此不会误改书名、标签、章节标题或正文。

### 6.2 动态 JavaScript 文案

由 JavaScript 创建的通知、弹窗、按钮、加载状态和空状态必须在创建时调用 `EpubBrowserI18n.t()`。已打开且需要随语言变化更新的组件订阅 `localechange`，或在语言切换后由 `translateDocument(componentRoot)` 更新静态标记并重新渲染动态文案。

需要迁移的现有模块包括：

- `library.js`
- `bookshelf.js`
- `book.js`
- `chapter.js`
- `reading-progress.js`
- `annotation.js`
- `annotation-hub.js`
- `version-check.js`
- 与上述界面直接相关的生成模板和辅助脚本

业务判断不得继续依赖本地化后的 `textContent`。例如 `All`、`NoTag` 等筛选值继续使用稳定的 `data-*` 标识，显示文字才使用翻译。

### 6.3 语言选择器

语言选择器位于书架页 `library-breadcrumb` 的 `library-meta` 内，与 Annotations 和 Login 属于同一组操作。控件使用地球图标和原生 `<select>`，选项显示“中文”和“English”。

原生选择器保留键盘、触屏和屏幕阅读器能力。控件本身具有本地化的可访问名称。窄屏时沿用 `library-meta` 的换行策略，不创建新的悬浮按钮，也不占用阅读器内容空间。

切换后的流程为：

```text
用户选择语言
  → 校验并持久化 locale
  → 更新 html.lang
  → 翻译当前文档
  → 更新标题、描述与 manifest 链接
  → 发出 localechange
  → 已打开的动态组件刷新文案
```

书籍页和章节页在加载时应用已保存的语言，但不提供第二个切换入口。

## 7. PWA 与页面元数据

项目提供英文和简体中文两份 Web App Manifest。I18N 运行时在 `<head>` 中同步完成语言解析，并在浏览器处理 manifest 前插入当前语言的 `<link rel="manifest">`；`<noscript>` 提供英文 manifest 回退。产品名 `EPUB Browser` 不翻译，应用描述、快捷方式等可读元数据分别本地化。

页面 `<title>`、description、Apple Web App 可读元数据也由当前语言更新。若 JavaScript 不可用，英文页面和英文 manifest 仍然完整可用。

Service Worker 和静态资源发布流程必须包含 I18N 运行时与两份 manifest。内容寻址规则继续用于不可变脚本；manifest 使用可稳定访问且不被长期错误缓存的路径。

## 8. 日期、数字与复数

日期和数字优先使用 `Intl.DateTimeFormat`、`Intl.NumberFormat` 与 `Intl.PluralRules`。调用方传入原始值，不手动拼接英文单位或标点。

在缺少相应 `Intl` 能力的旧浏览器中：

- 数字退回无分组的十进制字符串。
- 日期退回稳定的数字年月日格式。
- 复数退回英文 `one`/`other` 与中文单一形式。

降级不会阻止页面功能。

## 9. API 错误与状态本地化

前端不得把可预期的服务端英文 `message` 直接作为主要用户提示。本次迁移为所有会向浏览器展示错误的既有 API 响应增加稳定 `code`，同时保留 `message` 以兼容旧客户端。前端按 `code` 映射到 `errors.*` 翻译键；未知错误显示本地化的通用提示，并将原始细节写入开发日志。

网络失败、JSON 解析失败和功能不可用等纯客户端错误由前端直接映射到稳定翻译键。用户输入、书名和用户名作为纯文本参数插值。

## 10. 故障处理与降级

- 不支持的 locale 回退 `en`。
- 当前语言缺键时回退英文值。
- 英文也缺键时显示键名，并在开发控制台记录警告。
- 存储读写异常不阻止初始化。
- 单个 DOM 节点翻译失败不终止其余节点翻译。
- I18N 脚本整体不可用时，模板中的英文回退文案继续工作。
- 动态组件不允许因为订阅回调失败而阻断其他语言变化监听器。

## 11. 数据兼容性

本项目只改变显示层，不修改以下稳定数据：

- 书籍哈希与章节索引。
- 书架 JSON 结构、分组数据和同步版本。
- `All`、`NoTag` 等内部筛选标识。
- 标注记录、颜色值和存储位置。
- 阅读进度键与用户名隔离规则。
- 主题、阅读模式和现有设置值。
- 现有 API 路径与成功响应结构。

已有浏览器数据无需迁移。新增的 locale 值独立保存。

## 12. 测试策略

### 12.1 I18N 运行时单元测试

覆盖：

- 浏览器语言解析与区域映射。
- 持久化选择优先级。
- 无效值和存储异常降级。
- 翻译键查找、英文回退和缺键行为。
- 参数插值及纯文本安全边界。
- 复数、日期和数字格式化。
- `localechange` 订阅与取消订阅。
- 两份词典键集合完全一致。

### 12.2 生成页面测试

验证书架、书籍和章节页面：

- 加载内容寻址的 I18N 资源。
- 书架 breadcrumb 包含唯一语言选择器。
- 书籍页和章节页没有重复语言入口。
- `<html lang>` 与正文内容 `lang` 能独立表达。
- 标题、元数据、placeholder、title 和 aria-label 均有翻译绑定。
- 英文回退内容在脚本不可用时仍可理解。

### 12.3 组件与回归测试

在中英文下覆盖书架、搜索、分组、登录、阅读进度、章节导航、阅读模式、设置、标注、标注中心、安装提示和版本提示。重点验证：

- 语言切换不刷新页面。
- 已打开弹窗同步更新。
- 业务逻辑不依赖翻译后的显示文本。
- server 与 `--no-server` 使用相同语言行为。
- Kindle 与禁用存储场景可降级。
- 原有书架、标注、连续阅读和进度同步测试继续通过。

### 12.4 防回归检查

对主要前端模块增加面向 UI 字符串的硬编码检查。检查允许书籍内容、测试夹具、日志和非用户可见常量，但新出现的按钮、通知、确认框、占位符和无障碍英文必须进入词典。该检查用于阻止后续 AI 和普通功能绕过统一翻译层。

## 13. 验收标准

本子项目在同时满足以下条件时完成：

1. 首次访问按浏览器语言选择中文或英文，并能正确回退英文。
2. 书架 breadcrumb 中可以即时切换语言，刷新和跨页面后选择仍然保留。
3. 所有现有浏览器 UI 在 `en` 与 `zh-CN` 下完整可用，没有混杂的硬编码英文用户文案。
4. 书籍及用户内容保持原文，界面语言不会改变 EPUB 内容语言。
5. 动态弹窗、通知、确认框和无障碍文案全部本地化。
6. 中英文 PWA 元数据按当前语言生效。
7. server 与静态部署均通过测试。
8. 现有持久化数据和同步协议保持兼容。
9. I18N 失败或旧浏览器能力不足时，核心阅读功能仍可使用。

## 14. 后续子项目接口

AI 服务端基础和自适应 AI 帮读体验必须依赖本规格提供的界面 locale，不得建立第二套 UI 语言状态。AI 输出语言是独立设置，可在后续设计中提供“跟随界面、跟随书籍、中文、English”等选项；它不能反向修改 `EpubBrowserI18n` 的界面语言。
