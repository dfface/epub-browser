# 标注中心设计

**日期：** 2026-08-18
**状态：** 已实现

## 目标

让读者能回顾整座书库中已标注的书，并在单本书内按原书阅读顺序查看所有标注。读者可从任一标注直接回到准确的原文位置。

本功能必须同时支持两种产品模式：

- **Build 模式**（`--no-server`）：在静态书库与书籍页中提供完整的标注面板，读取该浏览器中的本地 IndexedDB 标注。
- **Server 模式**：使用用户当前选择的标注存储；云端存储复用现有 API 和用户名隔离，本地存储继续使用 IndexedDB。

## 已选方案与边界

采用类似 Bookshelf 的全屏标注弹窗，而不是独立页面、书架标签或书库筛选器。

弹窗保留从跨书回顾到原文跳转的完整路径，同时不把读者带离书库或当前书籍目录；将来的搜索与筛选仍可在该面板内扩展。

首版包含：

- 有标注书籍的聚合首页；
- 单书、按章节和书中顺序的标注回顾；
- 从标注回到原文并定位高亮；
- Build 与 Server 的一致入口和可用性；
- 空、加载失败、缺少目录或无法精确定位的降级状态。

首版不包含：搜索、颜色筛选、仅看笔记筛选、批量操作、在标注中心编辑或删除标注。编辑和删除继续留在阅读页的标注交互中。

## 面板与导航

书库与书籍目录都加载同一份 `annotation-hub.js` / `annotation-hub.css`，按入口打开一个惰性创建的全屏模态框：

1. **跨书总览**：书库顶部信息区的“标注”按钮打开。
   - 书库页在顶部信息区增加“标注”入口。
   - 只显示有标注的书，按该书最新标注时间倒序排列。
   - 每张书籍卡显示封面、书名、作者、标注数量和最近标注时间。
   - 点击书籍在同一个面板内进入该书视图。

2. **本书标注**：每本书的目录页提供“标注”按钮，直接打开此状态。
   - 首屏显示书名与总标注数；顶部“所有有标注的书”返回跨书总览。
   - 标注按 `chapter_index` 升序分组，组内按创建时间升序，保持阅读时的原书节奏。
   - 每个标注卡显示原文摘录、笔记（只有非空时显示）、高亮颜色、章节标题与创建时间。
   - 点击整个标注卡返回原文。

总览没有标注时，说明如何在阅读页选择文本创建标注。关闭按钮、点击遮罩和 Escape 都会关闭面板并把焦点与页面滚动位置还给原入口。

## 数据与组件

### 共享标注读取接口

现有 `annotation.js` 将 IndexedDB、后端存储和存储选择逻辑封装在阅读器交互模块内。标注中心不能直接初始化该模块：它会尝试注册选区高亮和创建阅读器设置界面。

将“读取当前所选存储中的全部标注、按书读取标注、探测后端可用性”提取为不依赖阅读器 DOM 的共享数据接口。阅读器现有逻辑和新的标注中心都通过该接口读取数据；创建、编辑和删除的现有接口及行为保持不变。

### 标注中心前端

新增可嵌入的标注中心脚本和样式：

- 读取当前标注存储、`/book-metadata.json` 和单书 `/book/<hash>/toc.json`；
- 将标注按 `book_hash` 聚合，计算数量和该书最新时间；
- 将单书标注按章节分组，并把章节序号映射为目录标题；
- 用安全的文本节点或 HTML 转义渲染用户原文与笔记；
- 管理全屏面板的焦点圈定、Escape 关闭、触发按钮焦点恢复和背景滚动锁定。

目录中没有匹配项时，使用“第 N 章”作为章节标题。书籍元数据缺失时显示书籍标识和通用书籍图标，不让一条坏数据阻断整个列表。

### 生成与资源发布

书库首页与书籍目录各自引用标注面板的 CSS/JS。它们均使用现有 `rewrite_asset_urls`，因此新资源会通过现有 `AssetPublisher` 以内容寻址 URL 发布。

这样 Build 输出本身完整可部署；Server 模式继续复用现有 API，无需增加页面路由或扩展既有注释 API。

## Build 与 Server 行为

标注中心始终尊重 `annotation_storage_type`：

| 运行模式 | 当前存储 | 数据来源 | 预期行为 |
| --- | --- | --- | --- |
| Build | 本地 | IndexedDB | 正常显示此浏览器的本地标注。 |
| Build | 云端 | 无可用后端 | 清楚说明云端标注在静态站点不可访问；不自动切换为本地数据。 |
| Server | 本地 | IndexedDB | 正常显示此浏览器的本地标注。 |
| Server | 云端 | `/api/annotations` | 使用现有 `X-Username` 隔离后读取全部或单书标注。 |

不进行隐式本地/云端回退，因为两份数据可能不同；静默回退会让读者误以为标注遗失或完整同步。

## 回到原文

每张标注卡链接到：

`/book/<book-hash>/chapter_<chapter-index>.html?annotation=<annotation-id>`

章节脚本在标注还原完成后读取该参数，找到同 ID 的高亮节点，滚动到适合阅读的位置，并短暂加上聚焦样式。分页阅读模式也必须切换到包含该节点的可见页。

若 EPUB 更新、原文变化或高亮还原失败导致找不到节点，仍然打开正确章节，提示“未能定位此标注”，且绝不删除或改写该标注。定位应沿用现有标注还原的重试时机，避免在初次布局尚未稳定时误报失败。

面板在跳转前关闭；点击关闭、遮罩或 Escape 时恢复打开前的页面滚动位置与触发按钮焦点。

## 异常与可访问性

- 读取标注、书籍元数据或目录失败时展示原因和“重试”操作，不显示空白页面。
- 后端不可用时区分“无标注”和“无法读取标注”。
- 书籍卡和标注卡使用原生链接或键盘等效交互，原文摘录与笔记作为文本而非未转义 HTML 注入。
- 面板复用主题变量、响应式宽度和内容寻址资源；小屏优先使用单列卡片，不依赖悬停操作，并为按钮保留至少 44px 点击目标。

## 验证策略

1. **纯数据逻辑测试**：用 Node 测试或可独立加载的工具函数验证跨书聚合、最新时间排序、单书章节分组、目录和元数据降级。
2. **生成页面测试**：Python 测试验证书库和目录页含模态入口与内容寻址资源，且不再生成 `/annotations/index.html`。
3. **静态交付测试**：验证 Build 输出的相关 immutable assets 和书籍目录 JSON 可被普通静态文件托管访问。
4. **Server 回归测试**：复用并补充现有 API 测试，确认 `/api/annotations` 的全部读取和按书读取仍按用户名隔离；标注中心不要求新 API。
5. **章节定位测试**：验证章节页面识别 `annotation` 查询参数，在标注节点可用时请求聚焦，在节点缺失时保留章节并报告可恢复错误。
6. **静态检查**：运行完整 Python 测试套件、相关 Node 测试、`node --check` 与 `git diff --check`。

## 验收标准

- Build 和 Server 生成的书库都能从书库与单书目录打开全屏标注面板。
- 本地和云端存储都只显示当前所选存储的数据；云端按既有用户名规则隔离。
- 标注中心首页只列出有标注的书，排序和计数正确。
- 本书标注按章节与书中顺序显示，信息不全时仍有可读降级。
- 从任意标注能进入对应章节、突出显示原文；无法定位时不损坏数据。
- 关闭面板后能回到原页面、原滚动位置和原触发按钮。
