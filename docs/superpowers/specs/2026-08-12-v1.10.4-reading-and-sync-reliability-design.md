# v1.10.4 Reading and Sync Reliability Design

## Goal

Ship one reliability-focused release that reuses book resources efficiently, stores server-synchronized bookshelves in SQLite, and preserves the reader's viewport while continuous reading loads and evicts chapters.

## Included Changes

### Book Resource Caching

The already-merged cache policy keeps generated HTML and mutable metadata at `no-cache`, while files beneath `/book/<hash>/resources/` receive `Cache-Control: public, max-age=2592000`. This covers book covers, chapter illustrations, EPUB stylesheets, and fonts. The v1.10.4 release retains that behavior and its server regression tests.

### SQLite Bookshelves in Server Mode

The existing `annotations.db` gains a `bookshelves` table with one row per username:

```sql
CREATE TABLE IF NOT EXISTS bookshelves (
    username TEXT PRIMARY KEY,
    version INTEGER NOT NULL,
    data TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
)
```

`data` is the complete nested bookshelf JSON document. The browser continues to render immediately from `localStorage`; SQLite is the authoritative server-side synchronization copy.

`POST /sync` continues accepting `username`, `version`, and `data`. Its current optimistic-version behavior is preserved: an equal version returns `304`, an older client receives the server `version` and `data`, and a newer client atomically replaces the stored row. The first request for an absent SQLite row imports the highest-version legacy `epub-browser-bookshelf-<username>-<version>.json` file from `sync_dir` or the library directory. Legacy files are not deleted in this release and no new legacy files are written.

### Continuous Reading Viewport Stability

Continuous reading keeps a five-chapter reading window. On loading the next chapter, the reader may evict the chapter above the viewport; on loading the previous chapter, it may evict the chapter below the viewport. The reader must preserve the visible reading anchor across either operation.

Before a DOM insertion or eviction, capture a stable visible anchor: the first text-bearing element intersecting the viewport and its top offset relative to the viewport. After the DOM mutation and a layout frame, calculate that same anchor's new document position and scroll by the exact offset difference. This replaces calculations based on a removed section's `getBoundingClientRect().height` or overall document-height deltas, both of which are wrong in the presence of margins and delayed image layout.

The current window size, lazy chapter fetching, URL replacement, and bounded-memory behavior remain unchanged. Image loads that change an in-window chapter's layout must not cause a reading-position jump; use a `ResizeObserver` or image-load correction only while an anchor-preservation transaction is active, then disconnect it after layout settles.

## Non-Goals

- Do not convert browser `localStorage` bookshelf state into a server-only UI.
- Do not split nested bookshelf groups into relational tables.
- Do not add authentication; username remains an identifier, not a security boundary.
- Do not change chapter window size, fetch strategy, or reader interaction design.

## Validation

- Python server tests cover SQLite creation, write/read/version-conflict behavior, and legacy JSON import through `/sync`.
- Existing cache tests retain the 30-day EPUB-resource cache policy and `no-cache` generated pages.
- JavaScript unit tests cover reading-window eviction direction and a pure anchor-offset helper.
- A Chrome browser regression run opens a generated EPUB, enables continuous reading, crosses the five-chapter window boundary, and verifies the same visible text anchor remains at the same viewport offset after the mutation.
- The full Python and JavaScript test suites pass before release notes and version metadata are updated.
