# v1.10.4 Reading and Sync Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release v1.10.4 with cached EPUB resources, SQLite-backed server bookshelf synchronization, and continuous-reading viewport stability.

**Architecture:** Preserve the existing browser bookshelf document and `/sync` payload while replacing server-side JSON-file persistence with an atomic SQLite row. Extract continuous-reading viewport anchoring into a small browser/Node-compatible helper so both top insertion and top eviction restore the same visible content at the same viewport offset after DOM mutations. Retain the existing 30-day EPUB-resource cache policy already merged on `main`.

**Tech Stack:** Python 3, SQLite (`sqlite3`), Starlette, Node built-in test runner, browser DOM APIs, `unittest`.

## Global Constraints

- Keep `/sync` request fields (`username`, `version`, `data`) and response conflict semantics compatible with existing clients.
- Keep `localStorage` as the browser's immediate and offline bookshelf cache.
- Import the highest-version legacy bookshelf JSON record on demand; do not create, update, or delete legacy JSON files.
- Generated HTML and metadata remain `no-cache`; `/book/<hash>/resources/` remains `public, max-age=2592000`.
- Preserve the five-chapter continuous reading window, network loading, and URL replacement behavior.
- Do not add authentication or change user identity semantics in this release.

def test_sync_persists_the_shelf_in_sqlite(self):
