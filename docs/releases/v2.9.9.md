# EPUB Browser v2.9.9 — Server 模式 Kindle 极简页内联脚本放行（主题/字号/i18n 生效）

发布日期 / Release date: 2026-08-31

## 中文

v2.9.9 修复 Server 模式下 Kindle 极简页的主题、字号与本地化（i18n）不生效的问题。v2.9.8 已在模板层修复了 e-Ink Kindle WebKit 上的主题切换（改用 `background-color` + `!important`、改用 ES5 显式循环），并让 SSG 模式生效；但 Server 模式仍不生效。

根因：Server 模式对所有阅读器页面套用了相同的严格 CSP，内联脚本通过 `sha256` 哈希放行。然而老款 e-Ink Kindle 的 WebKit 不支持 CSP 哈希源，遇到无法识别的 `script-src 'self' 'sha256-...'` 时会拒绝执行**所有**内联 `<script>`，于是 `kTheme()` / `kFont()` 与 i18n 脚本全部不运行——表现就是"主题/字号按了没反应"，且界面语言回到英文（i18n 也丢失）。SSG 静态文件不带该 CSP，所以 SSG 模式正常。

修复：三个 Kindle 极简页——极简书架 `/kindle-library.html`、书页 `/book/<id>/kindle.html`、章节页 `/book/<id>/kindle_chapter_N.html`——改用 `script-src 'self' 'unsafe-inline'`。这些页面是封闭、已 sanitize 的只读渲染，放行内联脚本安全且必要；普通阅读器页面仍使用哈希策略，不受影响。新增回归测试锁定该行为。

### 修复与改进

- **Server 模式 Kindle 主题/字号/i18n 生效**：极简页 CSP 由 `sha256` 哈希切换为 `'unsafe-inline'`，老款 e-Ink Kindle WebKit 不再拦截内联脚本；主题切换、字号调节与本地化字符串（如"主题"）恢复生效。

### 影响范围

- **部署与格式范围**：仅 Server 模式下的 Kindle 极简页；普通阅读器页面（哈希策略）与 SSG 输出不变；仅 EPUB。
- **触发条件**：在 Server 模式 Kindle 上切换主题、调整字号或查看本地化界面。

### 升级说明

- **Server 部署**：重启 Server 即生效（CSP 与模板均为请求时生效），无需重新转换 EPUB，不涉及内容缓存 schema 或 SQLite 迁移。
- **SSG 部署**：原本即生效，无需重新生成。
- **无需配置**：无新增配置项。

## English

v2.9.9 fixes theme, font size, and localization (i18n) not working on the Kindle minimal surfaces in **Server** mode. v2.9.8 fixed the template layer for e-Ink Kindle WebKit (switching to `background-color` + `!important` and an explicit ES5 loop) and made SSG mode work, but Server mode still did not.

Root cause: Server mode applied the same strict CSP to all reader pages, allowing inline scripts only via `sha256` hashes. Legacy e-Ink Kindles ship a WebKit that does not understand CSP hash sources; facing an unrecognized `script-src 'self' 'sha256-...'`, it refuses to run **every** inline `<script>`. That killed `kTheme()` / `kFont()` and the i18n script — hence "theme/font buttons do nothing" and the UI language falling back to English. SSG static files carry no such CSP, so SSG mode worked.

Fix: the three Kindle minimal pages — the minimal shelf `/kindle-library.html`, the book page `/book/<id>/kindle.html`, and the chapter page `/book/<id>/kindle_chapter_N.html` — now use `script-src 'self' 'unsafe-inline'`. These pages are a closed, already-sanitized read surface, so allowing inline scripts is both safe and necessary; ordinary reader pages keep the hash policy and are unaffected. A new regression test locks in the behavior.

### Fixes and improvements

- **Kindle theme/font/i18n now apply in Server mode**: the minimal surfaces' CSP switches from `sha256` hashes to `'unsafe-inline'`, so legacy e-Ink Kindle WebKit no longer blocks the inline scripts; theme switching, font resizing, and localized strings (e.g. "主题" / "Theme") work again.

### Affected scope

- **Deployment and format scope**: only the Kindle minimal surfaces in Server mode; ordinary reader pages (hash policy) and SSG output are unchanged; EPUB only.
- **Trigger**: toggling theme, resizing font, or viewing the localized UI on a Server-mode Kindle.

### Upgrade notes

- **Server deployment**: restart the Server to take effect (CSP and templates are rendered per request); no EPUB re-conversion, no content-cache schema or SQLite migration.
- **SSG deployment**: already working; no regeneration needed.
- **No configuration**: no new options.
