# EPUB Browser v2.8.0 — PDF 成为一等阅读格式

发布日期 / Release date: 2026-08-29

![PDF 在 EPUB Browser 共用阅读器中渲染：原始页面、导航、主题与阅读工具保持在同一阅读舞台中。](assets/v2.8.0-pdf-reader.png)

## 中文

v2.8.0 在不复制 EPUB 阅读器界面的前提下，将 PDF 作为一等书籍格式接入 EPUB Browser。PDF 的每一页对应一个 `chapter_<n>.html` 章节，继续复用书库、书籍详情、目录、阅读设置、标注、查词、百科和阅读洞察等既有能力；SSG 与 Server 使用同一组页面模板和本地 PDF.js 资源。

### 新功能

- **PDF 一页一章节**：PDF 第 1 页对应 `chapter_0.html`，每页都会出现在书籍目录中；文档内嵌 outline 会作为对应页的标题标记，而不会替代完整的页码目录。
- **SSG 与 Server 同步支持**：SSG 写出完整的静态阅读站点和单个 `document.pdf`；Server 缓存完整 PDF 与派生元数据，并通过鉴权、支持 Range 的同源路由交付文档。两种模式复用相同的书籍页、章节壳、阅读控件和 PDF.js 渲染逻辑。
- **完整的 PDF 阅读模式**：支持滚动阅读（连续）、滚动阅读（非连续）和翻页模式，以及适合宽度、适合页面、任意比例缩放、全屏、目录跳转和页间导航。
- **PDF 文本选择与标注**：带可用文本层的 PDF 复用 EPUB 的选择操作弹窗，支持高亮、笔记、复制、查词和百科；标注继续使用现有数据模型、设置面板和同步能力。扫描版或纯图片 PDF 仍可阅读，但不会伪造不可用的文本选择功能。
- **PDF 封面与元数据**：转换时提取标题、作者、页数、outline 和首屏封面；当文档元数据缺失时，书名回退到原始文件名。Library 和书籍详情使用同一封面源，并显示清晰的 PDF 格式标记。
- **稳定的 PDF 书籍身份**：PDF 使用相邻的 `.epub-browser.json` sidecar 保存书籍 ID；即使配置为 embedded，PDF 也会安全回退到 sidecar。源文件暂时移出监控目录时记录会软删除，重新放回后恢复原书籍 ID、元数据和关联用户数据。

### 阅读体验与性能

- **专业阅读舞台**：PDF 页面始终留在阅读舞台内部，超大缩放时由舞台承担横向滚动；页面宽度不再突破布局或遮挡悬浮工具栏。
- **缩放行为统一**：页面宽度档位直接对应 PDF 缩放，适合宽度和适合页面每次都会根据当前舞台重新计算，不会继承此前手动放大或缩小的残余比例。
- **连续模式按需渲染**：保留当前页前后有限页面的渲染窗口，远页释放昂贵的 canvas 和文本层，但保留稳定占位尺寸；快速跳页和连续滚动不再出现永久白页、页面跳动或大块错误留白。
- **自适应页间距与加载状态**：页间距随缩放级别收敛，加载期间显示主题一致的 loading 状态，不再先闪出空白纸张。
- **主题一致的画布**：阅读舞台跟随浅色、护眼、纸张和深色主题；深色模式不再反转 PDF 页面或让正文发灰，文档原始颜色保持可读。
- **即时语言切换**：Chapter 设置中的标注 Tab、开关、颜色和导出控件使用动态 i18n 绑定，切换界面语言后无需刷新页面。
- **能力降级更明确**：PDF 隐藏章节内目录、AI 阅读、问问 AI、打印、下载和预览入口；书籍目录、阅读设置、标注设置、搜索和阅读计时仍保持可用。

### Server、管理与集成

- **统一书籍管理**：标签管理和书籍管理能够识别 PDF 格式；修改 PDF 的书名、作者或标签后，Library、书籍详情、管理列表和阅读洞察都会按书籍 ID 显示最新元数据。
- **OpenAPI 与 WebHook 兼容**：书籍响应和管理接口返回 PDF 的 `format`，PDF 的元数据变更、标签变更和软删除恢复继续产生带格式信息的 `book.updated` 事件。
- **友好的登录失效处理**：未登录或 Session 失效后访问 Server 的 Library、书籍详情或章节 HTML，会跳转到登录页并保留安全的返回地址；JSON API 继续返回结构化的鉴权错误。
- **更稳健的 PDF 交付**：Server 校验缓存代次、文件身份、访问权限和 Range 边界，使用 inline disposition 与安全响应头；同一文件代次的验证结果会缓存，避免连续章节重复计算完整文件摘要。

### 第三方资源与示例

- PDF.js 模块与 worker 在构建 PyPI、Docker 或发布资源时按锁定清单下载、校验并生成哈希资产；浏览器运行时不访问 CDN。
- 公共版权的 `Alice_in_Wonderland.pdf` 及其书籍 ID sidecar 加入 `examples/`，用于 SSG、Server、封面、目录和身份稳定性的回归测试。

### 升级说明

- Server 首次启动时会自动将 SQLite 状态库迁移到 schema v19，为书籍记录补充 `source_format`，并兼容修复 PDF 功能分支与 v2.7.0 元数据分支曾并行使用 schema v18 的数据库。无需手动迁移，但生产部署仍建议先备份完整 `server-dir`。
- 本版本不修改 EPUB 内容缓存 schema，也不提高 `SERVER_OUTPUT_REVISION`；已有 EPUB 无需重新转换。
- PDF 使用独立的 `server-pdf-v2` 内容缓存和 metadata schema v2。首次加入 PDF 时会生成完整 PDF 缓存、封面和页级元数据；源文件变化时会原子重建这些派生内容。
- 新增运行依赖 `pypdf`、`pypdfium2` 和 Pillow。通过 PyPI 或 Docker 升级会自动安装；源码部署需要重新安装项目依赖。
- 发布资产必须先执行仓库的 vendor hydration/verification 流程。PDF.js 只在构建期获取，生产运行时无需且不允许依赖外部 CDN。

## English

v2.8.0 makes PDF a first-class book format without introducing a second reader interface. Each PDF page maps to a `chapter_<n>.html` chapter and continues to reuse the existing Library, book detail, table of contents, reading settings, annotations, dictionary, encyclopedia, and reading-insights surfaces. SSG and Server share the same page templates and local PDF.js assets.

### New features

- **One PDF page per chapter**: PDF page 1 maps to `chapter_0.html`, and every page remains present in the book TOC. Embedded outlines annotate their destination pages instead of replacing the complete page-number TOC.
- **Matching SSG and Server support**: SSG writes a complete static reading site and one `document.pdf`. Server caches the complete PDF and derived metadata, then delivers it through an authenticated, range-capable same-origin route. Both modes reuse the same book pages, chapter shells, reading controls, and PDF.js renderer.
- **Complete PDF reading modes**: Continuous scrolling, non-continuous scrolling, and paginated reading are supported together with fit width, fit page, arbitrary zoom, fullscreen, TOC navigation, and previous/next page navigation.
- **PDF text selection and annotations**: PDFs with a usable text layer reuse the EPUB selection popup for highlights, notes, copy, dictionary lookup, and encyclopedia lookup. Existing annotation storage, settings, and synchronization remain in use. Scanned or image-only documents stay readable without exposing selection actions that cannot work.
- **PDF covers and metadata**: Conversion extracts title, authors, page count, outlines, and a first-page cover. When document metadata has no usable title, the original filename is used. Library and book detail use the same cover source and show a clear PDF format badge.
- **Stable PDF identity**: PDFs store their book ID in an adjacent `.epub-browser.json` sidecar; an embedded storage configuration safely falls back to that sidecar. Moving a source out of a watched directory soft-deletes its record, while restoring the file recovers the same book ID, managed metadata, and related user data.

### Reading experience and performance

- **A bounded reading stage**: PDF pages remain inside the reader stage, with horizontal overflow handled by that stage at high zoom instead of escaping the layout or covering floating controls.
- **Consistent zoom semantics**: Page-width presets directly represent PDF zoom. Fit width and fit page recalculate from the current stage every time and do not inherit a stale manual zoom multiplier.
- **Demand-rendered continuous mode**: A bounded window around the current page retains expensive canvases and text layers while distant pages keep stable geometry. Fast navigation and long scrolling no longer leave permanent blank pages, resize loops, or oversized empty regions.
- **Adaptive gaps and explicit loading**: Page spacing tightens with zoom, and theme-aware loading states replace blank paper flashes while a page is being rendered.
- **Theme-aligned canvas**: The stage follows light, eye-care, paper, and dark themes. Dark mode no longer inverts PDF pages or washes out text; original document colors remain readable.
- **Immediate language switching**: The Chapter settings annotation tab, toggle, colors, and export controls use live i18n bindings, so changing the interface language no longer requires a refresh.
- **Explicit capability degradation**: PDF hides in-chapter TOC, AI Reading, Ask AI, print, download, and preview controls. Book TOC, reading settings, annotation settings, search, and reading-time tracking remain available.

### Server, administration, and integrations

- **Unified book administration**: Tag and book management understand PDF format. Renaming a PDF or changing its authors or tags updates Library, book detail, administration, and reading insights through the stable book ID.
- **OpenAPI and WebHook compatibility**: Book and administration responses expose PDF `format`; PDF metadata changes, tag changes, and soft-delete restoration continue to emit `book.updated` events with format information.
- **Friendly expired-session handling**: Visiting Server Library, book-detail, or chapter HTML without a valid session redirects to sign-in with a safe return target. JSON APIs continue to return structured authorization errors.
- **Hardened PDF delivery**: Server validates cache generation, file identity, authorization, and Range boundaries and uses inline disposition plus secure response headers. Validation is cached per immutable file generation to avoid hashing the complete file on every chapter request.

### Third-party assets and examples

- PDF.js modules and workers are downloaded during PyPI, Docker, or release-asset builds from a locked manifest, verified, and published under hashed names. Browser runtime never reaches a CDN.
- The public-domain `Alice_in_Wonderland.pdf` and its book-ID sidecar are included under `examples/` for SSG, Server, cover, TOC, and identity regression coverage.

### Upgrade notes

- On first Server startup, SQLite automatically migrates to schema v19, adding `source_format` and repairing databases created while the PDF and v2.7.0 managed-metadata branches independently used schema v18. No manual migration is required, though production deployments should back up the complete `server-dir` first.
- This release does not change the EPUB content-cache schema or raise `SERVER_OUTPUT_REVISION`; existing EPUB books do not need reconversion.
- PDF uses the separate `server-pdf-v2` content cache and metadata schema v2. Adding a PDF generates the complete PDF cache, cover, and page metadata; changing the source atomically rebuilds those derived files.
- Runtime dependencies now include `pypdf`, `pypdfium2`, and Pillow. PyPI and Docker upgrades install them automatically; source deployments should reinstall project dependencies.
- Release artifacts must pass the repository vendor hydration and verification flow. PDF.js is fetched only at build time, and production runtime neither needs nor permits an external CDN dependency.
