# v2.17.1

## 改进

- **按书架排列顺序排序**：主书库与 Kindle 书架的排序下拉新增「书架顺序」。已加入书架的书按书架文档的深度优先遍历结果排列，完整保留分组以及组内拖拽形成的顺序；未入架的书仍按手动顺序排在其后，并以书籍 ID 稳定决胜。Server 与 ES5 客户端共用同一套遍历规则，原有「书架优先」（按加入时间由新到旧）行为不变；旧书架数据没有 `added` 时间戳时仍按当前显示顺序推导。新增 17 种语言文案。

### 影响范围

- 新排序覆盖 SSG 与 Server 的主书库和 Kindle 书架（EPUB / PDF 均可）；管理后台书籍列表的排序选项不变。
- 书架数据格式向后兼容，无需迁移；EPUB `content/` 与 PDF 缓存修订均未变（`server-content-v11`、`server-pdf-v2`），SQLite schema 仍为 34。
- 无新增 API、CLI 参数或登录要求；排序偏好继续保存在浏览器本地，URL 中的 `?sort=` 仍然优先。

### 升级说明

- Server：部署并重启即可，无需重新转换书籍或执行数据库迁移；仍建议按惯例在升级前备份 `data/`。
- SSG：需重新生成并整站发布静态输出，以应用新的排序脚本、选项文案与哈希资源。
- 已有排序偏好与 `?sort=` 链接行为不变；没有保存过偏好时仍默认「手动顺序」。

## Improvements

- **Sort by the bookshelf arrangement**: The main library and Kindle bookshelf gain a "Bookshelf order" option. Shelf books follow a depth-first walk of the bookshelf document, preserving both groups and the drag-and-drop order inside them; non-shelf books keep their manual order behind them, with book IDs as a stable tie-break. Server and the ES5 client share the same traversal. The existing "Bookshelf first" option (newest additions first) is unchanged, and legacy shelves without `added` timestamps still derive them from display order. The new label ships in all 17 locales.

### Affected scope

- The new sort covers the main library and Kindle bookshelf in both SSG and Server, for EPUB and PDF. The administration book list keeps its existing options.
- The bookshelf format stays backward compatible and needs no migration. Neither the EPUB `content/` nor the PDF cache revision changed (`server-content-v11`, `server-pdf-v2`), and SQLite schema remains 34.
- No new API, CLI flag or login requirement. Sort preferences stay in browser-local storage, and a `?sort=` URL parameter still takes precedence.

### Upgrade notes

- Server: deploy and restart. No book reconversion or database migration is needed; backing up `data/` before upgrading remains recommended.
- SSG: regenerate and republish the full static output to pick up the new sorting script, option label and hashed assets.
- Existing sort preferences and `?sort=` links behave as before; when no preference is saved, the library still defaults to "Manual order".
