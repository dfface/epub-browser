# v2.15.0

## 新功能

- **EPUB 全书搜索（#21，仅 Server）**：登录读者可从书籍页弹窗或章节页抽屉搜索整本 EPUB。结果按章节分组，每页固定显示 50 条并支持完整分页；点击结果可跳转并高亮正文，当前标签页还会记住每本书上次的关键词和结果页码。搜索使用独立的 SQLite FTS5 索引与磁盘 LRU 缓存，默认保留 20 本书，可在「一般设置」调整。PDF 不提供此能力，SSG 不生成搜索资源或接口。
- **启动缓存构建提速与分阶段进度（仅 Server）**：元数据探测与缓存转换复用同一次 EPUB 解包，按最近阅读顺序优先恢复缓存上限内的书籍；已淘汰书籍保留轻量书库信息，打开时可从源文件恢复。启动进度分别展示解包与缓存构建阶段、计数和当前书籍。
- **书库分页适配响应式网格**：每页数量随书库网格列数调整，避免末行仅显示少量书籍，保持分页后的每一页排版完整。
- **阅读器第三方资源按需加载**：仅在对应功能需要时加载阅读器 vendor 资源，减少章节页初始加载的不必要请求。

## 修复

- 稳定 Server 关闭时的 SQLite 连接处理，避免关闭过程中的并发问题。
- 修正公开 API 的 PDF 章节列表，使其通过 PDF 渲染器读取章节信息。
- 没有旧版书籍 ID 时跳过不必要的迁移源文件扫描。
- 将 EPUB 清洗和 EPUB/PDF 共享页面渲染拆分为独立模块，并完善回归测试与多语言项目文档。

### 影响范围

- 全书搜索、搜索索引缓存和启动缓存进度仅用于 Server；全书搜索仅支持 EPUB，不改变 PDF 或 SSG 的能力边界。
- 响应式书库分页与阅读器资源按需加载用于共享页面；SSG 需重新生成以应用新模板和哈希资源。
- EPUB `content/` 与 PDF 缓存修订均未变（`server-content-v11`、`server-pdf-v2`）；本次不涉及书籍内容缓存 schema 升级。

### 升级说明

- Server：部署并重启即可，无需重新转换 EPUB 或 PDF。启动时会为 `general_settings` 增加 `search_index_cache_limit` 列，并将 SQLite `user_version` 提升到 33；升级前建议备份 `data/`，回退到旧版本需恢复升级前的数据库。
- 搜索索引在首次搜索时按需构建，默认按 LRU 保留 20 本书的索引；可在「一般设置」调整缓存数量。
- SSG：重新生成并整站发布静态输出，以应用共享模板、分页和资源加载更新；书籍 URL 与 CLI 参数未变化。

## Features

- **Full-book EPUB search (#21, Server only)**: Signed-in readers can search an entire EPUB from a book-page dialog or chapter-page drawer. Results are grouped by chapter, paginated at 50 results per page without truncating the result set, and clicking a hit jumps to and highlights the passage. The current tab remembers the last query and result page for each book. Search uses separate SQLite FTS5 indexes with a disk-backed LRU cache for 20 books by default, configurable in General settings. PDF books do not expose search, and SSG output contains neither search assets nor endpoints.
- **Faster startup cache builds with staged progress (Server only)**: Metadata probing and cache conversion now share one EPUB extraction pass. Recently read books within the configured cache limit are restored first, while evicted books keep lightweight shelf metadata and can be restored from their sources when opened. Startup progress reports extraction and cache building as separate stages with counters and the current book.
- **Responsive library pagination**: Page size follows the book-grid column count so pages retain complete rows instead of leaving a short trailing row.
- **On-demand reader vendor assets**: Third-party reader assets load only when their corresponding features need them, avoiding unnecessary requests during initial chapter rendering.

## Fixes

- Stabilized SQLite connection handling during Server shutdown to avoid concurrency issues while closing.
- Corrected PDF chapter lists in the public API to read chapter information through the PDF renderer.
- Skipped unnecessary migration source scans when no legacy book IDs exist.
- Separated EPUB sanitization and shared EPUB/PDF page rendering into dedicated modules, with expanded regression coverage and updated localized project documentation.

### Affected scope

- Full-book search, search-index caching and startup cache progress are Server-only. Full-book search supports EPUB only and does not change the PDF or SSG capability boundaries.
- Responsive library pagination and on-demand reader assets use shared pages; SSG sites need regeneration to pick up the new templates and hashed assets.
- Neither the EPUB `content/` nor the PDF cache revision changed (`server-content-v11`, `server-pdf-v2`); no book content-cache schema upgrade is required.

### Upgrade notes

- Server: deploy and restart; no EPUB or PDF reconversion is needed. Startup adds `search_index_cache_limit` to `general_settings` and advances SQLite `user_version` to 33. Back up `data/` before upgrading; rolling back to an older release requires the pre-upgrade database.
- Search indexes are built on demand on the first search. The LRU cache keeps indexes for 20 books by default and can be adjusted in General settings.
- SSG: regenerate and republish the full static output to apply the shared template, pagination and asset-loading updates. Book URLs and CLI flags are unchanged.
