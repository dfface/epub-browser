# EPUB Browser v2.0.4

发布日期 / Release date: 2026-08-20

## 中文

这是一个提升书籍身份稳定性与桌面滚动阅读体验的维护版本。

### 新功能与改进

- **书籍 ID 跟随 EPUB 文件**：首次处理尚未带标识的 EPUB 时，EPUB Browser 会生成稳定 ID，并写入 OPF 的 `epub-browser:book-id` 元数据。移动、重命名或修改书籍内容后重新生成，仍会关联原有书籍、标注、进度与书架记录。
- **SSG 与 Server 使用同一身份来源**：两种模式都会优先读取 EPUB 内嵌 ID。Server 会沿用已有数据库 ID 写回源文件，已移除后重新加入的书籍也能恢复原记录；同时导入多个带有相同 ID 的副本时会明确报告冲突。
- **可选桌面章节侧栏**：滚动模式可在设置中开启常驻章节栏，当前章节会随阅读位置实时高亮并自动保持可见。该功能默认关闭，仅在宽度足够的桌面视口显示，较窄窗口继续使用弹出章节目录。
- **更清晰的目录层级**：书籍级导航显示为“章节”，当前页面内的标题导航显示为“本章目录”，避免两个“目录”入口含义不清。
- **更完整的键盘与辅助技术支持**：桌面阅读控件改用语义化按钮和导航区域，补充焦点样式、可访问名称、跳到正文入口与减少动效支持。

### 修复

- 修复桌面端长书名和章节名导致面包屑换行、挤乱阅读布局的问题；过长内容现在会在同一行内省略。
- 修复连续滚动切换章节时，左侧高亮、地址栏和面包屑没有同步更新的问题。
- 修复刷新页面或重新打开章节侧栏后，当前高亮章节没有自动滚动到可见位置的问题。
- 调整常驻章节栏断点，使原有 1000px 阅读宽度和圆形工具栏在宽屏上保持不变，并避免较窄桌面视口发生控件重叠。

### 行为变化

- **源 EPUB 可能被修改**：没有内嵌 ID 且允许安全写入时，首次处理会原子重写 EPUB 容器，在 OPF 中加入一条元数据。写入前后会校验 ZIP 结构和未修改资源，并保留文件权限与归档元数据；仍建议为不可替代的原始文件保留备份。
- **只读或不适合重写的 EPUB**：Server 遇到只读、已签名、符号链接、硬链接或不受支持的 ZIP 结构时不会改写源文件，并退回数据库 ID；SSG 无法为这类文件建立可携带身份时会停止构建并报告原因。
- **复制文件会复制身份**：复制已经写入 ID 的 EPUB 会得到同一本书的身份。不要在同一书库中同时加入这些副本，否则会被视为 ID 冲突。

### 兼容性

- 不需要数据库迁移。已有 Server 书籍会优先把原数据库 ID 写入可写 EPUB，因此既有标注、阅读进度与书架关联保持不变。
- 桌面章节侧栏默认关闭，不会改变现有阅读布局；需要时可在阅读设置中开启。
- `--watch` 识别首次写入后的最新文件指纹，后续扫描会直接复用内嵌 ID，不会因工具自身写入而持续重复更新。

## English

This maintenance release makes book identity more durable and improves continuous reading on desktop.

### New Features and Improvements

- **Book IDs now travel with EPUB files**: When an EPUB has no EPUB Browser identity, the first processing run generates a stable ID and stores it as `epub-browser:book-id` metadata in the OPF package. Moving, renaming, or editing the book no longer disconnects it from its existing annotations, progress, bookshelf placement, or generated URL.
- **One identity source for SSG and Server**: Both modes now prefer the embedded EPUB ID. Server writes an existing database ID back to the source when possible and can reactivate a previously removed book under the same record. Importing multiple copies with the same embedded ID reports a clear conflict.
- **Optional desktop chapter sidebar**: Scroll mode can keep the book's chapter list visible from Reading Settings. The active chapter follows the reading position and stays in view. The option is off by default, appears only on sufficiently wide desktop viewports, and falls back to the existing chapter popup on narrower windows.
- **Clearer navigation hierarchy**: Book-level navigation is labeled “Chapters,” while headings within the current document are labeled “This chapter,” removing the ambiguity between two table-of-contents controls.
- **Better keyboard and assistive-technology support**: Desktop reading controls now use semantic buttons and navigation regions, with visible focus states, accessible names, a skip-to-content link, and reduced-motion support.

### Fixes

- Fixed long book and chapter titles wrapping the desktop breadcrumb and disrupting the reader layout. Long labels now truncate within a single line.
- Fixed the chapter sidebar, URL, and breadcrumb falling out of sync while continuous scrolling crosses chapter boundaries.
- Fixed the active chapter not scrolling into view after a refresh or after reopening the chapter sidebar.
- Refined the persistent-sidebar breakpoint so the original 1000px reader width and circular tool controls remain intact on wide screens without overlapping on narrower desktop viewports.

### Behavior Changes

- **Source EPUBs may be modified**: If an EPUB has no embedded ID and can be rewritten safely, its first processing run atomically rebuilds the container with one additional OPF metadata entry. EPUB Browser validates the ZIP structure and unchanged resources before replacement and preserves file permissions and archive metadata. Keep a backup of irreplaceable originals.
- **Read-only or unsafe-to-rewrite EPUBs**: Server does not rewrite read-only, signed, symbolic-link, hard-linked, or unsupported ZIP inputs and falls back to a database-only ID. SSG stops with a clear error when it cannot establish a portable identity for such an input.
- **Copying a file also copies its identity**: A copy of an already tagged EPUB represents the same book. Adding both copies to one library is treated as an ID conflict.

### Compatibility

- No database migration is required. Existing Server books write their current database ID into writable EPUBs first, preserving annotations, reading progress, and bookshelf relationships.
- The desktop chapter sidebar is off by default, so existing reading layouts do not change unless it is enabled in Reading Settings.
- `--watch` records the post-write fingerprint and reuses the embedded ID on subsequent scans, avoiding a repeated update loop caused by EPUB Browser's own write.
