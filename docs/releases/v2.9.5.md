# EPUB Browser v2.9.5 — Server 响应压缩、不可变资产缓存修复与 HTML 回退编码修复

发布日期 / Release date: 2026-08-31

## 中文

v2.9.5 修复了统一解析管线引入的一个乱码问题：当 XHTML 需要回退到 HTML 解析器时，无编码声明的 UTF-8 字节会被 lxml 按 latin-1 解码，弯引号（`’`）等真实 Unicode 字符变成 `â€™` 形式的乱码，影响部分书籍的描述与回退解析的章节。现在回退解析前会显式解码（尊重 BOM 与 meta charset 声明，UTF-8 兜底）。同时为 Server 响应启用了 gzip 压缩，并修复了认证中间件把内容寻址的不可变资产缓存头覆盖为 `no-cache` 的问题——`/assets/immutable/` 资源重新享受一年期的 immutable 缓存，重复访问不再逐个重新校验。

### 修复与改进

- **HTML 回退编码修复**：lxml 的 HTML 解析器对检测不到编码的输入按 latin-1 解码，把 EPUB 强制要求的 UTF-8 内容变成乱码（`’` → `â\x80\x99`）。现在 `parse_xhtml_bytes` / `parse_xhtml_document` / `parse_xhtml_fragment` 的 HTML 回退前会显式解码字节：BOM 优先、其次 meta charset 声明、最后 UTF-8 兜底，并剥离 XML 声明以避免 lxml 拒绝带编码声明的字符串。受影响书籍的书卡描述不再显示 `Donâ€™t`，`meta charset="windows-1252"` 等老书声明也继续被正确尊重。
- **Server 响应 gzip 压缩**：通过 Starlette 内置 GZipMiddleware 压缩 HTML、JSON、JS、CSS 与 SVG 文本响应；自动跳过已压缩的二进制内容（图片、字体、音视频、压缩包）与 Range（206）响应，小于 500 字节的响应不压缩，并设置 `Vary: Accept-Encoding`。纯文本传输体积显著下降。
- **不可变资产缓存修复**：认证中间件曾把每个认证后响应强制为 `private, no-cache`，使 `/assets/immutable/<hash>` 的长期缓存失效，每次页面加载都要重新校验所有脚本与样式。现在内容寻址资产保留 `private, max-age=31536000, immutable`，配合现有 ETag 条件请求，重复访问的资产往返大幅减少。

### 影响范围

- **部署与格式范围**：仅影响 Server（EPUB 与 PDF 均受益于压缩与资产缓存）；SSG 输出不变，无需改动。
- **触发条件**：Server 返回的大于 500 字节的文本响应；认证后访问 `/assets/immutable/` 资产；书籍描述或章节包含真实 UTF-8 标点且需要 HTML 回退解析。

### 升级说明

- **重启 Server 即生效**：压缩与缓存头是运行时行为，不需要重新转换 EPUB/PDF，也不涉及内容缓存 schema 或 SQLite 迁移。
- **Brotli 可选**：本版本通过 gzip 达成压缩收益；如需要更高压缩率，可在部署层（如 nginx `brotli on;`）可选启用 Brotli 预压缩，运行时无需修改。

## English

v2.9.5 fixes a mojibake bug introduced by the unified parsing pipeline: when XHTML falls back to the HTML parser, UTF-8 bytes without an encoding declaration were decoded as latin-1, so real Unicode characters like the right single quote (`’`) came back as `â€™`, affecting some book descriptions and fallback-parsed chapters. The fallback now decodes bytes explicitly (BOM first, then a meta charset declaration, then UTF-8). It also enables gzip compression for Server responses and fixes the authentication middleware overriding content-addressed asset cache headers with `no-cache` — `/assets/immutable/` resources are immutable again for a year, so repeated visits stop revalidating every asset.

### Fixes and improvements

- **HTML-fallback encoding fix**: lxml's HTML parser decodes input whose encoding it cannot detect as latin-1, garbling the UTF-8 content EPUB mandates (`’` → `â\x80\x99`). `parse_xhtml_bytes`, `parse_xhtml_document`, and `parse_xhtml_fragment` now decode bytes explicitly before the fallback — a BOM wins, then a meta charset declaration, then UTF-8 — and strip XML declarations so lxml accepts the decoded string. Book-card descriptions no longer render `Donâ€™t`, while legacy documents declaring `meta charset="windows-1252"` are still decoded correctly.
- **gzip for Server responses**: Starlette's built-in GZipMiddleware now compresses text responses — HTML, JSON, JS, CSS, and SVG — while skipping already-compressed binary types (images, fonts, audio/video, archives), Range (206) responses, and payloads under 500 bytes, and adds `Vary: Accept-Encoding`. Transfer size for text drops substantially.
- **Immutable-asset cache fix**: The authentication middleware forced every authenticated response to `private, no-cache`, defeating the long-lived cache on `/assets/immutable/<hash>` and forcing a revalidation of every script and stylesheet on each page load. Content-addressed assets now keep `private, max-age=31536000, immutable`, so repeated visits see far fewer asset round-trips, with ETag conditional requests still supported.

### Affected scope

- **Deployment and format scope**: Server only (both EPUB and PDF benefit from compression and asset caching); SSG output is unchanged and needs no changes.
- **Trigger**: Server text responses larger than 500 bytes; authenticated requests to `/assets/immutable/` assets; book descriptions or chapters containing real UTF-8 punctuation that require HTML-fallback parsing.

### Upgrade notes

- **Restart the Server to pick it up**: compression and cache headers are runtime behaviour — no EPUB/PDF reconversion, content-cache schema change, or SQLite migration is needed.
- **Brotli optional**: this release delivers compression via gzip; for even higher ratios, enable Brotli pre-compression at the deployment layer (e.g. nginx `brotli on;`) with no runtime changes.
