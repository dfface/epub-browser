# EPUB Browser v2.3.0 — Governed AI reading and faster chapter changes

发布日期 / Release date: 2026-08-23

## 中文

v2.3.0 让 Server 模式的 AI 阅读更可治理、更可靠，也让大型私人书库的日常管理更轻。管理员可以查看并重试 AI 后台任务；书籍管理支持拼音检索、分页和按需编辑。普通滚动阅读换章不再重载整个阅读器页面；管理工作区与登录反馈也更加清晰、安全。

### 新功能

- **AI 任务管理**：管理员可以在管理面板按状态、分页查看 AI 阅读任务，了解进度和失败原因，并安全重试可重试的失败任务。重试会重新核对当前权限、书籍可见性、配置和阅读材料。
- **更高效的书籍管理**：书籍管理改为轻量索引，支持标题、作者、EPUB 标签和服务器标签的拼音/字面搜索、可见性与标签筛选、分页浏览。点击“管理”后才加载该书的完整设置，并用一次原子保存更新可见性、成员授权、标签和 AI 阅读档案。

### 改进

- **普通滚动换章更顺畅**：目录、前后章按钮和键盘切换现在只替换章节正文，阅读器外壳、主题与设置保持不变；浏览器前进/后退仍会还原正确章节。切章时 AI Canvas 会取消旧章节的异步状态，只恢复目标章节的结果，避免旧导读写入新正文。
- **长章节 AI 阅读更贴合模型窗口**：AI 阅读会按照当前模型的上下文窗口、输出预留和提示词预算压缩或分段材料，而不是依赖固定字符上限；超长章节仍可完成阅读任务。
- **更可靠的持久 AI 任务**：后台 worker 按实际执行的材料标识结果；内容在排队期间变化后，不会复用或写入过期缓存。强制生成和重试会重新生成，且同一执行材料仍保持单飞去重。
- **更清晰的管理工作区**：管理面板新增概览及“用户、AI 阅读、标签、书籍”分区导航，概览可显示当前数量并直接跳转。AI 设置按连接、执行限制、成员默认值和凭据分组，并明确显示未启用、已配置或仍需要 API Key 的状态。
- **更安全的管理操作**：保存和创建会显示进行中状态并防止重复提交；关闭含未保存变更的面板会先确认。清空缓存、删除标签、停用用户、修改角色和撤销会话都会先说明影响。标签列表还会显示关联的有效书籍数，书籍筛选可一键清除。
- **登录限流可解释**：密码尝试触发限流时，登录页会显示剩余等待分钟数，API 同时返回 `Retry-After`，不会再误报为用户名或密码错误。

### 稳定性与升级

- **更稳健的 SQLite 升级**：Server 数据库升级强化了外键、唯一约束和查询索引校验；升级前会安全创建 WAL 一致性备份。只读的旧数据库会在私有可写暂存副本中迁移，原文件保持不变。
- **无手工内容缓存迁移**：这次更新不改变 Server EPUB 内容缓存 schema，也不要求重新转换书籍。部署新版本并重启 Server 即可获得新的界面和阅读行为；SQLite 会自动执行兼容迁移。
- **SSG 保持纯静态**：任务管理、书籍管理、权限与 AI 能力仍只存在于 Server 模式；静态站点不会加载这些 API 或账户数据。

## English

v2.3.0 makes Server-mode AI reading easier to govern and more reliable, while keeping day-to-day library administration light. Administrators can inspect and retry AI background work; book management adds pinyin search, paging, and on-demand editing. Normal scrolling can now change chapters without reloading the entire reader, and administration and sign-in feedback are clearer and safer.

### New features

- **AI job management**: Administrators can browse paginated AI-reading jobs by status, inspect progress and failures, and safely retry eligible failures. A retry rechecks current access, book visibility, configuration, and reading material.
- **Efficient book management**: The book manager now uses a lightweight index with pinyin and literal search across titles, authors, EPUB tags, and server tags, plus visibility/tag filters and paging. Full settings load only after choosing Manage, and one atomic save updates visibility, member access, tags, and the AI-reading profile.

### Improvements

- **Smoother normal-scroll chapter changes**: Contents links, chapter controls, and keyboard navigation now replace only the chapter body, preserving the reader shell, theme, and preferences. Browser Back and Forward still restore the correct body. AI Canvas cancels prior-chapter async state on a change and restores only the target chapter, so an older guide cannot land in new text.
- **Long-chapter AI reading that respects model limits**: AI reading budgets material against the configured model context window, prompt overhead, and output reserve rather than a fixed character limit; exceptionally long chapters can still complete.
- **Reliable durable AI jobs**: Workers identify results from the material they actually execute. If a book changes while work is queued, stale cache entries are neither reused nor written. Forced generations and retries regenerate, while matching executed material remains single-flight deduplicated.
- **Clearer administration workspace**: An overview plus Users, AI reading, Tags, and Books navigation makes administration easier to scan and jump through. AI settings group connection, execution limits, member defaults, and credentials, and clearly report whether AI is disabled, configured, or still needs an API key.
- **Safer administrative actions**: Save and create controls show in-progress state and prevent duplicate submissions; closing a panel with unsaved changes asks first. Cache clearing, tag deletion, user disabling, role changes, and session revocation explain their effect before proceeding. Tags show their active-book usage and book filters can be reset in one click.
- **Explainable sign-in throttling**: When password attempts trigger throttling, the login page shows the remaining wait in minutes and the API returns `Retry-After`, rather than presenting the result as invalid credentials.

### Stability and upgrade notes

- **Hardened SQLite upgrades**: Server database upgrades strengthen foreign keys, uniqueness rules, and query-index verification, with WAL-consistent backups. A read-only legacy database migrates through a private writable staging copy, leaving the original untouched.
- **No manual content-cache migration**: This release does not change the Server EPUB content-cache schema or require reconverting books. Deploy and restart the Server for the new UI and reading behavior; SQLite compatibility migration runs automatically.
- **SSG remains static**: Job administration, book administration, access control, and AI capabilities remain Server-only. Static output does not load these APIs or account data.
