# EPUB Browser v2.9.7 — Server 模式 Kindle 极简支持与阅读进度读写

发布日期 / Release date: 2026-08-31

## 中文

v2.9.7 把上一版引入的 Kindle 极简模式带到了 Server 部署：`--kindle` 现在同时作用于 SSG 与 Server。Server 模式下，库首页自动把真实的 e-Ink Kindle（老 WebKit）重定向到免依赖的极简书架页 `/kindle-library.html`，每本书的 `kindle.html` 与 `kindle_chapter_N.html` 也由服务端按需渲染，无需预生成；极简书架与书页均要求登录。针对 Kindle 阅读进度，极简页面从"只上报"升级为"读写"：页面先取 CSRF token，再读取服务端已保存的阅读位置（镜像进 cookie 供目录页定位），随后把当前章节写回服务端，跨设备继续阅读跟随服务端进度；心跳仍保持只上报。同时为没有 fetch 的老 Kindle WebKit 增加了无 JavaScript 登录回退（表单直发 + nonce 校验）。Kindle 书页顶部的书名链接现在回到 Kindle 模式的极简书架，而非完整阅读器。

### 新功能

- **Server 模式 `--kindle`（opt-in）**：`epub-browser serve --kindle`（及旧式命令的对应开关）开启 Kindle 支持。库页头部在 Kindle WebKit 浏览器中自动重定向到 `/kindle-library.html` 极简书架；`/book/<id>/kindle.html` 与 `kindle_chapter_N.html` 由服务端动态渲染（沿用与 SSG 完全一致的 ES5 内联页面），均受登录保护，书架只读、不暴露管理操作。
- **Kindle 阅读进度读写**：Server 模式下极简章节页先 `GET /api/csrf` 获取 CSRF token，`GET /api/reading-progress/{hash}` 读取服务端已存位置并镜像到本地 cookie，再 `PUT` 当前章节写回；目录页的 "Continue reading" 同样优先跟随服务端进度（只读，绝不写入）。心搏 `POST` 保持只上报。
- **无 JavaScript 登录回退**：登录表单新增隐藏 `auth_nonce` 字段；没有 `fetch` 的旧 Kindle WebKit 直接以表单 POST 登录，服务端按同源 + cookie nonce 校验，与 OIDC 关联表单同一套机制。

### 修复与改进

- **书名链接回到极简库**：Kindle 书页顶部的书名链接按部署模式指向 Kindle 模式书架——SSG 为相对链接 `kindle-library.html`（`file://` 打开同样可用），Server 为绝对路由 `/kindle-library.html`（避免相对解析到 `/book/<id>/kindle-library.html`）。页脚 "Open full reader"（`index.html?full=1`）保持不变。
- **页面脚注样式细节**：极简页面与书架沿用现有 Kindle 内联样式，深色/浅色主题一致，无任何外部资源依赖。

### 影响范围

- **部署与格式范围**：改动集中在 Server 模式的 Kindle 入口（书架、书页、登录回退）与两模式共用的极简页面脚本；仅 EPUB 书籍提供 Kindle 极简页面，PDF 书请求 `kindle.html` 返回 404。
- **触发条件**：以 `--kindle` 启动 Server 后用 e-Ink Kindle 或 Kindle WebKit 浏览器访问；Kindle 上打开极简章节页（进度读写）；无 fetch 的浏览器在 Server 上登录。

### 升级说明

- **Server 部署**：重启 Server 并加上 `--kindle` 开关即可；登录页面与 Kindle 书页均为请求时渲染，无需重新转换书籍。
- **SSG 部署**：不受影响（上一版行为保持不变）。
- **无需配置**：不涉及内容缓存 schema 或 SQLite 迁移；阅读进度走既有 `reading-progress` API。

## English

v2.9.7 brings the Kindle minimal mode introduced last release to Server deployments: `--kindle` now works for both SSG and Server. In Server mode the Library homepage automatically redirects real e-Ink Kindles (legacy WebKit) to the dependency-free minimal shelf at `/kindle-library.html`, and each book's `kindle.html` and `kindle_chapter_N.html` are rendered on demand — nothing to pre-generate; both the shelf and the book pages require login. Kindle reading progress is now read-write on the minimal surface: the page fetches a CSRF token, loads the server-side saved position (mirrored into the cookie so the index can resume it), then writes the current chapter back, so continue-reading follows the server across devices; heartbeats stay report-only. A no-JavaScript login fallback (plain form POST with a nonce) covers legacy Kindle WebKit without `fetch`. The book-title link on Kindle pages now returns to the Kindle minimal shelf instead of the full reader.

### New features

- **Server-mode `--kindle` (opt-in)**: `epub-browser serve --kindle` (and the equivalent legacy-invocation flag) enables Kindle support. The Library shell redirects Kindle WebKit browsers to the `/kindle-library.html` minimal shelf; `/book/<id>/kindle.html` and `kindle_chapter_N.html` are rendered dynamically (identical ES5 inline pages to SSG) and require login; the shelf is read-only with no management actions.
- **Read-write Kindle progress**: on the minimal chapter page the script fetches a CSRF token via `GET /api/csrf`, reads the stored position from `GET /api/reading-progress/{hash}` (mirrored into a cookie), then `PUT`s the current chapter back; the index's "Continue reading" also follows the server-side progress first (read-only, never writes). Heartbeat `POST`s stay report-only.
- **No-JavaScript login fallback**: the login form gains a hidden `auth_nonce` field; legacy Kindle WebKit without `fetch` submits a plain form POST validated via same-origin plus cookie nonce — the same mechanism as the OIDC association form.

### Fixes and improvements

- **Title links back to the minimal shelf**: the book-title link on Kindle pages points to the Kindle shelf per deployment mode — a relative `kindle-library.html` for SSG (works from `file://`) and the absolute route `/kindle-library.html` for Server (avoiding mis-resolution under `/book/<id>/kindle-library.html`). The "Open full reader" footer link (`index.html?full=1`) is unchanged.
- **Scope safety**: Kindle minimal pages exist only for EPUB books; requesting `kindle.html` for a PDF returns 404.

### Affected scope

- **Deployment and format scope**: Server-mode Kindle entry points (shelf, book pages, login fallback) plus the shared minimal-page scripts used by both modes; EPUB only — PDF books have no Kindle pages.
- **Trigger**: starting the Server with `--kindle` and browsing from an e-Ink Kindle or Kindle WebKit browser; opening a minimal chapter on a Kindle (read-write progress); logging in from a browser without `fetch`.

### Upgrade notes

- **Server**: restart with the `--kindle` flag; login pages and Kindle book pages render at request time, so no book reconversion is needed.
- **SSG**: unaffected (behaviour from the previous release is unchanged).
- **No configuration required**: no content-cache schema change or SQLite migration; progress uses the existing `reading-progress` API.
