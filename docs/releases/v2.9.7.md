# EPUB Browser v2.9.7 — Kindle 极简模式（SSG 与 Server）与阅读进度读写

发布日期 / Release date: 2026-08-31

## 中文

v2.9.7 引入了面向旧式 e-Ink Kindle 的极简模式，并同时覆盖 SSG 与 Server 两种部署。开启 `--kindle` 后，站点会为 Kindle WebKit 浏览器生成/渲染一套完全无外部依赖的页面：库页头部脚本把真实的 e-Ink Kindle（UA 含 `kindle` 且非 Silk）重定向到极简书架页，Kindle Fire（Silk）与 `?full=1` 仍保留完整 UI。极简页面全部为内联 ES5 CSS/JS，不含任何 `/assets/` 引用，主题、字号与阅读位置保存在 cookie 中，界面文案按书籍语言内联解析。SSG 模式下转换时额外写出 `kindle-library.html` 与每本书的 `kindle.html`、`kindle_chapter_N.html`；Server 模式下这些页面由服务端按需渲染（书架与书页均要求登录，书架只读）。阅读进度在极简面上保持读写：页面先取 CSRF token、读取服务端已存位置（镜像进 cookie），再把当前章节写回，跨设备继续阅读跟随服务端进度；心跳只上报。没有 `fetch` 的旧 Kindle WebKit 还可通过隐藏 nonce 的表单直发登录。Kindle 书页顶部的书名链接回到极简书架，而非完整阅读器。

### 新功能

- **`--kindle` 极简模式（SSG 与 Server）**：`epub-browser ssg --kindle` 与 `epub-browser serve --kindle`（含旧式调用开关）开启。库页头部脚本检测真实 e-Ink Kindle（UA 含 `kindle` 且不含 Silk）并重定向到极简书架；Silk / `?full=1` 保持完整 SPA。
- **极简书架页 `kindle-library.html`**：每本书一行、直链该书极简阅读器；SSG 输出在站点根目录，Server 渲染在 `/kindle-library.html`（登录后只读，无管理操作）。
- **极简书页与章节页**：每本书生成 `kindle.html`（目录 + Continue reading + 章节列表）与 `kindle_chapter_N.html`（正文、主题切换、字号调整、上一章/下一章与章节跳转）。全部 CSS/JS 内联、ES5、零外部资源；`kindle_theme` / `kindle_font_size` / 阅读位置存 cookie；文案按书籍语言内联解析，Kindle 无需加载 `i18n.js`。
- **阅读进度读写（Server）**：极简章节页先 `GET /api/csrf` 取 CSRF token，`GET /api/reading-progress/{hash}` 读取服务端已存位置并镜像进 cookie，再 `PUT` 当前章节写回；目录页 "Continue reading" 优先跟随服务端进度（只读，绝不写入）；心跳 `POST` 保持只上报。
- **无 JavaScript 登录回退（Server）**：登录表单新增隐藏 `auth_nonce` 字段；没有 `fetch` 的旧 Kindle WebKit 直接表单 POST 登录，服务端按同源 + cookie nonce 校验（与 OIDC 关联表单同一机制）。

### 修复与改进

- **书名链接回到极简库**：Kindle 书页顶部书名按部署模式指向 Kindle 模式书架——SSG 相对链接 `kindle-library.html`（`file://` 打开可用），Server 绝对路由 `/kindle-library.html`（避免相对解析到 `/book/<id>/kindle-library.html`）；页脚 "Open full reader"（`index.html?full=1`）保持不变。
- **范围安全**：极简页面仅 EPUB 书籍提供；PDF 请求 `kindle.html` 返回 404。未开启 `--kindle` 时 SSG 不输出极简页、Server 相关路由返回 404。
- **配套重构**：把 `setCookie` / `getCookie` / `deleteCookie` / `isKindleMode` 等工具函数从共享资产抽出并清理资产内的 Kindle 分支，极简页自包含这些逻辑。

### 影响范围

- **部署与格式范围**：SSG 生成期新增极简页面输出；Server 新增 Kindle 入口（书架、书页、登录回退）与共用极简页面脚本；仅 EPUB。SSG 模式为 opt-in 输出，默认行为不变。
- **触发条件**：`ssg --kindle` / `serve --kindle` 后，用 e-Ink Kindle 或 Kindle WebKit 浏览器访问站点；Kindle 上打开极简章节页（进度读写）；无 `fetch` 的浏览器在 Server 上登录。

### 升级说明

- **Server 部署**：重启并加 `--kindle` 开关；登录页与 Kindle 书页均为请求时渲染，无需重新转换书籍。
- **SSG 部署**：需要 `ssg --kindle` 重新生成静态站点（默认关闭，不加开关输出与之前完全一致）。
- **无需配置**：不涉及内容缓存 schema 或 SQLite 迁移；阅读进度走既有 `reading-progress` API。

## English

v2.9.7 introduces a dependency-free minimal mode for legacy e-Ink Kindles, covering both SSG and Server deployments. With `--kindle` enabled the site generates/renders pages with zero external dependencies for Kindle WebKit browsers: a header script redirects real e-Ink Kindles (user agent contains `kindle`, not Silk) to a minimal shelf, while Kindle Fire (Silk) and `?full=1` keep the full UI. The minimal pages are fully inlined ES5 CSS/JS with no `/assets/` references; theme, font size, and reading position live in cookies, and UI strings are inlined per book language. In SSG mode the conversion additionally writes `kindle-library.html` plus per-book `kindle.html` and `kindle_chapter_N.html`; in Server mode these are rendered on demand (the shelf and book pages require login; the shelf is read-only). Reading progress is read-write on the minimal surface: the page fetches a CSRF token, loads the server-side position (mirrored into the cookie), then writes the current chapter back, so continue-reading follows the server across devices; heartbeats stay report-only. Legacy Kindle WebKit without `fetch` can still sign in via a plain form POST carrying a hidden nonce. The book-title link on Kindle pages returns to the minimal shelf instead of the full reader.

### New features

- **`--kindle` minimal mode (SSG and Server)**: `epub-browser ssg --kindle` and `epub-browser serve --kindle` (and the legacy-invocation flag) enable it. A header script detects real e-Ink Kindles (UA contains `kindle`, not Silk) and redirects to the minimal shelf; Silk / `?full=1` keep the full SPA.
- **Minimal shelf `kindle-library.html`**: one plain row per book linking straight into that book's minimal reader; written at the site root by SSG, rendered at `/kindle-library.html` by Server (authenticated, read-only, no management actions).
- **Minimal book and chapter pages**: each book gets `kindle.html` (contents, Continue reading, chapter list) and `kindle_chapter_N.html` (text, theme toggle, font size, prev/next and chapter jumping). All CSS/JS is inlined, ES5, with zero external resources; `kindle_theme` / `kindle_font_size` / reading position are cookie-based; strings are inlined per book language so the Kindle never loads `i18n.js`.
- **Read-write reading progress (Server)**: the minimal chapter page fetches a CSRF token via `GET /api/csrf`, reads the stored position from `GET /api/reading-progress/{hash}` (mirrored into a cookie), then `PUT`s the current chapter back; the index's "Continue reading" follows the server-side progress first (read-only, never writes); heartbeat `POST`s stay report-only.
- **No-JavaScript login fallback (Server)**: the login form gains a hidden `auth_nonce` field; legacy Kindle WebKit without `fetch` submits a plain form POST validated via same-origin plus cookie nonce — the same mechanism as the OIDC association form.

### Fixes and improvements

- **Title links back to the minimal shelf**: the book-title link on Kindle pages points to the Kindle shelf per deployment mode — a relative `kindle-library.html` for SSG (works from `file://`) and the absolute route `/kindle-library.html` for Server (avoiding mis-resolution under `/book/<id>/kindle-library.html`). The "Open full reader" footer link (`index.html?full=1`) is unchanged.
- **Scope safety**: minimal pages exist only for EPUB books; requesting `kindle.html` for a PDF returns 404. Without `--kindle`, SSG writes no minimal pages and Server routes return 404.
- **Supporting refactor**: `setCookie` / `getCookie` / `deleteCookie` / `isKindleMode` helpers were pulled out of the shared assets and the in-asset Kindle branches cleaned up; the minimal pages now carry that logic themselves.

### Affected scope

- **Deployment and format scope**: SSG gains minimal-page output at generation time; Server gains Kindle entry points (shelf, book pages, login fallback) and shares the minimal-page scripts; EPUB only. SSG output is opt-in, so the default build is unchanged.
- **Trigger**: running `ssg --kindle` / `serve --kindle` and browsing from an e-Ink Kindle or Kindle WebKit browser; opening a minimal chapter on a Kindle (read-write progress); logging in from a browser without `fetch` on the Server.

### Upgrade notes

- **Server**: restart with the `--kindle` flag; login pages and Kindle book pages render at request time, so no book reconversion is needed.
- **SSG**: regenerate the static site with `ssg --kindle` (off by default; builds without the flag are byte-for-byte unchanged in behaviour).
- **No configuration required**: no content-cache schema change or SQLite migration; progress uses the existing `reading-progress` API.
