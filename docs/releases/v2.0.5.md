# EPUB Browser v2.0.5

发布日期 / Release date: 2026-08-20

## 中文

v2.0.5 将稳定书籍身份的默认载体改为源 EPUB 旁边的可见 sidecar，同时保留显式写入 OPF 的选择。

### 新功能与行为变化

- **默认使用可见 sidecar**：SSG、Server、`--watch` 和旧版命令语法默认使用 `--book-id-storage sidecar`，生成 `BOOK.epub.epub-browser.json`，不改写 EPUB 字节。
- **整条命令统一选择**：可用 `--book-id-storage embedded` 为一次命令中的所有书籍选择 OPF 内嵌模式。该模式可能重建 EPUB ZIP；只读、签名、链接或不受支持的源文件会被拒绝，不再退回 database-only ID。
- **平滑迁移 v2.0.4 身份**：已有 OPF 内嵌 ID 会原值复制到 sidecar，既不重写 EPUB，也不删除内嵌元数据。切换载体时同样保留未选中的载体。
- **基于指纹的复用与移动识别**：Server 只有在已验证源指纹与数据库一致且缓存有效时才复用内容。仅移动未修改 EPUB 时，可通过唯一 SHA-256 匹配的孤立 sidecar/非活跃记录恢复原 ID。
- **明确拒绝不确定状态**：载体 ID 不一致、活动书籍重复 ID、多个移动候选或多个非活跃候选都会报错，不会自动猜测或修复。

### 安全与兼容性

- 恢复了示例目录中 EPUB 的原始字节，既有公开 ID 改由相邻 sidecar 保存；GitHub Pages 流程会比较生成前后的输入哈希，防止再次意外改写。
- `book_id` 仍与 URL 和客户端数据中的 `book_hash` 完全相同，现有公开链接无需改变。
- 不需要数据库 schema 迁移；已有标注、阅读进度、书架和缓存关联保持不变。

## English

v2.0.5 makes a visible sidecar beside each source EPUB the default stable-identity carrier while retaining explicit OPF storage.

### Features and behavior changes

- **Visible sidecars by default**: SSG, Server, `--watch`, and legacy syntax default to `--book-id-storage sidecar`, creating `BOOK.epub.epub-browser.json` without changing EPUB bytes.
- **One invocation-wide choice**: `--book-id-storage embedded` selects OPF storage for every book in the command. It may rebuild the EPUB ZIP; read-only, signed, linked, or unsupported sources are refused, with no database-only fallback.
- **Safe v2.0.4 migration**: Existing embedded OPF IDs are copied unchanged into sidecars without rewriting the EPUB or deleting embedded metadata. Switching carriers also leaves the non-selected carrier intact.
- **Fingerprint-based reuse and move recognition**: Server reuses generated content only when a verified source fingerprint agrees with the database and the cache is valid. Moving an unchanged EPUB can recover its ID from one unique SHA-256-matching orphan sidecar or inactive record.
- **Explicit uncertainty failures**: Disagreeing carriers, duplicate active IDs, multiple move sidecars, and ambiguous inactive records now fail instead of being guessed or repaired automatically.

### Safety and compatibility

- The original example EPUB bytes have been restored and their established public IDs now live in adjacent sidecars. The GitHub Pages workflow compares input hashes before and after generation to prevent future source mutation.
- `book_id` remains exactly the same value as URL/client `book_hash`, so established public URLs do not change.
- No database schema migration is required; annotations, reading progress, bookshelves, and existing cache relationships remain intact.
