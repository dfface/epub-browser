# EPUB Browser v1.10.5

发布日期 / Release date: 2026-08-12

## 中文

这是一个为 **server 模式**加入章节阅读进度同步的维护版本。

### 改进

- **服务端保存最后阅读章节**：server 模式会将每位用户、每本书的最后阅读章节写入服务器 SQLite 数据库。重新打开书籍时，阅读器会从服务器读取该记录，并将“继续阅读”定位到已同步的章节。
- **连续阅读也能同步**：在连续滚动阅读、切换章节，以及关闭或刷新页面前，阅读器都会上报当前章节；不再仅依赖浏览器本地的章节记录。
- **请求乱序不回退进度**：客户端将章节更新串行化，并忽略过期请求的失败结果，避免网络延迟或页面卸载时的请求把较新的章节记录误判为失败。
- **可从书籍页清除**：使用“清除阅读进度”时，浏览器本地记录和对应的服务端章节记录都会一并删除。

### 兼容性

本地阅读记录仍会保留，作为离线和兼容性回退。新接口为 `GET`、`PUT`、`DELETE /api/reading-progress/{book_hash}`，按现有 server 模式的用户名标识隔离记录；书架 `/sync` 接口不受影响。服务端同步的是章节，不包含章节内的滚动位置或翻页位置。

## English

This maintenance release adds chapter-level reading-progress synchronization for **server mode**.

### Improvements

- **Server-side last-chapter storage**: Server mode stores the last-read chapter for each user and book in its SQLite database. When the book is opened again, the reader retrieves that record and uses it for Continue Reading.
- **Continuous reading is covered**: The reader reports the active chapter during continuous scrolling, when changing chapters, and before a page closes or reloads. Progress is no longer limited to the browser's local chapter record.
- **Out-of-order requests do not roll progress back**: Chapter updates are serialized, and failures from stale requests are ignored so network latency or unload-time requests cannot incorrectly supersede newer progress.
- **Clear progress everywhere**: Clear Reading Progress removes both the local browser record and the corresponding server-side chapter record.

### Compatibility

Local reading records remain available as an offline and compatibility fallback. The new endpoints are `GET`, `PUT`, and `DELETE /api/reading-progress/{book_hash}`; records are scoped by the username identity already used by server mode, while the bookshelf `/sync` API is unchanged. Server synchronization records the chapter only, not an in-chapter scroll or paginated position.
