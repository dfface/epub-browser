# EPUB Browser v2.2.1 — EPUB compatibility and reading-summary fixes

发布日期 / Release date: 2026-08-22

## 中文

v2.2.1 修复部分由不同工具生成的 EPUB 无法写入稳定书籍 ID 或更新 Server 缓存的问题，并让标注与 AI 阅读汇总显示更完整的章节信息。失败的书籍可以在升级后重新扫描，无需手工修改原书。

### 修复

- **兼容带换行的 EPUB mimetype**：当 `mimetype` 的正确值后仅多出 CR/LF 换行时，现在可以安全写入 embedded `book_id`。重写仍保留原有 ZIP 条目顺序、压缩方式和非 OPF 内容。
- **保留根相对章节链接**：`/leetcode/...` 一类根相对导航链接不再被误判为 EPUB 压缩包内部绝对路径，修复 `Unsafe EPUB internal path` 导致的章节转换失败。
- **补全汇总中的章节信息**：标注汇总现在显示零基章节编号和 TOC 标题；AI 阅读汇总会从当前 Server 内容缓存读取章节标题，不再只显示 `Chapter N`。
- **稳定 AI 后台任务生命周期**：多个应用生命周期同时启动或停止时，各事件循环会独立管理 AI worker，避免跨事件循环的任务异常。

### 安全与升级

- 只容忍 `mimetype` 正确值末尾的 CR/LF；缺失或包含其它内容的 `mimetype` 仍会被拒绝。
- EPUB 内部路径、目录穿越、加密条目、签名书籍和不支持的压缩方式继续执行原有安全检查。
- 不需要数据库迁移，也没有配置、命令行或 Server 内容缓存 schema 变更。汇总标题在重启 Server 后即可更新，无需重转书籍；此前更新失败的书籍会在重新扫描时正常转换。

## English

v2.2.1 fixes EPUBs produced by some authoring tools failing to receive a stable book ID or refresh their Server cache, and gives annotation and AI-reading summaries more complete chapter labels. Previously failed books can be scanned again after upgrading without manually editing the source EPUB.

### Fixes

- **EPUB mimetype line-ending compatibility**: An otherwise correct `mimetype` value with trailing CR/LF line endings can now be safely rewritten with an embedded `book_id`. ZIP entry order, compression metadata, and non-OPF content remain preserved.
- **Root-relative chapter navigation**: Links such as `/leetcode/...` are no longer interpreted as absolute paths inside the EPUB archive, preventing `Unsafe EPUB internal path` chapter-conversion failures.
- **Complete chapter labels in summaries**: Annotation summaries now combine the zero-based chapter number with the TOC title. AI-reading summaries load chapter titles from the current Server content cache instead of falling back to `Chapter N` alone.
- **Stable AI background lifecycle**: Concurrent application lifecycles now keep AI workers isolated to their own event loops, preventing cross-loop task failures during startup or shutdown.

### Security and upgrade notes

- Only CR/LF after the correct `mimetype` value is tolerated. Missing entries or values with other content are still rejected.
- Existing checks for EPUB internal paths, directory traversal, encrypted entries, signed books, and unsupported compression remain in force.
- No database migration, configuration/CLI change, or Server content-cache schema change is required. Summary labels update after a Server restart without reconverting books; books that previously failed can convert normally on the next scan.
