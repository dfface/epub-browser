# EPUB Browser v2.6.0 — 可复现的本地浏览器依赖

发布日期 / Release date: 2026-08-29

## 中文

v2.6.0 让 EPUB Browser 的浏览器资源更容易审计、复现和离线交付。发布包、Docker 镜像和 SSG 输出继续保持自包含，不需要在阅读时访问公共 CDN；每项第三方资源现在都有明确版本、来源、摘要和许可证记录。

### 新功能

- **锁定的浏览器依赖供应链**：Font Awesome、highlight.js、KaTeX、markdown-it、Mermaid、pinyin-pro、SortableJS、web-highlighter、GLightbox 和 PDF.js 都从固定的上游归档生成。构建过程校验归档与文件摘要、大小边界、许可证和允许安装的文件集合，异常内容会直接阻止发布。
- **本地 PDF.js 运行资源**：PDF.js `6.2.108` 的主模块和 worker 由同一份锁定包提供，并随发布产物一起交付，不会混用 CDN worker。这为后续 PDF 阅读能力提供可验证的本地渲染基础；本版本本身不宣称开放 PDF 阅读入口。
- **可验证的离线发布产物**：wheel 和 source distribution 都包含运行所需的浏览器资源、许可证、来源锁和第三方声明。发布门禁会在禁网环境中从 source distribution 重建 wheel，并与直接构建的 wheel 核对必要文件清单。

### 改进

- **图片预览采用 MIT 组件**：GLightbox `3.3.1` 替代 Fancybox，同时保留阅读器内的图片放大、关闭和章节切换生命周期。项目适配层会隔离 EPUB 图片与第三方组件配置，避免书籍内容进入不受信任的宿主页面路径。
- **运行时继续完全本地化**：Server、SSG 和已安装 wheel 只使用本地、带内容 hash 的不可变资源，不会在启动、打开书籍或安装已构建 wheel 时下载浏览器依赖。
- **许可证信息更完整**：Mermaid 与 PDF.js 预构建 bundle 中包含的组件被逐项登记；这不会让浏览器分别加载这些包，但能让发布者准确核对再分发义务。
- **一致的构建流程**：本地开发、GitHub Pages、PyPI 和 Docker 使用同一份锁与校验器。源码目录不会静默联网，开发者可显式运行 `python3 tools/sync_vendor_assets.py fetch` 完成首次水合。

### 修复

- 修复偶发损坏的上游归档响应会立即中断长批次水合的问题；下载器会有限重试，但只有摘要完全匹配的归档才能进入生成目录。
- 加强归档路径、符号链接、硬链接、特殊文件、重复成员、展开大小和重定向协议检查，避免不安全内容越过 vendor 目录边界。
- 加强 wheel、source distribution 和 Docker 发布校验，拒绝非规范路径、大小写或 Unicode 冲突、陈旧重建证据及被篡改的发布产物。

### 升级说明

- 从 PyPI wheel 或正式 Docker 镜像升级的用户无需额外下载浏览器依赖，也无需重新转换 EPUB。Server 更新后重启即可；SSG 部署需要重新生成并完整发布输出目录。
- 从 Git checkout 运行或自行构建发行包的开发者，需要先执行 `python3 tools/sync_vendor_assets.py fetch`，随后可用 `python3 tools/sync_vendor_assets.py verify` 完全离线校验生成目录。
- 本版本不修改 Server SQLite schema、EPUB 内容缓存 schema 或公开 API，也不提高 Server 内容缓存修订。

## English

v2.6.0 makes EPUB Browser's browser assets reproducible, auditable, and safe to deliver offline. Wheels, Docker images, and SSG output remain self-contained and require no public CDN while reading; every redistributed browser dependency now has an exact version, source, digest, and license record.

### New features

- **Locked browser-asset supply chain**: Font Awesome, highlight.js, KaTeX, markdown-it, Mermaid, pinyin-pro, SortableJS, web-highlighter, GLightbox, and PDF.js are generated from exact upstream archives. Builds verify archive and file digests, size limits, licenses, and an explicit installation allowlist, failing the release when any check differs.
- **Locally packaged PDF.js runtime**: The PDF.js `6.2.108` main module and worker come from the same locked package and ship with release artifacts, so a local module is never paired with a CDN worker. This provides a verifiable rendering foundation for later PDF reading support; this release does not claim to expose a PDF reader entry point by itself.
- **Offline-verifiable release artifacts**: Wheels and source distributions include the required browser assets, licenses, source lock, and third-party notices. The release gate rebuilds a wheel from the source distribution without network access and compares its required inventory with the directly built wheel.

### Improvements

- **MIT-licensed image previews**: GLightbox `3.3.1` replaces Fancybox while preserving in-reader image zoom, dismissal, and chapter-navigation lifecycle. The project adapter keeps EPUB image data isolated from third-party host-page configuration.
- **Fully local runtime delivery**: Server, SSG, and installed wheels use only local content-addressed immutable assets. Starting the application, opening a book, or installing an already-built wheel never downloads browser dependencies.
- **Complete license attribution**: Components bundled inside the prebuilt Mermaid and PDF.js files are recorded individually. Browsers do not load those packages separately, but publishers can now audit their redistribution obligations accurately.
- **One build contract everywhere**: Local development, GitHub Pages, PyPI, and Docker use the same lock and verifier. A source checkout never contacts the network implicitly; developers explicitly run `python3 tools/sync_vendor_assets.py fetch` for first-time hydration.

### Fixes

- Fixed transiently corrupted upstream archive responses aborting a long hydration run immediately. Downloads now retry a bounded number of times, while only an archive with the exact locked digest can enter the generated tree.
- Hardened archive-path, symlink, hardlink, special-file, duplicate-member, expansion-size, and redirect-protocol checks so unsafe content cannot escape the vendor root.
- Hardened wheel, source-distribution, and Docker release verification against non-canonical paths, case or Unicode collisions, stale rebuild evidence, and tampered artifacts.

### Upgrade notes

- Users upgrading from a PyPI wheel or official Docker image do not need to download browser dependencies separately or reconvert EPUB files. Restart an updated Server deployment; regenerate and publish the complete output directory for SSG deployments.
- Developers running from a Git checkout or building distributions must first run `python3 tools/sync_vendor_assets.py fetch`. `python3 tools/sync_vendor_assets.py verify` then validates the generated tree completely offline.
- This release does not change the Server SQLite schema, EPUB content-cache schema, public APIs, or Server content-cache revision.
