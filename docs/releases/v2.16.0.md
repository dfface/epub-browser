# v2.16.0

## 新功能

- **Kindle 模式支持 PDF（#17）**：启用 `--kindle` 后，PDF 每页在转换时渲染为图片（`kindle_pdf/page_N.jpg`），并与 EPUB 共用同一套 Kindle 阅读外壳：导航 dock、阅读设置、进度、目录和空状态。书籍页统一为 `kindle.html`，章节页为 `kindle_chapter.html`；没有目录时显示提示与章节/页码跳转，书库条目打开书籍页，「继续阅读」直达已保存的章节或页。SSG 与 Server 均输出这些页面；Server 的页图片是按需生成的派生缓存，随书籍缓存淘汰一并清理。加密或无法渲染的 PDF 只在书籍页显示不支持提示，书库链接仍可打开。
- **Kindle 屏保周起始日**：账户设置可选择一周从周一或周日开始，月历与星期标签按所选设置显示，默认周一。新增文案覆盖 17 种语言。
- **阅读快捷键与导航（#62）**：`Ctrl/Cmd+C` 复制划选文字（标注高亮会清除原生选区），`Ctrl/Cmd+K` 在书库、书籍页和章节页打开搜索；章节目录跟随当前阅读位置并提供「定位当前章节」按钮；桌面与移动端新增返回书籍首页的快捷按钮，与浮动「回到顶部」并存。
- **Docker 默认启用 Kindle 极简模式**：官方镜像的 `CMD` 与多语言文档加入 `--kindle`，无需手动追加参数即可使用 Kindle 页面。

## 改进

- **Server 与 PDF 性能**：一次书库协调内复用每本书的缓存校验结果，避免每次转换后重复校验（#64）；全书搜索只为命中结果页的章节构建 UTF-16 偏移表，300 章中文索引的零命中查询从约 529 ms 降至 7 ms（#65）；PDF 页派生元数据按 Server 缓存代际缓存（#67）；PDF.js 全文检索按页复用已提取文本，使用上限 500 万字符的 LRU 缓存（#66）。新增 `tools/benchmark_server_reconcile.py`，用于测量协调耗时、首个可读书籍耗时与缓存校验次数。

## 修复

- PDFium 渲染加全局锁，避免并发生成 Kindle 页图片时报「Unable to render PDF page」。
- 为旧版 Chromium 补齐 PDF.js 6 所需的 JavaScript API（主线程与模块 Worker）；确实不支持时显示浏览器升级提示，而不是反复报告加载失败。
- 被淘汰的 Kindle PDF 页缓存会从源文件自动重建，不再误报书籍不支持；初始化流程允许多个待处理 setup nonce，重复打开 `/setup` 不再失败。
- PDF 页面加载失败、无目录与跳页等状态补充明确提示，并提供 17 语言文案。

### 影响范围

- Kindle PDF 页面、共享阅读器模板与快捷键覆盖 SSG 与 Server（EPUB / PDF）；Kindle 周起始日、屏保设置与按需页图片缓存为 Server 专属。
- Docker 部署的默认行为变化：镜像现在默认带 `--kindle`；不希望生成 Kindle 页面时需显式覆盖 `CMD`。
- EPUB `content/` 与 PDF 缓存修订均未变（`server-content-v11`、`server-pdf-v2`）；Kindle 页图片是可选或按需生成的派生内容，不要求重转已有书籍。

### 升级说明

- Server：部署并重启即可，无需重新转换 EPUB 或 PDF。启动时自动为 `kindle_screensavers` 增加 `week_start` 列，SQLite `user_version` 提升到 34；升级前建议备份 `data/`，回退到旧版本需恢复升级前的数据库。
- 使用 `--kindle` 的部署首次打开某本 PDF 的 Kindle 页面时按需生成页图片；这些图片属于派生缓存，会在书籍缓存淘汰时清理，再次打开时重新生成。
- SSG：需重新生成并整站发布静态输出，以生成 PDF 的 `kindle_pdf/page_N.jpg`、`kindle.html`、`kindle_chapter.html`，以及新的哈希资源与 i18n 包。
- Docker 用户：新镜像默认启用 `--kindle`；若沿用自定义 `CMD`，需自行决定是否添加该参数。
- 书籍 URL、CLI 参数含义与内容缓存格式均未变化。

## Features

- **Kindle reading for PDF books (#17)**: With `--kindle`, each PDF page is rendered to an image (`kindle_pdf/page_N.jpg`) during conversion and shares the EPUB Kindle shell: navigation dock, reading settings, progress, TOC and empty states. Book pages use `kindle.html` and chapter pages `kindle_chapter.html`. Books without a TOC show a hint plus a chapter/page jump, shelf entries open the book page, and "continue reading" deep-links to the saved chapter or page. Both SSG and Server emit these pages; on Server, page images are lazily generated derived cache and are removed when the book cache is evicted. Encrypted or un-renderable PDFs show an unsupported notice only on their book page, while shelf links keep working.
- **Kindle screensaver week start**: Account settings can choose whether the week starts on Monday or Sunday. The month calendar and weekday labels follow the choice; Monday is the default. New copy ships in all 17 locales.
- **Reader shortcuts and navigation (#62)**: `Ctrl/Cmd+C` copies a selection (the highlighter clears the native range), and `Ctrl/Cmd+K` opens search on library, book and chapter pages. Chapter contents follow the reading position and expose a "locate current section" button; desktop and mobile gain a book-home shortcut alongside the floating Top button.
- **Kindle minimal mode enabled by default in Docker**: The official image's `CMD` and the localized documentation now include `--kindle`, so no extra flag is needed for Kindle pages.

## Improvements

- **Server and PDF performance**: A single library reconcile reuses each book's successful cache validation instead of revalidating after every conversion (#64). Full-book search builds UTF-16 offset tables only for chapters contributing to the requested page, cutting a zero-hit query on a 300-chapter Chinese index from about 529 ms to 7 ms (#65). PDF page-derived metadata is cached per Server cache generation (#67), and PDF.js full-text search reuses extracted page text through a bounded LRU of 5 million characters (#66). A new `tools/benchmark_server_reconcile.py` reports reconcile time, time to the first readable book and validation counts.

## Fixes

- PDFium rendering is serialized under a global lock, so concurrent Kindle page image generation no longer fails with "Unable to render PDF page".
- Older Chromium builds receive the JavaScript APIs required by PDF.js 6 in both the main thread and the module worker; genuinely unsupported browsers get an upgrade notice instead of a misleading retry error.
- Evicted Kindle PDF page caches are rebuilt from source instead of reporting the book as unsupported, and the setup flow accepts multiple pending nonces so repeated `/setup` loads succeed.
- PDF page load failures, empty TOCs and page jumps now have clear messages, with copy in all 17 locales.

### Affected scope

- Kindle PDF pages, shared reader templates and shortcuts cover both SSG and Server, for EPUB and PDF. The week-start preference, screensaver settings and lazy page-image cache are Server-only.
- Docker default behavior changes: the image now passes `--kindle`. Override `CMD` explicitly if Kindle pages are not wanted.
- Neither the EPUB `content/` nor the PDF cache revision changed (`server-content-v11`, `server-pdf-v2`). Kindle page images are optional or lazily generated derived content, so existing books do not need reconversion.

### Upgrade notes

- Server: deploy and restart; no EPUB or PDF reconversion is needed. Startup adds the `week_start` column to `kindle_screensavers` and advances SQLite `user_version` to 34. Back up `data/` before upgrading; rolling back to an older release requires the pre-upgrade database.
- With `--kindle`, page images for a PDF are generated on first use. They are derived cache, removed when the book cache is evicted, and regenerated the next time the book is opened.
- SSG: regenerate and republish the full static output to emit `kindle_pdf/page_N.jpg`, `kindle.html`, `kindle_chapter.html`, plus new hashed assets and locale bundles.
- Docker users: the new image enables `--kindle` by default. If you use a custom `CMD`, decide whether to add the flag yourself.
- Book URLs, CLI flag semantics and content cache formats are unchanged.
