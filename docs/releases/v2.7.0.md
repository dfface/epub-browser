# EPUB Browser v2.7.0 — 统一的 Server 书籍元数据管理

发布日期 / Release date: 2026-08-29

## 中文

v2.7.0 让 Server 模式真正接管书籍元数据。EPUB 中的书名、作者和标签只在书籍首次进入缓存时用于初始化；此后，管理员可以直接在 EPUB Browser 中维护这些信息，而无需修改或重新读取原始书籍文件。

### 新功能

- **由 SQLite 托管书籍元数据**：Server 在生成或登记书籍缓存时，将 EPUB 的书名、作者和标签导入状态数据库。完成初始化后，页面、搜索、管理功能和外部接口都以数据库中的当前值为准。
- **可编辑的书名与作者**：管理员可以在书籍管理的设置弹窗中修改书名和作者。保存后，Library、书籍详情和管理列表会立即显示新值。
- **统一的标签管理**：书籍自带标签与后来添加的标签不再分成两套。管理员可以创建、重命名、分配和删除同一组标签；重命名会更新所有关联书籍，删除标签也会同时删除其书籍关联。

### 改进

- **更清晰的管理界面**：书籍设置由行内展开改为独立弹窗，主要保存操作固定在右侧，低频的“清除 AI 结果”位于左侧。关闭、取消和破坏性操作都使用项目统一的对话框组件，不再调用浏览器原生确认框。
- **更易扫描的标签页面**：标签默认以名称、使用书籍数和操作按钮展示，只在编辑时出现输入框；表单、按钮、焦点恢复、错误提示和横向标签页导航也经过无障碍与小屏适配。
- **17 种语言使用同一套标签语义**：所有支持的界面语言都使用普通“标签”文案，不再向用户区分“AI 标签”“服务端标签”或只读的 EPUB 标签。
- **OpenAPI 1.1 反映当前元数据**：书籍响应新增结构化 `authors`，并统一返回数据库托管的 `title` 与 `tags`。原有 `author` 字符串和旧标签字段继续保留，现有客户端可以渐进迁移。
- **WebHook 跟踪元数据变化**：修改书名、作者或书籍标签，以及重命名或删除已关联标签时，都会产生 `book.updated` 事件，自动化系统可以及时同步。

### 修复

- 修复 Server 页面在数据库标签与 EPUB 内置标签之间产生两套状态、导致管理结果与书籍展示不一致的问题。
- 修复删除标签后仍可能保留书籍关联的问题。
- 修复标签校验错误把普通标签称为“AI tag”的问题；所有用户可见错误现在都使用统一标签术语。
- 修复书籍或标签保存成功后，背景 Library 列表不能立即反映新书名、作者或标签的问题。

### 升级说明

- Server 首次启动时会自动将 SQLite 状态库迁移到 schema v18，并在书库协调过程中为已有书籍初始化托管元数据。无需手动迁移，但生产部署仍建议先备份完整 `server-dir`。
- 本版本不修改 EPUB 内容缓存 schema，也不提高 Server 内容缓存修订。已有书籍无需重新转换；更新并重启 Server 即可。
- 元数据编辑、标签管理、OpenAPI 写入和 WebHook 为 **Server 专属**。SSG 仍直接使用 EPUB 元数据，不依赖 SQLite 或 `/api/*`。
- OpenAPI 保留 `author`、`ai_tags` 和 `epub_tags` 等兼容字段，但这些字段不再代表界面中的不同标签来源。新客户端应优先使用 `authors` 和 `tags`。

## English

v2.7.0 makes the Server deployment the owner of book metadata. EPUB titles, authors, and tags initialize a book when it first enters the cache; after that, administrators can maintain those values directly in EPUB Browser without editing or rereading the source book.

### New features

- **SQLite-managed book metadata**: When Server generates or registers a book cache, it imports the EPUB title, authors, and tags into the state database. Pages, search, administration, and external integrations then use the current database values.
- **Editable titles and authors**: Administrators can change a book's title and authors in the Book management settings dialog. Library, book detail, and administration views reflect saved values immediately.
- **One tag system**: Imported and subsequently created tags are no longer separate concepts. Administrators can create, rename, assign, and delete one shared set of tags; renaming updates every assigned book, while deletion also removes all book associations.

### Improvements

- **Clearer administration flow**: Book settings now open in a dedicated dialog instead of expanding inside the list. The primary save action stays on the right, while the less frequent “Clear AI results” action stays on the left. Close, cancel, and destructive actions use the shared dialog components instead of native browser confirmation prompts.
- **A more scannable tag page**: Tags normally show their name, usage count, and actions, with an input appearing only during editing. Forms, target sizes, focus restoration, error feedback, and horizontally scrollable administration tabs were also refined for accessibility and small screens.
- **One tag vocabulary in all 17 locales**: Every supported interface language now presents tags as ordinary tags, without exposing separate “AI tag,” “server tag,” or read-only EPUB-tag concepts.
- **OpenAPI 1.1 returns current metadata**: Book responses add structured `authors` and consistently return the managed `title` and `tags`. The legacy `author` string and compatibility tag fields remain available so existing clients can migrate gradually.
- **WebHooks track metadata changes**: Updating a title, authors, or book tags—and renaming or deleting an assigned tag—emits a `book.updated` event so automation can stay synchronized.

### Fixes

- Fixed Server pages maintaining separate database and EPUB tag states, which could make administration results disagree with book displays.
- Fixed tag deletion leaving book associations behind.
- Fixed validation messages describing an ordinary tag as an “AI tag.” All user-visible errors now use the unified tag vocabulary.
- Fixed the background Library view not immediately reflecting saved title, author, or tag changes.

### Upgrade notes

- On first Server startup, the SQLite state database automatically migrates to schema v18, and existing books receive managed metadata during library reconciliation. No manual migration is required, though production deployments should back up the complete `server-dir` first.
- This release does not change the EPUB content-cache schema or raise the Server content-cache revision. Existing books do not need reconversion; update and restart Server.
- Metadata editing, tag administration, OpenAPI writes, and WebHooks are **Server-only**. SSG continues to use EPUB metadata directly and does not depend on SQLite or `/api/*`.
- OpenAPI retains compatibility fields such as `author`, `ai_tags`, and `epub_tags`, but they no longer represent separate tag sources in the interface. New clients should prefer `authors` and `tags`.
