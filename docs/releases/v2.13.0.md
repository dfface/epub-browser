# v2.13.0

## 新功能

- **书库排序（#22）**：主书库、Kindle 极简书架和管理后台共用同一套排序规则：手动顺序、书名 A–Z / Z–A、最近添加、最近更新。排序先作用于全部可见书籍，再应用分页。Server 按账户保存手动顺序，SSG 保存在浏览器本地。
- **书库目录分页**：主书库每页显示 24 本，提供上一页/下一页、页码跳转和页码状态；搜索与排序结果同样分页。
- **个人生词本（#27，仅 Server）**：阅读时查词会按账户记录单词、书籍与章节（EPUB 章节或 PDF 页）来源。生词本支持搜索、掌握状态（新词 / 学习中 / 已掌握）、首次与最近查询时间、跳回来源，以及删除单词或移除某本书的查询记录。新增 Session 接口 `/api/vocabulary`、PAT 接口 `/api/v1/me/vocabulary` 和 `vocabulary:read`、`vocabulary:write` 两个 scope。
- **公开 API 列表游标分页与文档增强（#28）**：列表接口统一返回 `items` 与 `next_cursor`，默认 `limit=24`、最大 100；保持筛选条件不变，把 `next_cursor` 作为 `cursor` 获取下一页，`null` 表示末页。支持按书籍、章节、格式、掌握状态等筛选，并可用 `fields` 选择标注字段。OpenAPI 3.1 文档与 `/api-docs` 为每个操作新增参数说明、curl 请求示例和复制按钮。新增文案覆盖 17 种语言。

## 修复

- 管理后台的书籍元数据缺失或损坏时，书库元数据仍可从书籍记录回退显示书名、作者和标签，不再跳过该书。
- 词典入口会携带当前章节或页码，生词本可准确记录查词发生的位置。

### 影响范围

- 排序与书库分页覆盖 SSG 与 Server 的主书库、Kindle 书架；排序也用于管理后台书籍列表。
- 生词本、公开 API 分页与 API 文档增强仅在 Server 提供（需登录或 PAT）；SSG 不加载 Server 专属资源，也不依赖 `/api/*`。
- EPUB `content/` 与 PDF 缓存修订均未变（`server-content-v11`、`server-pdf-v2`），本次只涉及页面、资源、i18n 与应用数据。

### 升级说明

- Server：部署并重启即可，无需重新转换 EPUB 或 PDF。启动时自动创建 `library_orders`、`vocabulary_words`、`vocabulary_lookups` 表，并将 SQLite `user_version` 提升到 30；升级前建议备份 `data/`，回退到旧版本需恢复升级前的数据库。
- 公开 API 客户端：列表默认响应由旧格式改为 `items` / `next_cursor`。仍依赖 `words` 响应的客户端可传 `page=1` 或 `page_size` 使用原有分页格式，但这两种参数不能与 `cursor`、`limit` 同时使用。
- SSG：需重新生成并整站发布静态输出，以应用排序、分页、书籍时间戳元数据和新增哈希资源。
- 书籍 URL、CLI 参数和内容缓存格式均未变化；既有 PAT 仍可用，新 scope 仅用于生词本接口。

## Features

- **Library sorting (#22)**: The main catalogue, minimal Kindle bookshelf and administration book list now share one set of sort orders: manual order, title A–Z / Z–A, recently added and recently updated. Sorting applies to all visible books before pagination. Server persists manual order per account; SSG keeps it in the browser.
- **Catalogue pagination**: The main library shows 24 books per page with previous/next controls, page jump and a page-status label. Search and sort results are paginated the same way.
- **Personal vocabulary lists (#27, Server only)**: Dictionary lookups while reading are recorded per account with the word, book and source location (an EPUB chapter or PDF page). The vocabulary panel supports search, mastery states (new / learning / mastered), first and latest lookup times, jumping back to the source, and deleting a word or removing its lookups from one book. New Session endpoints `/api/vocabulary`, PAT endpoints `/api/v1/me/vocabulary`, and the `vocabulary:read` and `vocabulary:write` scopes were added.
- **Cursor pagination for public API lists and richer API docs (#28)**: List endpoints now return `items` and `next_cursor`, with a default `limit` of 24 and a maximum of 100. Pass `next_cursor` as `cursor` with unchanged filters to fetch the next page; `null` marks the last page. Filters cover book, chapter, format and mastery, while `fields` selects annotation fields. The OpenAPI 3.1 document and `/api-docs` now show parameter details, curl examples and a copy button for every operation. New copy ships in all 17 locales.

## Fixes

- When managed book metadata is missing or invalid, library metadata falls back to the book record so title, authors and tags still render instead of dropping the book.
- The dictionary entry now carries the current chapter or page index, so vocabulary sources are recorded accurately.

### Affected scope

- Sorting and catalogue pagination cover the main library and Kindle bookshelf in both SSG and Server; sorting also applies to the administration book list.
- Vocabulary lists, public API pagination and the API documentation enhancements are Server-only (session login or PAT). SSG loads no Server-only assets and depends on neither `/api/*` nor login state.
- Neither the EPUB `content/` nor the PDF cache revision changed (`server-content-v11`, `server-pdf-v2`); this release touches pages, assets, i18n and application data only.

### Upgrade notes

- Server: deploy and restart; no EPUB or PDF reconversion is needed. Startup automatically creates the `library_orders`, `vocabulary_words` and `vocabulary_lookups` tables and advances SQLite `user_version` to 30. Back up `data/` before upgrading; rolling back to an older release requires the pre-upgrade database.
- Public API clients: the default list response changed from the legacy shape to `items` / `next_cursor`. Clients relying on the old `words` response can pass `page=1` or `page_size` to keep the legacy pagination format, but these parameters cannot be combined with `cursor` or `limit`.
- SSG: regenerate and republish the full static output to pick up sorting, pagination, book timestamp metadata and new hashed assets.
- Book URLs, CLI flags and content cache formats are unchanged. Existing PATs keep working; the new scopes apply only to vocabulary endpoints.
