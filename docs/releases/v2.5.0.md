# EPUB Browser v2.5.0 — 开放接口、自动化与完整多语言界面

发布日期 / Release date: 2026-08-28

## 中文

v2.5.0 让 EPUB Browser 更容易接入个人工具和自动化流程，同时把完整阅读体验扩展到 17 种界面语言。Server 管理员可以安全地开放版本化 API、配置带签名的 WebHook；读者则获得更紧凑的 AI 问答、标注分享和小屏阅读体验。

### 新功能

- **带作用域的个人访问令牌（PAT）**：Server 用户可在账户设置中创建、查看使用状态和撤销令牌，并选择固定有效期或永不过期。令牌仅在创建时完整显示，可按书库、书架、进度、标注和书评分别授予只读或写入权限。
- **版本化 OpenAPI 接口**：外部客户端可通过 `Authorization: Bearer <PAT>` 调用 `/api/v1/*`，读取获授权的书籍、目录与已清洗章节正文，也可管理令牌所有者的书架、阅读进度、标注和书评。章节正文支持已清洗 HTML 与纯文本格式。
- **管理员数据读取接口**：具有 `admin:data:read` 的管理员 PAT 可只读访问所有用户的书架、进度、标注、书评、阅读会话与洞察、AI 对话和 AI 结果；密码、会话 Cookie、PAT 密文和服务密钥不会通过这些接口公开。
- **可浏览的 API 文档**：登录后可在 `/api-docs` 按分组、方法、路径、作用域或描述检索接口，并从 `/openapi.json` 下载 OpenAPI 3.1 文档。页面品牌、导航和响应式布局与 Library 主站保持一致。
- **带签名的 WebHook 自动化**：管理员可配置、测试、停用、轮换密钥和删除 WebHook 端点，订阅书籍创建、更新、移除、转换成功或失败，以及书评创建、更新或删除事件。投递记录持久化保存，非 2xx 响应会自动重试，签名密钥仅在创建或轮换时显示。
- **新增 12 种界面语言**：在英语、简体中文、繁体中文、日语和韩语之外，新增西班牙语、德语、法语、俄语、意大利语、巴西葡萄牙语、阿拉伯语、印尼语、印地语、越南语、泰语和马来语。Library、Book、Chapter、账户与管理面板、AI 阅读和 API Docs 的可见文案均已覆盖。

### 改进

- **AI 问答更容易回看**：Book 与 Chapter 共用的问问 AI 侧栏新增问题定位轨道，问题较多时可快速跳转到每次用户提问；滚动条被视觉隐藏，同时保留滚动能力。
- **更清晰的提问起点**：空对话提供多条完整、可直接使用的问题示例，每条独占一行；章节标题保留为当前上下文，不再重复展示多余的引导标题。
- **更统一的 AI 面板**：全屏、关闭、输入框和提交按钮与主站设计语言对齐；标题栏与导航栏高度一致，小屏可全屏打开，并能从移动控制区进入问问 AI。
- **完整的 AI 回答排版**：Book 与 Chapter 的问问 AI 现在共用安全的 Markdown 渲染组件，能够正确呈现连续编号、嵌套列表、分隔线、引用、代码块与表格。历史回答无需重新生成即可按新格式展示，模型输出中的原始 HTML、危险链接和远程图片也不会被直接加载。
- **规范化标注分享**：标注汇总中的每个条目都可单独复制；整书复制和导出采用一致的 Markdown 结构，保留书名、章节、原文、笔记和来源链接。
- **更可靠的公开资源边界**：登录页、API Docs 和主站共用 Library 品牌图标；无需登录即可加载的图标、清单和启动资源不再被鉴权误拦截。

### 修复

- 修复部分语言下 Book 页面在窄屏产生横向溢出、主要阅读操作被裁切的问题。
- 修复阿拉伯语界面会把非阿拉伯语书名、目录和章节正文错误排成从右到左的问题；应用界面仍保持 RTL，EPUB 内容按自身语言自动确定方向。
- 章节目录的云端同步状态在小屏只显示紧凑云朵图标，宽屏显示“云朵 + 同步”，避免长语言文案或用户名挤压章节标题。
- 已完成 AI 阅读的章节在小屏只显示紧凑魔杖图标，宽屏显示“魔杖 + AI 阅读”，与云端同步状态采用一致的响应式标记规则。
- 修复 WebHook 工作线程在不同事件循环间相互干扰、过期投递租约无法恢复，以及转换事件遗漏的问题。

### 升级说明

- Server 首次启动时会自动将 SQLite 状态库迁移到 schema v17。无需手动迁移，但生产部署仍建议先备份完整 `server-dir`。
- PAT、OpenAPI 写入接口、管理员跨用户读取接口和 WebHook 均为 **Server 专属**；SSG 输出不会包含这些能力。
- 管理员本来即可直接访问 Server 数据库；本版本进一步允许拥有 `admin:data:read` 作用域的管理员 PAT 通过 API 读取所有用户的非密钥数据。请只向可信自动化系统签发该作用域，并像保护管理员凭据一样保护令牌。
- 无需重新转换 EPUB，也无需提高 Server EPUB 内容缓存修订。更新并重启 Server 即可获得新页面、翻译与接口；SSG 部署请重新生成并完整发布输出目录。
- WebHook 目标应使用 HTTPS，并在接收端验证时间戳和 HMAC 签名。书评事件只包含用户 ID、书籍 ID、动作和时间，不包含评分或书评正文。

## English

v2.5.0 makes EPUB Browser easier to connect to personal tools and automation while extending the complete reading experience to 17 interface languages. Server administrators can expose a scoped, versioned API and configure signed WebHooks; readers get a denser Ask AI workflow, better annotation sharing, and more reliable small-screen layouts.

### New features

- **Scoped personal access tokens**: Server users can create, inspect, and revoke PATs in Account settings, choosing a fixed lifetime or no expiration. A token is shown in full only once and can receive separate read or write scopes for the library, bookshelf, progress, annotations, and reviews.
- **Versioned OpenAPI endpoints**: External clients can call `/api/v1/*` with `Authorization: Bearer <PAT>` to read authorized books, tables of contents, and sanitized chapter content, or manage the token owner's bookshelf, progress, annotations, and reviews. Chapter content is available as sanitized HTML or plain text.
- **Administrator data access**: An administrator PAT with `admin:data:read` can read every user's bookshelf, progress, annotations, reviews, reading sessions and insights, AI conversations, and AI results. Passwords, session cookies, PAT secrets, and service credentials are never exposed by these endpoints.
- **Browsable API reference**: Signed-in users can search `/api-docs` by group, method, path, scope, or description and download the OpenAPI 3.1 document from `/openapi.json`. Branding, navigation, and responsive behavior now match the Library application.
- **Signed WebHook automation**: Administrators can create, test, disable, rotate, and delete WebHook endpoints for book creation, updates, removal, conversion success or failure, and review creation, updates, or deletion. Deliveries are durable, non-2xx responses are retried, and signing secrets are shown only on creation or rotation.
- **Twelve additional interface languages**: Spanish, German, French, Russian, Italian, Brazilian Portuguese, Arabic, Indonesian, Hindi, Vietnamese, Thai, and Malay join English, Simplified Chinese, Traditional Chinese, Japanese, and Korean. Visible copy is covered across Library, Book, Chapter, Account and Administration, AI reading, and API Docs.

### Improvements

- **Faster navigation through long AI conversations**: The shared Book and Chapter Ask AI sidebar now has a question rail for jumping to each user prompt. The visual scrollbar is hidden without removing scrolling.
- **Better conversation starters**: Empty conversations offer several complete, ready-to-use questions on separate rows. The chapter title remains visible as context without a redundant introductory heading.
- **A consistent AI panel**: Fullscreen, close, composer, and submit controls now match the main design system. Header heights align, fullscreen works on small screens, and Ask AI is available from mobile controls.
- **Complete formatting for AI answers**: Ask AI on Book and Chapter pages now shares a safe Markdown renderer for continuous numbering, nested lists, horizontal rules, quotations, code blocks, and tables. Existing answers render correctly without regeneration, while raw model HTML, unsafe links, and remote images are not loaded directly.
- **Standards-friendly annotation sharing**: Every annotation in the summary can be copied independently. Whole-book copy and export use the same Markdown structure with book, chapter, quotation, note, and source-link context.
- **Reliable public assets**: Login, API Docs, and the main application share the Library mark. Icons, manifests, and bootstrap assets that must load before authentication are no longer blocked by authorization checks.

### Fixes

- Fixed narrow Book layouts that could overflow horizontally and clip primary reading actions in some languages.
- Fixed Arabic UI direction leaking into non-Arabic book titles, tables of contents, and chapter text. The application shell remains RTL while EPUB content chooses its own direction.
- Cloud-sync state in the chapter list now uses a compact cloud icon on small screens and “cloud + sync” on wider screens, so long translations and usernames no longer crowd chapter titles.
- Chapters with completed AI reading now use a compact wand icon on small screens and “wand + AI reading” on wider screens, matching the responsive cloud-sync marker pattern.
- Fixed WebHook workers interfering across event loops, expired delivery leases not recovering, and missing conversion events.

### Upgrade notes

- On first Server startup, the SQLite state database automatically migrates to schema v17. No manual migration is required, though production deployments should back up the complete `server-dir` first.
- PATs, OpenAPI write operations, administrator cross-user reads, and WebHooks are **Server-only** and are not included in SSG output.
- Administrators could already open the Server database directly. This release also allows administrator PATs carrying `admin:data:read` to read every user's non-secret application data through the API. Grant this scope only to trusted automation and protect such tokens like administrator credentials.
- No EPUB reconversion or Server EPUB-content-cache revision is required. Restart an updated Server deployment to apply pages, translations, and APIs. Regenerate and publish the complete output directory for SSG deployments.
- Use HTTPS for WebHook destinations and verify timestamps and HMAC signatures at the receiver. Review events include only user ID, book ID, action, and time—never rating or review text.
