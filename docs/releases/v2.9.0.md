# EPUB Browser v2.9.0 — OIDC 单点登录与安全用户删除

发布日期 / Release date: 2026-08-29

## 中文

v2.9.0 为 Server 部署加入通用 OpenID Connect（OIDC）登录。管理员可以接入 Authelia、Authentik、Keycloak 或其他兼容 Provider，让读者绑定现有账户或按策略自动创建成员，同时继续使用 EPUB Browser 原有的权限、书架、标注和阅读数据。本版本也补齐了管理员删除用户的安全流程，在操作前清楚展示会受影响的数据。

### 新功能

- **通用 OIDC 单点登录**：管理后台新增独立的 OIDC 配置页，可设置 Provider 名称、Issuer、Client ID、Client Secret、Redirect URI、Scopes 和用户名 Claim。登录入口使用管理员设置的 Provider 名称，不绑定特定厂商。
- **绑定现有账户或自动创建成员**：未知外部身份可以通过一次本地用户名和密码验证绑定已有账户；管理员也可以开启自动创建，新用户将以普通成员身份安全加入。OIDC Claim 不会自动授予管理员权限。
- **账户身份管理**：成员可以在账户设置中查看和关联外部身份；管理员可以在用户管理中查看绑定状态并解除错误关联。系统会阻止移除密码为空用户的唯一登录方式。
- **安全删除用户**：没有关联数据的用户经过普通确认即可删除；有关联数据时，界面会按类别列出将删除或保留转交的数据，并要求精确输入用户名进行二次确认。

### 安全性与可靠性

- OIDC 使用 Authorization Code Flow、PKCE、state、nonce 和短时一次性事务，并验证 Provider discovery、Issuer、签名、Audience、时间范围和回调地址。
- 外部身份只由准确的 `(issuer, subject)` 组合识别，不会根据可变化的用户名、显示名称或邮箱自动绑定账户。
- Provider Token 不会持久化；Client Secret 不会通过管理 API 读回或写入页面。管理员本地密码登录始终保留为恢复入口。
- 删除用户在单个数据库事务中重新计算影响并校验外键。共享词典等保留数据会转交给执行删除的管理员，避免留下无效归属。
- 登录、关联、账户与删除界面已覆盖 17 种语言，并针对桌面、移动端、深色模式、键盘操作和至少 44px 触控目标完成验证。

### 升级说明

- Server 首次启动时会自动将 SQLite 状态库迁移到 schema v20，增加 OIDC 设置、外部身份和短时登录事务。无需手动迁移，但生产部署仍建议先备份完整 `server-dir`。
- 本版本新增运行依赖 `Authlib` 和 `httpx`；通过 PyPI 或 Docker 升级会自动安装，源码部署需要重新安装项目依赖。
- 不改变 EPUB 或 PDF 内容缓存结构及 revision，已有书籍无需重新转换。OIDC 与用户删除仅适用于 Server，SSG 输出不包含相关配置、接口或运行时依赖。
- 升级并重启 Server 后，在管理后台的 **OIDC 登录** 页完成 Provider 配置。Redirect URI 必须与 Provider 中登记的地址完全一致。

## English

v2.9.0 adds standards-based OpenID Connect (OIDC) sign-in to Server deployments. Administrators can connect Authelia, Authentik, Keycloak, or another compatible Provider, let readers link existing accounts or provision members according to policy, and keep using EPUB Browser's existing permissions, bookshelves, annotations, and reading data. This release also completes administrator user deletion with a clear preview of affected data.

### New features

- **Generic OIDC single sign-on**: A dedicated administration page configures the Provider name, issuer, client ID, client secret, redirect URI, scopes, and username claim. The sign-in action uses the configured display name and contains no vendor-specific behavior.
- **Link an existing account or provision a member**: An unknown external identity can prove ownership of an existing account once with its local username and password. Administrators can instead enable automatic provisioning, which always creates a regular member; OIDC claims never grant administrator access.
- **Identity management**: Members can view and link their external identity from account settings. Administrators can inspect identity status and remove an incorrect link from user management. EPUB Browser prevents a passwordless user from removing their only usable sign-in method.
- **Guarded user deletion**: A user with no related data needs a standard confirmation. When related data exists, the dialog groups everything that will be deleted or retained and transferred, then requires the exact username before deletion can proceed.

### Security and reliability

- OIDC uses Authorization Code Flow, PKCE, state, nonce, and short-lived single-use transactions, with validation of Provider discovery, issuer, signature, audience, time bounds, and callback URI.
- External identities are recognized only by the exact `(issuer, subject)` pair. Mutable usernames, display names, and email addresses are never automatic account-binding evidence.
- Provider tokens are not persisted, and client secrets are never returned by the administration API or placed in the page. Local administrator password sign-in remains available as a recovery path.
- User deletion recomputes its impact inside one database transaction and verifies foreign-key integrity. Retained shared dictionaries and similar ownership records transfer to the administrator performing the deletion.
- Sign-in, association, account, and deletion surfaces are localized across all 17 supported languages and verified for desktop, mobile, dark mode, keyboard operation, and 44-pixel touch targets.

### Upgrade notes

- On first Server startup, SQLite automatically migrates to schema v20 for OIDC settings, external identities, and short-lived login transactions. No manual migration is required, though production deployments should back up the complete `server-dir` first.
- Runtime dependencies now include `Authlib` and `httpx`. PyPI and Docker upgrades install them automatically; source deployments should reinstall project dependencies.
- This release does not change EPUB or PDF content-cache schemas or revisions, so existing books do not need reconversion. OIDC and user deletion are Server-only and do not appear in SSG configuration, APIs, or runtime assets.
- After upgrading and restarting Server mode, configure the Provider under **OIDC Login** in administration. The redirect URI must exactly match the URI registered with the Provider.
