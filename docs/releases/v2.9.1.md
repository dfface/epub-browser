# EPUB Browser v2.9.1 — 可靠的 OIDC 账户关联与安全日志

发布日期 / Release date: 2026-08-29

## 中文

v2.9.1 修复了部分从历史版本升级的 Server 在提交 OIDC 账户关联时返回 500 的问题，并完善了用于 Docker 和生产环境排障的日志安全边界。升级后，旧身份表会自动、安全地迁移，不需要手工修改 SQLite。

### 修复

- **OIDC 账户关联不再因旧表结构失败**：历史版本曾创建过一张字段较少的 `user_identities` 表。v2.9.0 无法识别该遗留结构，导致关联现有账户时出现服务器错误。schema v21 会在一个事务中识别并重建旧表，然后继续完成关联。
- **保留历史身份记录**：如果旧身份表已有记录，迁移会保留 Provider、Subject、本地用户、显示名称和时间信息，并校验迁移前后记录数及外键完整性。遇到未知结构时会停止迁移，避免静默损坏数据。

### 日志与安全性

- **可关联的服务器错误**：未处理的服务器错误会返回不含内部细节的通用响应，并附带 `X-Request-ID`；服务端错误日志使用同一 ID，便于从用户反馈定位对应堆栈。
- **OIDC 参数不再进入访问日志**：HTTP 访问日志会移除查询字符串，避免 Authorization Code、state 和短时关联 token 被写入 Docker 日志。
- **明确的日志级别**：新增 `--log-level debug|info|warning|error`，默认 `error`，避免普通信息和警告打断 SSG 的终端进度。`--log` 继续作为 `--log-level info` 的兼容别名；HTTP 访问日志只在 `info` 和 `debug` 下开启。

### 升级说明

- Server 首次启动时会自动将 SQLite 状态库迁移到 schema v21。生产升级前仍建议备份完整的 `server-dir`。
- 本版本不改变 EPUB 或 PDF 内容缓存结构及 revision，已有书籍无需重新转换。
- 使用 Docker 时升级镜像并重启容器即可。若需要运行详情和 HTTP 访问日志，请显式添加 `--log` 或 `--log-level info`。

## English

v2.9.1 fixes a server error that could occur when linking an OIDC identity on Server installations upgraded from certain historical versions. It also strengthens logging for Docker and production diagnostics without exposing OIDC query parameters. The legacy identity table is repaired automatically; no manual SQLite edits are required.

### Fixes

- **Reliable OIDC account linking after upgrades**: A historical release could leave behind a smaller `user_identities` table. v2.9.0 did not distinguish that legacy contract and could fail when an existing account was linked. Schema v21 detects and rebuilds the old table in one transaction before association continues.
- **Existing identity records are preserved**: When the legacy table contains data, migration retains the Provider, subject, local user, display name, and timestamps, then verifies row counts and foreign-key integrity. An unknown table contract stops migration instead of risking silent data damage.

### Logging and security

- **Correlatable server errors**: An unhandled server failure returns the same generic response without internal details and now includes `X-Request-ID`. Server error logs use the matching ID so an operator can locate the relevant stack trace.
- **OIDC parameters stay out of access logs**: HTTP access logging removes query strings so authorization codes, state values, and short-lived association tokens are not written to Docker logs.
- **Explicit log levels**: `--log-level debug|info|warning|error` is available with `error` as the default, keeping routine messages and warnings out of SSG terminal progress. `--log` remains an alias for `--log-level info`; HTTP access logging is enabled only at `info` and `debug`.

### Upgrade notes

- Server automatically upgrades its SQLite state database to schema v21 on first startup. Back up the complete `server-dir` before a production upgrade as usual.
- EPUB and PDF content-cache schemas and revisions are unchanged, so existing books do not need reconversion.
- For Docker, update the image and restart the container. Add `--log` or `--log-level info` explicitly when operational and HTTP access logs are needed.
