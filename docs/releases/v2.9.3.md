# EPUB Browser v2.9.3 — 登录、汇总与翻页体验修复

发布日期 / Release date: 2026-08-30

## 中文

v2.9.3 修复慢速网络下重复提交登录表单时，用户已经登录成功却仍看到 403 和“用户名或密码不正确”的问题。登录结果现在会按真实原因反馈；AI 阅读汇总和标注汇总不再预先下载页面尚未使用的大体积详情数据；桌面和移动端翻页交互、分页排版与全站通知也完成了一轮集中修复。

### 修复与改进

- **重复登录直接进入目标页面**：第一个登录请求成功建立会话后，来自同一旧登录页的重复请求会复用现有会话并返回安全处理后的跳转地址，不再因缺少 CSRF token 返回 403，也不会再次验证密码或替换会话。
- **避免表单重复提交**：登录请求进行期间会禁用提交按钮并忽略后续提交，慢速网络或连续点击不再产生多个并发登录请求。
- **准确显示失败原因**：只有服务端明确返回 `invalid_credentials` 时才显示“用户名或密码不正确”并标记输入框；请求校验失效、尝试次数过多、网络不可达和未知服务错误分别显示对应提示。
- **AI 阅读分层加载**：书籍列表通过 `/api/ai/library?view=summary` 只读取书籍信息和结果数量；进入某本书后，再通过该书的 results 接口读取实际展示的标题、摘要、语言、版本、时间和删除权限。完整 AI 阅读正文及未使用的生成配置字段不再进入汇总响应。
- **标注按需加载**：标注总览通过 `view=summary` 由 SQLite 直接按书统计数量和最近更新时间，不再一次性返回所有标注正文、笔记和定位信息；进入某本书后才加载该书的完整标注。
- **兼容现有 API 调用**：两个接口未传 `view` 时仍返回原有完整结构，已有客户端无需同步升级。
- **阅读导航统一进入工具栏**：桌面章节页删除底部 navigation 和重复的“书籍”入口；滚动模式的上一章、下一章常驻右侧阅读工具栏，翻页模式在两者之间按顺序显示上一页、重新加载分页和下一页。页码跳转改为与设置一致的工具栏按钮，点击后在按钮旁滑入紧凑页码窗口；移动端保留底部布局，并在翻页模式增加页码跳转按钮。
- **翻页模式只保留可用操作**：桌面和移动阅读工具栏都会隐藏不受支持的“AI 阅读”和“问问 AI”。翻页模式设置会隐藏连续滚动、章节侧栏、自动隐藏章节侧栏和导航栏行为；自动隐藏阅读工具栏仍可正常开关，“点击翻页”移入设置且只在翻页模式可用。
- **分页排版使用真实可读区域**：章节模板不再生成底部导航；滚动模式正文卡片与顶部导航、底部页脚保持一致留白，翻页正文则预留自适应上下安全边距。`createPages()` 首次分页直接按最终样式计算可用高度；用户调整窗口宽度或高度时会重新计算页数，并按原阅读比例定位到最接近的页面。高度变化只响应浏览器 `resize`，不会加入可能由分页重排反复触发的尺寸观察链。
- **更安全的点击翻页**：首次进入翻页模式时默认启用点击翻页，设置中的信息提示会说明左右翻页区和移动端中间区域。文本选择、拖动、长按、双击选词和取消的触控手势不会触发翻页，也不会误切换移动端纯净阅读模式；用户明确关闭过该功能时仍保留原偏好。
- **页按钮可以连续跨章**：当前章第一页仍可通过“上一页”进入上一章，最后一页仍可通过“下一页”进入下一章；只有到达整本书真正的开头或结尾时按钮才会禁用。
- **通知视觉统一**：纯净模式、点击翻页、分页重载及其他历史提示统一使用标准通知组件的主题表面、文字、边框、圆角与阴影。成功、信息、警告和错误不再使用整块高饱和背景，只保留克制的语义色标记，同时维持 `status`/`alert` 无障碍语义。

### 影响范围

- **受影响版本**：截至 v2.9.2 的 Server 部署。
- **触发条件**：登录响应返回前重复提交表单；慢速网络、多标签页或连续点击会提高出现概率。
- **部署与格式范围**：登录和汇总 API 修复仅影响 Server；共享阅读器的工具栏、分页、手势和通知改进同时适用于 SSG 与 Server，并覆盖 EPUB/PDF 支持的对应阅读模式。EPUB/PDF 内容缓存不受影响，AI 阅读仍仅适用于 EPUB。

### 升级说明

- v2.9.3 不新增 SQLite migration，也不改变 EPUB/PDF 内容缓存 revision；升级镜像并重启即可，已有书籍无需重新转换。
- 登录 nonce 仍用于保护匿名登录请求。本次修复只把已经成功登录后的同源旧表单重复请求视为幂等跳转，不放宽其他写请求的 CSRF 校验。

## English

v2.9.3 fixes a slow-network sign-in race where an account was already authenticated but a repeated form submission still produced a 403 and was misleadingly shown as an incorrect username or password. Sign-in failures now reflect their actual cause, AI-reading and annotation summaries avoid downloading large details that the overview has not yet used, and page-turning layout, interactions, and notifications receive a focused reliability pass across desktop and mobile.

### Fixes and improvements

- **Repeated sign-in goes to the requested page**: After the first request establishes a session, a repeated request from the same stale sign-in page reuses that session and returns a sanitized redirect. It no longer fails CSRF validation, rechecks the password, or replaces the session.
- **Prevent duplicate form submissions**: The submit button is disabled while sign-in is pending, and additional submissions are ignored. Slow connections and repeated clicks therefore do not create concurrent login requests.
- **Accurate failure messages**: Only an explicit `invalid_credentials` response shows the username-or-password message and marks those fields invalid. Expired request validation, rate limiting, network failures, and unknown service errors each use a distinct message.
- **Layered AI-reading loading**: `/api/ai/library?view=summary` returns only book information and result counts. Opening a book then fetches its displayed titles, summaries, languages, versions, timestamps, and delete permissions from that book's results endpoint. Full AI content and unused generation settings no longer enter summary responses.
- **Annotations load on demand**: The annotation overview uses `view=summary`, letting SQLite aggregate each book's count and latest update without returning every highlight, note, or position. Full annotations are fetched only after a book is opened.
- **Existing API clients remain compatible**: Omitting `view` preserves the original complete response for both endpoints.
- **Reading navigation is consolidated in the toolbar**: Desktop chapter pages no longer render the bottom navigation or its duplicate Book action. Previous and Next Chapter remain in the right reading toolbar in scrolling mode; page-turning mode inserts Previous Page, Reload Pagination, and Next Page between them. Page Jump is now a normal toolbar action that opens a compact anchored page-number panel. Mobile keeps its bottom layout and gains a page-jump action in page-turning mode.
- **Page-turning mode shows only supported controls**: Unsupported AI Reading and Ask AI actions are hidden in both desktop and mobile toolbars. Continuous scroll, chapter-sidebar, chapter-sidebar auto-hide, and navigation-behavior settings are hidden while page-turning mode is active; reading-toolbar auto-hide remains available. Click to Turn Page now lives in Settings and is enabled only in page-turning mode.
- **Pagination measures the real reading area**: The chapter template no longer emits bottom navigation. Scrolling cards now keep matching space below the top navigation and above the footer, while paginated content receives adaptive top and bottom safe space. The first `createPages()` pass measures the final styled height directly; user-driven window width or height changes recalculate the page count and return to the nearest proportional page. Height changes are handled only by browser `resize`, avoiding a resize-observer feedback chain during pagination reflow.
- **Safer click-to-turn gestures**: Click to Turn Page defaults on for readers entering page-turning mode for the first time, and its Settings help explains the left/right page zones and the mobile center zone. Text selection, dragging, long presses, double-click selection, and cancelled pointer gestures no longer turn pages or accidentally toggle mobile distraction-free reading. An explicitly saved off preference remains respected.
- **Page buttons continue across chapters**: Previous Page remains available on a chapter's first page when a previous chapter exists, and Next Page remains available on the last page when another chapter follows. The controls are disabled only at the true beginning or end of the book.
- **Notifications share one visual standard**: Distraction-free reading, click-to-turn, pagination reload, and other legacy messages now use the standard notification surface, text, border, radius, and shadow. Success, information, warning, and error states use restrained semantic accents instead of full saturated fills while preserving accessible `status` and `alert` semantics.

### Affected scope

- **Affected versions**: Server deployments through v2.9.2.
- **Trigger**: The sign-in form is submitted again before its first response completes; slow networks, multiple tabs, and repeated clicks make this more likely.
- **Deployment and format scope**: Sign-in and summary API fixes are Server-only. Shared-reader toolbar, pagination, gesture, and notification improvements apply to both SSG and Server and to the corresponding EPUB/PDF reading modes. EPUB/PDF content caches are unchanged; AI reading remains EPUB-only.

### Upgrade notes

- v2.9.3 adds no SQLite migration and changes neither the EPUB nor PDF content-cache revision. Pull the updated image and restart; existing books do not need reconversion.
- The anonymous sign-in nonce remains in place. This fix treats only a same-origin repeated request from a stale sign-in page after successful authentication as an idempotent redirect; CSRF checks for other state-changing requests remain unchanged.
